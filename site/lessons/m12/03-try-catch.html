try/catch: поймать и обработать

Хватит падать. Научимся перехватывать (ловить) исключение и делать «план Б»: показать понятное сообщение, переспросить пользователя, продолжить работу. А в Мастерской напишем ввод числа, который не ломается ни от какого мусора.

try — попробуй, catch — план Б

Опасный код кладут в блок try («попробуй»). Сразу за ним пишут блок catch («поймай»): он перехватывает исключение нужного типа, если его выбросили внутри try, и говорит, что делать дальше:

import java.util.Scanner;

public class AgeInput {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        String text = scanner.nextLine();
        try {
            int age = Integer.parseInt(text);
            System.out.println("Через год тебе будет " + (age + 1));
        } catch (NumberFormatException e) {
            System.out.println("«" + text + "» — это не число");
        }
        System.out.println("Спасибо!");
    }
}
try { … }

Охраняемый участок. Java выполняет его строку за строкой, как обычно, но «следит»: не вылетит ли исключение.

catch (NumberFormatException e)

Обработчик. В скобках — какой тип исключений перехватываем и имя переменной, в которую попадёт ссылка на перехваченный объект исключения. Обычно её называют e (от exception). Перехватывается только этот тип — ArithmeticException сюда не попадёт.

{ System.out.println(…); }

План Б: что делать вместо упавшего кода. Здесь — вежливое сообщение.

System.out.println("Спасибо!");

После try/catch программа продолжает работу в любом случае: исключение перехвачено, авария отменяется.

Аналогия: страховочная сетка

Акробат (код в try) работает как обычно. Сорвался (исключение) — падает не на арену, а в сетку (catch). Представление продолжается. Нет сетки — падение заканчивает шоу.

Что выполнится, а что — нет

Главное правило: как только в try вылетело исключение, остаток try пропускается. Java не возвращается назад, чтобы «доделать».

try {
    System.out.println("1");
    int x = Integer.parseInt("сорок");
    System.out.println("2");
} catch (NumberFormatException e) {
    System.out.println("3");
}
System.out.println("4");
Предскажи: что напечатает этот код?

1, 3, 4 — каждое на своей строке. «1» печатается, parseInt("сорок") выбрасывает исключение, «2» пропускается, срабатывает catch («3»), потом код после («4»). А если бы там было parseInt("40") — вывелось бы 1, 2, 4: catch выполняется только при исключении.

С перехваченным объектом исключения e можно работать — это обычный объект, у него можно вызывать методы:

КодЧто даст для parseInt("сорок")
e.getMessage()метод возвращает сообщение: For input string: "сорок"
System.out.println(e)тип + сообщение: java.lang.NumberFormatException: For input string: "сорок"
e.printStackTrace()полный stack trace, как при падении, но программа не падает
Переменные из try не видны снаружи

age, объявленная внутри try, живёт только в его фигурных скобках — как переменная цикла в модуле 5. Нужна после try/catch — объяви её до try. И дай ей значение в обоих путях, иначе компилятор скажет variable age might not have been initialized.

🛠 Мастерская: ввод числа с повтором

Задача. Метод readInt(Scanner scanner) читает строки, пока пользователь не введёт целое число, и возвращает его. На каждый неудачный ввод — сообщение. Решаем по шаблону Мастерской.

  1. Пойми задачу. Вход — любые строки, выход — одно целое число. Примеры: «42» → 42. «abc» → переспросить. « 7 » → 7 (пробелы по краям уберём). Пустая строка → переспросить. «3.5» → переспросить: не целое. «99999999999» → переспросить: не влезает в int, parseInt тоже выбросит NumberFormatException.
  2. Реши руками. «Читаю строку. Пробую превратить в число. Не вышло — говорю об этом и читаю следующую. Вышло — всё, ответ готов». Повторяется пара «прочитать + попробовать» — значит, цикл. Сколько раз — заранее неизвестно.
  3. Роли переменных. line — временная: текущая попытка, на следующем круге её заменит новая. Счётчика нет. Ответ отдаём сразу через return — он же и выход из цикла.
  4. Псевдокод. «Повторять всегда: прочитать строку и обрезать пробелы; попробовать вернуть число из неё; если не число — напечатать сообщение (и цикл пойдёт на новый круг)».
static int readInt(Scanner scanner) {
    while (true) {
        String line = scanner.nextLine().trim();
        try {
            return Integer.parseInt(line);
        } catch (NumberFormatException e) {
            System.out.println("«" + line
                    + "» — не целое число, попробуй ещё раз");
        }
    }
}

5. Код — вот он, строка в строку по псевдокоду. while (true) — цикл без условия выхода: выходим из него через return, когда число получилось. 6. Трассировка. Пользователь ввёл «abc», потом «7». Впиши значения сам:

🔎 Для любопытных: почему не scanner.nextInt()?

Можно и так: на «abc» nextInt() выбросит InputMismatchException. Но есть ловушка: «abc» остаётся на ленте ввода. Следующий круг цикла снова вызовет nextInt(), снова наткнётся на «abc» — и программа бесконечно будет печатать «не число». Чтобы этого не было, в catch нужно «доесть» плохое слово: scanner.next();. Вариант с nextLine() + parseInt от этой ловушки свободен: строка уже прочитана целиком, что бы в ней ни было.

Несколько catch и их порядок

В одном try могут случиться разные беды. На каждую — свой catch, они проверяются сверху вниз, срабатывает первый подходящий:

String[] words = {"ноль", "один", "два"};
try {
    int index = Integer.parseInt(text);
    System.out.println(words[index]);
} catch (NumberFormatException e) {
    System.out.println("Это не число");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Нет слова с номером " + text);
}
Предскажи: что напечатается для text = "1", "5" и "x"?

«один» — всё хорошо. «Нет слова с номером 5» — индекс за границей массива. «Это не число» — parseInt не справился, до массива дело не дошло.

Теперь ловушка. Есть исключения «общего вида»: catch с таким типом перехватывает сразу многие. Например, RuntimeException — общий родитель всех четырёх исключений из урока 1 (откуда он взялся — в уроке 5). Если поставить его первым:

try {
    int index = Integer.parseInt(text);
    System.out.println(words[index]);
} catch (RuntimeException e) {
    System.out.println("Что-то пошло не так");
} catch (NumberFormatException e) {
    System.out.println("Это не число");
}
WrongOrder.java:6: error: exception NumberFormatException has already been caught

Общий catch первым перехватывает все исключения, второй catch никогда не сработает. Недостижимый код Java не пропускает — как строку сразу после return. Правило: catch идут от частного к общему, общий — последним, «на всё остальное».

Аналогия: сортировка на почте

Сортировщик раскладывает письма по ячейкам. Сначала — точные адреса: «ул. Ленина, 5». В самом конце — ячейка «всё остальное». Если начать с «всё остальное», в точные ячейки не попадёт ни одно письмо.

Один catch на несколько типов: |

Если для разных исключений план Б одинаковый, не копируй catch — перечисли типы через вертикальную черту | (читается «или»). Это называется multi-catch:

try {
    int index = Integer.parseInt(text);
    System.out.println(words[index]);
} catch (NumberFormatException | ArrayIndexOutOfBoundsException e) {
    System.out.println("Плохой номер: " + text);
}

Ограничение: типы в multi-catch не должны быть «родителем и потомком». catch (NumberFormatException | IllegalArgumentException e) не скомпилируется: NumberFormatException — разновидность IllegalArgumentException, его и так перехватит второй тип. Компилятор так и скажет: Alternatives in a multi-catch statement cannot be related by subclassing.

Коротко

  • try { опасный код } catch (Тип e) { план Б } — перехватить исключение и продолжить работу.
  • После исключения остаток try пропускается; catch выполняется, только если исключение было и подошло по типу.
  • У перехваченного e можно вызвать getMessage(), printStackTrace().
  • Несколько catch проверяются сверху вниз: от частного к общему, иначе ошибка компиляции «has already been caught».
  • Multi-catch catch (A | B e) — один план Б для нескольких типов (не родственных).
  • Ввод с повтором: while (true) + nextLine().trim() + return Integer.parseInt(...) в try.
