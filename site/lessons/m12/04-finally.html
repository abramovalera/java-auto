finally и try-с-ресурсами

Есть дела, которые нужно сделать при любом исходе: выключить плиту, закрыть соединение с базой данных, вернуть ключи. Для них в Java есть finally — блок, который выполняется всегда. Даже когда в try стоит return.

Повторение

finally выполняется всегда

После try и catch можно добавить третий блок — блок finally («наконец»). Он выполняется в любом случае: было выброшено исключение или нет, перехватили его в catch или нет.

try {
    System.out.println("Включаю плиту и готовлю");
    cook(dish);                       // может выбросить исключение
    System.out.println("Ужин готов");
} catch (IllegalStateException e) {
    System.out.println("Ужин сгорел: " + e.getMessage());
} finally {
    System.out.println("Выключаю плиту");
}
Аналогия: уходя с кухни, выключи плиту

Ужин удался, сгорел или тебе срочно позвонили и пришлось убежать — плиту выключаешь в любом случае. finally — это «выключить плиту»: действие, которое нельзя пропустить ни при каком исходе.

Блок catch при этом не обязателен: бывает try { … } finally { … } без catch — «ловить не буду, но прибраться за собой обязан». А вот одинокий try без catch и без finally не скомпилируется: 'try' without 'catch', 'finally' or resource declarations.

Предскажи: что напечатает программа и в каком порядке? try { print("A"); int x = 5 / 0; print("B"); } finally { print("C"); } print("D"); — catch нет.

A, C, а потом stack trace ArithmeticException. «B» пропущена — после исключения. «C» — finally выполняется даже без catch. «D» не напечатается: исключение никто не перехватил, оно полетело дальше по стеку и уронило программу. Это сценарий ③ со схемы.

Головоломка: finally и return

Самый популярный вопрос про исключения на собеседовании. В try стоит return — метод вроде бы уже закончился. Выполнится ли finally?

public class ReturnPuzzle {
    public static void main(String[] args) {
        System.out.println(check());
    }

    static String check() {
        try {
            System.out.println("try");
            return "из try";
        } finally {
            System.out.println("finally");
        }
    }
}
Предскажи вывод — три строки.

try, finally, из try. Да, finally выполняется даже после return. Посмотри по шагам, как это происходит.

Два продолжения головоломки, оба любят на собеседованиях:

static int first() {
    int x = 1;
    try {
        return x;
    } finally {
        x = 2;
    }
}

static int second() {
    try {
        return 1;
    } finally {
        return 2;
    }
}
Предскажи: что вернут first() и second()?

first() вернёт 1. Значение для return вычислено и отложено до finally: в момент return x было 1. Изменение x в finally на отложенное значение уже не влияет.

second() вернёт 2. return в finally «перебивает» return из try: отложенная 1 отбрасывается. Так делать нельзя никогда: return в finally ещё и тихо проглатывает исключение из try. IDEA подсветит это предупреждением.

Правило

В finally — только уборка: закрыть, освободить, выключить. Никаких return и никаких новых исключений. Если finally сам выбросит исключение, оно заменит исходное, и настоящая причина аварии потеряется.

Зачем finally: освобождаем ресурсы

Ресурс — то, что программа взяла у системы и обязана вернуть: открытый файл, соединение с базой данных, сетевое подключение к серверу. Не вернул — ресурс «утёк»: висит занятым, пока программа не закончится.

Классическая беда серверов: обработчик заказа открыл соединение с базой, упал на середине — и соединение так и осталось висеть. У базы их ограниченное число, скажем 100. После сотни упавших заказов свободных соединений нет, и магазин перестаёт отвечать всем покупателям. Решение — закрывать в finally:

DemoConnection db = new DemoConnection();
try {
    db.send("сохранить заказ №15");
    // … ещё шаги, любой может упасть …
} finally {
    db.close();   // закроется при любом исходе
}

Похожую «уборку при любом исходе» ты встретишь в модуле 17 у тестов: она выполняется после каждого теста, даже если тест упал, — тот же принцип, что у finally.

try-с-ресурсами: закрывает само

Писать finally { x.close(); } каждый раз скучно, и легко забыть. Поэтому в Java 7 появилась короткая запись — try-with-resources (try с ресурсами). Ресурс создаётся прямо в круглых скобках после try и закрывается автоматически:

public class ConnectionDemo {
    public static void main(String[] args) {
        try (DemoConnection db = new DemoConnection()) {
            db.send("");
            System.out.println("Заказ сохранён");
        } catch (IllegalArgumentException e) {
            System.out.println("Заказ не сохранён: " + e.getMessage());
        }
    }
}

class DemoConnection implements AutoCloseable {
    DemoConnection() {
        System.out.println("Соединение открыто");
    }

    void send(String query) {
        System.out.println("Отправляю «" + query + "»");
        if (query.isEmpty()) {
            throw new IllegalArgumentException("пустой запрос");
        }
    }

    @Override
    public void close() {
        System.out.println("Соединение закрыто");
    }
}
  • В скобки try можно положить только объект, который реализует интерфейс AutoCloseable — помнишь интерфейсы из модуля 11? Это контракт «у меня есть метод close()». Scanner, файлы, соединения его реализуют.
  • Строка throw new … создаёт объект исключения и выбрасывает его — «бросает» исключение сами. Подробно в уроке 6.
  • Заметь порядок: «Соединение закрыто» напечаталось раньше, чем «Заказ не сохранён». Ресурс закрывается сразу при выходе из try — до catch и finally.

Scanner — тоже ресурс. Поэтому IDEA иногда подчёркивает new Scanner(System.in) жёлтым: «ресурс не закрыт». Можно так:

try (Scanner scanner = new Scanner(System.in)) {
    String name = scanner.nextLine();
    System.out.println("Привет, " + name);
}   // здесь scanner.close() вызовется сам

Несколько ресурсов в одном try

В скобках можно объявить сразу несколько ресурсов — через точку с запятой. Закроются все, причём в обратном порядке: последний открытый — первым. Как в жизни: зашёл в подъезд, потом в квартиру; выходишь — сначала закрываешь дверь квартиры, потом подъезда.

public class DoorsDemo {
    public static void main(String[] args) {
        try (Door entrance = new Door("подъезд");
             Door flat = new Door("квартира")) {
            System.out.println("Я дома");
        }
    }
}

class Door implements AutoCloseable {
    private final String name;

    Door(String name) {
        this.name = name;
        System.out.println("Открыта дверь: " + name);
    }

    @Override
    public void close() {
        System.out.println("Закрыта дверь: " + name);
    }
}
Предскажи: какие пять строк напечатает программа и в каком порядке?

Открыта дверь: подъезд, Открыта дверь: квартира, Я дома, Закрыта дверь: квартира, Закрыта дверь: подъезд. Открываются ресурсы слева направо, закрываются — справа налево. Это важно, когда второй ресурс зависит от первого: например, чтение файла через объект, который сам держит открытый файл, — сначала закрывают «верхний», потом «нижний».

Осторожно с System.in

Закрытый Scanner закрывает и System.in — клавиатуру до конца программы уже не прочитать, даже новым Scanner. Поэтому в маленьких программах курса Scanner для клавиатуры можно не закрывать. А для файлов try-с-ресурсами — правило хорошего тона. Подробно — в модуле 15 «Файлы и ввод-вывод».

🔎 Для любопытных: когда finally всё-таки НЕ выполнится

Почти всегда — выполнится. Исключения из правила: System.exit(0) внутри try (программа завершается немедленно, JVM просто останавливается), бесконечный цикл в try (до finally дело не дойдёт), «убийство» процесса извне (кнопка Stop в IDEA) или падение самой JVM. Обычные return, break, continue и исключения finally не обходят.

Вопрос с собеседования: final, finally, finalize

Три похожих слова — три совсем разные вещи:

  • final — модификатор (модули 2 и 10): переменной нельзя присвоить новое значение, метод нельзя переопределить, от класса нельзя наследовать.
  • finally — блок после try/catch, который выполняется всегда. Этот урок.
  • finalize() — старый метод класса Object: его когда-то вызывал сборщик мусора перед удалением объекта. Работал ненадёжно (неизвестно, когда и вызовется ли вообще), поэтому с Java 9 он помечен устаревшим (deprecated) — не используй. Чтобы что-то закрыть, есть finally и try-с-ресурсами.

Проверь себя

Поговори с наставником

Напиши: «Я прошёл урок 12.4. Задай мне три головоломки про finally и return, а я объясню каждую». После этого реши задачу m12-t02 «Кто за кем: try, catch, finally».

Коротко

  • finally выполняется всегда: без исключения, с перехваченным и с неперехваченным. Даже после return в try.
  • return сначала вычисляет значение, потом выполняется finally, потом метод возвращает отложенное значение.
  • В finally — только уборка. return или исключение в finally перебивают результат и прячут настоящее исключение.
  • Ресурсы (файл, соединение с базой, сетевое подключение) закрывают в finally — или короче, через try (Ресурс r = …) { }.
  • try-с-ресурсами работает с AutoCloseable и закрывает ресурс до catch и finally. Несколько ресурсов — через ;, закрываются в обратном порядке. Подробно — модуль 15.
  • final — модификатор, finally — блок, finalize() — устаревший метод Object, не используем.
