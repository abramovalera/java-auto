Что такое исключение

Программа делила пиццу на друзей — и вдруг красный текст, и всё остановилось. Разберёмся, что на самом деле произошло, куда «летит» исключение и почему для разработчика это одна из главных тем всей Java.

⏱ 20 минут💥 исключения🧠 стек по шагам

Программа «падает»

Ты уже видел это много раз: в панели Run вместо ответа — красные строки, а программа закончилась раньше времени. Вот программа, которая делит пиццу поровну между друзьями. Друзей, к сожалению, ноль:

public class Pizza {
    public static void main(String[] args) {
        System.out.println("Считаем пиццу");
        printShare(8, 0);
        System.out.println("Приятного аппетита!");
    }

    static void printShare(int slices, int friends) {
        int each = share(slices, friends);
        System.out.println("Каждому: " + each);
    }

    static int share(int slices, int friends) {
        return slices / friends;
    }
}

Запусти её в IDEA — внизу, в панели Run, будет вот что:

Компилятор ничего не заметил: с точки зрения синтаксиса всё правильно. Беда случилась во время работы, на строке 14: целое число на ноль делить нельзя. Java не может продолжать как ни в чём не бывало — и выбрасывает исключение.

Исключение (exception)
Сигнал «случилось что-то, из-за чего я не могу выполнить эту строку». В Java это объект: в нём записано, что случилось (тип и сообщение) и где (стек вызовов).
Выбросить исключение (throw)
Прервать обычное выполнение и «запустить» этот объект вверх по цепочке вызовов, пока кто-нибудь его не поймает.
Перехватить (поймать) исключение (catch)
Принять его в блоке catch и что-то сделать: показать сообщение, попросить ввести заново, попробовать ещё раз. Научимся в уроке 3.
Предскажи: почему не напечаталось «Приятного аппетита!», хотя строка 5 ни в чём не виновата?

Исключение никто не перехватил. Оно пролетело через share, printShare и main, и Java завершила программу целиком. Всё, что должно было выполниться после аварии, просто не выполнилось. exit code 1 — знак, что программа закончилась аварией, а не нормально (тогда было бы 0).

Знакомься: четыре самых частых

У каждого исключения есть тип — имя класса, которое говорит, какого рода беда. Имя всегда заканчивается на Exception и, если перевести, почти дословно описывает проблему. Вот четыре, которые ты встретишь чаще всего:

➗

ArithmeticException

Арифметическая ошибка. Почти всегда — целочисленное деление на ноль: 8 / 0.

📦

ArrayIndexOutOfBoundsException

Индекс вне границ массива: a[3], когда в массиве 3 элемента (индексы 0, 1, 2).

🕳️

NullPointerException

Вызвали метод у null — у ссылки, которая никуда не указывает. Сокращённо NPE.

🔢

NumberFormatException

Строку не удалось превратить в число: Integer.parseInt("12a").

int a = 8 / 0;                        // ArithmeticException

int[] arr = new int[3];
arr[3] = 1;                           // ArrayIndexOutOfBoundsException

String name = null;
System.out.println(name.length());   // NullPointerException

int n = Integer.parseInt("12a");     // NumberFormatException

А вот что про каждое из них скажет Java 21. Читай не только тип, но и сообщение после двоеточия — оно часто подсказывает причину прямым текстом:

java.lang.ArithmeticException: / by zero
java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
java.lang.NullPointerException: Cannot invoke "String.length()" because "name" is null
java.lang.NumberFormatException: For input string: "12a"

Смотри, какие они разговорчивые: «индекс 3 вне границ для длины 3», «не могу вызвать length(), потому что name равно null», «для входной строки "12a"». Половину ошибок можно починить, просто внимательно прочитав сообщение.

Предскажи: что выбросит Integer.parseInt(" 15") — с пробелом перед цифрами?

NumberFormatException: For input string: " 15". parseInt строгий: пробел — не цифра. Поэтому строку от пользователя сначала чистят методом trim() из модуля 8. А Integer.parseInt("") — пустая строка — тоже NumberFormatException.

Как исключение «всплывает» по стеку

Вспомни стек вызовов из модуля 7: каждый вызов метода кладёт на стопку новый фрейм, а работает только верхний. В момент аварии стопка такая: main → printShare → share. Что делает Java, когда в share случилось деление на ноль?

  1. Создаёт объект исключения ArithmeticException, записывает в него сообщение и снимок стека — и выбрасывает его.
  2. Смотрит: есть ли в текущем методе блок catch, который перехватит такое исключение? В share нет — метод прерывается прямо посреди строки, его фрейм снимают.
  3. Исключение прилетает в метод, который вызвал share, — в printShare, на строку 9. Там тоже нет catch — фрейм снимают, строка 10 так и не выполнится.
  4. То же в main. Стек опустел, а исключение так никто и не перехватил.
  5. Тогда за дело берётся сама JVM: печатает stack trace в консоль (красным, в поток ошибок) и завершает программу с кодом 1.
Аналогия: жалоба в большой компании

Курьер не может доставить посылку: адреса не существует. Сам решить не может — передаёт жалобу начальнику смены. Тот тоже не знает, что делать, — передаёт директору склада. Если и директор не разберётся — жалоба уходит на самый верх, и работа останавливается. Исключение — эта жалоба, а catch — человек, который наконец говорит: «Я разберусь».

Пройди аварию по шагам

Смотри, как меняется стек. Обрати внимание: когда исключение пролетает через метод, фрейм снимается без return — метод не возвращает никакого значения, он просто прерывается.

Заметил? Stack trace — это и есть стопка фреймов в момент аварии: share сверху, main внизу. Java сфотографировала стек, когда создавала исключение. Читать такие «фотографии» научимся в следующем уроке.

Ошибка компиляции или исключение?

В модуле 1 мы делили ошибки на три вида. Исключения — это ровно «ошибки выполнения»: код скомпилировался, программа запустилась, и уже на ходу что-то пошло не так.

Ошибка компиляцииИсключение
Когдадо запуска, javac не пропускает кодво время работы программы
Кто находиткомпилятор, IDEA подчёркивает краснымJVM, когда доходит до опасной строки
Примерзабыл ;, опечатка в имениделение на ноль, «abc» вместо числа
Зависит от данных?нет — код просто неправильныйчасто да: 8 / friends работает, пока friends ≠ 0

Последняя строка — самая важная. Одна и та же программа с одними данными работает, а с другими падает. Поэтому исключения так коварны: на твоём компьютере всё хорошо, а пользователь ввёл «двенадцать» вместо «12».

Предскажи: если в программе про пиццу вызвать printShare(8, 4), что напечатается?

«Считаем пиццу», «Каждому: 2», «Приятного аппетита!». Никакого исключения: тот же код, но данные другие. Опасная строка опасна только при некоторых значениях.

Зачем это разработчику

В настоящей программе исключения — обычное дело: файл не нашёлся, сервер не ответил, пользователь ввёл буквы вместо суммы. А в модуле 17 ты научишься писать тесты на JUnit, и там тот же секрет: упавший тест — это исключение. Тест «проверяет» результат специальными методами-проверками. Если результат не тот, проверка выбрасывает исключение, тест прерывается, а JUnit (программа, которая запускает тесты) перехватывает его и рисует красный крестик.

❌

AssertionError

«Ожидалось одно, получилось другое»: expected: <5> but was: <4>. Главный сигнал упавшей проверки в тесте.

🔍

NoSuchElementException

Scanner ждал ещё одно число, а ввод уже закончился. Нельзя прочитать то, чего нет.

📁

FileNotFoundException

Программа хотела открыть файл с заказами, а его нет на диске. Тоже прилетает со stack trace.

Главный навык разработчика

Разработчик каждый день видит в логах сервера или в панели Run stack trace на 30–80 строк. Кто умеет за минуту найти в нём строку своего кода и понять причину, тот работает в разы быстрее. Поэтому весь этот модуль — про то, чтобы исключения перестали пугать.

Поговори с наставником

Напиши: «Я прошёл урок 12.1. Дай мне три коротких куска кода, а я угадаю, какое исключение вылетит в каждом и почему».

Коротко

  • Исключение — объект-сигнал «не могу выполнить эту строку» с типом, сообщением и снимком стека.
  • Оно выбрасывается в глубине и всплывает по стеку вызовов, снимая фреймы, пока его не перехватят в catch.
  • Не перехватил никто — JVM печатает stack trace и завершает программу с exit code 1.
  • Частые: ArithmeticException, ArrayIndexOutOfBoundsException, NullPointerException, NumberFormatException. Читай и тип, и сообщение.
  • Сбой в программе и упавший тест — это исключение, поэтому stack trace — главный инструмент разработчика.
