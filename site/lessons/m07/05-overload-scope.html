Перегрузка и область видимости

Почему println печатает и числа, и строки? Как несколько методов могут носить одно имя? И почему переменную из main не видно в другом методе? Две темы, которые часто встречаются на собеседованиях.

⏱ 20 минут🧠 трассировка⚡ 2 проверки

Повторение

Одно имя — разные методы

Ты пишешь System.out.println(5), println("кот"), println(2.5), println(true) — и всё работает. Неужели один метод умеет принимать что угодно? Нет: в классе PrintStream объявлено около десятка разных методов с одним и тем же именем println: println(int x), println(String x), println(double x), println(boolean x), println()… Java сама выбирает подходящий по типу аргумента, который ты передал.

Это называется перегрузка методов (overloading): несколько методов с одним именем, но разными параметрами. Так можно и в своём классе:

public class Maxes {
    public static void main(String[] args) {
        System.out.println(max(3, 7));          // 7
        System.out.println(max(3, 7, 5));       // 7
        System.out.println(max(2.5, 1.5));      // 2.5
    }

    static int max(int a, int b) {
        if (a > b) {
            return a;
        }
        return b;
    }

    static int max(int a, int b, int c) {
        // перегруженные методы могут звать друг друга
        return max(max(a, b), c);
    }

    static double max(double a, double b) {
        if (a > b) {
            return a;
        }
        return b;
    }
}
Аналогия: «открыть»

Ты говоришь «открой» — и это разные действия: открыть дверь (ключом), открыть банку (открывашкой), открыть книгу (руками). Слово одно, а что делать, понятно по тому, что тебе дали. Так и компилятор: имя одно, а нужный метод он выбирает по аргументам.

Сигнатура: что должно отличаться

Компилятор различает методы по сигнатуре — это имя метода плюс список типов параметров по порядку. Сигнатура max(int, int) отличается от max(int, int, int) и от max(double, double) — значит, все трое могут жить в одном классе.

Что отличаетсяПерегрузка?
Количество параметров: area(double) и area(double, double)✅ да
Типы параметров: print(int) и print(String)✅ да
Порядок типов: f(int, String) и f(String, int)✅ да (но так делают редко — легко запутаться)
Только имена параметров: f(int a) и f(int b)❌ нет — для компилятора одно и то же
Только тип возвращаемого значения: int f(int) и double f(int)❌ нет — ошибка

Последняя строка — частый вопрос на собеседовании. Почему тип возвращаемого значения не считается? Потому что возвращаемое значение можно не использовать: глядя на вызов f(5);, компилятор не понял бы, какой из двух методов ты имел в виду. Ошибка будет такой: method f(int) is already defined in class … — «метод f(int) уже есть».

Предскажи: в классе есть только static void show(double x). Скомпилируется ли show(5)? Что напечатается, если метод печатает x?

Да, напечатается 5.0. Аргумент — литерал 5 типа int; он без потерь помещается в double, и компилятор сам расширит его — как при double d = 5; из модуля 2. А вот наоборот (метод с int, вызов с 5.5) — ошибка: из double в int сам по себе компилятор не переводит, можно потерять дробную часть.

🔎 Для любопытных: когда компилятор не может выбрать

Есть два метода: f(int a, double b) и f(double a, int b). Вызов f(1, 2) подходит к обоим: в первом расширим второй аргумент, во втором — первый. Ни один не лучше другого, и компилятор честно скажет: reference to f is ambiguous — «вызов неоднозначен». Вывод: не делай перегрузки, которые отличаются только порядком похожих типов.

Область видимости: где живёт переменная

Вторая тема урока. Попробуем из одного метода присвоить значение локальной переменной другого:

public class Scope {
    public static void main(String[] args) {
        int score = 10;
        addBonus();
        System.out.println(score);
    }

    static void addBonus() {
        score = score + 5;      // ошибка!
    }
}
Scope.java:9: error: cannot find symbol
        score = score + 5;
        ^
  symbol:   variable score
  location: class Scope

Так ошибку покажет javac (и сайт кнопкой «Проверить»). А в редакторе IDEA она видна ещё до запуска:

Компилятор не знает никакой score в методе addBonus. И он прав: score объявлена в теле main, значит, она локальная переменная main и живёт только там. Её область видимости (scope) — от строки объявления до закрывающей скобки main.

Аналогия: квартиры в доме

Класс — это дом, методы — квартиры. В квартире 5 живёт кот Барсик, в квартире 12 — тоже кот Барсик. Это два разных кота: каждый живёт у себя, и позвать Барсика из соседней квартиры нельзя — тебя там не слышно. Так и переменные: у каждого метода свои, даже если имена совпадают.

С точки зрения памяти всё логично. Локальные переменные лежат во фрейме метода. Пока работает addBonus, фрейм main лежит ниже, но заглядывать в чужой фрейм метод не умеет. А когда метод закончился, его фрейма вообще нет — переменных тоже.

Как правильно? Данные между методами передают через параметры (туда: аргумент при вызове) и return (обратно: возвращаемое значение):

public static void main(String[] args) {
    int score = 10;
    score = addBonus(score);       // отдали значение и забрали результат
    System.out.println(score);     // 15
}

static int addBonus(int points) {
    return points + 5;
}

«А нельзя ли завести одну переменную на весь класс, чтобы её видели все методы?» Можно — это поле класса. Но с полями нужно уметь обращаться, и это тема модуля 9 «Классы и объекты». Пока передаём данные через параметры — это и честнее: по сигнатуре метода сразу видно, что ему нужно.

Блоки внутри метода

Область видимости бывает и меньше метода. Любые фигурные скобки — тело if, for, while — это блок. Переменная, объявленная в блоке, живёт до его закрывающей скобки:

public static void main(String[] args) {
    int total = 0;                      // видна до конца main
    for (int i = 1; i <= 3; i++) {      // i видна только в цикле
        int square = i * i;             // square — только внутри тела цикла
        total += square;
    }
    System.out.println(total);          // ✅ 14
    System.out.println(i);              // ❌ cannot find symbol
    System.out.println(square);         // ❌ cannot find symbol
}

Блок — как комната в квартире: что положил в комнате, видно в этой комнате. Из прихожей не видно, что лежит в спальне. А вот то, что лежит в прихожей (total), видно из всех комнат.

✅

Можно

Одно и то же имя в разных методах или в двух соседних циклах: for (int i…) и ещё раз for (int i…) ниже. Это разные переменные в разных областях.

❌

Нельзя

Объявить переменную с тем же именем внутри блока, где она уже видна: int x = 1; if (…) { int x = 2; }. Ошибка variable x is already defined in method main.

Предскажи: скомпилируется ли? if (true) { int a = 5; } System.out.println(a);

Нет, cannot find symbol. Область видимости переменной a кончилась на закрывающей скобке тела if. Если a нужна после блока — объяви её до блока, а внутри только присваивай.

Напиши: «Я прошёл урок 7.5. Покажи мне несколько пар методов, а я скажу, перегрузка это или ошибка компиляции, и объясню почему».

Коротко

  • Перегрузка — методы с одним именем и разными параметрами (количество, типы, порядок типов). println — пример перегрузки.
  • Сигнатура = имя + типы параметров. Имена параметров и тип возвращаемого значения в неё не входят.
  • Компилятор выбирает перегрузку по типам аргументов: сначала точное совпадение, потом расширение (int → double).
  • Область видимости локальной переменной — от объявления до конца своего блока { }. Чужие переменные из другого метода не видны: cannot find symbol.
  • Данные между методами передаём через параметры (аргументы вызова) и return (возвращаемое значение).
