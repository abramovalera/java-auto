Как передаются аргументы

Метод поменял число — а снаружи ничего не изменилось. Метод поменял массив — а снаружи изменилось! Разбираемся, почему так, с картой памяти в руках. Это любимый вопрос на собеседованиях.

Повторение

Загадка с числом

Объявим метод, который прибавляет 10 к своему параметру. Что напечатает main?

public class PassValue {
    public static void main(String[] args) {
        int a = 5;
        addTen(a);
        System.out.println(a);
    }

    static void addTen(int x) {
        x = x + 10;
        System.out.println("внутри: " + x);
    }
}
Предскажи: две строки вывода — какие?

внутри: 15, а потом 5. Параметру x присвоили 15, а переменная a у main так и осталась 5. Почему — смотри трассировку.

Правило: Java передаёт копию

Запомни одно правило — его спрашивают почти на каждом собеседовании по Java:

Главное правило

Java всегда передаёт в метод копию значения (по-английски — pass by value). Параметр — это новая локальная переменная в новом фрейме, которую инициализировали копией значения аргумента. Что бы метод ни делал со своим параметром, переменная снаружи не изменится.

Аналогия: ксерокопия

Ты даёшь другу ксерокопию своей контрольной. Он может зачеркнуть ответы, разрисовать её, порвать — твой оригинал лежит у тебя целый.

Как тогда получить изменённое число? Пусть метод его вернёт через return, а ты сам присвоишь возвращённое значение нужной переменной:

static int addTen(int x) {
    return x + 10;
}

// в main:
int a = 5;
a = addTen(a);           // теперь a = 15 — мы сами перезаписали её результатом
Предскажи: удастся ли так поменять местами два числа? 
static void swap(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}
// в main: int x = 1, y = 2; swap(x, y); System.out.println(x + " " + y);

Нет, выведет «1 2». Метод честно поменял местами значения своих параметров a и b — копий аргументов — и его фрейм тут же сняли. Классическая задачка с собеседований: метод swap для примитивов в Java написать нельзя.

Загадка с массивом

Теперь то же самое, но с массивом. Метод удваивает все элементы:

public class PassArray {
    public static void main(String[] args) {
        int[] nums = {1, 2, 3};
        doubleAll(nums);
        System.out.println(nums[0] + " " + nums[1] + " " + nums[2]);
    }

    static void doubleAll(int[] arr) {
        for (int i = 0; i < arr.length; i++) {
            arr[i] = arr[i] * 2;
        }
    }
}
Предскажи: «1 2 3» или «2 4 6»?

2 4 6. На этот раз изменения видны снаружи. Противоречие с правилом? Нет! Смотри, что именно скопировалось.

Копия значения и копия ссылки

Правило то же самое — копируется значение переменной. Просто у переменной-массива значение — это ссылка, «адрес» массива в куче.

Аналогия: копия ключа

Ты дал другу копию ключа от своей квартиры. Ключ — копия, а квартира одна. Друг зашёл и переставил мебель — вернувшись, ты увидишь перестановку. Ссылка на массив — это ключ, массив — квартира.

Когда метод меняет что-то снаружи себя — не через возвращаемое значение, а «по пути», — это называют побочным эффектом (side effect). Иногда это ровно то, что нужно: например, метод «отсортируй массив» или «переверни массив на месте». Но такой метод должен честно говорить об этом своим именем: sortArray, reverseInPlace, fillWithZeros. Сюрприз «я просто посчитал сумму, а массив почему-то обнулился» — источник неприятных багов.

Ловушка: присвоить параметру новый массив

Последний, самый хитрый случай. Что, если метод не меняет элементы, а присваивает параметру ссылку на новый массив?

static void replace(int[] arr) {
    arr = new int[]{9, 9, 9};    // arr теперь смотрит на НОВЫЙ массив
    arr[0] = 100;                // меняем новый массив
}

// в main:
int[] nums = {1, 2, 3};
replace(nums);
System.out.println(nums[0]);
Предскажи: 1, 9 или 100?

1. Присваивание arr = new int[]{…} перенаправило копию стрелки — параметр в фрейме replace. Стрелка nums в main по-прежнему смотрит на старый массив {1, 2, 3}. Дальше метод меняет новый массив, который после return никому не нужен (его уберёт сборщик мусора).

Аналогия: друг выбросил свою копию ключа и сделал ключ от другой квартиры. Мебель он переставит там — в твоей квартире всё по-старому.

✏️

arr[i] = …

Присваивание элементу массива, на который ведёт ссылка. Видно снаружи.

🔀

arr = …

Присваивание параметру: перенаправляет только свою копию ссылки. Снаружи не видно.

📦

x = … (примитив)

Присваивание параметру: меняет свою копию числа. Снаружи не видно.

🔎 Для любопытных: а строки (String)?

String — тоже объект в куче, и в метод передаётся копия ссылки на него. Но строку в Java нельзя изменить — у неё нет элементов, которым можно присвоить новое значение, как у массива. Поэтому со строками метод может только перенаправить свою копию ссылки, а это снаружи не видно. На практике строки ведут себя «как примитивы». Почему строки неизменяемые и что из этого следует — в модуле 8.

Напиши: «Я прошёл урок 7.4. Спроси меня, как в Java передаются аргументы, как на собеседовании, — а я отвечу и нарисую стек и кучу в чате».

Коротко

  • Java всегда передаёт в метод копию значения аргумента (pass by value): параметр инициализируется этой копией.
  • Примитив (int, double, boolean…): метод работает с копией числа — снаружи изменений не видно. Нужно новое значение — верни его через return.
  • Массив: копируется ссылка, а массив в куче один. Присваивания элементам arr[i] = … видны снаружи.
  • Присваивание arr = new … в теле метода перенаправляет только его копию ссылки — снаружи не видно.
  • Метод, который меняет переданный массив, должен говорить об этом именем: reverseInPlace, sortArray.
