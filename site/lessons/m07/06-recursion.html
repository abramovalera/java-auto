Рекурсия: метод вызывает сам себя

Метод может вызвать… самого себя. Звучит как фокус, но это мощный способ решать задачи. Посмотрим, как при этом растёт стек, зачем нужен базовый случай и что такое StackOverflowError.

Повторение

Какой я в очереди?

Ты стоишь в длинной очереди в кино и хочешь узнать, какой ты по счёту. Выйти и посчитать нельзя. Что делать? Спросить у того, кто впереди: «Ты какой по счёту?» Он не знает — и спрашивает того, кто впереди него. И так далее до самого первого человека. Первый знает точно: «Я — первый!»

Ответ идёт обратно по цепочке: «я первый» → «значит, я второй» → «значит, я третий»… и доходит до тебя. Каждый сделал крошечный шаг: спросил впереди стоящего и прибавил 1.

Это и есть рекурсия: задача решается через ту же задачу, но поменьше. В Java — метод, в теле которого есть вызов этого же метода с другим аргументом.

Рекурсия
Когда в теле метода есть вызов этого же метода. Сам метод называют рекурсивным.
Базовый случай
Ситуация, когда ответ известен сразу и метод больше себя не вызывает. Как первый в очереди: «я первый».
Рекурсивный шаг
Вызов себя с аргументом для задачи поменьше — так, чтобы с каждым шагом приближаться к базовому случаю.

Обратный отсчёт

Простейший пример — обратный отсчёт до старта ракеты:

public class Countdown {
    public static void main(String[] args) {
        countdown(3);
    }

    static void countdown(int n) {
        if (n == 0) {           // базовый случай
            System.out.println("Старт!");
            return;
        }
        System.out.println(n);
        countdown(n - 1);       // рекурсивный шаг: та же задача, но на 1 меньше
    }
}

Метод говорит: «Чтобы отсчитать от n, напечатай n, а потом вызови себя с аргументом n − 1». А когда n дошло до 0 — «Старт!» и стоп. Посмотри, что при этом творится на стеке — тут самое интересное.

Проверь это в IDEA: поставь точку останова на строку System.out.println("Старт!"); и запусти отладку 🐞. В панели Frames будет видно, что countdown лежит на стеке четыре раза:

Предскажи: что напечатает программа, если в countdown поменять местами строки 11 и 12 — сначала вызов себя, потом печать?

Старт!, 1, 2, 3. Теперь каждый вызов сначала уходит «вглубь» и печатает значение своего параметра n только на обратном пути, когда стек разматывается. Первым допечатает самый верхний фрейм (n = 1), последним — нижний (n = 3). Код до рекурсивного вызова выполняется по пути вниз, код после — по пути наверх.

Факториал: рекурсия с результатом

Факториал числа n (пишут n!) — произведение всех чисел от 1 до n: 4! = 1 · 2 · 3 · 4 = 24. В модуле 5 ты считал его циклом. А теперь заметим: 4! = 4 · 3!. И 3! = 3 · 2!. Каждый факториал — это n, умноженное на факториал поменьше. А 1! = 1 и 0! = 1 — это мы знаем сразу.

static int factorial(int n) {
    if (n <= 1) {                      // базовый случай: 0! = 1! = 1
        return 1;
    }
    return n * factorial(n - 1);       // рекурсивный шаг: n! = n · (n−1)!
}
Факториал растёт очень быстро

13! = 6 227 020 800 — это уже больше, чем влезает в int (максимум около 2,1 миллиарда). Помнишь переполнение из модуля 3? factorial(13) с типом возвращаемого значения int вернёт мусор. Для факториалов до 20! объявляй метод с типом long, дальше не хватит и его.

StackOverflowError: когда стек кончился

Что будет, если забыть базовый случай?

public class Endless {
    public static void main(String[] args) {
        countdown(3);
    }

    static void countdown(int n) {
        System.out.println(n);
        countdown(n - 1);          // базового случая нет!
    }
}

Метод вызывает себя снова и снова, и каждый вызов кладёт на стек новый фрейм. Но под стек выделен ограниченный кусок памяти. Через несколько тысяч фреймов (точное число зависит от настроек JVM и размера фрейма) место кончается — и Java аварийно останавливает программу: StackOverflowError, «переполнение стека». В stack trace — тысячи одинаковых строк: тот самый метод, лежащий на стеке сам на себе.

Аналогия: стопка тарелок до потолка

Тарелки кладут, кладут и ни одной не снимают. Рано или поздно стопка упрётся в потолок. Базовый случай — это момент, когда наконец начинают снимать.

Переполнение бывает, даже если базовый случай есть, но до него нельзя дойти. Например, базовый случай if (n == 0), а метод вызвали с аргументом -1: n будет −2, −3, … и никогда не станет нулём. Поэтому в факториале выше условие n <= 1, а не n == 1: так метод не уйдёт в бесконечность и на 0, и на отрицательных.

Кстати, сайт Stack Overflow — главный форум программистов, где ищут ответы на вопросы, — назван как раз в честь этой ошибки. Ты туда ещё не раз попадёшь из поисковика 🙂

Как придумать рекурсию

Рецепт из трёх вопросов:

  1. Базовый случай. Для какого самого маленького входа ответ очевиден? (0! = 1; отсчёт от 0 — «Старт!»; число из одной цифры — сумма цифр равна ему самому.)
  2. Как уменьшить задачу? Как выразить возвращаемое значение через результат вызова с аргументом поменьше? (n! = n · (n−1)!)
  3. Поверь. Пиши рекурсивный шаг так, будто метод для меньшего входа уже работает. Не пытайся в голове развернуть все вызовы — за тебя это сделает стек.

Попробуй: собери объявление метода power(base, exp) с двумя параметрами — возведение в степень. Например, 25 = 2 · 24, а любое число в степени 0 равно 1.

🔎 Для любопытных: рекурсия или цикл?

Любую рекурсию можно переписать циклом, и наоборот. Факториал и степень циклом считать проще и быстрее: не тратится стек, нет риска StackOverflowError. Здесь они нужны, чтобы понять механизм.

Рекурсия по-настоящему хороша там, где сама задача «вложенная»: папки внутри папок (обойти все файлы на диске), HTML-элементы внутри элементов (так устроена любая страница сайта), меню с подменю. Там цикл получается громоздким, а рекурсия — естественной: «обработай папку = обработай файлы + обработай каждую вложенную папку тем же методом».

Два вызова сразу: числа Фибоначчи

Числа Фибоначчи: 1, 1, 2, 3, 5, 8, 13… Первые два — единицы, а каждое следующее — сумма двух предыдущих. Само определение уже рекурсивное: fib(n) = fib(n−1) + fib(n−2). Базовый случай — первые два числа: fib(1) = fib(2) = 1.

public class Fibonacci {
    public static void main(String[] args) {
        for (int i = 1; i <= 7; i++) {
            System.out.print(fib(i) + " ");
        }
    }

    static int fib(int n) {
        if (n <= 2) {                      // базовый случай: fib(1) = fib(2) = 1
            return 1;
        }
        return fib(n - 1) + fib(n - 2);    // два рекурсивных вызова
    }
}

Программа напечатает 1 1 2 3 5 8 13. Новое здесь — в рекурсивном шаге два вызова. Java вычисляет выражение слева направо: сначала целиком выполняется fib(n - 1) со всеми своими вызовами, и только потом — fib(n - 2). Поэтому вызовы складываются не в цепочку, как у факториала, а в дерево:

Предскажи: сколько всего раз будет вызван метод fib, если вызвать fib(5)?

9 раз. Сам fib(5) — 1 вызов, внутри него fib(4) — это всё дерево с картинки, 5 вызовов, и fib(3) — ещё 3 вызова (он сам, fib(2) и fib(1)). Итого 1 + 5 + 3 = 9.

Красиво, но медленно

Дерево растёт очень быстро, и одни и те же значения считаются снова и снова. fib(45) — это больше двух миллиардов вызовов и несколько секунд ожидания, fib(50) — уже около минуты. Стек при этом не переполняется: в стопке одновременно не больше n фреймов, они кладутся и снимаются. Просто работы слишком много. Циклом с двумя переменными-накопителями то же число считается мгновенно — попробуй написать такой вариант сам.

Напиши: «Я прошёл урок 7.6. Дай мне рекурсивный метод, а я нарисую в чате, как растёт и разматывается стек, и скажу, что он напечатает».

Коротко

  • Рекурсия — метод вызывает сам себя с аргументом для задачи поменьше.
  • Нужны два куска: базовый случай (return сразу, без вызова) и рекурсивный шаг, который приближает к базовому случаю.
  • Каждый вызов — отдельный фрейм со своими параметрами и локальными переменными. Стек растёт до базового случая, потом разматывается.
  • Код до рекурсивного вызова работает по пути вниз, код после — по пути наверх.
  • Нет базового случая или до него не дойти — StackOverflowError: стек не бесконечный.
  • В рекурсивном шаге может быть два вызова, как в числах Фибоначчи: fib(n - 1) + fib(n - 2). Получается дерево вызовов — красиво, но одни и те же значения считаются много раз.
