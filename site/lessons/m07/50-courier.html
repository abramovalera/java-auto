Джавик-курьер, часть 4: свои команды

У Джавика всего пять команд: шаг, два поворота, взять и отдать. Сегодня ты научишь его новым — «развернись», «доедь до стены», «проедь N клеток». Это будут твои методы, а run превратится в короткий план, который читается как текст.

Повторение

Игра: что уже было и что нового

Напомню правила «Джавика-курьера». Поле из клеток: стены, дорога, 📦 посылки, 🏠 адреса, 🏁 склад, откуда Джавик стартует. Он смотрит в одну из четырёх сторон, «слева» и «справа» — относительно его взгляда. Врезался в стену, отдал посылку не там или кончились ходы — поездка окончена.

  • Часть 1 (модуль 4): метод decide на каждом ходу выбирал одну команду.
  • Часть 2 (модуль 5): метод run вызывается один раз, а Джавиком командуют циклы.
  • Часть 3 (модуль 6): маршрут в массиве и дорога домой без датчиков.

Правило то же, что и раньше: код пишешь в IntelliJ IDEA, на сайте только смотришь поездку. Управлять Джавиком руками нельзя — только программой. В части 4 у каждого уровня свой класс и свой файл в папке module-07; заготовки уже там.

Главная мысль части 4: из готовых команд робота собираем свои команды — turnAround, driveToWall, driveSteps. Внутри каждой — пара строк. Зато run становится планом, который читается как текст: «взять, доехать до стены, отдать, развернуться…». Это та же декомпозиция, что в Мастерской 7.7, только на роботе.

Почему метод получает robot параметром

Посмотри на заголовок: public static void run(CourierRobot robot). Здесь CourierRobot — тип параметра (имя класса робота, как String или Scanner), а robot — имя параметра. Игра создаёт Джавика — объект — и при вызове run передаёт его аргументом.

Теперь ты объявляешь свой метод «развернуться». Ему тоже нужен Джавик: кого разворачивать? Но переменная robot — параметр run, то есть локальная переменная его фрейма. Другой метод её не видит — это область видимости из урока 7.5. Значит, Джавика надо передать: при вызове пишешь аргумент robot, а в объявлении своего метода — параметр CourierRobot robot.

Аналогия: дубликат ключа

Ты даёшь другу дубликат ключа от своей машины и просишь перепарковать её. Ключей два, а машина одна. Друг переставил машину — и ты, выйдя во двор, видишь её на новом месте. Параметр robot — такой дубликат: метод получает копию ссылки и двигает того самого Джавика.

Предскажи: метод turnAround(robot) развернул Джавика. Куда тот смотрит, когда run продолжит со следующей строки?

Развёрнутым. Объект один: метод работал с ним через копию ссылки, поэтому все повороты и шаги видны и в run. Сравни с числом: если бы метод получил int и изменил его, в вызывающем методе ничего бы не поменялось — менялась бы копия числа.

Имя параметра может быть любым (CourierRobot r тоже работает), но удобно называть его так же — robot. Две частые ошибки новичка выглядят в IDEA так:

Не забудь static

run объявлен со словом static, поэтому и твои методы пока пиши со static. Без него IDEA подчеркнёт вызов и скажет Non-static method … cannot be referenced from a static context. Что это значит подробно — в модуле 9, а пока просто добавь static.

★ «Челнок»: одно и то же три раза

На складе 🏁 лежат три посылки, адрес 🏠 — в конце прямой улицы. Руки у Джавика маленькие: за раз он берёт только одну посылку. Значит, ездить придётся три раза: туда с посылкой, обратно пустым. Длина улицы на каждой карте своя.

Если писать без своих методов, получится длинная простыня. Посмотри на неё схемой — каждый прямоугольник это одно действие, а за многими из них стоит несколько строк кода:

Узнаёшь признак из урока 7.1? Одно и то же много раз. Без методов «до стены» и «разворот» пришлось бы набрать по шесть раз — и в каждой копии можно ошибиться. Даже если обернуть поездку в цикл, внутри одной поездки эти куски всё равно повторяются дважды.

Идея: дадим каждому повторяющемуся куску имя. Объяви два своих метода — вот их заголовки, а тела напишешь сам:

static void driveToWall(CourierRobot robot)

«Доехать до стены»: ехать вперёд, пока впереди свободно. Ничего не возвращает — только двигает Джавика, поэтому void. Сколько клеток ехать, метод узнаёт сам, датчиком: длина улицы ему не нужна.

static void turnAround(CourierRobot robot)

«Развернуться»: повернуться на месте лицом в обратную сторону. Подумай, из каких команд робота это собрать и сколько их нужно.

Когда оба метода готовы, run пишется почти словами из условия: взял — доехал — отдал — развернулся — вернулся — развернулся. Кто читает такой run, понимает план, даже не заглядывая в методы. А заглянуть всегда можно: Ctrl+B.

Предскажи: что будет, если в конце поездки забыть второй разворот — тот, что на складе?

Джавик вернётся на склад и будет стоять лицом к стене за складом. Следующую посылку он возьмёт, но «до стены» не сделает ни шага — стена уже впереди. И drop() случится прямо на складе — ошибка: отдать посылку можно только на адресе. В поездке это хорошо видно: Джавик взял посылку и не сдвинулся.

Предскажи: как узнать, сколько раз повторить поездку?

Два честных способа. Посылок ровно три — можно повторить поездку счётчиком три раза. А можно спросить датчик: пока на складе есть посылка (parcelHere()) — везём. Второй способ лучше: он не сломается, если посылок станет пять.

Заметь: driveToWall из этого уровня сработает на любой длине улицы — он смотрит на датчик, а не считает. Хороший метод не знает лишнего: делает одну работу и не зависит от того, кто и где его вызвал.

★★ «Квартал»: метод с параметром

Новая улица идёт на восток, а дома стоят в нишах слева от дороги. Джавик уже везёт по посылке на каждый дом. Где дома, подскажет новый метод робота robot.houses(): он возвращает массив int[] — на скольких клетках от склада стоит каждый дом, по возрастанию. Например, [2, 5, 9]. На каждой карте числа свои.

Здесь «доехать до стены» не поможет: надо остановиться ровно напротив дома. Нужна команда «проехать N клеток» — и N каждый раз разное. Значит, это метод с параметром:

static void driveSteps(CourierRobot robot, int steps)

Два параметра: кого везти и сколько клеток. При вызове driveSteps(robot, 3) аргументы раскладываются по порядку: robot → в robot, 3 → в steps. Внутри — цикл из модуля 5, который делает steps шагов.

Предскажи: houses() вернул [2, 5, 9]. Сколько клеток проехать перед каждым домом?

2, 3 и 4 — а не 2, 5 и 9. Номера в массиве считаются от склада, а Джавик после первого дома стоит уже на клетке 2. До второго дома ему 5 − 2 = 3 клетки, до третьего 9 − 5 = 4. Всего 2 + 3 + 4 = 9 — ровно номер последнего дома. Если ехать «от склада» каждый раз, после первого дома Джавик проедет 5 и окажется на клетке 7, свернёт налево — а там стена: врезался. Значит, в run нужно помнить, где Джавик сейчас.

У каждого дома одно и то же: заехать в нишу, отдать посылку и вернуться на улицу лицом на восток, чтобы ехать дальше. Это второй кандидат в метод — например, static void deliverLeft(CourierRobot robot). Вот что должен сделать Джавик у дома:

Предскажи: на шаге 6 Джавик смотрит на юг ↓. Каким поворотом вернуть его лицом на восток →?

Одним поворотом налево. Представь, что ты стоишь лицом на юг: твоя левая рука показывает на восток. Три поворота направо тоже приведут туда же, но это три хода вместо одного, а ходы на карте ограничены. А на шаге 4 пригодился твой turnAround из «Челнока» — свои методы переиспользуются.

Каждый уровень — свой класс

turnAround из CourierShuttle в CourierHouses сам не появится: метод живёт в своём классе. Объяви его заново в новом файле — пара строк.

★★★ «Середина улицы»: метод возвращает число

Посылку ждут ровно посередине прямой улицы. Но табличек с адресом здесь нет: atTarget() на этой карте не работает, а проверка на сайте не пропустит код, где он вызывается. Длина улицы каждый раз своя, и заранее её никто не скажет.

Как найти середину? Так же, как ты сделал бы в тёмном коридоре: дойти до конца, считая шаги, развернуться и пройти назад нужное число. Значит, «доехать до стены» теперь должен не только ехать, но и доложить, сколько проехал:

static int driveToWall(CourierRobot robot)

Тип возвращаемого значения int: метод двигает Джавика до стены и через return отдаёт число проеханных клеток. Внутри появится переменная-счётчик. Вызов можно поставить справа от = и сохранить ответ в переменную.

Имя то же, что в «Челноке», но там метод был void. Это не перегрузка: тип возвращаемого значения в сигнатуру не входит (урок 7.5), и в одном классе два таких метода не ужились бы. Здесь проблемы нет — у «Середины» свой класс. Пригодится и driveSteps из «Квартала»: обратно ехать как раз нужное число клеток.

Самое хитрое — посчитать, сколько ехать назад. Посчитай на бумаге. Клетки нумеруем от склада: склад — клетка 0. Если клеток чётное число, середин две — адрес на той, что ближе к складу.

Проверь таблицу: что получилось для 7 и 8 клеток?

7 клеток: метод вернёт 6, не 7 — склад уже клетка, на которой Джавик стоит, шагов на один меньше, чем клеток. Середина — клетка 3, назад от клетки 6 ехать 3.

8 клеток: метод вернёт 7. Середин две — 3 и 4, адрес на клетке 3. Назад от клетки 7 ехать 4.

Вот подвох. Правило «назад — половину того, что проехал» для 7 клеток даёт 6 / 2 = 3 — верно. А для 8 клеток 7 / 2 тоже 3 (целочисленное деление из модуля 3 отбрасывает дробь), хотя нужно 4: Джавик промахнётся на клетку. Найди своё правило, которое даёт верное число для обеих строк, — и проверь его ещё на улицах из 6 и 9 клеток.

Метод, который и действует, и возвращает ответ, — обычное дело. driveToWall «проехал и доложил»: run получает число и решает, что делать дальше. Возвращённое значение можно и не сохранять — тогда метод просто проедет, а число пропадёт. Но здесь оно нам очень нужно.

  2. Ниже выбери уровень и нажми «▶ Запустить мой код». Сайт скомпилирует твой файл и запустит Джавика на трёх разных картах.
  3. То же самое — кнопка «▶ Проверить» на странице «Практика»: там уровень засчитается, когда пройдены все три карты.

Прошёл уровень — разбери решение с наставником: /check и номер уровня (он написан под кнопкой «Проверить» в «Практике», например m07-c1).Прошёл уровень — разбери решение с DeepSeek: промпт «Проверь решение» (кнопка внизу страницы).

Как читать поездку:

  • Вкладки «Карта 1–3» с ✓ и ✗. Сайт сам открывает первую карту, где что-то пошло не так.
  • ▶ Смотреть / ⏸ — проиграть поездку; ◀ и ▶ — ход назад и вперёд; ползунок — перемотка; можно выбрать скорость.
  • Справа: номер хода, команда, сколько посылок везёт, и список «Перед ходом Джавик спросил» — какие датчики он опросил и что они ответили. Там же видно, что вернул houses().
  • Красная надпись — что случилось: врезался, отдал не там, кончились ходы. Внизу — «Программа напечатала», если ты что-то выводил через System.out.println. Отличный способ подсмотреть, что вернул твой driveToWall.
  • Не компилируется — сайт покажет ошибку компилятора 🛠. Нет своих методов, которых ждёт уровень, — появится подсказка 💡, например «Нужно минимум два своих метода с параметром CourierRobot».

Присмотрись к столбцу «команда»: там только move, turnLeft, take… Твоих turnAround и driveSteps в поездке нет. Свои методы — для людей, которые читают код. Робот видит только свои пять команд, а твой метод просто вызывает их по очереди: run → твой метод → команда робота. Это и есть стек вызовов из урока 7.3.

★ «Челнок»

💡 Подсказка 1 — с чего начать

Забудь пока про три посылки. Научи Джавика одной поездке: взять, доехать до адреса, отдать. Запусти и посмотри поездку. Потом верни его на склад. Когда одна поездка работает от начала до конца, повторить её — дело техники.

Удобно начать с run и сразу писать вызовы driveToWall(robot) и turnAround(robot), будто методы уже есть. IDEA подчеркнёт их красным — Alt+Enter → Create method.

💡 Подсказка 2 — тела методов

Разворот — это поворот на 180°, а одна команда поворачивает на 90°. «До стены» — цикл из модуля 5: повторяй шаг, пока впереди нет стены. В цикле обязательно должна быть команда, которая двигает Джавика, иначе условие никогда не изменится.

💡 Подсказка 3 — план на русском

Пока на складе есть посылка: взять её; доехать до стены; отдать; развернуться; доехать до стены; развернуться. Переведи каждую строку плана в одну строку run.

★★ «Квартал»

💡 Подсказка 1 — с чего начать

Запусти пустую заготовку и посмотри в поездке, что вернул houses(). Сначала доставь посылку только в первый дом: проехать нужное число клеток, заехать в нишу, отдать. Работает — переходи к остальным.

💡 Подсказка 2 — откуда ехать

Заведи в run переменную «где Джавик сейчас» — на складе это 0. Сколько ехать до дома — разница между номером дома и тем, где Джавик сейчас. После доставки не забудь обновить эту переменную. Заезд в нишу — по схеме из урока, а последний поворот — в ответе к предсказанию под ней.

💡 Подсказка 3 — план на русском

Где я сейчас = 0. Для каждого номера дома из массива: проехать (номер дома − где я сейчас) клеток; теперь я у этого дома; заехать в нишу слева, отдать посылку и вернуться на улицу лицом на восток. «Проехать N клеток» — метод driveSteps, «заехать в нишу» — второй свой метод.

★★★ «Середина улицы»

💡 Подсказка 1 — с чего начать

Напиши только driveToWall, который возвращает число, и в run напечатай его результат через System.out.println. Запусти: в «Программа напечатала» на каждой карте будет длина пути. Проверь по поездке, что число совпадает с числом шагов.

💡 Подсказка 2 — сколько назад

Заполни таблицу из урока для улиц из 6, 7, 8 и 9 клеток: что вернул метод, номер клетки с адресом, сколько ехать назад. Посмотри на столбец «номер клетки с адресом»: каким действием с числом шагов он получается во всех четырёх строках? Целочисленное деление тебе в помощь.

💡 Подсказка 3 — план на русском

Доехать до стены и запомнить, сколько проехал. Развернуться. Узнать номер клетки с адресом (правило из таблицы). Проехать назад столько клеток, сколько от стены до этой клетки. Отдать посылку. Про atTarget() забудь — только счёт.

Поговори с наставником

Спроси, если что-то осталось непонятным: «Почему мой метод не видит переменную robot из run, если они в одном классе?», «Почему, когда метод поворачивает робота, в run робот тоже повёрнут, а int, изменённый внутри метода, снаружи не меняется?», «Объясни на примере робота-курьера, чем параметр отличается от аргумента». Готовое решение уровня не проси: лучше расскажи свой план словами и попроси найти в нём дыру.

Коротко

  • Из готовых команд робота собираем свои методы: turnAround, driveToWall, driveSteps. Тогда run читается как план.
  • Джавик — объект. Свой метод получает его параметром CourierRobot robot: переменная из run локальная, а в параметр копируется ссылка на того же Джавика.
  • Свой метод вызываем по имени и с аргументом: turnAround(robot), а не robot.turnAround() и не turnAround().
  • Параметр делает метод гибким: driveSteps(robot, steps) проедет столько, сколько попросят. В «Квартале» едем от предыдущего дома, а не от склада.
  • Метод может и действовать, и возвращать результат: int driveToWall «проехал и доложил». В «Середине улицы» число шагов на 1 меньше числа клеток, а целочисленное деление требует проверки на чётной и нечётной длине.
