Параметры и return

Кнопка, которая всегда делает одно и то же, — скучно. Научим методы принимать данные через параметры и возвращать результат.

⏱ 25 минут🔍 трассировка⚡ 2 проверки

Повторение

Параметр — окошко для данных

Наш printLine() печатает линию всегда одной длины. А если в одном месте нужна линия на 10 знаков, а в другом — на 30? Писать два метода? Нет — пусть метод получает длину снаружи.

public class Lines {
    public static void main(String[] args) {
        printLine(10);
        System.out.println("Заголовок");
        printLine(30);
    }

    static void printLine(int length) {
        for (int i = 0; i < length; i++) {
            System.out.print("-");
        }
        System.out.println();
    }
}
----------
Заголовок
------------------------------
static void printLine(int length)

В скобках объявления — параметр: объявлена переменная length типа int. Это пустое окошко: «сюда положат число, когда вызовут».

printLine(10);

В скобках вызова — аргумент: конкретное значение 10. Вызываем метод и передаём аргумент 10 — им инициализируется параметр: в теле метода length равна 10.

Аналогия: бланк заказа

В кафе у тебя бланк: «Напиток: ____, размер: ____». Параметры — это пустые графы бланка, они одинаковые для всех. Аргументы — то, что ты вписал: «капучино», «большой». Каждый заказ — свои аргументы, а бланк один.

Параметр
Переменная в объявлении метода: int length. У неё есть тип и имя.
Аргумент
Значение, которое передают при вызове: 10, x + 1, size. Это может быть число, переменная или целое выражение — Java сначала вычислит его.
Предскажи: что напечатает printLine(0);?

Пустую строку. Параметр length получит 0, тело цикла не выполнится ни разу (0 < 0 — ложь), а вызов System.out.println() после цикла просто переведёт строку. Граничные значения вроде 0 — первое, что стоит проверить у любого метода.

Несколько параметров

Параметров может быть сколько угодно — через запятую, у каждого свой тип:

static void printRow(String symbol, int count) {
    for (int i = 0; i < count; i++) {
        System.out.print(symbol);
    }
    System.out.println();
}

// в main:
printRow("=", 5);    // =====
printRow("*", 3);    // ***

Аргументы передаются в параметры строго по порядку: первый аргумент инициализирует первый параметр, второй — второй. Имена при вызове не пишутся, поэтому компилятор следит за количеством и типами:

ВызовЧто скажет компилятор
printRow("=", 5)✅ всё в порядке
printRow(5, "=")❌ перепутан порядок: incompatible types: int cannot be converted to String
printRow("=")❌ не хватает аргумента: method printRow in class Lines cannot be applied to given types, ниже — required: String,int / found: String

Сообщение cannot be applied to given types выглядит страшно, но читается легко: required — что метод ждёт, found — что ты ему дал. Сравни две строчки — и сразу видно, где промах.

return: метод возвращает результат

Пока наши методы только печатали. Но часто нужно, чтобы метод посчитал что-то и вернул результат тому, кто его вызвал. Для этого вместо void пишут тип возвращаемого значения, а в теле — return:

static int square(int x) {
    return x * x;
}
static int square(int x)

int перед именем — тип возвращаемого значения: «этот метод отдаёт обратно целое число».

return x * x;

return — «вернуть»: вычислить выражение и вернуть его значение туда, откуда метод вызвали. Выполнение метода на этом заканчивается.

Аналогия: гонец в магазин

Ты отправляешь младшего брата в магазин и даёшь ему 100 рублей (аргумент). Он возвращается с хлебом — это возвращаемое значение. А если просишь «выключи свет в коридоре», он сходит и вернётся с пустыми руками — это метод void: дело сделано, приносить нечего.

Главное: вызов метода, который что-то возвращает, — это выражение. Его можно использовать везде, где можно написать число: инициализировать переменную, сложить, передать аргументом:

int a = square(3);                        // a = 9
int sum = square(3) + square(4);          // 9 + 16 = 25
System.out.println(square(5));            // 25
if (square(a) > 50) {                     // square(9) = 81, условие истинно
    System.out.println("Большой квадрат");
}
System.out.println(square(square(2)));    // square(4) = 16
Предскажи: что выведет square(1 + 2) * 2?

18. Сначала Java вычисляет выражение-аргумент: 1 + 2 = 3. Потом вызывает метод: square(3) возвращает 9. И только потом умножает возвращённое значение: 9 * 2 = 18.

Посмотрим по шагам

Пройди трассировку. Обрати внимание, как у метода add появляется свой рабочий стол со своими переменными, а после return он исчезает — остаётся только возвращаемое значение.

return заканчивает метод сразу

return — это не просто «вот ответ», а ещё и «уходим отсюда немедленно». Всё, что ниже, уже не выполнится. Поэтому в методе может быть несколько return — в разных ветках if:

static String sign(int n) {
    if (n > 0) {
        return "плюс";
    }
    if (n < 0) {
        return "минус";
    }
    return "ноль";
}

Если n = 7, сработает первый return, и до проверки n < 0 дело не дойдёт. Тип возвращаемого значения тут String — метод может возвращать любой тип: int, double, boolean, String, даже массив.

Компилятор строго следит за return. Две частые ошибки:

🚫

missing return statement

Метод обещал вернуть int, но есть путь, где return не встретится. Например, все return спрятаны внутри if, а после них ничего. Компилятор не гадает, что условие «точно выполнится», — он требует ответ на каждом пути.

🧱

unreachable statement

Строка сразу после return в том же блоке. До неё выполнение никогда не дойдёт — «недостижимый код». Java считает это ошибкой, а не мелочью.

В методе void тоже можно написать return; — без значения. Это значит «выйти из метода прямо сейчас»:

static void printAge(int age) {
    if (age < 0) {
        System.out.println("Возраст не бывает отрицательным");
        return;                       // дальше не идём
    }
    System.out.println("Тебе " + age + " лет");
}
Результат можно потерять

Строка square(5); сама по себе компилируется: метод вернёт 25 и… никуда его не денет. Возвращаемое значение молча выбросится. Хочешь им воспользоваться — инициализируй им переменную или сразу используй в выражении.

Предскажи: скомпилируется ли метод static int abs(int n) { if (n < 0) { return -n; } }?

Нет: missing return statement. Если n не отрицательное, метод дойдёт до конца, ничего не вернув. Нужно добавить return n; в конце.

Печатать или возвращать?

Новички часто пишут методы, которые печатают ответ, вместо того чтобы его возвращать через return. Сравни:

🖨️

Печатает

static void printSquare(int x) — показал число на экране, и всё. Сложить два таких квадрата, сравнить, сохранить — нельзя: число ушло в консоль.

🎁

Возвращает

static int square(int x) — вернул число в программу. Хочешь — печатай, хочешь — складывай, сравнивай, передавай в другой метод.

Правило: метод, который считает, должен возвращать. Печатать пусть будет main или отдельный метод «показать». Так методы можно собирать, как кубики.

Где это пригодится

В любом интернет-магазине это основа основ. Метод getCartTotal(prices) получает массив цен из корзины и возвращает сумму, а программа использует возвращённое значение дальше: сравнивает с балансом карты, считает скидку, печатает чек — if (balance >= getCartTotal(prices)) { … }. Если бы метод только печатал сумму, сделать с ней было бы нечего.

Частая ошибка — попытаться использовать результат метода void. Он ничего не возвращает, значит, подставить на место вызова нечего:

public class VoidMistake {
    public static void main(String[] args) {
        System.out.println(printSquare(3));   // ошибка
        int x = printSquare(4);               // ошибка
    }

    static void printSquare(int n) {
        System.out.println(n * n);
    }
}

IDEA подчеркнёт оба вызова красным, а компилятор скажет так:

VoidMistake.java:3: error: 'void' type not allowed here
        System.out.println(printSquare(3));   // ошибка
                                      ^
VoidMistake.java:4: error: incompatible types: void cannot be converted to int
        int x = printSquare(4);               // ошибка
                           ^
2 errors

'void' type not allowed here — «тип void здесь не разрешён»: println ждёт значение, а вызов printSquare(3) ничего не даёт. void cannot be converted to int — «пустоту нельзя превратить в int». Лечение одно: если результат нужен — метод должен его возвращать (static int square(int n) { return n * n; }), а если метод только печатает — вызывай его отдельной строкой: printSquare(3);.

Метод может вернуть массив и получить Scanner

Тип возвращаемого значения может быть любым — в том числе массивом. Тогда в заголовке пишут int[], а в теле — return с массивом. А параметром можно передать что угодно, даже Scanner. Вот метод, который читает с клавиатуры n чисел и возвращает их массивом:

import java.util.Scanner;

public class ReadScores {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int[] scores = readArray(sc, 3);
        System.out.println("Сумма: " + sum(scores));
    }

    static int[] readArray(Scanner sc, int n) {
        int[] arr = new int[n];
        for (int i = 0; i < n; i++) {
            arr[i] = sc.nextInt();
        }
        return arr;
    }

    static int sum(int[] arr) {
        int total = 0;
        for (int i = 0; i < arr.length; i++) {
            total += arr[i];
        }
        return total;
    }
}
static int[] readArray(Scanner sc, int n)

Тип возвращаемого значения — int[], «массив целых». Параметров два: Scanner, из которого читать, и сколько чисел прочитать.

return arr;

Метод возвращает массив, который сам создал и заполнил. В main им инициализируется переменная scores. Почему массив при этом не копируется, разберём в уроке 7.4.

int[] scores = readArray(sc, 3);

Вызываем метод readArray и передаём аргументы: наш sc и число 3.

Один Scanner на всю программу

Создавай Scanner один раз в main и передавай его в методы параметром. Не надо писать new Scanner(System.in) в каждом методе: Scanner читает ввод «с запасом», и первый может забрать себе числа, которые предназначались второму. Особенно это заметно, когда ввод приходит сразу целиком — как при автопроверке задач.

Предскажи: что выведет программа, если ввести 4 7 1?

Сумма: 12. readArray прочитает три числа 4, 7, 1 в новый массив и вернёт его. Им инициализируется scores, потом вызываем sum(scores), и он возвращает 4 + 7 + 1 = 12.

Проверь себя

Поговори с наставником

Напиши: «Я прошёл урок 7.2. Придумай мне три метода по описанию, а я скажу для каждого, какие у него параметры и тип результата — без кода тела».

Коротко

  • Параметры — переменные в объявлении метода: static void printRow(String symbol, int count). Аргументы — значения, которые передают при вызове: printRow("=", 5).
  • Аргументы передаются в параметры по порядку; число и типы должны совпасть.
  • Тип перед именем — тип возвращаемого значения. return значение; возвращает результат и сразу завершает метод.
  • Вызов метода, который что-то возвращает, — выражение: его значением можно инициализировать переменную, складывать, передавать аргументом дальше.
  • Ошибки: missing return statement — не на всех путях есть return; unreachable statement — код после return.
  • Метод, который считает, должен возвращать, а не печатать. Результат void-метода использовать нельзя: 'void' type not allowed here.
  • Метод может вернуть массив (static int[] readArray(Scanner sc, int n)). Scanner создаём один раз в main и передаём в методы параметром.
