Мастерская: разбиваем задачу на методы

Большую задачу трудно решить целиком — и не нужно. Учимся резать её на маленькие методы с понятными именами, каждый из которых решить легко. Это называется декомпозиция.

Задача и шаг 1: пойми её

Задача: совершенные числа

Число называется совершенным, если оно равно сумме всех своих делителей, кроме себя самого. Например, 6: его делители 1, 2, 3, и 1 + 2 + 3 = 6. Пользователь вводит N — выведи через пробел все совершенные числа от 1 до N.

Шаблон Мастерской ты знаешь с модуля 4. Первый шаг — понять задачу: что на входе, что на выходе, и пара примеров руками, включая граничные.

Вход NВыходПочему
106до 10 совершенное только 6
306 2828 = 1 + 2 + 4 + 7 + 14
5пустая строкасовершенных чисел меньше 6 нет
1, 0 или −7пустая строкау 1 делителей «кроме себя» нет, сумма 0 ≠ 1; числа ≤ 0 не перебираем

Если сразу начать писать код, голова будет держать всё одновременно: ввод, перебор чисел, перебор делителей, сумму, сравнение, печать. Это как готовить обед из трёх блюд, не разделив его на блюда. Разделим.

Шаг 2: реши руками и найди подзадачи

Проверим руками пару чисел и запишем, что мы делали:

  • 6: делители меньше 6 — это 1, 2, 3. Сумма 6. Совпало с числом — совершенное ✓.
  • 12: делители 1, 2, 3, 4, 6. Сумма 16. Не совпало ✗.

Что повторялось? Для каждого числа мы делали одно и то же: нашли сумму делителей → сравнили с числом. А всё вместе — для каждого числа от 1 до N. Получилось три подзадачи, вложенные друг в друга. Каждая — кандидат в метод:

Декомпозиция
Разбиение большой задачи на маленькие независимые части. Главный навык программиста — важнее знания синтаксиса.
Аналогия: ремонт квартиры

Никто не делает «ремонт» одним действием. Это «снять обои», «выровнять стены», «поклеить новые». А «выровнять стены» — это «зашпаклевать» и «зашкурить». Делишь, пока каждый кусок не станет понятным действием, которое можно поручить одному мастеру. Метод — это и есть такой мастер.

Шаги 3–4: роли переменных и псевдокод

Теперь каждую подзадачу решаем отдельно, не думая об остальных. Начнём снизу.

МетодРоли переменныхПсевдокод
sumOfDivisors(number)d — шагающая (кандидаты в делители), sum — накопительsum = 0; для d от 1 до number − 1: если number делится на d — прибавь d к sum; верни sum

printPerfectUpTo(n)i — шагающая (числа от 1 до n)для i от 1 до n: если i совершенное — напечатай i и пробел; в конце переведи строку

Заметь: псевдокод printPerfectUpTo говорит «если i совершенное» — и не объясняет, как это проверить. Это не его забота: он просто доверяет методу isPerfect. Каждый метод видит только свой кусочек задачи.

Как выбирать, что станет методом

Если кусок решения можно назвать коротким глаголом («посчитать сумму делителей», «проверить, совершенное ли») и описать вход (параметры) и выход (возвращаемое значение) — делай из него метод. Признак, что метод слишком большой: в его имени просится «и» (readAndPrintAndCheck), или он не помещается на экран.

Шаг 5: код — переводим псевдокод

Удобный приём: начни с main и пиши вызовы так, будто нужные методы уже объявлены. IDEA подчеркнёт незнакомое имя красным — поставь на него курсор, нажми Alt+Enter → Create method, и IDEA сама создаст заготовку — объявление метода с правильными параметрами. Потом заполняешь заготовки одну за другой.

import java.util.Scanner;

public class PerfectNumbers {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int n = scanner.nextInt();
        printPerfectUpTo(n);
    }

    static void printPerfectUpTo(int n) {
        for (int i = 1; i <= n; i++) {
            if (isPerfect(i)) {
                System.out.print(i + " ");
            }
        }
        System.out.println();
    }

    static boolean isPerfect(int number) {
        return sumOfDivisors(number) == number;
    }

    static int sumOfDivisors(int number) {
        int sum = 0;
        for (int d = 1; d < number; d++) {
            if (number % d == 0) {
                sum += d;
            }
        }
        return sum;
    }
}

Вызов метода с типом возвращаемого значения boolean ставится прямо в условие, аргумент — счётчик i. Читается как текст: «если i совершенное».

return sumOfDivisors(number) == number;

Сравнение == — само по себе выражение со значением true или false. Не нужно писать if (…) return true; else return false; — возвращаем значение выражения сразу.

Предскажи: что вернёт isPerfect(1)? А что выведет программа при N = 0?

isPerfect(1) вернёт false: тело цикла в sumOfDivisors не выполнится ни разу (1 < 1 — ложь), метод вернёт 0, а 0 ≠ 1. При N = 0 тело цикла в printPerfectUpTo тоже не выполнится — выведется пустая строка. Граничные случаи отработали без единого лишнего if.

Шаг 6: проверь трассировкой

Проверим самый нижний кирпичик на числе 6. Впиши значения sum сам — это и есть таблица трассировки «шаг | d | sum».

Главный плюс методов: каждый можно проверить отдельно. Сомневаешься в sumOfDivisors — вызови его из main с аргументами 6, 12, 1 и посмотри на возвращаемые значения. Именно так устроены тесты в реальных проектах: каждый тест проверяет один метод на нескольких входах. Через десять модулей ты будешь делать это с JUnit.

Как придумывать имена методов

Хорошее имя — половина декомпозиции. Читая if (isPerfect(i)), ты понимаешь код, даже не заглядывая в метод. Правила:

Что делает методКак назватьПримеры
Действие, ничего не возвращаетглагол + чтоprintReceipt, showMenu, reverseArray
Считает и возвращает значение (return)глагол calculate/count/find + что, или существительное-результатcalculateTotal, countVowels, findMax, sumOfDivisors
Отвечает «да/нет» (boolean)вопрос: is/has/can + чтоisPrime, isEven, hasDiscount, canBuy

Плохие имена

doIt, method1, calc, process, check — непонятно, что делают. prime для boolean-метода — это вопрос или число?

👍

Хорошие имена

По имени ясно, что метод делает и что вернёт: isPrime(n) — вопрос «простое ли n?», возвращаемое значение true/false.

По-английски

Java позволяет русские имена, но в работе их не пишут: код читают коллеги по всему миру. Не знаешь слово — посмотри в переводчике, это нормально.

Твоя очередь: простые числа

Тот же приём ты применишь в задаче «Простые числа до N» на странице практики. Код не дадим — но шаблон Мастерской пройдём вместе на уровне плана.

  1. Пойми. Простое число — больше 1 и делится нацело только на 1 и на себя. 2, 3, 5, 7, 11… А 1 — не простое, 0 и отрицательные — тоже. Пример: N = 10 → 2 3 5 7.
  2. Подзадачи. «Проверить одно число» → метод isPrime(n) с типом возвращаемого значения boolean. «Перебрать числа до N и напечатать простые» → метод printPrimesUpTo(n).
  3. Роли. В isPrime — шагающая переменная (счётчик цикла) перебирает кандидатов в делители. Нашёлся делитель — ответ ясен сразу (вспомни, что return заканчивает выполнение метода).
  4. Граничные случаи. Что вернёт твой isPrime для 1, для 2, для 0? Проверь до запуска тестов.

Коротко

  • Декомпозиция: делим задачу сверху вниз, пока каждый кусок не станет простым методом с одной работой.
  • Каждый метод решаем отдельно и доверяем остальным: printPerfectUpTo не знает, как устроен isPerfect.
  • Удобно начинать с main, вызывая ещё не объявленные методы, а заготовки объявлений создавать через Alt+Enter.
  • Имена: действие — глагол + что, вычисление — calculate/count/find, вопрос — is/has/can. По-английски, в camelCase.
  • Короткие методы легко проверить по отдельности — на этом построено тестирование с JUnit (модуль 17).
