От чертежа к коду: класс и объект

Помнишь чертёж «Кот» из самого первого урока? Пора написать его по-настоящему: свой класс, свои объекты в куче и ссылки на них.

Зачем нужны свои классы

Допустим, программа ведёт учёт котов в приюте. С тем, что ты уже знаешь, данные придётся раскладывать по разным переменным или по нескольким массивам:

String[] names = {"Мурзик", "Барсик", "Пушок"};
int[] ages     = {3, 5, 1};
double[] weights = {4.2, 5.8, 2.1};

// возраст Барсика — ages[1], вес — weights[1], имя — names[1]
// удалил кота из одного массива и забыл про другой — всё поехало

Имя, возраст и вес одного кота живут в трёх разных местах, а связывает их только одинаковый номер. Ошибёшься в номере — и возраст Барсика достанется Пушку.

Хочется, чтобы всё про одного кота лежало вместе, в одной «вещи». Для этого в Java есть классы. Ты описываешь новый тип данных — «Кот» — и дальше работаешь с котами целиком, а не с кусочками.

Ты уже знаешь типы int, double, String. Сегодня ты научишься придумывать свои типы. Это главная идея Java — недаром её называют объектно-ориентированным языком.

Где это в реальных программах

В реальных программах почти всё — объекты. Клиент банка (имя, телефон, email) — объект. Его счёт — тоже объект: у него есть данные (номер, баланс) и действия «пополнить», «снять» (методы). Без классов большие программы не пишут.

Класс — это чертёж

Опишем кота. Создай в папке module-09 новый класс: правый клик → New → Java Class → имя Cat. И напиши:

public class Cat {
    String name;
    int age;
    double weight;
}
public class Cat {

Объявление класса Cat: объявляем новый класс. С этой секунды в программе есть новый тип данных — такой же, как String, только твой.

String name;

Поле — переменная, объявленная прямо в классе, а не внутри метода. У каждого кота будет своё имя.

int age;

Ещё одно поле — возраст. Полей может быть сколько угодно, любых типов.

}

Метода main тут нет — и не нужно. Класс Cat — не программа, а описание: какие данные есть у любого кота.

Аналогия: бланк анкеты

Класс — это пустой бланк с графами «Имя», «Возраст», «Вес». Сам по себе бланк — не кот. Объект — заполненная анкета конкретного кота. Бланк один, анкет — сколько угодно, и в каждой свои данные.

Класс
Описание нового типа: какие данные (поля) и какие действия (методы) будут у его объектов.
Поле
Переменная внутри класса. Своя копия поля есть у каждого объекта.
Объект (экземпляр)
Конкретная «вещь», созданная по классу. Мурзик и Барсик — два объекта класса Cat.
Имена классов

Имя класса — существительное с большой буквы: Cat, BankAccount, ShoppingCart. Поля — с маленькой: name, age. Это не прихоть, а договорённость всех Java-программистов: по регистру сразу видно, где класс, а где переменная.

new: строим объект по чертежу

Теперь создадим объекты — котов. Рядом с Cat.java создай класс CatDemo — в нём будет main:

public class CatDemo {
    public static void main(String[] args) {
        Cat murzik = new Cat();
        murzik.name = "Мурзик";
        murzik.age = 3;

        System.out.println(murzik.name + ", " + murzik.age + " года");
    }
}
Cat murzik

Объявляем переменную murzik типа Cat. Как String s, только тип наш. Переменная будет хранить не сам объект-кот, а ссылку на него — помнишь номерок из гардероба (урок 2.4)?

new Cat()

Создание объекта (экземпляра) класса Cat оператором new; скобки () — вызов конструктора (о нём — в уроке 9.3). Java выделяет место в куче, раскладывает там поля и возвращает ссылку — номерок. Этой ссылкой и инициализируется murzik.

murzik.name = "Мурзик";

Точка — обращение к полю объекта, «зайти внутрь»: по ссылке из murzik дойти до объекта и присвоить значение его полю name.

murzik.age

Так же читаем значение поля: «поле age того объекта, на который указывает ссылка в murzik».

Классы Cat и CatDemo лежат в одной папке, поэтому CatDemo видит Cat без всяких подключений. Запускать нужно CatDemo — у него есть main.

Предскажи: что напечатает System.out.println(murzik.weight);, если вес мы так и не записали?

0.0. Поля нового объекта Java сама заполняет значениями по умолчанию — как элементы нового массива из модуля 6: числа — 0 и 0.0, boolean — false, ссылки (в том числе String) — null. Поэтому new Cat() сразу даёт кота с именем null и возрастом 0.

Если IDEA пишет «Duplicate class»

Все папки курса — части одного проекта, и два класса с одинаковым именем в разных папках мешают друг другу. Если IDEA подчеркнула имя класса и пишет duplicate class, значит, такое имя уже есть в другом модуле. Назови свой класс иначе, например Cat9. Удобнее всего — поставить курсор на имя класса и нажать Shift+F6 (Rename): IDEA переименует и класс, и файл, и все места, где он используется.

Две ссылки — один кот

Строка Cat same = murzik; — самое важное место урока. Здесь не создаётся новый объект: переменная same инициализируется копией ссылки из murzik. Копируется только номерок. Новый объект появляется только там, где написано new.

Аналогия: ключи от квартиры

У тебя есть ключ от квартиры. Ты сделал дубликат и отдал другу. Квартира от этого не удвоилась! Если друг переставит диван, ты, придя домой, увидишь диван на новом месте. Переменные-ссылки — это ключи, объект — квартира.

А как проверить, один это кот или два одинаковых? Оператор == для объектов сравнивает ссылки: «ведут ли номерки к одному и тому же пальто». Ты уже встречал это со строками в модуле 8.

Cat a = new Cat();
a.name = "Пушок";
Cat b = new Cat();
b.name = "Пушок";
Cat c = a;

System.out.println(a == b);   // false: два разных объекта, хоть и одинаковые
System.out.println(a == c);   // true: одна и та же ссылка

Ссылки можно увидеть своими глазами в отладчике (ты знаешь его по модулям 5 и 7). Поставь точку останова на строку с первым println, запусти 🐞 Debug — и раскрой переменные в панели Variables:

Номера вроде @815 отладчик раздаёт сам, у тебя они будут другими. Важно не число, а совпадает ли оно у двух переменных.

Предскажи: после c.name = "Снежок"; что напечатает System.out.println(a.name);?

Снежок. c и a указывают на один объект. Меняешь через одну ссылку — видно через другую. А у b имя осталось «Пушок»: это отдельный кот.

Сравнить котов «по содержимому» (одинаковые ли у них имена и возраст) оператор == не умеет. Для этого есть метод equals — ты знаешь его по строкам. Как научить ему свои классы, разберём в модуле 10.

null и NullPointerException

Переменная типа Cat может не указывать ни на какого кота — тогда в ней null, «пустой номерок». Читать поле по пустому номерку нельзя: идти некуда.

public class Ghost {
    public static void main(String[] args) {
        Cat ghost = null;
        System.out.println("Ищу кота...");
        System.out.println(ghost.name);
        System.out.println("Нашёл!");
    }
}

Программа скомпилировалась — компилятор не знает, что в ghost будет null. А при запуске упала на строке 5 с NullPointerException (NPE) — «исключение пустой ссылки». Java честно пишет: не могу прочитать поле name, потому что ghost — null.

  • Cannot read field "name" — пытались прочитать поле;
  • Cannot assign field "name" — пытались записать в поле;
  • Cannot invoke "..." — пытались вызвать метод (это будет в следующем уроке).
Предскажи: напечатается ли «Нашёл!»?

Нет. Исключение останавливает программу на строке 5. Всё, что ниже, уже не выполнится.

Самая частая ошибка в Java

NPE — чемпион среди ошибок Java-программистов: «клиента в базе не нашли, в переменной null, а мы вызываем у неё метод». Как только видишь NPE — ищи в строке из stack trace, какая переменная слева от точки оказалась null, и выясняй, почему туда не попал объект.

Коротко

  • Класс — чертёж нового типа: class Cat { String name; int age; }. Переменные внутри класса — поля.
  • new Cat() создаёт объект (экземпляр) в куче, вызывая конструктор, и возвращает ссылку. Поля нового объекта: 0, 0.0, false, null.
  • Точка — обращение к полю объекта по ссылке («пройти по ссылке к объекту»): murzik.name.
  • Cat b = a; копирует ссылку, а не объект: дальше a и b — один и тот же кот. == сравнивает ссылки.
  • По ссылке null нельзя читать поля и вызывать методы — будет NullPointerException.
