Мастерская: построй свою иерархию вызовов

В прошлом уроке ты увидел, что println передаёт работу по цепочке объектов JDK. Теперь построишь свою: кофейня из десяти классов, где один заказ запускает всю цепочку. Потом сломаешь её на самом дне, прочитаешь stack trace и пройдёшь всё отладчиком.

Повторение

Задача и шаг 1: пойми её

Построим кофейню. Посетитель делает один вызов — shop.order("капучино"), — а внутри срабатывает целая цепочка: кофейня вызывает метод баристы, бариста — метод кофемашины, та — метод бойлера, и так до датчика температуры на самом дне. Каждый класс отвечает за одно дело и знает только своего соседа снизу. Ровно как цепочка объектов за System.out.

Что на входе? Один вызов метода сверху. Что на выходе? Каждый уровень печатает строку, когда начинает работу, и строку, когда закончил. Отступ — по два пробела на этаж, чтобы видеть глубину. Должно получиться так:

Кофейня: принят заказ «капучино»
  Бариста: готовлю капучино
    Кофемашина: варю
      Бойлер: грею воду
        Насос: качаю воду
          Клапан: открываю
            Нагреватель: включаю
              Термостат: проверяю
                Датчик: 92 градуса
              Термостат: норма
            Нагреватель: выключаю
          Клапан: закрываю
        Насос: готово
      Бойлер: готово
    Кофемашина: готово
  Бариста: готово
Кофейня: заказ готов
Заказ выдан!
Предскажи: почему строки «готово» идут в обратном порядке — сначала Термостат, а Кофейня последней?

Это стек вызовов: последним вызван — первым закончится. Термостат не может сказать «норма», пока датчик не вернёт температуру. Нагреватель не может выключиться, пока не закончил термостат. Кофейня ждёт дольше всех — она начала первой. Вывод — это стек, нарисованный боком: вниз — вызовы, вверх — возвраты.

класс Звено:
    поле: сосед = новый объект класса Сосед
    метод работать():
        напечатать (отступ + "Звено: начинаю")
        сосед.работать()
        напечатать (отступ + "Звено: готово")

Откуда возьмутся объекты-соседи? Каждый класс создаёт своего соседа в инициализаторе поля (урок 9.3): private final Barista barista = new Barista();. Значит, одна строка new CoffeeShop() запустит лавину: конструктор кофейни создаст баристу, конструктор баристы — кофемашину, и так до датчика. Девять объектов от одного new!

Когда объект хранит в полях другие объекты и пользуется ими, говорят: объект состоит из других. Это называется композиция. Кофейня «имеет» баристу, бариста «имеет» кофемашину — как машина имеет двигатель и колёса. Композиция — главный способ собирать большие программы из маленьких классов; в модуле 10 ты сравнишь её с наследованием.

Приём из урока 9.1: существительные → классы

Откуда взялись именно эти десять классов? Опиши кофейню словами и подчеркни существительные: «Кофейня принимает заказ, бариста готовит его на кофемашине; в машине бойлер с насосом, клапаном и нагревателем, а термостат слушает датчик». Каждое существительное — кандидат в класс, глаголы («готовит», «греет», «проверяет») — его методы.

Почему поле, а не new прямо в методе

Можно писать и new Barista().prepare(drink) внутри order. Но тогда при каждом заказе создавался бы новый объект Barista — «нанимался новый бариста». В жизни бариста один и обслуживает много заказов — поэтому он поле кофейни. Так же System.out держит нужные ему объекты в полях, а не создаёт их заново на каждый println.

Шаг 5: код — переводим псевдокод

Создай в module-09 файл CoffeeDemo.java. Все классы — в нём: сверху public-класс с main, ниже остальные без public. Вот верх и низ цепочки:

public class CoffeeDemo {
    public static void main(String[] args) {
        CoffeeShop shop = new CoffeeShop();
        shop.order("капучино");
        System.out.println("Заказ выдан!");
    }
}

class CoffeeShop {
    private final Barista barista = new Barista();

    void order(String drink) {
        System.out.println("Кофейня: принят заказ «" + drink + "»");
        barista.prepare(drink);
        System.out.println("Кофейня: заказ готов");
    }
}

class Barista {
    private final CoffeeMachine machine = new CoffeeMachine();

    void prepare(String drink) {
        System.out.println("  Бариста: готовлю " + drink);
        machine.brew();
        System.out.println("  Бариста: готово");
    }
}

Если IDEA пишет duplicate class

Имена Valve, Heater, Boiler могли уже встретиться тебе в других модулях. Все папки курса — один проект, поэтому два класса с одинаковым именем конфликтуют. Добавь приставку: CoffeeValve, CoffeeHeater — на суть упражнения это не влияет.

Эксперимент 1: сломай дно и прочитай stack trace

Датчик сломался. Добавь в measure() первой строкой:

class TemperatureSensor {
    int measure() {
        throw new RuntimeException("Датчик сломался");
    }
}

IDEA подчеркнёт строки ниже throw как недостижимые — удали их (печать и return), после throw метод всё равно не продолжится:

Запусти:

Номера строк у тебя будут свои. Теперь читаем снизу вверх — так ты видишь всю иерархию в порядке вызовов:

  1. CoffeeDemo.main, строка 4 — с него всё началось: вызов shop.order(…).
  2. CoffeeShop.order → Barista.prepare → CoffeeMachine.brew → … каждая строка «at» — этаж стека, а номер — строка, на которой этот метод вызвал метод соседа и ждал возврата.
  3. TemperatureSensor.measure, строка 95 — вершина: здесь выброшено исключение. Сверху — сообщение: RuntimeException: Датчик сломался.

Заметь: во всех строках файл один — CoffeeDemo.java, хотя классы разные. Stack trace показывает и класс, и файл, где он написан. Щёлкни в IDEA по синему CoffeeDemo.java:84 — редактор прыгнет ровно на вызов sensor.measure() в термостате.

Предскажи: почему в выводе нет ни одной строки «готово» и нет «Заказ выдан!»?

Исключение не возвращает управление обычным путём. Оно пролетает через все этажи вверх, снимая фреймы, и ни один метод не доходит до своей следующей строки. До main оно долетело необработанным — программа завершилась, а JVM напечатала stack trace. Перехватывать исключение по дороге (блок try-catch) научимся в модуле 12.

Красный текст может «влезть» в середину

Stack trace печатается в System.err, а твои строки — в System.out. Помнишь урок 9.6? Это два разных объекта PrintStream, и каждый выводит текст сам по себе. Поэтому в IDEA красные строки иногда появляются раньше или посередине чёрных. Это нормально: порядок между двумя потоками вывода не гарантирован.

Эксперимент 2: пройди цепочку отладчиком

Верни датчик в рабочее состояние (печать и return 92). Теперь посмотрим ту же лестницу вживую.

  1. Поставь breakpoint на строку shop.order("капучино"); в main. Запусти Debug 🐞.
  2. Жми F7 (Step Into). Это твои классы, а не JDK, — фильтр их не трогает, и отладчик честно заходит в order.
  3. В order строка с System.out.println — жми F8, чтобы не проваливаться в JDK. На строке barista.prepare(drink) — снова F7. И так этаж за этажом.
  4. Следи за панелью Frames: стопка растёт — order, prepare, brew… На дне, в measure, в ней 10 фреймов — ровно столько, сколько строк «at» было в stack trace.
  5. В панели Variables раскрой this — у каждого звена в поле видна ссылка на соседа (barista = Barista@…). Это и есть цепочка объектов из кучи.
  6. Щёлкни в Frames по фрейму prepare — увидишь его drink = "капучино". Вернись на верхний фрейм.
  7. Выбирайся: Shift+F8 (Step Out) несколько раз — и смотри, как фреймы снимаются, а в консоли появляются строки «готово».

Ещё эксперименты

Попробуй и объясни, что увидел

1. Авария посередине. Перенеси throw из датчика в Valve.open(). Сколько строк «at» стало? Какие строки «начал» успели напечататься?

2. Двойной заказ. Вызови shop.order(…) в main два раза: «капучино» и «латте». Создастся ли новый бариста для второго заказа? (Подсказка: где он создаётся — в поле или в методе?)

3. Забытый new. Замени в Boiler private final WaterPump pump = new WaterPump(); на private WaterPump pump;. Что напечатается и какое исключение будет? На какой строке и почему именно там?

4. Замкнутый круг ★★★. Пусть термостат вместо датчика вызывает… кофемашину (в поле — new CoffeeMachine()). Что случится? Подсказка: получится бесконечная цепочка new ещё при создании объектов — и Java упадёт с StackOverflowError, переполнением стека, как бесконечная рекурсия из модуля 7.

Где это в реальных программах

Интернет-магазин устроен ровно так: кнопка «Оплатить» вызывает метод корзины cart.checkout(card), тот — метод платёжного сервиса, тот — метод банка, банк — свою базу данных. Сорвался платёж — в stack trace лестница из десятков этажей. Ты теперь знаешь, как по ней спускаться.

Задача «Ракетный старт» на странице практики — такая же цепочка, но про ракету и с точным выводом: проверка сравнит каждую строку и посчитает классы.

Проверь себя

Покажи наставнику

Напиши: «Я построил кофейню из 10 классов и сломал датчик. Вот мой stack trace — давай я объясню каждую строку, а ты проверь». И вставь свой stack trace.

Коротко

  • Цепочка объектов: каждый класс держит в поле ссылку на соседа и вызывает его метод — так устроены и System.out, и большие программы. Объект, собранный из других объектов в полях, — это композиция.
  • Какие нужны классы, подскажут существительные в описании задачи, какие методы — глаголы.
  • Вниз — вызовы, вверх — возвраты (LIFO). Отступы в выводе рисуют форму стека.
  • Исключение на дне пролетает все этажи; stack trace читаем снизу вверх — порядок вызовов, сверху — место аварии.
  • Отладчик: F7 в свои методы, F8 через println, Shift+F8 наверх; Frames = тот же стек, что в stack trace.
