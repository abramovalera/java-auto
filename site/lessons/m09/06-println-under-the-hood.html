Java — это гора готового кода

Когда ты установил JDK, ты получил не только компилятор javac и JVM. Самая большая часть JDK — стандартная библиотека: тысячи готовых классов, которые за тридцать лет написали программисты Oracle и сообщества. String, Math, Scanner, Arrays — все они оттуда. Твой HelloWorld в пять строк стоит на вершине горы из миллионов строк чужого кода.

Аналогия: городская библиотека

Тебе нужен рецепт пирога — ты не пишешь кулинарную книгу с нуля, а идёшь в отдел «Кулинария», находишь книгу и открываешь нужную главу. Программист так же: нужно напечатать текст — идёт в «отдел» java.io, берёт «книгу» PrintStream и «главу» println. Знать наизусть все книги не нужно, нужно уметь искать и читать.

И главное: эта библиотека — не чёрный ящик. Её исходный код лежит у тебя на компьютере, и его можно открыть и прочитать, как свой.

  1. В IDEA открой панель Project (Alt+1) и прокрути в самый низ — там узел External Libraries.
  2. Раскрой < 21 > (твой JDK) → java.base → java → lang. Перед тобой полки отдела java.lang: Math, String, System…
  3. Дважды щёлкни по System — откроется настоящий исходник класса, тот самый, что работает в каждой Java-программе мира.
🔎 Для любопытных: где это лежит на диске

Внутри папки JDK (у тебя — что-то вроде C:\Users\…\.jdks\temurin-21…) есть файл lib\modules — там байт-код всех классов библиотеки, его читает JVM. А рядом lib\src.zip — исходники на Java, их показывает IDEA. Если вместо исходника IDEA показывает «Decompiled .class file», значит src.zip не нашёлся — сверху будет кнопка Download Sources.

Разбираем строку по кусочкам

Теперь ты знаешь всё, чтобы прочитать заклинание. В нём ровно четыре детали, и каждую ты уже проходил в этом модуле:

Прочитаем вслух: «обращаемся к static-полю out класса System; в нём хранится ссылка на объект класса PrintStream; вызываем у этого объекта метод println и передаём ему аргумент "Hi"».

Это легко проверить: ту же самую строку можно разложить на шаги. Набери в module-09:

import java.io.PrintStream;

public class LongHand {
    public static void main(String[] args) {
        PrintStream console = System.out;     // ② достали объект из static-поля
        console.println("Hi");                // ③ вызвали метод объекта
        console.println(42);                  //    другой println — для int

        java.lang.System.out.println("Hi");   // ① полное имя класса — работает
    }
}
PrintStream console = System.out;

Объявляем переменную console типа PrintStream и инициализируем её ссылкой из static-поля System.out — как Cat same = murzik;. Нового объекта не создали: console и System.out — два номерка от одного «пальто».

console.println("Hi");

Вызов метода println у объекта, на который ссылается console, с аргументом "Hi". Внутри println this указывает на тот же объект, что и System.out.

java.lang.System

Полное имя класса: пакет + имя. Можно, но никто так не пишет — java.lang подключён сам.

Предскажи: а без строки import java.io.PrintStream; скомпилируется?

Нет: cannot find symbol: class PrintStream. Класс PrintStream живёт в пакете java.io, а не в java.lang. Почему же в обычном HelloWorld import не нужен? Потому что там слово PrintStream нигде не написано! import нужен только для того, чтобы компилятор понял имя, которое ты пишешь. Пользоваться объектом чужого класса можно и без import — главное не писать его имя.

Заглянем в класс System

Открой System (Ctrl+клик по слову System в любом своём файле). Класс огромный, но нас интересует несколько строк. Упрощённо они выглядят так:

package java.lang;

public final class System {

    private System() { }                       // создать объект System нельзя

    public static final InputStream in = null;   // клавиатура
    public static final PrintStream out = null;  // обычный вывод
    public static final PrintStream err = null;  // вывод ошибок

    public static long currentTimeMillis() { … } // текущее время
    public static void exit(int status) { … }    // завершить программу
    …
}
private System() { }

Конструктор есть, но private — снаружи его не вызвать. new System() не скомпилируется: System() has private access in java.lang.System. Объект System никому не нужен — у класса всё static.

public static final PrintStream out

Вот он, наш out: public — виден всем, static — один на класс, обращаемся System.out, final — присвоить другое значение нельзя: System.out = null; — ошибка компиляции.

in и err

Ещё два «соседа» out. System.err — второй объект PrintStream, для сообщений об ошибках (в IDEA он печатает красным, туда же Java пишет stack trace). System.in — поток с клавиатуры.

Теперь понятна строка, которую ты пишешь с модуля 2: new Scanner(System.in) — «создай новый объект класса Scanner и передай в конструктор ссылку из static-поля in класса System». Ни одного магического слова!

🔎 Для любопытных: почему там написано = null?

В исходнике действительно стоит out = null. Настоящий объект кладёт туда сама JVM при старте программы, ещё до твоего main: она вызывает внутренний метод System.initPhase1(), который создаёт PrintStream поверх «файла» номер 1 (стандартный вывод) и записывает его в поле в обход final — это может только сама JVM. А легальный способ подменить вывод — метод System.setOut(другойPrintStream): после него все println пойдут туда, куда скажешь.

Класс PrintStream и десять println

Теперь «провалимся» в сам println: Ctrl+клик по слову println. Откроется файл PrintStream.java из пакета java.io. Нажми Ctrl+F12 — появится список всех методов класса — и начни набирать println. Их десять:

МетодКогда выбирается
println()без аргументов — просто перевод строки
println(boolean x)println(true)
println(char x)println('A')
println(int x)println(42)
println(long x), println(float x), println(double x)другие числа
println(char[] x)массив символов печатается как текст
println(String x)println("Hi")
println(Object x)любой объект — например, твой кот

Это перегрузка из модуля 7 в чистом виде: одно имя, разные параметры. Компилятор смотрит на тип аргумента и выбирает подходящий метод ещё до запуска программы. Поэтому println(42) и println("42") — вызовы разных методов.

А что внутри println(String)? Если убрать технические детали, по смыслу он устроен так:

public void println(String x) {
    print(x);      // напечатать текст
    newLine();     // и перевести строку
}
public void println(String x)

Обычный метод объекта: public, без static, ничего не возвращает. Ты сам пишешь такие с урока 9.2.

print(x); newLine();

println = print + перевод строки — отсюда и «ln» в названии (от line, «строка»). Сам println ничего не рисует: он вызывает другие методы этого же объекта.

Видишь узор? Каждый метод делает чуть-чуть и вызывает следующий. println → print → write → … Куда ведёт эта лестница — на следующем шаге.

🔎 Для любопытных: настоящий код println в JDK 21 
public void println(String x) {
    if (getClass() == PrintStream.class) {
        writeln(String.valueOf(x));
    } else {
        synchronized (this) {
            print(x);
            newLine();
        }
    }
}

getClass() == PrintStream.class — «я самый обычный PrintStream?». У System.out — да, и тогда короткая дорога: writeln печатает строку и перевод строки за один заход. Ветка с print(x); newLine(); — для «наследников» PrintStream (модуль 10); в Java 8 только она и была. synchronized (this) защищает от ситуации, когда две части программы печатают одновременно и буквы перемешиваются, — это многопоточность, модуль 16.

Предскажи (классика собеседований): скомпилируется ли System.out.println(null);?

Нет! reference to println is ambiguous — «вызов неоднозначен». null подходит сразу к трём методам со ссылочным параметром: println(char[]), println(String) и println(Object). Object компилятор отбросит как самый общий, а между char[] и String выбрать не может — они равноправны. А вот String s = null; System.out.println(s); работает и печатает null: тип переменной однозначно указывает на println(String).

Что дальше: println передаёт работу по цепочке

Сам println ничего на экране не рисует. Он делает свою маленькую часть работы и вызывает метод другого объекта, тот — метод следующего, и так несколько раз. Внутри System.out не один объект, а небольшая цепочка: каждый держит в поле ссылку на следующего. Один превращает буквы в байты (числа, которыми компьютер хранит текст), другой копит их, чтобы отправлять пачками, третий отдаёт их наружу. На самом дне Java просит операционную систему (Windows) вывести байты, а IDEA показывает их буквами в панели Run.

Почему бы не сделать один метод «напечатай», который сразу зовёт ОС? Потому что у каждого этажа своя работа, и каждый класс делает только её. Это главный принцип хорошего кода: одна ответственность на класс.

Аналогия: отправка письма

Ты пишешь письмо и отдаёшь секретарю (println). Переводчик переводит его на язык адресата (буквы → байты). Письма складывают в мешок, пока он не наполнится, — гонять курьера ради одной открытки дорого. Курьер везёт мешок на почтамт (операционная система), а почтальон кладёт письмо в ящик получателю (IDEA). Ты при этом знаешь только секретаря.

Это устройство даёт свободу: поменяй нижний этаж — и тот же println будет писать не в консоль, а в файл. В модуле 15 ты так и сделаешь.

Запоминать этажи наизусть не нужно. Главное: System.out.println — это обычный вызов метода у объекта, а за ним стоит цепочка других объектов. Если интересно, как именно буквы «Hi» превращаются в байты и доходят до ОС, — загляни в блок «для любопытных».

Ниже — упрощённый код нескольких классов JDK, собранный в одну ленту. Мы выбросили всё лишнее (проверки, блокировки, обработку ошибок), но имена классов, методов и порядок вызовов — настоящие, из JDK 21. Жми «Шаг ▶» и следи за стеком: он растёт этаж за этажом. Справа в «куче» — объекты, из которых собран System.out.

Честно про упрощение. В настоящем JDK 21 этажей ещё больше — шестнадцать. Между нашими добавятся служебные методы вроде implWriteln, implWrite, StreamEncoder.implFlushBuffer. Вот настоящий стек в момент, когда байты уходят в операционную систему (снят на Temurin 21.0.13; сверху — вершина, снизу — твой main; жирным — этажи из тренажёра):

Классов здесь всего пять (PrintStream, OutputStreamWriter, StreamEncoder, BufferedOutputStream, FileOutputStream), а методов — пятнадцать. Метод на самом дне, writeBytes, помечен словом native: у него нет тела на Java, он написан на языке C внутри JVM и обращается к операционной системе.

Вот за что отвечает каждый этаж:

Кракозябры. Если программа закодировала текст в UTF-8, а консоль читает байты как другую кодировку (например, старую Windows-1251), «Привет» превращается в «РџСЂРёРІРµС‚». Ломается этаж «символы → байты» или обратный ему в консоли. Поэтому сервер курса запускает твою программу с параметром -Dstdout.encoding=UTF-8 — он настраивает именно этот этаж.

Миллион println. У System.out включён autoFlush («отправлять сразу»), поэтому каждый println доходит до операционной системы. Если печатать миллион строк в цикле, программа будет заметно тормозить именно на вызовах ОС. Профессиональный приём — собрать текст в StringBuilder (модуль 8) и напечатать одним println.

Провались сам: навигация по коду в IDEA

Схемы — это хорошо, но настоящий навык — самому найти, что внутри любого метода. Создай в module-09 класс и проделай всё руками:

public class Peek {
    public static void main(String[] args) {
        System.out.println("Hi");

}
  1. Зажми Ctrl и наведи мышь на println — слово станет ссылкой. Щёлкни (или поставь курсор и нажми Ctrl+B, «Go to Declaration»). Откроется PrintStream.java — ровно на методе println(String). Сверху вкладки видно: файл только для чтения, это код JDK.
  2. Настоящий код println сложнее нашего упрощения — не пугайся, разбирать его не нужно. Просто щёлкни с Ctrl по writeln внутри него — окажешься в следующем методе цепочки. Так можно спускаться и дальше, но глубоко нырять не обязательно.
  3. Возвращайся обратно по своим следам: Ctrl+Alt+← (Back), вперёд — Ctrl+Alt+→.
  4. Находясь в PrintStream.java, нажми Ctrl+F12 (File Structure) — список всех полей и методов класса. Набери println — увидишь все десять перегрузок.
  5. Вернись в Peek, Ctrl+клик по out — попадёшь в System.java, на объявление public static final PrintStream out.
  6. Поставь курсор на println и нажми Ctrl+Q — всплывёт документация (Javadoc): что делает метод, словами авторов JDK.

Провались сам: отладчик и Step Into

Навигация показывает код. Отладчик показывает код в движении — с живыми значениями переменных и настоящим стеком. Ты уже пользовался им в модуле 7, теперь — глубже.

  1. В Peek щёлкни по полю слева от номера строки с println — появится красная точка, breakpoint (точка останова).
  2. Запусти не ▶, а жука 🐞 (Debug, Shift+F9). Программа замрёт на красной строке, внизу откроется панель Debug.
  3. Нажми F7 (Step Into, «шаг внутрь»). Сюрприз: отладчик не зайдёт в println, а просто выполнит строку. По умолчанию IDEA пропускает классы JDK (java.*, javax.*, jdk.*, sun.*…), чтобы ты не утонул в чужом коде при обычной отладке.
  4. Перезапусти отладку и на той же строке нажми Alt+Shift+F7 — Force Step Into, «шаг внутрь силой». Ты внутри PrintStream.println! В панели Variables видно this = PrintStream@… и x = "Hi".
  5. Смотри на список Frames слева в панели Debug: это стек вызовов. Верхний — где ты сейчас, нижний — main. Щёлкни по любому фрейму ниже — справа покажутся переменные того метода: можно «спуститься» к main и увидеть его args.
  6. Выбирайся наверх: Shift+F8 (Step Out) — доработать текущий метод и выйти в вызвавший. Или F9 (Resume) — отпустить программу до следующей точки останова.

Чтобы спускаться дальше обычной F7, временно отключи фильтр: File → Settings → Build, Execution, Deployment → Debugger → Stepping → сними галочку Do not step into the classes. Теперь F7 ведёт по каждой ступеньке: writeln, implWriteln, write, … Через десяток нажатий ты окажешься в FileOutputStream.write. После эксперимента верни галочку на место.

Предскажи: ты стоишь внутри PrintStream.println и щёлкаешь в Frames по нижнему фрейму main. Программа вернётся в main?

Нет. Щелчок по фрейму ничего не выполняет — он только показывает переменные того метода. Программа так и стоит внутри println, все фреймы на месте. Двигают выполнение только кнопки шагов и Resume.

Подсмотри стек без отладчика

Есть способ увидеть «под капотом» println прямо в выводе программы: устроить аварию внутри println. Когда println получает объект, он просит у него текст методом toString() (подробно — в уроке 9.8). А мы сделаем объект, который на этом месте взрывается:

public class Boom {
    public static void main(String[] args) {
        Bomb bomb = new Bomb();
        System.out.println(bomb);
    }
}

class Bomb {
    public String toString() {
        throw new RuntimeException("Бум внутри toString!");
    }
}

throw new RuntimeException("…") — создаём объект исключения и выбрасываем его («бросить аварию»): выполнение прерывается, и если исключение никто не перехватит, программа остановится. Подробно исключения — в модуле 12, сейчас нам нужен только след, который они оставляют:

Читаем снизу вверх — в порядке вызовов:

  1. at Boom.main(Boom.java:4) — твой main, строка 4, вызвал println. Дно стека.
  2. at java.base/java.io.PrintStream.println(…) — код JDK. Префикс java.base/ — имя модуля JDK, в котором лежат java.lang и java.io. Видишь его — значит, это чужой, библиотечный код.
  3. at java.base/java.lang.String.valueOf(…) — println(Object) первым делом вызывает String.valueOf(x), чтобы получить текст.
  4. at Bomb.toString(Boom.java:10) — а valueOf вызвал метод toString у нашего объекта. Тут исключение и выбросилось. Вершина стека.

Твой код в этом следе — сверху и снизу, а JDK — в середине, как начинка в бутерброде. Номера строк JDK (4454, 1187) у тебя могут быть другими: они зависят от точной версии JDK.

Главное правило чтения stack trace

Ищи первые сверху строки без java.base/ и других чужих пакетов — это твой код, ошибка почти наверняка там. Код JDK и библиотек проверен миллионами людей. В большом проекте след выглядит так же, только длиннее: сверху — твой класс, в середине — десятки строк библиотек, внизу — твой main.

Проверь себя

Поговори с наставником

Напиши: «Я прошёл урок 9.6. Можно я разложу тебе System.out.println("Hi") по кусочкам своими словами — класс, поле, объект, метод, аргумент, — а ты задашь каверзные вопросы?»

Коротко

  • JDK — огромная библиотека готовых классов, разложенных по пакетам. Её исходники можно открыть в IDEA: External Libraries или Ctrl+B.
  • System — класс из java.lang; out — его public static final поле; в нём хранится ссылка на объект PrintStream; println — метод этого объекта, перегруженный 10 раз.
  • println не рисует сам: он передаёт работу по цепочке объектов JDK, а в конце текст выводит операционная система. Одна ответственность на класс. Подробный путь — в блоке «для любопытных», запоминать его не нужно.
  • Навигация: Ctrl+B, Ctrl+Alt+←, Ctrl+F12, Ctrl+Q. Отладчик: F7, Alt+Shift+F7 в JDK, Shift+F8 наверх, панель Frames — стек.
  • В stack trace строки с java.base/ — JDK; ищи первую сверху строку своего кода.
