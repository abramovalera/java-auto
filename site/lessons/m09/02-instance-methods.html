Методы объекта и this

Объект умеет не только хранить данные, но и что-то делать: кот мяукает, счёт пополняется, лампа включается. Учим объекты действовать — и узнаём, откуда метод знает, «чей» он.

⏱ 20 минут🧠 стек и this🧩 без static

Повторение

Данные есть — а действия где?

Сейчас всё, что касается кота, делает main: сам склеивает строку для печати, сам прибавляет возраст. Если таких мест в программе десять — описание кота будет склеиваться в десяти местах, и в каждом можно ошибиться.

System.out.println(murzik.name + ", " + murzik.age + " г.");
System.out.println(barsik.name + ", " + barsik.age + " г.");
murzik.age = murzik.age + 1;   // день рождения

Логичнее, чтобы кот сам умел рассказать о себе и сам отмечал день рождения. Для этого методы пишут прямо в классе — и без слова static:

public class Cat {
    String name;
    int age;

    void describe() {
        System.out.println(name + ", " + age + " г.");
    }

    void birthday() {
        age++;
    }
}
Cat murzik = new Cat();
murzik.name = "Мурзик";
murzik.age = 3;

murzik.describe();   // Мурзик, 3 г.
murzik.birthday();
murzik.describe();   // Мурзик, 4 г.
void describe()

Объявление метода объекта (по-другому — метода экземпляра). Нет слова static — значит, метод вызывают у конкретного кота.

name + ", " + age

Внутри метода поля доступны просто по имени. Но чьи? Того кота, у которого метод вызвали.

murzik.describe();

Вызов метода describe у объекта murzik: «Мурзик, опиши себя». Слева от точки — ссылка на объект, справа — какой метод у него вызвать.

Аналогия: кнопки на технике

У каждой стиральной машины есть кнопка «Старт». Модель одна (класс), машин много (объекты). Нажимаешь «Старт» на машине в ванной — крутится именно она, а не соседская. Метод объекта — такая кнопка: washer1.start() запускает первую машину, washer2.start() — вторую.

Откуда метод знает, чей он: this

Код метода describe один на всех котов. Как он понимает, чьё name печатать? Секрет: при вызове murzik.describe() Java незаметно передаёт в метод ещё один параметр — ссылку на объект слева от точки. Внутри метода она называется this («этот») — ссылка на текущий объект, у которого вызвали метод.

Ты пишешьJava понимает как
murzik.describe();вызвать describe, где this = ссылка из murzik
barsik.describe();вызвать describe, где this = ссылка из barsik
name внутри методаthis.name — поле объекта, на который смотрит this

Посмотри, как это выглядит в памяти. У фрейма метода describe есть своя переменная this — и при каждом вызове она указывает на другого кота.

Заметил? Класс Cat в этом примере написан в том же файле, что и CatDemo, и без слова public. Так можно — подробности в уроке 9.5. В задачах модуля будем писать именно так: один файл, несколько классов. Только не объявляй один класс дважды: если у тебя уже есть Cat.java, второй class Cat в другом файле IDEA назовёт duplicate class.

Методы с параметрами и результатом

Методы объекта бывают какими угодно — с параметрами, с return, как в модуле 7. Разница одна: у них под рукой поля объекта.

class Cat {
    String name;
    int age;
    double weight;

    void feed(double grams) {            // меняет объект
        weight = weight + grams / 1000;
    }

    boolean isKitten() {                 // отвечает на вопрос
        return age < 1;
    }

    String greet(String who) {           // собирает строку
        return name + " мурлычет для " + who;
    }

    boolean isOlderThan(Cat other) {     // сравнивает с другим котом
        return age > other.age;
    }
}
void feed(double grams)

Меняет состояние объекта: полю weight этого кота присваивается новое значение. Возвращаемого значения нет — void.

boolean isKitten()

Метод-вопрос. Такие часто называют с is: isKitten, isEmpty, isBlank (последние два — у String, из модуля 8).

isOlderThan(Cat other)

Параметр может иметь тип класса — тогда в метод передаётся ссылка на объект. age — поле «этого» кота (this), other.age — поле объекта, ссылку на который передали аргументом.

Предскажи: Мурзику 3, Барсику 5. Что вернут murzik.isOlderThan(barsik) и barsik.isOlderThan(murzik)?

false и true. В первом вызове this — Мурзик (3), other — Барсик (5): 3 > 5 — нет. Во втором наоборот. Один и тот же метод, но «кто спрашивает» — решает объект слева от точки.

Когда this писать обязательно

Обычно this. можно не писать: name и так означает this.name. Но бывает, что у параметра такое же имя, как у поля:

void rename(String name) {
    name = name;          // ❌ ничего не происходит!
}

void rename2(String name) {
    this.name = name;     // ✅ поле объекта = параметр
}

Внутри метода имя name сначала ищется среди локальных переменных и параметров, и только потом среди полей. Параметр name «загораживает» поле с тем же именем — это называется затенение (shadowing). Строка name = name; присваивает параметр сам себе, а поле объекта не трогает.

IDEA подсказывает

Строку name = name; IDEA подсветит жёлтым: Variable is assigned to itself — «переменная присвоена сама себе». Жёлтая подсветка — не ошибка компиляции, но почти всегда признак бага. Читай такие предупреждения.

Объект без объекта не работает

Метод объекта всегда нужно вызывать у объекта. Две частые ошибки новичков:

public class CatDemo {
    public static void main(String[] args) {
        describe();                 // ❌ ошибка компиляции

        Cat nobody = null;
        nobody.describe();          // ❌ скомпилируется, но упадёт
    }
}

В IDEA обе ошибки видны ещё до запуска, но выглядят по-разному — красная и жёлтая:

  1. describe(); без объекта — компилятор спросит «describe у кого?» и не найдёт такого метода в CatDemo: cannot find symbol. А если бы метод был в том же классе, но без static, ошибка была бы non-static method describe() cannot be referenced from a static context. Почему main — static и что это значит, разберём в уроке 9.4.
  2. nobody.describe(); — синтаксически верно, но в переменной null. При запуске: NullPointerException: Cannot invoke "Cat.describe()" because "nobody" is null.

Чтобы было ещё нагляднее, собери программу из строк: объявление класса с методом и вызов этого метода у объекта.

Проверь себя

Поговори с наставником

Напиши: «Объясни мне this ещё раз на другом примере — не на котах. А потом я сам придумаю класс с тремя методами и покажу тебе».

Коротко

  • Методы объекта пишут в классе без static и вызывают через точку: murzik.describe().
  • Внутри метода есть скрытая ссылка this — на объект слева от точки. Поля по имени — это поля this.
  • Если параметр называется как поле, он его затеняет. Пиши this.name = name.
  • Метод объекта без объекта не вызвать; по ссылке null — NullPointerException.
