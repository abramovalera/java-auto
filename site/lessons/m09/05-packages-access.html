Повторение

Пакеты: папки для классов

В Java тысячи готовых классов, а в рабочем проекте — ещё сотни своих. Чтобы в них не утонуть, классы раскладывают по пакетам (package). Пакет — это папка с классами плюс часть их полного имени.

Аналогия: контакты в телефоне

Знакомых Саш у тебя пятеро. В телефоне они записаны как «Саша Петров (работа)», «Саша из спортзала». Полное имя снимает путаницу. В Java так же: классов List два — java.util.List (список) и java.awt.List (элемент окна). По полному имени не перепутаешь.

У твоих классов в module-09 строки package нет — они лежат в так называемом пакете по умолчанию (безымянном). Для учебных задач это нормально. В рабочем проекте первой строкой файла всегда идёт пакет, а папки повторяют его имя:

package ru.shop.cart;     // файл лежит в папке ru/shop/cart

public class Cart {
    …
}

Имена пакетов пишут маленькими буквами, часто начиная с перевёрнутого адреса сайта компании: у магазина с сайтом shop.ru пакеты будут называться ru.shop.cart, ru.shop.payment и так далее. Так классы разных компаний никогда не путаются, даже если называются одинаково.

import — это просто сокращение

Писать полное имя каждый раз долго:

// работает, но громоздко
java.util.Scanner sc = new java.util.Scanner(System.in);

Строка import говорит компилятору: «когда я пишу Scanner, я имею в виду java.util.Scanner»:

import java.util.Scanner;        // один класс
import java.util.*;              // все классы пакета java.util

public class Input { … }
  • import ничего не загружает и не копирует — это только сокращение имени для компилятора. Байт-код с import и с полным именем одинаковый.
  • Пишется в начале файла, после package (если он есть) и до класса.
  • Классы из того же пакета импортировать не нужно — поэтому CatDemo видит Cat без import.
  • Пакет java.lang импортирован всегда сам. Поэтому String, System, Math, Integer работают без единой строки import.
IDEA импортирует сама

Написал Scanner, а он красный? Нажми Alt+Enter → Import class. Если классов с таким именем несколько (как с List), IDEA спросит, какой нужен, — тут важно выбрать правильный пакет. Серые неиспользуемые import убирает Ctrl+Alt+O.

Предскажи: скомпилируется ли строка java.lang.System.out.println("Hi");?

Да. Это просто полное имя класса System. Импорт java.lang позволяет его сократить, но писать полностью никто не запрещает. В уроке 9.6 мы разберём эту строку по кусочкам.

Модификаторы доступа: кто что видит

Перед объявлением класса, поля, метода или конструктора можно поставить модификатор доступа — слово, которое говорит, кому он виден. Таких уровней четыре:

МодификаторКому виденАналогия: дом
privateтолько внутри своего классаличный дневник в ящике стола
(ничего не писать)всем классам своего пакетакухня — для всей семьи в доме
protectedсвоему пакету + классам-наследникам в других пакетахсемья + дети, которые переехали (наследование — модуль 10)
publicвсемпочтовый ящик на улице

Уровень «ничего не писать» называют package-private (доступ в пределах пакета). До сих пор у полей котов не было модификатора — поэтому CatDemo из того же пакета и мог обращаться к полю напрямую: murzik.name.

protected по-настоящему понадобится в модуле 10. Сейчас главное — private и public.

Зачем прятать поля: private

Счёт в банке. Если поле balance открыто, любой код может сделать с ним что угодно:

class Account {
    int balance;
}

// где-то в программе:
Account acc = new Account();
acc.balance = -1_000_000;     // и никто не помешал

Закроем поле модификатором private и дадим «окошки» — методы объекта, которые сами проверяют, можно ли так делать:

class Account {
    private int balance;                 // снаружи не видно

    void deposit(int amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    boolean withdraw(int amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
            return true;
        }
        return false;                    // денег не хватило
    }

    int getBalance() {
        return balance;                  // посмотреть можно, поменять — нет
    }
}
Bank.java:28: error: balance has private access in Account
        acc.balance = -1_000_000;
           ^

Это текст javac — так ошибку покажет сайт. А в редакторе IDEA:

Теперь acc.balance = … снаружи — ошибка компиляции. Изменить баланс можно только вызовом методов deposit и withdraw у объекта, а они не пустят отрицательную сумму. Объект сам отвечает за то, чтобы его данные были правильными. Эта идея называется инкапсуляция — первый из «трёх китов» ООП, о них весь модуль 10.

Аналогия: банкомат

Ты не открываешь сейф банкомата отвёрткой и не пересчитываешь купюры руками. У банкомата есть кнопки — «снять», «пополнить», «баланс». Внутри он проверяет ПИН и лимиты. Поля private — сейф, публичные методы — кнопки.

Геттеры и сеттеры

Для закрытых (private) полей принято объявлять методы со стандартными именами:

Куда писать

Переделай свой Cat.java: добавь private к полям, поле vaccinated и методы ниже (конструктор и остальные методы, которые у тебя уже есть, оставь). Сразу покраснеют места в CatDemo.java, где ты обращался к полям напрямую, например murzik.name: 'name' has private access in 'Cat'. Это защита в действии — замени их на геттеры: murzik.getName(). Строки, которые присваивают значения полям (murzik.age = 3;), удали: значения теперь задаёт конструктор.

public class Cat {
    private String name;
    private int age;
    private boolean vaccinated;

    public Cat(String name, int age) {
        this.name = name;
        setAge(age);                           // проверка в одном месте
    }

    public String getName() {                  // геттер: get + Имя поля
        return name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {              // сеттер: set + Имя поля
        if (age < 0) {
            System.out.println("Возраст не может быть отрицательным");
            return;
        }
        this.age = age;
    }

    public boolean isVaccinated() {            // для boolean — is…
        return vaccinated;
    }
}
  • Геттер (от get — «получить»): getName(), для boolean — isVaccinated().
  • Сеттер (от set — «установить»): setAge(int age). Именно в нём живёт проверка.
  • Не каждому полю нужен сеттер. Имя кота после рождения не меняется — сеттера setName нет, и это правильно. Поле, которое не должно меняться, можно даже сделать private final.
Alt+Insert

IDEA генерирует геттеры и сеттеры сама: Alt+Insert → Getter and Setter. Имена getX, setX, isX — договорённость всех Java-программистов: по ним и люди, и многие готовые инструменты сразу понимают, что метод читает или меняет поле. Поэтому соглашение об именах — не мелочь.

Предскажи: зачем конструктор вызывает setAge(age), а не пишет this.age = age?

Чтобы проверка возраста жила в одном месте. Если завтра правило поменяется («не старше 30»), менять придётся только сеттер — и конструктор тоже начнёт его соблюдать.

Файлы и классы: один public на файл

Последний кусочек — как классы раскладываются по файлам. Правила:

  1. В файле может быть сколько угодно классов, но public — не больше одного.
  2. Если public-класс есть, файл называется точно как он: public class CatShelter → CatShelter.java.
  3. Остальные классы в файле — без модификатора (package-private): их видят только классы этого пакета.
  4. Каждый класс компилируется в свой .class: из одного файла с тремя классами получится три файла байт-кода.
public class CatShelter {                    // public — имя файла
    public static void main(String[] args) {
        ShelterCat cat = new ShelterCat("Мурзик");
        System.out.println(cat.getName());
    }
}

class ShelterCat {                           // без public — в том же файле
    private final String name;

    ShelterCat(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }
}
Так пишем задачи этого курса

В задачах модуля 9 всё решение — в одном файле: сверху public-класс с main (его имя дано в условии), ниже — вспомогательные классы без public. Помни: все папки курса — один проект в пакете по умолчанию, поэтому имя любого класса, даже вспомогательного, должно быть уникальным на весь проект. Иначе IDEA скажет duplicate class. Поэтому в условиях задач имена классов уже придуманы — используй их.

🔎 Для любопытных: компактные файлы — main без класса

В новых версиях Java (окончательно — с Java 25) для маленьких программ можно писать совсем коротко, без объявления класса и без static:

void main() {
    IO.println("Привет!");
}

Компилятор сам «завернёт» такой файл в класс. Это сделано для обучения и маленьких скриптов. Мы учимся на Java 21 и пишем по-классически: в рабочих проектах всё равно везде полноценные классы.

Коротко

  • Пакет — папка с классами и часть полного имени: java.util.Scanner. import — сокращение имени, а не загрузка кода.
  • java.lang (String, System, Math…) и свой пакет доступны без import.
  • Доступ: private (класс) → без слова (пакет) → protected (+ наследники) → public (все).
  • Поля прячут private, наружу дают методы: геттеры getX()/isX() и сеттеры setX() с проверками.
  • В файле один public-класс (имя = имя файла) и сколько угодно классов без public. Каждый класс — свой .class.
