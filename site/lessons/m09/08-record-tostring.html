toString и record

Почему println(cat) печатает какую-то абракадабру Cat@1b6d3586 и как это починить. И record — класс для данных, который пишется в одну строку.

⏱ 15 минут🧾 Java 16+🛒 корзина товаров

Повторение

Что печатает println(объект)

Cat murzik = new Cat("Мурзик", 3);
System.out.println(murzik);

Что за абракадабра? Вспомни урок 9.6: println(Object) вызывает String.valueOf(x), а тот вызывает метод toString() у объекта. Мы такой метод не писали — но он есть у любого объекта в Java «от рождения». Как именно он появляется — тема модуля 10 (класс Object, общий предок всех классов). Стандартный toString возвращает:

  • Cat — имя класса;
  • @ — разделитель;
  • 1b6d3586 — шестнадцатеричный «номер» объекта (хеш-код). У тебя будет другой, и меняется от запуска к запуску.

Для человека это бесполезно. Но toString можно написать свой — и тогда println, склейка строк и отладчик начнут показывать объект по-человечески.

Свой toString

class Cat {
    private String name;
    private int age;

    Cat(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "Кот " + name + ", " + age + " г.";
    }
}
Cat murzik = new Cat("Мурзик", 3);
System.out.println(murzik);                 // Кот Мурзик, 3 г.
String line = "Сегодня у врача: " + murzik; // склейка тоже зовёт toString
System.out.println(line);                   // Сегодня у врача: Кот Мурзик, 3 г.
public String toString()

Заголовок метода должен быть ровно таким: public, тип возвращаемого значения String, имя toString, без параметров. Ошибёшься (например, tostring или без public) — получится другой метод, и println его не вызовет.

@Override

Аннотация: «этот метод переопределяет метод, который уже есть» — заменяет готовый toString своим. Необязательна, но полезна: если ошибёшься в имени, компилятор скажет об этом. Подробно — модуль 10.

"…" + murzik

Склейка строки с объектом тоже вызывает toString. И отладчик IDEA показывает объекты в Variables через toString.

Где это пригодится

Когда программа пишет объект в журнал ошибок или тест JUnit сообщает «ожидали такой-то объект, а получили такой-то», объекты печатаются через toString. С User@4e25154f ничего не понять, а с User[login=admin, role=ADMIN] ошибка видна сразу. Хороший toString экономит часы поиска ошибок.

Alt+Insert → toString()

IDEA генерирует toString сама: Alt+Insert → toString(), отметь поля. Получится что-то вроде Cat{name='Мурзик', age=3}.

Свой toString виден и в отладчике: в панели Variables рядом с номером объекта появляется его текст. Объект теперь можно «прочитать», не раскрывая:

Класс для данных: сколько кода?

Часто класс нужен просто чтобы носить данные: товар (название, цена), пользователь (логин, email), точка (x, y). Чтобы сделать такой класс «как положено», нужно написать: private final поля, конструктор, геттеры, toString, а ещё equals и hashCode (модуль 10). Для товара из двух полей это около 30 строк:

record: класс в одну строку

С Java 16 для таких случаев есть record (по-английски «запись»):

public class Shop {
    public static void main(String[] args) {
        Product bread = new Product("Хлеб", 45);

        System.out.println(bread.title());   // Хлеб
        System.out.println(bread.price());   // 45
        System.out.println(bread);           // Product[title=Хлеб, price=45]
    }
}

record Product(String title, int price) { }
record Product(String title, int price)

Объявление record: имя и в скобках — компоненты, то есть поля. Компилятор создаёт для каждого private final поле.

new Product("Хлеб", 45)

Создаём объект оператором new и вызываем конструктор, который компилятор написал сам: аргументы передаются по порядку компонентов.

bread.title()

Методы доступа называются как поле, без get: title(), а не getTitle(). Это частая ошибка — bread.getTitle() не скомпилируется.

Product[title=Хлеб, price=45]

Готовый понятный toString. Ничего писать не нужно.

record неизменяемый. Поля final, сеттеров нет. Цена хлеба после создания не меняется: bread.price = 50; — ошибка компиляции. Нужна другая цена — создай новый объект: new Product("Хлеб", 50).

В record можно добавлять свои методы и static-методы, а проверку данных — в «компактный» конструктор, без списка параметров:

record Product(String title, int price) {
    Product {                                       // компактный конструктор
        if (price < 0) {
            throw new IllegalArgumentException(
                    "Цена не может быть отрицательной");
        }
    }

    int cost(int quantity) {                        // свой метод
        return price * quantity;
    }
}
Предскажи: что напечатает System.out.println(new Product("Сок", 120).cost(3));?

360. cost — обычный метод объекта: у этого товара price = 120, умножаем на 3. А при new Product("Сок", -5) компактный конструктор выбросит IllegalArgumentException прямо при создании — некорректный товар просто не появится на свет.

Корзина из record'ов

Соберём всё вместе: массив товаров (модуль 6) и подсчёт суммы. Обрати внимание: в элементах массива хранятся не сами объекты-товары, а ссылки на них.

Правило большого пальца: если объект — это «карточка с данными», которую создали и только читают, бери record. Если у объекта есть жизнь — пополнения, снятия, клики — пиши class. Подробнее о record и его соседях (enum, интерфейсы) — в модуле 11.

Коротко

  • println(obj) и "…" + obj вызывают toString(). Без своего — Cat@1b6d3586.
  • Свой: @Override public String toString() { return …; } — заголовок строго такой.
  • record Product(String title, int price) { } — класс для данных: final-поля, конструктор, методы title()/price(), toString, equals/hashCode.
  • record неизменяемый; можно добавлять методы и проверки в компактный конструктор.
  • Данные — record, поведение и изменяемое состояние — class.
