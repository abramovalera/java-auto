static: общее для всех объектов

Ты пишешь static с первого урока, и наконец пора узнать, что оно значит. Спойлер: это всё, что принадлежит классу целиком, а не отдельному объекту. И ответ на вопрос, почему main — static.

Повторение

Сколько котов мы создали?

Задача: приют хочет знать, сколько котов уже зарегистрировано, и выдавать каждому номер по порядку. Первая попытка — завести поле-счётчик:

Куда писать

Примеры урока — тот же кот, поэтому дописывай их в свой Cat.java: добавь поле и строчку count++ в свой «главный» конструктор Cat(String name, int age). Ниже показаны только нужные строки, остальное у тебя уже есть. Второй класс Cat не создавай — будет duplicate class.

class Cat {
    String name;
    int count;                  // попытка 1

    Cat(String name) {
        this.name = name;
        count++;
    }
}
Предскажи: создали трёх котов. Чему равно count у третьего?

1. И у первого 1, и у второго 1. Поле — своё у каждого объекта: каждый новый кот получает свежий count = 0 и увеличивает его до 1. Котам нужен один общий счётчик на всех.

Общее на всех поле объявляется с модификатором static — это статическое поле (поле класса; всё, что помечено static, называют статическими членами класса):

class Cat {
    static int count = 0;       // одна на весь класс
    String name;                // своя у каждого кота
    int number;                 // своя у каждого кота

    Cat(String name) {
        this.name = name;
        count++;                // общий счётчик +1
        number = count;         // запомнили свой номер
    }
}
Cat a = new Cat("Мурзик");
Cat b = new Cat("Барсик");
System.out.println(Cat.count);   // 2
System.out.println(b.number);    // 2
System.out.println(a.number);    // 1
Аналогия: доска в классе

У каждого ученика свой дневник — это обычные поля: у каждого свои оценки. А доска в классе одна на всех: написал на ней один — видят все. static-поле — это доска. Оно принадлежит не ученику, а классу.

Где живёт static-поле

Обычные поля лежат внутри каждого объекта. А static-поле живёт в единственной копии «при классе» — внутри объектов его нет. Оно появляется, когда класс впервые понадобился программе (ещё до первого new), и живёт до конца программы. Где именно JVM его хранит — для нас неважно: главное, что копия одна на всех.

Пройди по шагам: в «куче» тренажёра мы нарисуем класс отдельной карточкой, чтобы было видно, где лежит count.

static-методы: у класса, без объекта

Методы тоже бывают static — ты писал только такие весь модуль 7. Статический метод принадлежит классу, а не объекту, и вызывается через имя класса:

class Cat {
    static int count = 0;
    String name;

    static String report() {
        return "Зарегистрировано котов: " + count;    // ✅ static видит static
    }

    static void broken() {
        System.out.println(name);                     // ❌ ошибка компиляции
    }
}

// в main:
System.out.println(Cat.report());

В IDEA строка broken() сразу станет красной:

А javac (и сайт кнопкой «Проверить») скажет то же самое своими словами:

Cat.java:10: error: non-static variable name cannot be referenced from a static context

Почему broken() не компилируется? У static-метода нет this: его вызывают у класса, а не у кота. Чьё name печатать — Мурзика? Барсика? Неизвестно. Поэтому компилятор и говорит: «к нестатической переменной нельзя обращаться из статического контекста».

Откуда → кудаМожно?Почему
метод объекта → поле/метод объекта✅есть this — понятно, чей
метод объекта → static-поле/метод✅общее доступно всем
static-метод → static-поле/метод✅оба «при классе»
static-метод → поле/метод объекта напрямую❌нет this. Можно только через объект: someCat.name

Вот почему main — static

Когда ты жмёшь ▶, JVM нужно с чего-то начать. Объектов ещё нет ни одного. Создавать объект твоего класса JVM не станет — она не знает, какие аргументы передать в его конструктор. Поэтому договорились: точка входа — static-метод, его можно вызвать вообще без объектов: CatDemo.main(args).

Теперь понятно, почему в модуле 7 все методы были static: мы вызывали их прямо из main, без объектов. А если в классе с main написать метод без static и вызвать его из main — получишь ту самую ошибку:

public class Hello {
    public static void main(String[] args) {
        greet();              // ❌ non-static method greet()
                              //    cannot be referenced from a static context
        new Hello().greet();  // ✅ создали объект — есть у кого вызвать
    }

    void greet() {
        System.out.println("Привет!");
    }
}

Расшифровка заклинания из первого урока: public — модификатор доступа «виден всем» (даже JVM; подробно — в уроке 9.5), static — статический метод, вызывается без объекта, void — ничего не возвращает, main — имя, которое ищет JVM, String[] args — массив строк-аргументов запуска. Ни одного непонятного слова не осталось!

Ты пользуешься static всё время

Посмотри на знакомые вызовы. Слева от точки бывает имя класса (с большой буквы) — это static. А бывает переменная со ссылкой на объект — это вызов метода у объекта.

ВызовЧто слева от точкиВид
Math.max(a, b)класс Mathstatic-метод
Math.PIкласс Mathstatic-поле (константа)
Integer.parseInt("42")класс Integerstatic-метод
Arrays.toString(arr)класс Arraysstatic-метод
name.length()объект-строка в переменнойметод объекта
scanner.nextInt()объект Scannerметод объекта
System.outкласс Systemstatic-поле!

Math.max — static, потому что ему не нужны ничьи данные: всё, что нужно, приходит в параметрах. Создавать «объект математики» бессмысленно. А name.length() — метод объекта: длина у каждой строки своя. Последняя строка таблицы — маленький сюрприз: System.out — это static-поле класса System. Через два урока мы разберём System.out.println до винтика.

Константы: static final

Если значение общее для всех и никогда не меняется, его объявляют константой класса — static final. final — «окончательно»: присвоить новое значение нельзя, компилятор не даст.

class Cat {
    static final int MAX_LIVES = 9;
    static final String SPECIES = "Felis catus";
}

// где угодно:
System.out.println(Cat.MAX_LIVES);   // 9
// ❌ cannot assign a value to static final variable MAX_LIVES
Cat.MAX_LIVES = 10;

Константы пишут БОЛЬШИМИ_БУКВАМИ через подчёркивание — так их сразу видно. Знакомые примеры: Math.PI, Integer.MAX_VALUE. В реальных программах так хранят настройки и лимиты: static final int MAX_PIN_ATTEMPTS = 3;

Не злоупотребляй static

Новичкам иногда хочется сделать static всё подряд — «так проще вызывать». Но тогда данные становятся общими для всех, и объекты теряют смысл: «у каждого кота своё имя» превращается в «у всех котов одно имя». Правило: static — только для того, что действительно общее (счётчик, константа, вспомогательная функция вроде Math.max).

Проверь себя

Поговори с наставником

Напиши: «Я прошёл урок про static. Спроси меня про пять вызовов из стандартной библиотеки, а я скажу, static они или нет, и объясню почему».

Коротко

  • static-поле — одно на весь класс (доска в классе), обычное поле — своё у каждого объекта (дневник).
  • К static-полям обращаются и static-методы вызывают через имя класса: Cat.count, Math.max.
  • В static-методе нет this — к полям объекта напрямую обращаться нельзя.
  • main — static, чтобы JVM могла вызвать его без объектов.
  • static final — константа: Math.PI, MAX_LIVES. И System.out — тоже static-поле.
