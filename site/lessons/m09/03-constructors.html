Конструкторы

Создавать кота в три строки и надеяться, что никто не забудет имя, — так себе план. Конструктор собирает объект сразу правильным: в одну строку и без «пустых» котов.

⏱ 20 минут🏭 конвейер new🔗 this(...)

Повторение

Проблема: «пустые» объекты

Cat murzik = new Cat();
murzik.name = "Мурзик";
murzik.age = 3;

Cat barsik = new Cat();
barsik.age = 5;          // а имя забыли...
barsik.describe();       // null, 5 г.

Три строки на каждого кота — долго. А главное, ничто не мешает забыть одну из них: получится кот без имени. В большой программе такой «полуфабрикат» всплывёт через сто строк как null или NullPointerException, и искать причину придётся долго.

Хочется так: «кот создаётся только с именем и возрастом, и точка». Для этого и придуман конструктор.

Конструктор: что делать при new

public class Cat {
    String name;
    int age;

    Cat(String name, int age) {
        this.name = name;
        this.age = age;
    }

    void describe() {
        System.out.println(name + ", " + age + " г.");
    }
}
Cat murzik = new Cat("Мурзик", 3);
Cat barsik = new Cat("Барсик", 5);
barsik.describe();       // Барсик, 5 г.
Cat(String name, int age)

Объявление конструктора. Конструктор — особый блок кода, похожий на метод: он вызывается при создании объекта оператором new. Два отличия от обычного метода: имя точно как у класса и нет типа возвращаемого значения — даже void.

this.name = name;

Классика: параметры конструктора называют так же, как поля, и полю this.name присваивают значение параметра name (вспомни затенение из прошлого урока).

new Cat("Мурзик", 3)

Создаём объект оператором new и вызываем конструктор: аргументы в скобках после new Cat передаются в параметры конструктора — по порядку, как при вызове метода.

Теперь new Cat() без аргументов не скомпилируется: «пустого» кота создать просто нельзя. Компилятор сам следит, чтобы никто не забыл имя.

Аналогия: сборка на заводе

Машина не выезжает с конвейера без колёс, а потом «колёса докрутим». Конструктор — последний пост конвейера: объект выходит из new сразу готовым к работе.

Несколько конструкторов и this(...)

Конструкторы можно перегружать, как методы из модуля 7: одно имя, разные параметры. Возраст котёнка из приюта часто неизвестен — пусть будет второй конструктор, только с именем:

Cat(String name, int age) {        // «главный» конструктор
    this.name = name;
    this.age = age;
}

Cat(String name) {                 // удобный вариант
    this(name, 0);                 // передаём работу главному
}

this(...) со скобками — это вызов другого конструктора этого же класса. Так вся настоящая работа живёт в одном месте, а остальные конструкторы только подставляют значения «по умолчанию». Захочешь добавить проверку — добавишь в одном месте, а не в трёх.

Правило: this(...) — только первой строкой

Если конструктор вызывает this(...), это должна быть его самая первая инструкция. Иначе ошибка компиляции: call to this must be first statement in constructor. Логика простая: сначала объект собирают «главным» способом, потом можно что-то донастроить.

ЗаписьЧто это
this.nameполе текущего объекта
this.describe()вызов метода у текущего объекта (обычно пишут просто describe())
this(name, 0)вызов другого конструктора этого класса — только в конструкторе и только первой строкой
Предскажи: что напечатает new Cat("Тиша"), если в конструкторы добавить печать? 
Cat(String name, int age) {
    System.out.println("главный");
    this.name = name;
    this.age = age;
}

Cat(String name) {
    this(name, 0);
    System.out.println("короткий");
}

Сначала «главный», потом «короткий». Короткий конструктор первой строкой передаёт управление главному, тот печатает своё, возвращается — и только потом короткий печатает своё. Это стек вызовов из модуля 7, только для конструкторов.

Конструктор по умолчанию

В уроке 9.1 у класса Cat не было конструктора, а new Cat() работал. Как так? Если ты не написал ни одного конструктора, компилятор сам незаметно добавляет пустой, без параметров:

class Cat {
    String name;
    // невидимо: Cat() { }
}

Но стоит написать хотя бы один свой конструктор — бесплатный исчезает. И старый код ломается. В IDEA это выглядит так:

        Cat c = new Cat();

Компилятор говорит прямо: конструктор просит String,int, а ты не передал ничего. Чинится двумя способами: передать аргументы или самому дописать конструктор без параметров, если «пустой» объект действительно имеет смысл.

Ловушки и хорошие привычки

Ловушка 1: void перед конструктором. Посмотри внимательно:

class Cat {
    String name;

    void Cat(String name) {     // ❌ это НЕ конструктор!
        this.name = name;
    }
}

Из-за void это обычный метод, который случайно называется как класс. Конструктора у класса нет — значит, есть только невидимый пустой. new Cat("Мурзик") не скомпилируется, а new Cat() создаст объект с name == null. Помни: у конструктора нет типа возвращаемого значения.

Ловушка 2: затенение в конструкторе. name = name; вместо this.name = name; — объект создастся, но имя останется null. Самая частая ошибка в конструкторах.

Хорошая привычка: проверяй данные в конструкторе. Конструктор — единственная дверь, через которую объект появляется на свет. Поставь у неё охранника:

Cat(String name, int age) {
    if (age < 0) {
        age = 0;               // отрицательный возраст не пускаем
    }
    this.name = name;
    this.age = age;
}
IDEA пишет конструктор за тебя

Внутри класса нажми Alt+Insert → Constructor, отметь поля — IDEA сгенерирует конструктор с this.x = x. Но сначала напиши пару штук руками, чтобы понимать, что она вставляет.

🔎 Для любопытных: блок инициализации

Кроме конструкторов в классе можно написать просто блок в фигурных скобках — инициализатор. Он выполняется при каждом new, вместе с инициализаторами полей (шаг ② конвейера), до тела конструктора:

class Cat {
    String name;
    {
        System.out.println("Создаётся кот");   // для любого конструктора
    }
    Cat(String name) {
        this.name = name;
    }
}

На практике его почти не пишут: общий код удобнее держать в «главном» конструкторе и вызывать через this(...). Но на собеседовании могут спросить про порядок: поля и блоки инициализации — сверху вниз, потом тело конструктора.

Коротко

  • Конструктор вызывается при создании объекта оператором new, называется как класс и не имеет типа возвращаемого значения.
  • new: память (поля 0/null) → инициализаторы полей → тело конструктора → ссылка в переменную.
  • Конструкторы можно перегружать; this(...) первой строкой вызывает другой конструктор этого класса.
  • Нет своих конструкторов — Java добавит пустой. Написал свой — пустой исчез.
  • Ловушки: void перед конструктором и name = name без this. Хорошая привычка — проверять данные в конструкторе.
