Переопределение методов и final

Наследник получил метод родителя, но хочет делать это по-своему: все животные «подают голос», но кот мяукает, а собака лает. Учимся переопределять методы, дополнять родителя через super и запрещать переделки словом final.

Одинаковое имя — своё поведение

Пусть все животные умеют подавать голос. В классе Animal объявим общий метод, а классы Cat и Dog переопределят его — объявят метод с той же сигнатурой (то же имя и те же параметры), но со своим телом:

Где набирать

Примеры урока — в новом пакете lesson10.l3 (как — в уроке 10.1). Voices.java с классами Animal, Cat, Dog пригодится и в следующем уроке.

public class Voices {
    public static void main(String[] args) {
        Animal a = new Animal();
        Cat c = new Cat();
        Dog d = new Dog();
        a.speak();
        c.speak();
        d.speak();
    }
}

class Animal {
    void speak() { System.out.println("..."); }
}

class Cat extends Animal {
    @Override
    void speak() { System.out.println("Мяу"); }
}

class Dog extends Animal {
    @Override
    void speak() { System.out.println("Гав"); }
}
Предскажи вывод программы

«...», «Мяу», «Гав». У каждого объекта вызывается его версия метода. Версия наследника заслоняет версию родителя — как новая запись поверх старой. Это и есть переопределение (по-английски override).

Аналогия: семейный рецепт

Бабушка передала рецепт борща всей семье. Мама готовит строго по нему. Тётя заменила в рецепте свёклу на томаты — у неё «борщ» тоже есть, но свой. Рецепт называется так же, а результат другой. Переопределённый метод — это тётин борщ: имя то же, содержание своё.

@Override: попроси компилятор проверить

@Override — это аннотация, пометка для компилятора: «я хочу переопределить метод родителя — проверь, что такой метод там действительно есть». Без неё код тоже работает. Зачем же она? Смотри — хочешь повторить, поправь класс Dog в Voices.java, а не объявляй второй:

class Dog extends Animal {
    void speek() { System.out.println("Гав"); }   // опечатка: speek, а не speak
}
Предскажи: что напечатает new Dog().speak();?

«...» — версию родителя! Из-за опечатки получился новый метод speek, а speak класс Dog просто унаследовал от Animal. Ошибки нет, программа молча делает не то. Такие баги ищут часами.

А с аннотацией компилятор поймает опечатку сразу:

error: method does not override or implement a method from a supertype
    @Override
    ^

Правила переопределения

Чтобы метод наследника считался переопределением, а не новым методом:

  1. Имя и параметры — те же самые: те же типы в том же порядке. speak(int times) — уже другой метод.
  2. Тип возвращаемого значения — тот же (или тип-наследник, об этом ниже «для любопытных»).
  3. Доступ не строже, чем у родителя. Был public — у наследника тоже должен быть public. Иначе: attempting to assign weaker access privileges.
  4. Нельзя переопределить private-метод (наследник его не видит), static-метод (он принадлежит классу, а не объекту) и final-метод (запрещено, см. ниже).

Если родитель возвращает Animal, наследник при переопределении может вернуть более узкий тип — Cat: @Override Cat copy() { … }. Кот является животным, так что обещание родителя «верну животное» выполнено. А вот вернуть String вместо Animal нельзя.

super.method(): дополнить, а не заменить

Часто наследник хочет не выбросить поведение родителя, а добавить к нему своё. Для этого внутри переопределённого метода вызывают метод родителя через super: super.имяМетода(). Пример — магазины на одной улице: каждый утром открывается одинаково, а булочная ещё и выкладывает хлеб:

public class Shops {
    public static void main(String[] args) {
        Bakery bakery = new Bakery();
        bakery.open();
    }
}

class Shop {
    void open() {
        System.out.println("Открываю двери");
        System.out.println("Включаю свет");
    }
}

class Bakery extends Shop {
    @Override
    void open() {
        super.open();  // общая часть — от родителя
        System.out.println("Выкладываю свежий хлеб");  // своё — дописали
    }
}
Предскажи: что будет, если убрать строку super.open();?

Напечатается только «Выкладываю свежий хлеб». Метод наследника полностью заменяет метод родителя; версия родителя сама по себе не вызывается. Забытый super.open() — частая логическая ошибка: двери магазина так и не открыли, а хлеб уже выкладывают.

Собери класс цветочного магазина сам — порядок строк важен:

final: «переделывать запрещено»

Иногда автор класса хочет, чтобы какой-то метод наследники не могли переопределить. Например, базовый рецепт задаёт порядок: подготовка → готовка → уборка. Если наследник переопределит этот порядок и забудет уборку, на кухне останется гора грязной посуды. Поэтому метод помечают final:

class Recipe {
    final void cook() {         // порядок фиксирован
        prepare();
        mainStep();
        cleanUp();
    }
    void prepare()  { System.out.println("Мою руки"); }
    void mainStep() { System.out.println("Пустой рецепт"); }
    void cleanUp()  { System.out.println("Мою посуду"); }
}

class Omelet extends Recipe {
    @Override
    void mainStep() { System.out.println("Взбиваю яйца"); }    // ✔ можно

    @Override
    void cook() { mainStep(); }     // ✗ ошибка компиляции
}
error: cook() in Omelet cannot override cook() in Recipe
  overridden method is final

Наследник меняет только «шаги» (mainStep, при желании prepare), а «сценарий» cook — один на всех. Такой приём называют шаблонным методом, на нём построены многие библиотеки: библиотека сама решает порядок, а ты пишешь только содержимое шагов.

final-класс: наследовать нельзя совсем

Слово final перед классом запрещает создавать от него наследников. Самый известный пример — String:

class MyString extends String { }   // ✗ cannot inherit from final String

Почему String — final

Строки неизменяемы (модуль 8), на этом держится пул строк и безопасность: строкой передают пароли, адреса, имена файлов. Если бы можно было сделать «хитрую строку»-наследника, которая меняется после проверки, всё это сломалось бы.

Ещё final-классы

Math, Integer, Double и другие обёртки. Твои классы — тоже можно: final class Money, если наследники ему не нужны.

📌

Три значения final

У переменной/поля — нельзя присвоить новое значение (модуль 2 и 9). У метода — нельзя переопределить. У класса — нельзя наследовать.

Рецепт неизменяемого класса

Строки неизменяемы — и это удобно: строку можно отдать кому угодно, испортить её нельзя. Такие же классы можно писать самому. Неизменяемый (immutable) класс — тот, у объекта которого после создания ничего не меняется. Рецепт из пяти шагов — в нём собраны все значения final и инкапсуляция из урока 1:

public final class Money {                       // 1. final-класс
    private final long kopecks;                  // 2. поля private final
    private final String currency;

    public Money(long kopecks, String currency) { // 3. всё задаём в конструкторе
        this.kopecks = kopecks;
        this.currency = currency;
    }

    public long getKopecks() { return kopecks; }  // 4. только геттеры
    public String getCurrency() { return currency; }

    public Money plus(Money other) {              // 5. «изменить» = вернуть новый объект
        return new Money(kopecks + other.kopecks, currency);
    }
}
  1. final class — наследник не сможет добавить изменяемые поля или переопределить методы «по-хитрому».
  2. Поля private final — снаружи не достать, а внутри после конструктора не переприсвоить.
  3. Все значения — через конструктор.
  4. Сеттеров нет, только геттеры.
  5. Метод, который «меняет», возвращает новый объект — как toUpperCase() у строки (модуль 8). Если поле — массив или другой изменяемый объект, в конструкторе и геттере делают его копию (защитная копия из урока 1).
Предскажи: что выведет этот код? 
Money a = new Money(500, "RUB");
Money b = a.plus(new Money(250, "RUB"));
System.out.println(a.getKopecks() + " " + b.getKopecks());

500 750. plus не трогает a — он создаёт и возвращает новый объект. Объект a как был 500 копеек, так и остался. Поэтому неизменяемые объекты можно спокойно передавать в любые методы и хранить в нескольких местах: никто не поменяет их «за спиной». Короткий путь к такому классу — record из модуля 9: его поля тоже private final.

Коротко

  • Переопределение — метод наследника с тем же именем и параметрами заменяет метод родителя.
  • @Override — проверка компилятором; ставь всегда.
  • Правила: та же сигнатура, тот же тип возвращаемого значения, доступ не строже; private, static и final не переопределяются.
  • super.method() — вызвать версию родителя и дописать своё.
  • final у метода — нельзя переопределить; у класса — нельзя наследовать (String).
  • Неизменяемый класс: final class, поля private final, всё в конструкторе, без сеттеров, «изменение» возвращает новый объект.
