Наследование: extends и super

Кот и собака — оба животные: у обоих есть имя, возраст, оба едят и спят. Писать это дважды? Нет: опишем общее один раз в классе-родителе, а коту и собаке дадим только их особенности.

Повторение

Копипаст — снова враг

Объявим классы Cat и Dog так, как умеем после модуля 9:

class Cat {
    String name;
    int age;
    void eat()   { System.out.println(name + " ест"); }
    void sleep() { System.out.println(name + " спит"); }
    void meow()  { System.out.println(name + ": Мяу!"); }
}

class Dog {
    String name;
    int age;
    void eat()   { System.out.println(name + " ест"); }
    void sleep() { System.out.println(name + " спит"); }
    void bark()  { System.out.println(name + ": Гав!"); }
}

Четыре строки из шести — одинаковые. Добавим попугая, хомяка, черепаху — и каждую правку («пусть eat печатает ещё и время») придётся вносить в пять мест. Забудешь одно — получишь баг. В модуле 7 мы избавлялись от копипаста методами. Для классов есть свой инструмент — наследование: новый класс получает поля и методы готового класса-родителя.

В играх та же история. У каждого персонажа есть имя, здоровье, умение ходить. Писать это в Warrior, Mage, Archer по отдельности? Нет — делают общий класс Hero, а персонажи от него наследуют. Так же и в магазине: у любого товара есть название и цена, а книга, телефон и футболка добавляют каждый своё.

extends: «возьми всё у родителя»

Вынесем общее в класс Animal, а Cat и Dog объявим его наследниками ключевым словом extends («расширяет»):

public class Zoo {
    public static void main(String[] args) {
        Cat cat = new Cat();
        cat.name = "Мурка";
        cat.eat();      // метод родителя
        cat.meow();     // свой метод
    }
}

class Animal {
    String name;
    int age;
    void eat()   { System.out.println(name + " ест"); }
    void sleep() { System.out.println(name + " спит"); }
}

class Cat extends Animal {
    void meow() { System.out.println(name + ": Мяу!"); }
}

class Dog extends Animal {
    void bark() { System.out.println(name + ": Гав!"); }
}
Предскажи: что выведет программа? В классе Cat ведь нет ни поля name, ни метода eat…

«Мурка ест», потом «Мурка: Мяу!». Класс Cat унаследовал от класса Animal поля name, age и методы eat, sleep. В объекте класса Cat они есть, как будто объявлены в самом Cat. А meow — его собственный метод.

Родитель (суперкласс, базовый класс)
Класс, от которого наследуют: Animal.
Наследник (подкласс, дочерний класс)
Класс, который наследует: Cat, Dog. Получает всё, что есть у родителя, и добавляет своё.
extends
Ключевое слово: class Cat extends Animal — класс Cat наследует класс Animal (дословно — «кот расширяет животное»).

Проверка «является»

Наследование описывает отношение «является» (по-английски is-a). Перед тем как написать class A extends B, произнеси вслух: «A является B». Звучит правдой — наследуй. Звучит странно — наследование тут не подходит.

  • «Кот является животным» ✔ → Cat extends Animal
  • «Сберегательный счёт является счётом» ✔ → SavingsAccount extends BankAccount
  • «Машина является двигателем» ✘ — машина имеет двигатель. Для «имеет» есть другой приём, о нём урок 7.
Только один родитель

В Java у класса может быть только один прямой родитель: class Cat extends Animal, Pet не скомпилируется. Зато цепочка может быть длинной: Kitten extends Cat, Cat extends Animal — котёнок получит всё и от кота, и от животного.

Конструкторы и super(...)

Хорошо бы, чтобы имя задавалось в конструкторе (и поле было private — урок 1 не забываем). Объявим конструктор в классе-родителе:

class Animal {
    private String name;
    private int age;

    Animal(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("Создано животное " + name);
    }

    String getName() { return name; }
}

class Cat extends Animal {
    private boolean indoor;

    Cat(String name, int age, boolean indoor) {
        super(name, age);            // сначала — часть родителя
        this.indoor = indoor;        // потом — своё
        System.out.println("Это кот, домашний: " + indoor);
    }
}
super(name, age);

Вызов конструктора родителя через super. Поля name и age — приватные поля Animal, конструктор Cat не может присвоить им значения сам. Он передаёт аргументы name и age конструктору родителя: «заполни свою часть, вот данные».

первая строка

Вызов super(...) должен стоять самой первой строкой (инструкцией) конструктора. Сначала строится «животная» часть объекта, потом «кошачья» — как дом: сначала фундамент, потом этажи.

Что будет при new Cat("Мурка", 3, true)? Пройди по шагам — следи за стеком вызовов слева.

Если super(...) не написать

Java подставит за тебя вызов без аргументов — super();. Если у родителя есть конструктор без параметров (или вообще нет конструкторов — тогда Java сама создаёт пустой конструктор по умолчанию), всё скомпилируется. А если у родителя есть только конструктор с параметрами:

class Dog extends Animal {
    Dog(String name) {
        // super(...) забыли — Java вставит super();
        System.out.println("Гав");
    }
}
error: constructor Animal in class Animal cannot be applied to given types;
    Dog(String name) {
                     ^
  required: String,int
  found:    no arguments

Читаем как в модуле 1: «конструктор Animal нельзя применить: требуется String,int, а найдено — без аргументов». Компилятор подставил невидимый super(), а у Animal такого нет. Починка — вызвать нужный конструктор явно: super(name, 1);

В IDEA та же ошибка видна сразу в редакторе, и формулировка там другая, попроще. А при запуске ▶ панель Build покажет текст javac, как выше:

Предскажи: скомпилируется ли Cat(String n) { this.indoor = true; super(n, 1); }?

Нет (в Java 21, которую мы используем). super(...) обязан быть первым — родительская часть объекта должна быть готова раньше, чем наследник начнёт с ним работать. Ошибка: call to super must be first statement in constructor.

Что видит наследник: private и protected

Вот неожиданность: у кота есть поле name (оно в объекте), но обратиться к полю name напрямую в методе класса Cat нельзя, если поле в Animal private. private — это «только для самого класса», даже дети не исключение.

class Cat extends Animal {
    void meow() {
        // ✗ name has private access in Animal
        System.out.println(name + ": Мяу!");
        // ✔ через геттер родителя
        System.out.println(getName() + ": Мяу!");
    }
}

Два честных пути: вызвать метод родителя (геттер) или ослабить доступ до protected — «для своих и для наследников».

Подвох protected

protected открывает доступ не только наследникам, но и всем классам того же пакета. Поэтому поля всё равно лучше держать private, а наследникам давать protected-методы или геттеры. Например, в BankAccount служебный метод «записать операцию в историю» — protected: его вызывают счета-наследники, а остальная программа — нет.

🔎 Для любопытных: а у Animal есть родитель?

Есть! Если не написать extends, Java считает, что класс наследует Object — общего прародителя всех классов. Поэтому у любого объекта есть методы toString() и equals(), которых ты не писал. Подробно — в уроке 5.

Коротко

  • class Cat extends Animal — класс Cat наследует класс Animal: получает все его поля и методы и добавляет свои.
  • Наследуй только при отношении «является» (is-a). «Имеет» — это не наследование.
  • У класса один прямой родитель; цепочки любой длины разрешены.
  • Конструктор наследника первой строкой вызывает super(...). Не написал — Java вставит super() без аргументов.
  • Объект строится от родителя к наследнику.
  • private родителя наследнику не виден напрямую; protected — виден (и всему пакету).
