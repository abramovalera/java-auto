Почему не массив: List и ArrayList

Массив — шкаф с фиксированным числом ячеек. А в жизни данных то больше, то меньше: товары в корзине, строки в таблице, сообщения в чате. Знакомься со списком — массивом, который растёт сам.

⏱ 20 минут📚 первая коллекция🔍 трассировка

Боль массива: размер навсегда

Вспомни модуль 6. Массив создаётся с размером, и этот размер больше никогда не меняется:

String[] cart = new String[3];
cart[0] = "хлеб";
cart[1] = "молоко";
cart[2] = "сыр";
cart[3] = "кефир";   // ❌ ArrayIndexOutOfBoundsException: места нет

Чтобы положить четвёртый товар, придётся создать новый массив побольше и переложить туда всё старое: cart = Arrays.copyOf(cart, 4);. А удалить товар из середины — вообще морока: сдвигать все элементы влево руками. И ещё нужно отдельно помнить, сколько ячеек реально занято.

Программисты делали это так часто, что в Java давно есть готовый класс, который всё это делает сам. Ты просто говоришь «добавь» и «удали» — а перекладывание происходит внутри.

Предскажи: зачем это в настоящих программах? Сколько товаров найдёт поиск в интернет-магазине?

Заранее — неизвестно. Сегодня в каталоге 12 товаров, завтра 15, после фильтра — 3. Программа магазина получает найденные товары от сервера и складывает их в коллекцию. Массив с фиксированным размером тут неудобен, а список — в самый раз. Поэтому методы вида «найди всё, что подходит» в Java-библиотеках обычно и возвращают список.

Резиновый пенал

Аналогия: пенал

Массив — жёсткий пенал с прорезями ровно под 12 карандашей. Тринадцатый не влезет, а пустая прорезь так и будет пустовать.

Список ArrayList — резиновый пенал: кладёшь сколько угодно карандашей, он растягивается. Вынул карандаш из середины — остальные сами сдвинулись, дырки нет.

Вот как создают список строк и работают с ним:

import java.util.ArrayList;
import java.util.List;

public class CartDemo {
    public static void main(String[] args) {
        List<String> cart = new ArrayList<>();
        cart.add("хлеб");
        cart.add("молоко");
        cart.add("сыр");
        cart.add("кефир");                 // места хватит всегда
        System.out.println(cart);          // [хлеб, молоко, сыр, кефир]
        System.out.println(cart.size());   // 4
    }
}
import java.util.ArrayList;

Коллекции живут в пакете java.util («утилиты»). Его нужно импортировать — IDEA предложит это сама по Alt+Enter.

List<String>

Тип переменной: список строк. В угловых скобках — тип элементов. Подробно про скобки — в следующем уроке.

new ArrayList<>()

Создаём пустой список в куче. Пустые скобки <> («ромб») значат: «тип элементов возьми слева».

cart.add("хлеб")

Добавить в конец. Размер вырос на 1.

System.out.println(cart)

Список печатается красиво, в квадратных скобках. Помнишь, массив печатался «паспортом» [I@1b6d…? Со списком Arrays.toString не нужен.

List — интерфейс, ArrayList — класс

Почему слева List, а справа ArrayList? Ты знаешь это из модуля 11 про интерфейсы:

List
Интерфейс — контракт «упорядоченный список: элементы идут по номерам, можно добавлять, получать по индексу, удалять». Сам он ничего не хранит.
ArrayList
Класс, который выполняет этот контракт с помощью массива внутри. Есть и другие реализации, например LinkedList (урок 6).

Объявляем переменную типа интерфейса и инициализируем её объектом класса: List<String> cart = new ArrayList<>(); — «объявляем переменную cart типа List<String> и инициализируем её новым объектом ArrayList». Так остальной код зависит только от контракта «список», и реализацию можно поменять в одном месте. Это то же правило, что «программируй через интерфейс» из модуля 11.

🔎 Для любопытных: как именно растёт ArrayList

Пустой new ArrayList<>() при первом add заводит массив на 10 ячеек. Когда ячейки кончаются, он создаёт новый массив размером старый + половина старого (10 → 15 → 22 → 33…) и копирует туда элементы — тот самый Arrays.copyOf. Копирование дорогое, но случается редко, поэтому в среднем add в конец — быстрая операция. Если заранее знаешь, что элементов будет 10 000, можно сразу задать ёмкость: new ArrayList<>(10_000). Это не размер! size() всё равно будет 0.

Главные методы списка

Индексы — как у массива, с нуля. Только вместо квадратных скобок — методы.

МетодЧто делаетАналог у массива
add(x)добавить в конец— (нужен новый массив)
add(i, x)вставить на место i, остальные сдвинутся вправосдвиг руками
get(i)взять элемент с номером ia[i]
set(i, x)заменить элемент с номером ia[i] = x
remove(i) / remove(x)удалить по номеру / по значению (первое совпадение), остальные сдвинутся влевосдвиг руками
size()сколько элементовa.length
contains(x)есть ли такой элемент (true/false)цикл поиска
indexOf(x)номер первого такого элемента или −1цикл поиска
isEmpty(), clear()пуст ли список; очистить его—

У массива — поле length без скобок, у строки — метод length(), у списка — метод size(). Путают все, IDEA подчеркнёт красным. А contains и indexOf сравнивают элементы через equals — как и положено для строк (модуль 8).

Пройди программу по шагам и предскажи значения сам:

Что будет, если в конце вызвать cart.get(2)?

Исключение IndexOutOfBoundsException: Index 2 out of bounds for length 2. В списке два элемента, номера 0 и 1. Ёмкость внутреннего массива тут ни при чём: список честно проверяет индекс по size().

Быстрая проверка

List.of — список, который нельзя менять

Часто список нужен сразу с готовыми значениями: дни недели, ожидаемые пункты меню в тесте. Для этого есть короткая запись:

List<String> expectedMenu = List.of("Главная", "Каталог", "Корзина");
System.out.println(expectedMenu.get(0));   // Главная
expectedMenu.add("Профиль");                // 💥 UnsupportedOperationException

List.of(...) создаёт неизменяемый список: читать можно, а add, remove, set бросают UnsupportedOperationException («операция не поддерживается»). Компилятор не предупредит — метод add в интерфейсе List есть, просто эта реализация его запрещает.

Вот как это выглядит при запуске — твой первый stack trace из коллекций:

Нужен изменяемый список с готовыми значениями?

Скопируй неизменяемый в новый ArrayList: List<String> menu = new ArrayList<>(List.of("Главная", "Каталог")); — теперь в menu можно добавлять.

Аналогия: меню в ламинате

List.of — меню ресторана, запаянное в пластик: читать удобно, дописать блюдо ручкой нельзя. Хочешь править — перепиши на обычный лист (new ArrayList<>(…)).

Зачем вообще нужны неизменяемые списки, если они «хуже»?

Они надёжнее. Если ты передал список в метод, никто случайно его не испортит. Справочные данные — дни недели, страны доставки, допустимые статусы заказа — обычно и хранят в List.of: менять их по ходу работы программы нельзя по смыслу.

🔎 Для любопытных: Arrays.asList — «полуизменяемый» список

Есть старый способ: Arrays.asList("а", "б"). Он даёт список-обёртку над массивом: set работает, а add и remove — нет (тот же UnsupportedOperationException), ведь массив внутри не растёт. Ещё List.of не разрешает null в элементах (будет NullPointerException), а Arrays.asList разрешает. На собеседованиях про эту разницу любят спросить.

Коротко

  • Массив не меняет размер. ArrayList растёт сам: внутри у него массив с запасом.
  • List — интерфейс (контракт), ArrayList — класс. Переменную объявляем типа интерфейса и инициализируем объектом класса: List<String> x = new ArrayList<>();
  • Методы: add, add(i, x), get, set, remove, size, contains, indexOf. Индексы с нуля, вне границ — IndexOutOfBoundsException.
  • Список печатается красиво: [a, b, c].
  • List.of(...) — неизменяемый: add бросает UnsupportedOperationException.
