Очередь и стек

Очередь в магазине: кто первым пришёл, того первым и обслужили. Стопка тарелок: берёшь ту, что положили последней. Два простых правила — и на них держатся кнопка «Назад» в браузере, Ctrl+Z и обработка заявок.

Повторение

Очередь: первым пришёл — первым ушёл

Очередь (Queue) работает по правилу FIFO — First In, First Out, «первым пришёл — первым ушёл». Новые встают в хвост, обслуживают из головы. Лучшая реализация в Java — ArrayDeque («эррей дэк», двусторонняя очередь на массиве).

Queue<String> queue = new ArrayDeque<>();
queue.offer("Аня");          // встала в хвост
queue.offer("Борис");
queue.offer("Вера");
System.out.println(queue.poll());   // Аня — забрали из головы
System.out.println(queue.peek());   // Борис — только посмотрели, кто следующий
System.out.println(queue);          // [Борис, Вера]
offer(x)
встать в хвост очереди.
poll()
забрать из головы (элемент удаляется). Очередь пуста — вернёт null.
peek()
посмотреть на голову, не забирая. Пусто — null.
Две версии каждого метода

У очереди есть и «строгие» близнецы: add, remove(), element(). Делают то же самое, но на пустой очереди не возвращают null, а бросают NoSuchElementException. Цикл «пока есть кого обслуживать» удобно писать на мягких: while (!queue.isEmpty()) { … queue.poll() … }.

Где очереди в жизни программиста: заявки в службу поддержки, задания на печать, сообщения между сервисами, обход ссылок сайта «по слоям» (поисковый робот кладёт найденные ссылки в очередь и обходит их по порядку).

Стек: последним пришёл — первым ушёл

Стек работает наоборот — LIFO, Last In, First Out. Как стопка тарелок: кладёшь сверху и берёшь сверху. Ты уже видел стек в модуле 7 — стек вызовов методов устроен именно так. Для стека в Java тоже берут ArrayDeque, только другими методами.

Одна тонкость: переменную стека объявляют типом не Queue, а Deque («дэк», double-ended queue — двусторонняя очередь). Это интерфейс, который разрешает класть и забирать элементы с обоих концов. У Queue методов push и pop нет, а у Deque есть. ArrayDeque выполняет контракт Deque, поэтому годится и в очередь, и в стек:

Queue<String> queue = new ArrayDeque<>();   // нужна очередь: offer, poll, peek
Deque<String> stack = new ArrayDeque<>();   // нужен стек: push, pop, peek

Методы стека:

push(x)
положить на верх стопки.
pop()
снять верхний (удаляется). Стек пуст — NoSuchElementException.
peek()
посмотреть на верхний, не снимая. Пусто — null.

Кнопка «Назад» в браузере — стек: каждая открытая страница кладётся сверху, «Назад» снимает верхнюю. Пройди по шагам:

Что будет, если нажать «Назад» ещё три раза: history.pop() × 3?

Первые два pop вернут «Каталог» и «Главная». Третий — на пустом стеке — бросит NoSuchElementException. Перед pop проверяй isEmpty() — так делает и браузер, когда кнопка «Назад» становится серой.

Класс Stack — устаревший

В Java есть класс Stack, и в старых статьях его используют. Он из Java 1.0 и медленнее. Сейчас стек делают на ArrayDeque — так советует сама документация Java. И ещё: в ArrayDeque нельзя класть null — будет NullPointerException.

PriorityQueue: очередь по важности

Иногда обслуживают не по порядку прихода, а по важности: в приёмном покое тяжёлых пациентов берут раньше. Для этого есть PriorityQueue — очередь с приоритетом. poll() всегда отдаёт самый маленький элемент (по естественному порядку: числа по возрастанию, строки по алфавиту).

PriorityQueue<Integer> pq = new PriorityQueue<>(List.of(5, 1, 4, 2, 3));
System.out.println(pq.poll());   // 1
System.out.println(pq.poll());   // 2
System.out.println(pq.peek());   // 3
А что напечатает System.out.println(pq) сразу после создания?

[1, 2, 4, 5, 3] — не отсортировано! Внутри PriorityQueue — «куча» (особое дерево), которая гарантирует только одно: наверху лежит минимум. Печать и for-each показывают внутренний порядок. Отсортированный порядок получается только если доставать элементы по одному через poll(). Частый вопрос с подвохом на собеседованиях.

Как задать свой порядок (например, «сначала самые большие» или «по приоритету заявки»), узнаешь в следующем уроке: PriorityQueue принимает тот же Comparator, что и сортировка.

А LinkedList?

В старых статьях очередь часто делают на LinkedList («связный список»): он тоже выполняет контракт Deque. Работает, но ArrayDeque быстрее и экономнее. Чем LinkedList отличается от ArrayList и зачем он вообще нужен, подробно разберём в уроке «Сравниваем близнецов». Пока запомни практическое правило:

Список — ArrayList, очередь и стек — ArrayDeque.

Проверь себя

Поговори с наставником

Напиши: «Назову три примера из жизни для очереди и три для стека, а ты проверь, не перепутал ли я FIFO и LIFO».

Коротко

  • Очередь — FIFO: offer в хвост, poll из головы, peek — посмотреть. На пустой — null.
  • Стек — LIFO: push, pop, peek. pop на пустом — исключение.
  • И очередь, и стек — на ArrayDeque. Класс Stack устарел, null в ArrayDeque класть нельзя.
  • PriorityQueue: poll отдаёт минимум, печать не отсортирована.
  • Для стека переменную объявляют типом Deque — двусторонняя очередь, у неё есть push/pop. Правило: список — ArrayList, очередь и стек — ArrayDeque.
