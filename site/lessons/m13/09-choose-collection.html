Карта коллекций: вся семья

Все коллекции Java — это интерфейсы (контракты «что умеет») и классы, которые эти контракты выполняют. Ниже — вся семья целиком. Нажимай на любой блок: слева появится, что это, в каком порядке хранит, пускает ли дубликаты и null, насколько быстрая, главные методы и когда её брать.

Как это запомнить

Три вопроса к задаче: нужен ли порядок по номеру? → List. Нужна ли уникальность? → Set. Нужно ли искать по ключу? → Map. А дальше выбираешь «близнеца»: обычный (Hash…/ArrayList), с порядком добавления (LinkedHash…) или отсортированный (Tree…). Подробно близнецы сравниваются в уроке «Сравниваем близнецов».

Сравнение коллекций в тестах: List против Set

list1.equals(list2) — true, только если те же элементы в том же порядке. set1.equals(set2) — порядок не важен, только состав. Проверяешь «в заказе ровно эти товары, порядок любой» — сравнивай множества: new HashSet<>(actual).equals(Set.of("Хлеб", "Молоко")). Порядок важен — сравнивай списки.

Напиши: «Придумай 5 задач из реальных программ (магазин, банк, игра), а я для каждой выберу коллекцию и объясню выбор по дереву решений».

Коротко

  • Collection → List, Set, Queue/Deque; Map — отдельно.
  • Дерево решений: по ключу → Map; уникальные → Set; с краёв → ArrayDeque; по важности → PriorityQueue; иначе → ArrayList.
  • Реализация выбирается по порядку: Hash — без порядка, Linked — порядок добавления, Tree — сортировка.
  • List.equals учитывает порядок, Set.equals — нет.
