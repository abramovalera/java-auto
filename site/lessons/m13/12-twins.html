Сравниваем близнецов: какой класс выбрать

ArrayList и LinkedList, HashSet и TreeSet, HashMap и LinkedHashMap — снаружи одинаковые методы, внутри совсем разное устройство. Разбираемся, чем они отличаются, почему это важно и как ответить на самый частый вопрос собеседования про коллекции.

Близнецы: одна семья — разное устройство

Ты уже знаешь интерфейсы List, Set, Map и Deque. У каждого несколько реализаций — классов, которые выполняют один и тот же контракт. Методы у них одинаковые: add, contains, get. А внутри они устроены по-разному — поэтому одна быстрее в одном, другая в другом, и хранят элементы в разном порядке.

ИнтерфейсБлизнецыЧем отличаются
ListArrayList · LinkedListмассив внутри или цепочка узлов
SetHashSet · LinkedHashSet · TreeSetпорядок: никакой · как добавляли · отсортировано
MapHashMap · LinkedHashMap · TreeMapтот же порядок, что у Set, — но по ключам
Deque / стекArrayDeque · LinkedList · старый Stackскорость и наследство старой Java

Правило запоминания для Set и Map: Hash — быстро и без порядка, LinkedHash — помнит порядок добавления, Tree — всегда отсортировано. Всю семью целиком смотри на карте коллекций.

ArrayList против LinkedList: как они устроены

Что делаемArrayListLinkedList
вызываем get(i) — берём элемент по индексу✅ мгновенно — O(1)🐢 медленно — O(n): идёт по цепочке
добавляем в конец — add(x)✅ быстро (иногда массив расширяется)✅ мгновенно
добавляем в начало — add(0, x)🐢 медленно — сдвигает все элементы✅ мгновенно — O(1)
ищем — contains(x)🐢 O(n) — перебирает всех🐢 O(n) — тоже перебирает
памятьменьшебольше: каждый узел хранит ещё две ссылки

Проверь сам. Создай в training класс TwinsSpeed, запусти и посмотри на числа:

import java.util.*;

public class TwinsSpeed {
    public static void main(String[] args) {
        List<Integer> array = new ArrayList<>();
        List<Integer> linked = new LinkedList<>();
        int n = 100_000;

        long t0 = System.nanoTime();
        for (int i = 0; i < n; i++) array.add(0, i);
        long t1 = System.nanoTime();
        for (int i = 0; i < n; i++) linked.add(0, i);
        long t2 = System.nanoTime();
        System.out.println("add(0): ArrayList "
                + (t1 - t0) / 1_000_000 + " мс, LinkedList "
                + (t2 - t1) / 1_000_000 + " мс");

        long sum = 0;
        t0 = System.nanoTime();
        for (int i = 0; i < 20_000; i++) sum += array.get(i * 4);
        t1 = System.nanoTime();
        for (int i = 0; i < 20_000; i++) sum += linked.get(i * 4);
        t2 = System.nanoTime();
        System.out.println("get(i): ArrayList "
                + (t1 - t0) / 1_000_000 + " мс, LinkedList "
                + (t2 - t1) / 1_000_000 + " мс");
    }
}
add(0): ArrayList 371 мс, LinkedList 4 мс
get(i): ArrayList 0 мс, LinkedList 876 мс

У тебя числа будут другими, но разница — в десятки и сотни раз, и в разные стороны. Читаем код: System.nanoTime() — вызываем статический метод, он возвращает текущее время в наносекундах; разница двух замеров, делённая на миллион, — миллисекунды.

Что выбрать на практике

ArrayList — почти всегда. Мы чаще читаем элементы по индексу и перебираем список, чем вставляем в начало. Для очереди и стека есть ArrayDeque — он быстрее LinkedList. Так что LinkedList в живом коде встречается редко, но на собеседовании про него спросят обязательно.

Скорость словами и буквой O

На собеседовании скорость называют «О большое» — как растёт время работы, когда элементов становится больше. Три значения, которых хватит:

⚡

O(1) — мгновенно

Время не зависит от размера. Как открыть квартиру по номеру: 10 квартир в доме или 1000 — один шаг. get(i) у ArrayList, contains у HashSet.

🎯

O(log n) — быстро

Каждый шаг отбрасывает половину. Как угадать число от 1 до 1000 за 10 вопросов «больше или меньше». TreeSet, TreeMap.

🐢

O(n) — медленно на больших данных

Время растёт вместе с размером: в 10 раз больше элементов — в 10 раз дольше. Как искать человека, обходя все квартиры. contains у List.

Частая ловушка

list.contains(x) в цикле по большому списку — медленно: O(n) внутри цикла. Если нужно много раз проверять «есть ли такой» — сначала положи элементы в HashSet, там contains мгновенный.

Hash, LinkedHash, Tree — коротко

Set и Map ты подробно разобрал в уроках 4 и 5. Для сравнения близнецов хватит одного примера — один и тот же словарь в трёх реализациях:

Map<String, Integer> ages = new HashMap<>(); // потом — Linked, Tree
ages.put("Оля", 25);
ages.put("Артём", 19);
ages.put("Ваня", 31);
ages.put("Белла", 22);
System.out.println(ages);

Замени HashMap на LinkedHashMap и на TreeMap — получишь:

HashMap:       {Артём=19, Ваня=31, Белла=22, Оля=25}
LinkedHashMap: {Оля=25, Артём=19, Ваня=31, Белла=22}
TreeMap:       {Артём=19, Белла=22, Ваня=31, Оля=25}

С множествами (HashSet, LinkedHashSet, TreeSet) — то же самое, только про сами элементы. Разница не только в порядке, но и в скорости: у Hash-версий поиск O(1), у Tree-версий — O(log n), зато они всегда отсортированы.

Стек: ArrayDeque против старого Stack

Очередь, стек и PriorityQueue разобраны в уроке 6. Здесь — только про выбор класса для стека. Оба умеют push/pop:

Deque<String> stack = new ArrayDeque<>();
stack.push("a");
stack.push("b");
stack.push("c");
System.out.println(stack);
String top = stack.pop();
System.out.println("сняли " + top + ", осталось " + stack);
[c, b, a]
сняли c, осталось [b, a]

Печать и снятие — отдельными строками: так сразу видно, что было до pop и что стало после. Класс Stack даст тот же результат, но он устарел — почему, в следующем шаге.

Эти классы появились в самой первой Java (1996), ещё до Collection Framework. Их не удалили, чтобы старые программы продолжали работать. Ты встретишь их в старом коде и на собеседовании — но в новом коде не бери.

Как ответить на собеседовании

Сначала ответь вслух сам, потом открой.

Чем ArrayList отличается от LinkedList?

ArrayList хранит элементы в массиве: доступ по индексу мгновенный (O(1)), но вставка и удаление в начале или середине медленные — приходится сдвигать элементы. LinkedList — цепочка узлов: вставка и удаление с краёв мгновенные, а доступ по индексу медленный (O(n)), и памяти он занимает больше. На практике почти всегда берут ArrayList.

HashSet, LinkedHashSet и TreeSet — в чём разница?

Все хранят только уникальные элементы. HashSet — без гарантии порядка, самый быстрый (O(1)). LinkedHashSet — помнит порядок добавления. TreeSet — держит элементы отсортированными, операции за O(log n), null не пускает.

HashMap или TreeMap? А LinkedHashMap?

HashMap — словарь по умолчанию, get и put за O(1), порядок ключей не гарантирован. LinkedHashMap — то же, но с порядком добавления. TreeMap — ключи всегда отсортированы, операции за O(log n), null-ключ нельзя.

Чем HashMap отличается от Hashtable?

Hashtable — устаревший класс из Java 1.0: все методы синхронизированы (медленнее) и null нельзя ни в ключ, ни в значение. HashMap не синхронизирован, допускает один null-ключ. Для работы из нескольких потоков вместо Hashtable берут ConcurrentHashMap.

Почему не Stack, а ArrayDeque?

Stack наследует устаревший Vector: синхронизирован без нужды и позволяет лишние операции. ArrayDeque через интерфейс Deque даёт те же push, pop, peek быстрее.

Коротко

  • Близнецы выполняют один интерфейс, но устроены по-разному — отсюда разные скорость и порядок.
  • ArrayList — массив: get(i) мгновенно, вставка в начало медленно. LinkedList — цепочка: края мгновенно, get(i) медленно. На практике — почти всегда ArrayList.
  • Set и Map: Hash — без порядка и быстро, LinkedHash — порядок добавления, Tree — отсортировано, O(log n), без null.
  • Скорость: O(1) — мгновенно, O(log n) — быстро, O(n) — растёт вместе с размером.
  • Vector, Stack, Hashtable — устарели: вместо них ArrayList, ArrayDeque, HashMap.
