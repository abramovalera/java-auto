Перебор: for-each, индекс и Iterator

Обойти список — легко. Удалить из него лишнее во время обхода — ловушка, на которой спотыкаются даже опытные: программа падает с ConcurrentModificationException или молча пропускает элементы. Разберёмся, почему и как правильно.

⏱ 20 минут🔍 трассировка💥 ConcurrentModificationException

Повторение

Три способа обойти список

List<String> links = List.of("Главная", "Каталог", "Корзина");

// 1. По индексу — когда нужен номер элемента
for (int i = 0; i < links.size(); i++) {
    System.out.println(i + ": " + links.get(i));
}

// 2. for-each — когда номер не нужен (чаще всего)
for (String link : links) {
    System.out.println(link);
}

// 3. Iterator — когда во время обхода нужно удалять
Iterator<String> it = links.iterator();
while (it.hasNext()) {
    String link = it.next();
    System.out.println(link);
}

Первые два ты знаешь по массивам (модуль 6). Только вместо a.length — size(), вместо a[i] — get(i). for-each работает с любой коллекцией: списком, множеством, очередью. А вот по индексу можно ходить только по списку — у множества номеров нет.

Третий способ выглядит самым громоздким. Но на самом деле for-each — это он и есть: компилятор превращает for (String link : links) ровно в такой цикл с итератором. Запомни это — через минуту пригодится.

Iterator — палец, который ведёт по списку

Итератор (от англ. iterate — «повторять, перебирать») — отдельный объект, который умеет проходить коллекцию по одному элементу. У него три метода:

hasNext()
«Есть ли ещё элементы впереди?» — true/false. Ничего не сдвигает.
next()
Шагнуть вперёд и вернуть элемент, через который перешагнул. Если элементов нет — NoSuchElementException.
remove()
Удалить элемент, который только что вернул next(). Безопасно — итератор сам поправит свою позицию.
Аналогия: контролёр в автобусе

Контролёр идёт по салону от первого пассажира к последнему. hasNext() — «есть ещё кто-то впереди?», next() — «подойти к следующему», remove() — «высадить того, у кого только что проверил билет». Высаживает сам контролёр — и он точно знает, где остановился.

💥 ConcurrentModificationException

Задача: убрать из списка отрицательные числа. Первая мысль — for-each и remove:

List<Integer> nums = new ArrayList<>(List.of(3, -1, 4, -5, 2));
for (Integer n : nums) {
    if (n < 0) {
        nums.remove(n);       // удаляем «в обход» итератора
    }
}

Запускаем — и программа падает:

Concurrent modification — «одновременное изменение». Почему упало? Вспомни: for-each — это скрытый итератор. Список ведёт счётчик изменений. Итератор при создании запомнил его значение и на каждом next() сверяет: «список менялся без меня?». Мы удалили элемент через nums.remove, в обход итератора, — счётчик не совпал, и итератор честно бросил исключение, чтобы не выдать мусор.

Аналогия: пересчёт людей в очереди

Ты пересчитываешь очередь пальцем: «первый, второй, третий…». Кто-то за твоей спиной ушёл, все сдвинулись. Твой палец теперь указывает не на того человека — пересчёт сломан. Итератор Java замечает такое и громко ругается, вместо того чтобы тихо насчитать неправильно.

Правильно — удалять через сам итератор:

it.remove() — только после next()

remove() удаляет то, что вернул последний next(). Вызвать его дважды подряд или до первого next() нельзя — будет IllegalStateException.

Тихая ловушка: удаление в цикле по индексу

«Ладно, — думает новичок, — обойду итератор и пройду по индексу». Исключения не будет. Будет хуже — тихая ошибка. Пройди по шагам:

Два способа починить цикл по индексу:

  • Идти с конца: for (int i = nums.size() - 1; i >= 0; i--). Удаление сдвигает только элементы правее, а их мы уже проверили.
  • После удаления не увеличивать i (написать i-- внутри if). Работает, но читается хуже.
Почему проход с конца не пропускает элементы? Проверь на [-1, -2, 3].

i = 2: тройка, оставляем. i = 1: −2, удаляем → [-1, 3]. i = 0: −1, удаляем → [3]. Каждый элемент проверен ровно один раз: сдвигались только те, что мы уже прошли.

🔎 Для любопытных: removeIf и «предпоследний элемент»

removeIf. В модуле 14 появятся лямбды, и удаление станет одной строкой: nums.removeIf(n -> n < 0);. Внутри — тот же безопасный обход.

Когда for-each не падает. Если удалить в for-each предпоследний элемент, исключения не будет! После удаления размер уменьшился, и hasNext() (он сравнивает позицию с размером) отвечает «элементов больше нет» — цикл заканчивается раньше, чем next() успеет проверить счётчик. Последний элемент при этом не проверяется вовсе. Это любимый вопрос «со звёздочкой» на собеседованиях — и ещё одна причина никогда так не делать.

Поговори с наставником

Напиши: «Объясню своими словами, почему for-each падает при удалении, а цикл по индексу молча пропускает элементы. Поправь меня, если ошибусь».

Коротко

  • Обход: по индексу (нужен номер, только List), for-each (чаще всего, любая коллекция), Iterator (нужно удалять).
  • for-each = скрытый итератор. Изменил коллекцию в обход него — ConcurrentModificationException.
  • Удаляй во время обхода через it.remove() — после it.next().
  • Удаление в цикле по индексу «вперёд» молча перепрыгивает элементы. Иди с конца.
  • В модуле 14: removeIf с лямбдой — то же самое одной строкой.
