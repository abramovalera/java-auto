Методы любой коллекции

Эти методы объявлены в интерфейсе Collection, поэтому их можно вызывать у любого List, Set и очереди. Набери примеры в Playground и читай каждую строку вслух: «вызываем метод … у коллекции … и передаём аргумент …».

ВызовЧто делаетЧто возвращает
c.add(x)добавляет элементtrue, если коллекция изменилась (у Set повтор → false)
c.remove(x)удаляет элемент x (первый найденный)true, если такой был
c.contains(x)проверяет, есть ли xboolean
c.size() / c.isEmpty()сколько элементов / пусто лиint / boolean
c.addAll(other)добавляет все элементы другой коллекцииtrue, если что-то добавилось
c.removeAll(other)удаляет всё, что есть в otherboolean
c.retainAll(other)оставляет только то, что есть и в otherboolean
c.removeIf(x -> условие)удаляет все элементы, подходящие под условиеboolean
c.clear()удаляет всёничего (void)

Три последних метода на множествах — это операции из математики: пересечение, объединение, разность.

Set<Integer> a = new HashSet<>(List.of(1, 2, 3, 4));
Set<Integer> b = new HashSet<>(List.of(3, 4, 5));

Set<Integer> both = new TreeSet<>(a);
both.retainAll(b);              // пересечение: есть и в a, и в b
Set<Integer> all = new TreeSet<>(a);
all.addAll(b);                  // объединение
Set<Integer> onlyA = new TreeSet<>(a);
onlyA.removeAll(b);             // разность: в a, но не в b
System.out.println(both + " " + all + " " + onlyA);
[3, 4] [1, 2, 3, 4, 5] [1, 2]

Читаем строку Set<Integer> both = new TreeSet<>(a);: объявляем переменную both и инициализируем её новым объектом TreeSet, передав конструктору a, — получается копия, поэтому исходное множество a не портится.

removeIf принимает условие в виде n -> n < 0 — это лямбда-выражение, подробно — в модуле 14. Пока читай его так: «для каждого n — удалить, если n < 0».

List<Integer> nums = new ArrayList<>(List.of(5, -2, 8, -1, 3));
nums.removeIf(n -> n < 0);
System.out.println(nums);
[5, 8, 3]

Методы List

ВызовЧто делает
list.get(i) / list.set(i, x)возвращает элемент с индексом i / заменяет его на x
list.add(i, x) / list.remove(i)вставляет на место i / удаляет по индексу (ловушка с List<Integer>)
list.indexOf(x) / lastIndexOf(x)индекс первого / последнего вхождения или −1
list.sort(Comparator)сортирует сам список (урок про сортировку)
list.subList(a, b)«окно» в список с a до b (не включая b) — не копия!
list.toArray(new String[0])возвращает массив с теми же элементами

Почему subList — окно, а не копия:

List<Integer> big = new ArrayList<>(List.of(1, 2, 3, 4, 5));
List<Integer> part = big.subList(1, 3);
System.out.println(part);
part.set(0, 99);
System.out.println(big);
[2, 3]
[1, 99, 3, 4, 5]

Мы вызвали set у part, а изменился big: обе переменные смотрят на одни и те же элементы. Нужна независимая копия — оберни: new ArrayList<>(big.subList(1, 3)).

Методы Map: рабочие приёмы

ВызовЧто делает
map.put(k, v)кладёт пару; если ключ уже был — заменяет значение и возвращает старое
map.get(k)возвращает значение или null, если ключа нет (ловушка с null)
map.getOrDefault(k, d)значение или d, если ключа нет
map.containsKey(k) / containsValue(v)есть ли такой ключ / такое значение
map.putIfAbsent(k, v)кладёт, только если ключа ещё нет
map.merge(k, 1, Integer::sum)счётчик: ключа не было — кладёт 1, был — прибавляет 1
map.computeIfAbsent(k, x -> new ArrayList<>())достаёт значение по ключу, а если его нет — создаёт и кладёт
map.keySet() / values() / entrySet()все ключи / все значения / все пары

Счётчик за одну строку. Вызываем метод merge у словаря и передаём три аргумента: ключ, значение по умолчанию и правило сложения Integer::sum (это ссылка на метод, модуль 14).

Map<String, Integer> counts = new TreeMap<>();
for (String w : List.of("да", "нет", "да", "да", "может")) {
    counts.merge(w, 1, Integer::sum);
}
System.out.println(counts);
System.out.println(counts.getOrDefault("нет", 0) + " "
        + counts.getOrDefault("никогда", 0));
{да=3, может=1, нет=1}
1 0

Не затереть существующее. putIfAbsent кладёт значение, только если ключа нет:

Map<String, Integer> stock = new HashMap<>();
stock.put("яблоки", 5);
stock.putIfAbsent("яблоки", 100);   // ключ есть — ничего не меняется
stock.putIfAbsent("груши", 3);      // ключа нет — кладём
System.out.println(new TreeMap<>(stock));
{груши=3, яблоки=5}

Группировка. Разложим имена по первой букве: computeIfAbsent возвращает список для буквы, а если его ещё нет — создаёт пустой и кладёт в словарь. У возвращённого списка сразу вызываем add.

Map<Character, List<String>> byLetter = new TreeMap<>();
for (String name : List.of("Аня", "Борис", "Алексей", "Вера", "Белла")) {
    byLetter.computeIfAbsent(name.charAt(0), k -> new ArrayList<>())
            .add(name);
}
System.out.println(byLetter);
{А=[Аня, Алексей], Б=[Борис, Белла], В=[Вера]}

Перебор пар — через entrySet(): каждая пара — объект Map.Entry, у него вызываем getKey() и getValue().

for (Map.Entry<String, Integer> e : counts.entrySet()) {
    System.out.println(e.getKey() + " -> " + e.getValue());
}
да -> 3
может -> 1
нет -> 1

Помощник Collections и готовые коллекции

Collections (с буквой s на конце) — не интерфейс, а класс-помощник со статическими методами: их вызывают у самого класса, без создания объекта.

ВызовЧто делает
Collections.sort(list) / reverse(list) / shuffle(list)сортирует / разворачивает / перемешивает сам список
Collections.max(c) / min(c)возвращает наибольший / наименьший элемент
Collections.frequency(c, x)сколько раз x встречается
Collections.unmodifiableList(list)обёртка «только для чтения» над списком
List.of(…) / Set.of(…) / Map.of(k, v, …)готовые неизменяемые коллекции
List.copyOf(list)неизменяемая копия: дальнейшие изменения оригинала на неё не влияют
Arrays.asList(…)список фиксированного размера поверх массива
List<Integer> nums = new ArrayList<>(List.of(5, 8, 3));
Collections.sort(nums);
System.out.println(nums + " max=" + Collections.max(nums)
        + " min=" + Collections.min(nums));
Collections.reverse(nums);
System.out.println(nums);
System.out.println(Collections.frequency(List.of("a", "b", "a", "a"), "a"));
[3, 5, 8] max=8 min=3
[8, 5, 3]
3

Ловушки

Новые ловушки — с примерами ниже. Те, что уже разобраны в уроках модуля, — ссылкой: если не помнишь, вернись.

Неизменяемые и «наполовину изменяемые» списки

List<String> fixed = Arrays.asList("a", "b", "c");
fixed.set(0, "z");          // можно: размер не меняется
System.out.println(fixed);
fixed.add("d");             // нельзя: размер фиксирован

List<String> frozen = List.of("a", "b");
frozen.add("c");            // нельзя: список неизменяемый
[z, b, c]
Exception in thread "main" java.lang.UnsupportedOperationException

UnsupportedOperationException — «операция не поддерживается»: метод add у таких списков есть (его требует интерфейс), но работать он отказывается. Нужен обычный изменяемый список — создай его копией: new ArrayList<>(List.of("a", "b")).

В тестах на JUnit

Коллекции в тестах проверяют не циклом, а готовыми проверками AssertJ (модуль 17): assertThat(names).containsExactly("Аня", "Борис") — точно эти элементы в этом порядке, containsExactlyInAnyOrder(…) — в любом порядке, hasSize(3), contains(…), doesNotContain(…).

Проверь себя

Потренируйся с ИИ

Напиши: «Дай мне 5 мини-задач на методы коллекций Java: merge, getOrDefault, computeIfAbsent, removeIf, retainAll. По одной, я пишу код сам, а ты проверяешь и подсказываешь, но решение не пишешь».

Коротко

  • У любой коллекции: add, remove, contains, size, addAll / retainAll / removeAll (объединение, пересечение, разность), removeIf.
  • Map: getOrDefault вместо голого get, merge для счётчиков, putIfAbsent, computeIfAbsent для группировки, перебор через entrySet().
  • Collections — класс-помощник со статическими методами: sort, reverse, max, min, frequency.
  • List.of, Set.of, Map.of — неизменяемые и без null; Arrays.asList — фиксированного размера; subList — окно, а не копия.
  • Нужна изменяемая копия — new ArrayList<>(…).
