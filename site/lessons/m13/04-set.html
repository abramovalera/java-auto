Set: только уникальные

Множество хранит каждое значение один раз и умеет мгновенно отвечать «есть такое или нет?». Разберём HashSet, LinkedHashSet и TreeSet — и наконец увидим, зачем в модуле 10 ты писал equals и hashCode.

Повторение

Зачем множество

Множество (Set) — коллекция, где каждое значение встречается не больше одного раза. Положил дубликат — его просто не добавят. Метод add честно скажет, получилось ли: вернёт true или false.

Set<String> guests = new HashSet<>();
System.out.println(guests.add("Аня"));     // true — добавили
System.out.println(guests.add("Борис"));   // true
System.out.println(guests.add("Аня"));     // false — Аня уже есть
System.out.println(guests.size());         // 2
System.out.println(guests.contains("Борис")); // true — и очень быстро
Аналогия: список гостей на вечеринку

Охранник на входе вычёркивает пришедших. Второй раз один и тот же человек в зал «не войдёт» — он уже там. А вопрос «Аня пришла?» охранник решает за секунду, не перебирая всех гостей по одному.

Где это нужно в реальных программах:

  • Проверить уникальность: у всех заказов в выгрузке разные номера? Сложи номера в список и в множество — если размеры не совпали, есть дубликат: new HashSet<>(ids).size() == ids.size().
  • Убрать повторы: собрать все разные категории товаров из каталога.
  • Быстро проверять «было ли»: уже обработанные заказы, уже занятые логины при регистрации.
В списке [5, 3, 5, 5, 1] пять чисел. Какой будет размер new HashSet<>(список)?

3 — различных чисел три: 5, 3, 1. Конструктор множества принимает любую коллекцию и складывает её элементы, выкидывая повторы.

Три множества — три порядка

У интерфейса Set три главных реализации. Они одинаково отвергают дубликаты, но по-разному хранят порядок:

List<String> words = List.of("груша", "яблоко", "банан", "груша", "арбуз");

Set<String> hash   = new HashSet<>(words);
Set<String> linked = new LinkedHashSet<>(words);
Set<String> tree   = new TreeSet<>(words);

System.out.println(linked);  // [груша, яблоко, банан, арбуз] — как добавляли
System.out.println(tree);    // [арбуз, банан, груша, яблоко] — отсортировано
System.out.println(hash);    // какой-то порядок — не гарантирован!

Не полагайся на порядок HashSet

Иногда HashSet печатает элементы «как будто по порядку» — например, маленькие числа. Это совпадение устройства, а не обещание. Добавь ещё элементы или смени версию Java — порядок может стать другим. Тест, который сравнивает вывод HashSet с текстом, — бомба замедленного действия. Нужен порядок — бери LinkedHashSet или TreeSet.

У множеств есть операции из школьной математики — их удобно применять, чтобы сравнивать наборы данных:

МетодЧто остаётся в aПример: a = {1, 2, 3}, b = {2, 3, 4}
a.addAll(b)объединение: всё из обоих{1, 2, 3, 4}
a.retainAll(b)пересечение: только общие{2, 3}
a.removeAll(b)разность: из a убрать то, что есть в b{1}

Эти методы есть и у списков, но у множеств они работают намного быстрее. И помни: они меняют a. Нужен исходный — сначала сделай копию.

Как HashSet находит элемент мгновенно: корзины

Если бы множество хранило всё в одном ряду, contains перебирал бы элементы по одному — как поиск в массиве. С миллионом элементов — миллион сравнений. HashSet хитрее: внутри у него массив корзин (по-английски buckets).

  1. У элемента вызывается hashCode() — получается целое число, «отпечаток».
  2. Из этого числа вычисляется номер корзины (грубо — остаток от деления на число корзин).
  3. Внутри корзины обычно 0–1 элемент. Их сравнивают с новым через equals(): нашёлся равный — это дубликат.
Аналогия: почтовые ячейки в подъезде

Почтальон не обходит все квартиры, чтобы найти Иванова. Он смотрит на номер квартиры (это hashCode) и сразу идёт к нужной ячейке. В ячейке может лежать пара писем — их он уже сверяет по имени (это equals).

Свои объекты в HashSet: зачем equals и hashCode

Вот где пригодится модуль 10. Класс точки — без equals и hashCode:

class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
}

Set<Point> points = new HashSet<>();
points.add(new Point(1, 2));
points.add(new Point(1, 2));
System.out.println(points.size());   // ?
Предскажи: 1 или 2?

2. Это два разных объекта, и Java о «равенстве точек» ничего не знает. hashCode из класса Object у разных объектов почти всегда разный — они попадают в разные корзины, и до equals дело даже не доходит. Множество видит два разных элемента.

А в обычном списке?

Список ищет по-другому. Методы contains, indexOf и remove(объект) у ArrayList перебирают элементы по очереди и сравнивают каждый с искомым через equals. Корзин нет, hashCode списку не нужен — а вот без equals он сравнивает ссылки, как ==:

List<Point> route = new ArrayList<>();
route.add(new Point(1, 2));
System.out.println(route.contains(new Point(1, 2)));
System.out.println(route.indexOf(new Point(1, 2)));
Point всё тот же — без equals. Что напечатается?

false и -1. В списке лежит одна точка (1, 2), а ищем мы другой объект с теми же координатами. Без своего equals это «чужой» объект, и список его не находит — так же не сработает и route.remove(new Point(1, 2)). Переопредели equals (или возьми record) — получишь true и 0.

Контракт equals/hashCode — не формальность

Равные по equals объекты обязаны иметь равные hashCode. Нарушишь — HashSet и HashMap начнут вести себя «странно»: хранить дубликаты, не находить то, что лежит внутри. Переопределяешь одно — переопределяй и другое. IDEA сгенерирует оба: Alt+Insert → equals() and hashCode().

А помнишь record из модуля 11? record Point(int x, int y) {} — и equals с hashCode уже написаны за тебя по всем полям. Для данных, которые кладут в множества и словари, record — идеальный выбор.

🔎 Для любопытных: поменял поле — потерял объект

Если положить объект в HashSet, а потом изменить поле, от которого зависит hashCode, объект останется лежать в старой корзине. contains посчитает новый хеш, заглянет в другую корзину — и ответит false, хотя объект внутри. Поэтому ключи множеств и словарей лучше делать неизменяемыми: строки, числа, record.

TreeSet: всегда отсортировано

TreeSet хранит элементы в дереве — структуре, где они всегда стоят по порядку. Поэтому он умеет то, чего не умеет HashSet:

TreeSet<Integer> scores = new TreeSet<>(List.of(70, 95, 70, 40, 88));
// без повторов и по возрастанию
System.out.println(scores);          // [40, 70, 88, 95]
System.out.println(scores.first());  // 40 — минимум
System.out.println(scores.last());   // 95 — максимум

Чтобы сортировать, TreeSet должен уметь сравнивать элементы. Числа и строки умеют это «от природы». А свой класс — нет: new TreeSet<Point>() с обычными точками при первом же add упадёт с ClassCastException («Point cannot be cast to Comparable»). Как научить объекты сравниваться — в уроке 7.

Строки в TreeSet: в каком порядке встанут «яблоко», «Арбуз», «банан»?

[Арбуз, банан, яблоко] — здесь совпало с алфавитом. Но строки сравниваются по кодам символов, и все заглавные буквы идут раньше строчных: «Яблоко» с большой встало бы перед «арбуз» с маленькой. Хочешь без учёта регистра — приведи слова к одному регистру через toLowerCase().

Коротко

  • Set — только уникальные значения. add возвращает false на дубликат, contains работает быстро.
  • HashSet — без порядка, LinkedHashSet — порядок добавления, TreeSet — отсортировано (first, last).
  • HashSet: hashCode выбирает корзину, equals сравнивает внутри неё.
  • Свои объекты в HashSet — только с equals и hashCode (или record).
  • У списка contains, indexOf, remove(объект) ищут через equals: без него свой объект «не находится».
  • addAll, retainAll, removeAll — объединение, пересечение, разность.
