Map: словарь «ключ → значение»

Телефонная книга, гардероб с номерками, таблица «товар → цена». Map — самая полезная коллекция после списка. А в Мастерской решим классику собеседований: посчитать, сколько раз встречается каждое слово.

⏱ 30 минут🛠 Мастерская🔍 трассировка

Повторение

Словарь: по ключу — значение

В списке элемент ищут по номеру: «дай третий». А часто нужно искать по имени: «дай телефон Ани», «сколько стоит хлеб». Для этого есть Map (по-русски — словарь, отображение): набор пар ключ → значение.

Map<String, String> phones = new HashMap<>();
phones.put("Аня", "+7 900 111-22-33");
phones.put("Борис", "+7 900 444-55-66");

System.out.println(phones.get("Аня"));    // +7 900 111-22-33
System.out.println(phones.size());        // 2
Map<String, String>

Два типа в скобках: первый — ключ (по чему ищем), второй — значение (что храним). Здесь «имя → телефон».

phones.put("Аня", …)

Положить пару. Если ключ «Аня» уже есть, старое значение заменится новым.

phones.get("Аня")

Найти значение по ключу. Быстро, без перебора — HashMap использует те же корзины, что и HashSet, только хеш считается от ключа.

Аналогия: гардероб

Сдаёшь пальто — получаешь номерок. Номерок — ключ, пальто — значение. Номерки не повторяются (два одинаковых номерка — путаница), а вот пальто могут быть одинаковые. По номерку гардеробщик находит пальто сразу, не перебирая вешалки.

В реальных программах словари повсюду: корзина «товар → количество», цены «товар → цена», профиль пользователя «поле → значение», настройки «имя параметра → значение». Для готовых данных есть короткая запись Map.of("email", "anna@mail.ru", "city", "Казань") — как и List.of, она неизменяемая.

Методы и главная ловушка: null

МетодЧто делает
put(k, v)положить пару; если ключ был — заменить значение (вернёт старое)
get(k)значение по ключу или null, если ключа нет
getOrDefault(k, d)значение по ключу или d, если ключа нет
containsKey(k)есть ли такой ключ (быстро)
containsValue(v)есть ли такое значение (медленно: перебор всех пар)
remove(k)удалить пару по ключу
size(), isEmpty()сколько пар; пуст ли словарь

Самое важное в этой таблице — get возвращает null, если ключа нет. Исключения не будет — будет «пустота», которая выстрелит позже:

Map<String, Integer> prices = new HashMap<>();
prices.put("хлеб", 45);

Integer a = prices.get("сыр");          // null — сыра нет, но это не ошибка
// 💥 NullPointerException: распаковка null (урок 2)
int b = prices.get("сыр");
int c = prices.getOrDefault("сыр", 0);  // 0 — безопасно
if (prices.containsKey("сыр")) { … }    // или сначала спросить

IDEA заранее чует беду и подсвечивает опасную строку жёлтым. А при запуске — вот что получится:

Что напечатает: prices.put("хлеб", 50); System.out.println(prices.get("хлеб") + " " + prices.size());

50 1. Ключ «хлеб» уже был: put заменил 45 на 50, а не добавил вторую пару. Ключи в Map уникальны, как элементы в Set. (Кстати, множество ключей Map и правда хранит как Set.)

Свои объекты в роли ключа

Всё, что ты узнал про HashSet, верно и для ключей HashMap: ключ ищется по hashCode + equals. Свой класс-ключ без них — словарь «не найдёт» то, что сам хранит. Лучшие ключи — строки, числа, enum и record.

Перебор словаря

У Map нет итератора «по парам» напрямую. Зато она умеет отдать три вида на себя:

// 1. Только ключи
for (String product : prices.keySet()) {
    System.out.println(product);
}

// 2. Только значения
int total = 0;
for (int price : prices.values()) {
    total += price;
}

// 3. Пары целиком — самый частый вариант
for (Map.Entry<String, Integer> entry : prices.entrySet()) {
    System.out.println(entry.getKey() + " стоит " + entry.getValue());
}
keySet()
множество ключей (Set — ведь ключи уникальны).
values()
все значения (могут повторяться).
entrySet()
множество пар. Каждая пара — объект Map.Entry<K, V> с методами getKey() и getValue(). Entry — «запись», строчка в телефонной книге.
keySet + get или entrySet?

Можно перебирать ключи и для каждого вызывать get. Работает, но это лишний поиск на каждом шаге. entrySet отдаёт ключ и значение сразу — так и пиши, когда нужны оба.

Удалить пары во время перебора

Правило из урока 3 действует и для словаря: вызвать prices.remove(…) внутри for-each по keySet() или entrySet() — значит получить ConcurrentModificationException. Удаляют так же, как из списка, — через итератор. Его можно взять у любого из трёх видов:

Map<String, Integer> stock = new TreeMap<>();
stock.put("хлеб", 12);
stock.put("кефир", 0);
stock.put("сыр", 0);
stock.put("молоко", 5);

// убираем товары, которых не осталось
Iterator<Map.Entry<String, Integer>> it = stock.entrySet().iterator();
while (it.hasNext()) {
    Map.Entry<String, Integer> entry = it.next();
    if (entry.getValue() == 0) {
        it.remove();          // удаляет пару из самого словаря
    }
}
System.out.println(stock);    // {молоко=5, хлеб=12}

Читаем: у множества пар entrySet() вызываем метод iterator(); it.next() возвращает очередную пару, а it.remove() удаляет её — и из вида, и из самого словаря, ведь вид — это «окно» в словарь, а не копия.

Что будет, если в том же цикле написать stock.remove(entry.getKey()) вместо it.remove()?

ConcurrentModificationException на следующем it.next(): словарь изменили «в обход» итератора, и он это заметил — ровно как со списком в уроке 3. (В модуле 14 то же самое уместится в одну строку: stock.values().removeIf(v -> v == 0).)

HashMap, LinkedHashMap, TreeMap: порядок

Тот же расклад, что у множеств, — и даже имена похожи:

КлассПорядок пар при переборе и печатиПохож на
HashMapне гарантированHashSet
LinkedHashMapпорядок добавления ключейLinkedHashSet
TreeMapотсортировано по ключамTreeSet
// тип TreeMap, а не Map: нужен его метод firstKey
TreeMap<String, Integer> tree = new TreeMap<>();
tree.put("молоко", 89);
tree.put("кефир", 89);
tree.put("хлеб", 45);
System.out.println(tree);              // {кефир=89, молоко=89, хлеб=45}
System.out.println(tree.firstKey());   // кефир — самый «маленький» ключ

Словарь печатается в фигурных скобках: {ключ=значение, …}. TreeMap отсортировал пары по ключам (по алфавиту), а не по значениям. Нужен отсортированный результат — просто скопируй любой словарь в TreeMap: new TreeMap<>(hashMap).

Классическая ошибка: напечатали HashMap, запомнили вывод как «правильный ответ» — а на другом компьютере или в другой версии Java порядок другой. Если вывод сравнивают с образцом (как в задачах практики), печатай LinkedHashMap или TreeMap.

Мастерская: частота слов. Шаги 1–3

Задача (классика собеседований и аналитики логов): дан список слов. Посчитать, сколько раз встречается каждое слово.

Шаг 1. Вход и выход, примеры:

ВходВыходЗачем пример
[да, нет, да, может, да]да — 3, может — 1, нет — 1обычный
[ок, ок, ок]ок — 3все одинаковые
[раз]раз — 1одно слово
[]ничегопусто, не упасть

Шаг 2. Руками. Возьми листок и считай «палочками»: читаешь слово — ищешь его на листке. Нашёл — ставишь ещё одну палочку. Не нашёл — пишешь слово с одной палочкой. Листок «слово → палочки» — это и есть словарь Map<String, Integer>!

Шаг 3. Роли переменных.

word
Шагающая: по очереди каждое слово списка.
counts
Накопитель — но не одно число, а целый словарь накопителей: свой счётчик для каждого слова.
old
Временная: сколько было у слова до этого шага (0, если слова ещё не было).

Мастерская. Шаги 4–6: псевдокод, код, трассировка

Шаг 4. Псевдокод:

counts ← пустой словарь (слово → сколько раз)
для каждого слова word:
    old ← сколько уже насчитано у word (если нет — 0)
    записать в counts: word → old + 1
напечатать counts

Шаг 5. Код — строка в строку. «Если нет — 0» — это ровно getOrDefault:

List<String> words = List.of("да", "нет", "да");
// TreeMap — чтобы печать была по алфавиту
Map<String, Integer> counts = new TreeMap<>();
for (String word : words) {
    int old = counts.getOrDefault(word, 0);
    counts.put(word, old + 1);
}
System.out.println(counts);

Шаг 6. Трассировка. Предскажи значения сам:

А если вместо getOrDefault написать int old = counts.get(word); ?

На первом же новом слове get вернёт null, и распаковка в int бросит NullPointerException. Ровно та ловушка из раздела «Методы и главная ловушка: null» выше. Альтернатива без getOrDefault — if (counts.containsKey(word)) … else ….

Проверь себя

Тренируй план

Напиши наставнику: «Дай задачу на Map уровня собеседования. Я сначала распишу примеры, роли и псевдокод — проверь план до кода».

Коротко

  • Map<K, V> — пары «ключ → значение». Ключи уникальны, значения — любые.
  • put заменяет значение у существующего ключа. get по отсутствующему ключу — null (опасно при распаковке в int), getOrDefault — безопасно.
  • Перебор: keySet(), values(), entrySet() с getKey()/getValue(). Удалять пары во время перебора — только через it.remove() итератора.
  • HashMap — без порядка, LinkedHashMap — порядок добавления, TreeMap — по ключам.
  • Частота: counts.put(w, counts.getOrDefault(w, 0) + 1).
