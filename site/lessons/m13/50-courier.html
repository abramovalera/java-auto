★ Очередь заказов

Правило службы доставки: кто раньше заказал, тот раньше получил. Это ровно очередь из урока «Очередь и стек» — FIFO, «первым пришёл — первым ушёл». Сервер следит за порядком: отвёз не в том порядке — уровень не засчитан.

Подвох в том, что заказы приходят по ходу смены. В начале robot.orders() отдаёт только первые три. Пока Джавик развозит их, приходят новые — их отдаёт robot.newOrders(). Как в кафе: пока официант несёт первые блюда, люди продолжают заказывать.

Почему не подходит простой for

Первая мысль — перебрать список заказов:

for (String address : orders) {
    robot.goTo(address);
    robot.drop();
}

Джавик развезёт первые три заказа и остановится. А новые? Про них цикл ничего не знает: список orders взяли один раз, в начале. Сервер скажет: «Доставлено не всё: остались заказы».

Хорошо, тогда давай добавлять новые заказы прямо в этот список, внутри цикла:

for (String address : orders) {
    robot.goTo(address);
    robot.drop();
    orders.addAll(robot.newOrders());   // 💥 ConcurrentModificationException
}
Что случится на втором круге этого цикла?

Программа упадёт с ConcurrentModificationException — ловушка из урока «Перебор». for-each — это скрытый итератор. Список поменяли в обход него, и на следующем шаге итератор это замечает и бросает исключение. Менять коллекцию, по которой идёт for-each, нельзя.

Нужна коллекция, которая и есть «очередь»: забираешь заказ из головы, новые встают в хвост, а цикл крутится, пока очередь не пуста. Это Queue<String> на ArrayDeque. Методы ты уже знаешь:

offer(x)
поставить один заказ в хвост.
addAll(список)
поставить в хвост все элементы списка, в том же порядке. Есть у любой коллекции, и у Queue тоже.
poll()
забрать заказ из головы (он удаляется из очереди). Очередь пуста — вернёт null.
isEmpty()
пуста ли очередь — удобное условие для while.
Как на кухне кафе

Над окошком выдачи — планка с чеками. Новый чек повар цепляет справа, а готовить берёт самый левый. Сколько чеков придёт за вечер, заранее не знает никто — кухня просто работает, пока на планке что-то висит. Это и есть цикл «пока очередь не пуста».

На старте orders() = [Кафе, Почта, Кафе]. После 1-й доставки newOrders() отдаёт [Аптека], после 3-й — [Школа, Кафе]. В каком порядке Джавик объедет дома, если всё делать по очереди?

Кафе → Почта → Кафе → Аптека → Школа → Кафе. Аптека пришла рано, после первой доставки, но это не повод везти её сразу: она встаёт в хвост, за Почтой и вторым Кафе. Посмотри, как меняется очередь:

Что произошлоОчередь после этого
Старт: взяли заказы из orders()[Кафе, Почта, Кафе]
Отвёз в Кафе, пришёл заказ в Аптеку[Почта, Кафе, Аптека]
Отвёз на Почту, новых нет[Кафе, Аптека]
Отвёз в Кафе, пришли Школа и Кафе[Аптека, Школа, Кафе]
Дальше — по одному из головы[Школа, Кафе] → [Кафе] → []

Очередь опустела — смена окончена. Обрати внимание: Кафе встречается три раза, и Джавик честно едет туда три раза. На уровне ★ это разрешено.

★★ Один заезд на дом

Смена посложнее. Новых заказов больше нет — всё в orders() сразу. Зато адреса повторяются: например, [Кафе, Почта, Кафе, Аптека, Кафе]. И бензин дорогой: на этом уровне к каждому дому можно ехать один раз. Сервер считает вызовы goTo — их можно сделать столько, сколько в заказах разных домов. Порядок доставки здесь не важен.

Что будет, если ездить по списку как есть: для каждого адреса из [Кафе, Почта, Кафе, Аптека, Кафе] — goTo и drop?

Разных домов три: Кафе, Почта, Аптека. Значит, лимит — 3 вызова goTo. Первый — Кафе, второй — Почта, третий — снова Кафе (лишний заезд, но в лимит пока влезли). Четвёртый вызов, в Аптеку, уже за лимитом: поездка остановится с сообщением «goTo вызван 4-й раз, а на этом уровне можно не больше 3». До Аптеки Джавик так и не доедет.

Значит, сначала нужно посчитать, сколько посылок у каждого дома, и только потом ехать. «Дом → сколько посылок» — это пары ключ → значение, то есть словарь Map<String, Integer>. Ключ — адрес, значение — число посылок.

Как считать, ты уже делал в уроке «Map» — частота слов. Тот же приём на другом примере, голосование за пиццу:

Map<String, Integer> votes = new HashMap<>();
for (String pizza : List.of("Пепперони", "Маргарита", "Пепперони")) {
    votes.put(pizza, votes.getOrDefault(pizza, 0) + 1);
}
System.out.println(votes);   // {Маргарита=1, Пепперони=2} — порядок у HashMap не гарантирован
votes.getOrDefault(pizza, 0) + 1

Сколько голосов у этой пиццы уже есть, плюс один новый. Если пиццы ещё не было в словаре — getOrDefault вернёт 0, а не null. С простым get первая же новая пицца уронила бы программу: null не распаковать в int.

votes.put(pizza, …)

Кладём новое число. Ключ уже был — старое значение заменится.

Когда словарь готов, объезжаешь его, а не исходный список: перебор пар через entrySet(). Ключ пары говорит, куда ехать, значение — сколько раз сделать drop(). «Сколько раз» — это обычный цикл со счётчиком из модуля 5.

Почему не Set

Можно сложить адреса в HashSet — повторы исчезнут, и заездов станет ровно столько, сколько нужно. Но множество помнит только какие дома есть, а не сколько посылок у каждого. Отдашь в Кафе одну посылку вместо трёх — сервер скажет, что доставлено не всё.

Аптека: 1
Кафе: 3
Почта: 1

Как получить алфавитный порядок

Вспомни трёх «близнецов» словаря из урока «Map»:

РеализацияВ каком порядке напечатает адресаДля отчёта
HashMapкак получится: порядок не гарантирован✗ сервер скажет «напечатала не то»
LinkedHashMapв порядке первого появления в заказах✗ это не алфавит
TreeMapключи всегда отсортированы✓

Ключи у нас — строки, а строки TreeMap сортирует по алфавиту сам. Значит, ничего сортировать руками не нужно: достаточно выбрать правильную реализацию справа от =. Слева тип остаётся Map<String, Integer> — программируем через интерфейс.

Заметь: если считать сразу в TreeMap, Джавик и объезжать дома будет по алфавиту — перебор entrySet() у TreeMap идёт по отсортированным ключам. На ★★ и ★★★ порядок объезда не важен, так что это никому не мешает. А раз ★★★ — тот же файл, готовое решение ★★★ проходит и ★★.

Откуда взять «Всего»

«Всего» — сколько посылок отдано за смену, то есть сумма всех значений словаря. Её удобно копить переменной-накопителем, пока перебираешь пары. Можно и проще: это же число — сколько всего было заказов.

Печатай только отчёт

Сервер сравнивает весь вывод программы с ожидаемым отчётом. Отладочный System.out.println вроде «еду в Кафе» сломает сравнение. Формат строк — точь-в-точь: Аптека: 1 — имя, двоеточие, пробел, число.

Бонус: вернись после модуля 14

В модуле 14 будет Stream API. Там весь подсчёт «адрес → сколько раз» собирается одной цепочкой: группировка groupingBy со счётчиком прямо в TreeMap. Когда пройдёшь модуль 14 — вернись к этому уровню и перепиши отчёт стримом. Сравнишь: тот же результат, а строк в разы меньше.

★ Очередь заказов

💡 Подсказка 1 — с чего начать

Перед циклом нужна очередь, в которой уже лежат заказы из orders(). Её можно создать пустой и сложить туда список через addAll, а можно передать список прямо в конструктор ArrayDeque — так же, как копировали ArrayList.

💡 Подсказка 2 — какой цикл

Не for-each: сколько будет заказов, заранее неизвестно. Нужен while с условием «очередь не пуста». За один круг — ровно один заказ из головы.

💡 Подсказка 3 — план на русском
  1. Создать очередь адресов и положить в неё заказы на начало смены.
  2. Пока очередь не пуста:
    1. забрать адрес из головы;
    2. доехать туда автопилотом и отдать посылку;
    3. спросить у робота новые заказы и поставить их все в хвост.

Новые заказы проверяй после каждой доставки: пустой список в хвост ничего не добавит, а пришедший заказ не потеряется.

★★ Один заезд на дом

💡 Подсказка 1 — с чего начать

Раздели работу на два цикла: сначала посчитать, потом поехать. Пока первый цикл не закончился, Джавик стоит на складе. Первый цикл — копия подсчёта из примера с пиццей, только по orders().

💡 Подсказка 2 — по чему ехать

Второй цикл идёт по парам словаря, entrySet(), а не по orders(). Внутри — ровно один goTo. Отдача посылок — вложенный цикл: столько раз, сколько говорит значение пары.

💡 Подсказка 3 — план на русском
  1. Создать пустой словарь «адрес → число».
  2. Для каждого адреса из заказов: взять старое число (или 0) и положить на 1 больше.
  3. Для каждой пары словаря:
    1. доехать до дома из ключа;
    2. повторить «отдать посылку» столько раз, сколько в значении.

★★★ Отчёт смены

💡 Подсказка 1 — с чего начать

Код ★★ не выбрасывай — он уже развозит правильно. Поменять нужно одно слово при создании словаря и добавить печать в конце.

💡 Подсказка 2 — порядок и итог

Какая из трёх реализаций Map держит ключи по алфавиту — смотри таблицу в шаге про отчёт. Для строки «Всего» заведи переменную-накопитель до цикла по парам и прибавляй к ней значение каждой пары.

💡 Подсказка 3 — план на русском
  1. Считать заказы в словарь, который сам сортирует ключи.
  2. Объехать пары, как на ★★, и копить сумму значений.
  3. Ещё раз пройти по парам и для каждой напечатать «адрес: число».
  4. Последней строкой напечатать «Всего: » и сумму.
  5. Убрать все отладочные печати.
