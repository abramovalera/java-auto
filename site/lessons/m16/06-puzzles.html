Модуль 16 · Головоломки

Многопоточность: что выведется? Что будет при запуске?

Вопросы про потоки на собеседованиях почти всегда такие: короткий код и «что произойдёт?». Запускать нельзя — только думать и объяснять. Ответ «не знаю заранее» здесь тоже бывает правильным, если объяснишь почему.

⏱ 20 минут🧩 15 задачек★★★ — со звёздочкой
Как решать

Сначала скажи ответ вслух и объясни почему, потом кликай. Для каждого кода спроси себя: сколько тут потоков? Кто кого ждёт? Есть ли общие данные, которые меняют несколько потоков?

Что выведется на экран?

1. run() вместо start(). Что напечатает программа?

Thread t = new Thread(() ->
        System.out.println(Thread.currentThread().getName()));
t.run();
  • Thread-0
  • main
  • Ничего: поток не запущен

2. С join. Что напечатает программа?

Thread t = new Thread(() -> System.out.print("A"));
t.start();
t.join();
System.out.print("B");
  • AB, всегда
  • AB или BA — как повезёт
  • BA

3. Без join. Что напечатает программа?

static int x = 0;

public static void main(String[] args) {
    new Thread(() -> x = 5).start();
    System.out.println(x);
}
  • Всегда 5
  • Всегда 0
  • 0 или 5 — заранее неизвестно

4. Счётчик без synchronized. Что напечатает программа?

static int count = 0;

public static void main(String[] args) throws InterruptedException {
    Runnable r = () -> { for (int i = 0; i < 50_000; i++) count++; };
    Thread a = new Thread(r), b = new Thread(r);
    a.start(); b.start();
    a.join();  b.join();
    System.out.println(count);
}
  • Всегда 100000
  • Число не больше 100000, каждый раз разное
  • Всегда 50000

5. Future. Что напечатает программа?

ExecutorService pool = Executors.newFixedThreadPool(2);
Future<Integer> f = pool.submit(() -> {
    Thread.sleep(200);
    return 10;
});
System.out.print("Ждём ");
System.out.print(f.get() * 2);
pool.shutdown();
  • 20 Ждём
  • Ждём 20
  • Ждём null

6. Сначала заканчивается main. Что напечатает программа и завершится ли она?

public static void main(String[] args) {
    new Thread(() -> {
        try { Thread.sleep(500); } catch (InterruptedException e) { }
        System.out.println("Помощник закончил");
    }).start();
    System.out.println("main закончил");
}
  • «main закончил», и программа сразу завершается
  • «main закончил», через полсекунды «Помощник закончил»
  • «Помощник закончил», потом «main закончил»

Скомпилируется ли?

7. Переменная цикла в лямбде. Скомпилируется?

for (int i = 0; i < 3; i++) {
    new Thread(() -> System.out.println(i)).start();
}
  • Да, напечатает 0 1 2 в каком-то порядке
  • Нет: i не «фактически final»
  • Да, но упадёт при запуске

8. sleep в main. Скомпилируется?

public static void main(String[] args) {
    Thread.sleep(1000);
    System.out.println("Выспался");
}
  • Да, через секунду напечатает «Выспался»
  • Нет: не обработано InterruptedException

9. Runnable с результатом. Скомпилируется?

Runnable task = () -> {
    return 42;
};
  • Нет: run() ничего не возвращает
  • Да, это Callable
  • Да, 42 просто потеряется

Скомпилируется, но что будет при запуске?

10. Дважды start(). Что будет при запуске?

Thread t = new Thread(() -> System.out.println("Работаю"));
t.start();
t.start();
  • «Работаю» напечатается два раза
  • Один раз «Работаю» и исключение IllegalThreadStateException
  • Ошибка компиляции

11. Забыли shutdown. Что будет при запуске?

public static void main(String[] args) throws Exception {
    ExecutorService pool = Executors.newFixedThreadPool(2);
    Future<String> f = pool.submit(() -> "готово");
    System.out.println(f.get());
}
  • Напечатает «готово» и завершится
  • Напечатает «готово» и не завершится
  • Зависнет на get(), ничего не напечатав

12. ★★★ Daemon — для любопытных. Что будет при запуске?

public static void main(String[] args) {
    Thread t = new Thread(() -> {
        while (true) { }
    });
    t.setDaemon(true);
    t.start();
    System.out.println("Пока!");
}
  • Напечатает «Пока!» и будет работать вечно
  • Напечатает «Пока!» и завершится
  • Исключение: нельзя менять поток до запуска

Найди ошибку

13. Программа иногда зависает навсегда. Какая строка виновата?

1  void payment() {
2      synchronized (wallet) {
3          synchronized (basket) { pay(); }
4      }
5  }
6  void refund() {
7      synchronized (basket) {
8          synchronized (wallet) { giveBack(); }
9      }
10 }
  • Строка 2
  • Строка 7
  • Строка 3

14. Новичок «починил» гонку так. Помогло?

static volatile int count = 0;

// в каждом из 4 потоков:
for (int i = 0; i < 100_000; i++) {
    count++;
}
  • Да, volatile делает count++ безопасным
  • Нет, обновления всё равно теряются
  • Не скомпилируется: volatile нельзя увеличивать

15. ★★ Замок есть, а гонка осталась. Почему?

static int count = 0;

static void click() {
    synchronized (new Object()) {
        count++;
    }
}
  • synchronized не работает с Object
  • Каждый раз новый замок — потоки не ждут друг друга
  • static-методы нельзя синхронизировать

Читаем код

Теперь не «что выведется», а «что происходит в строке». Прочитай каждую строку вслух правильными словами: создание объекта потока, запуск потока, задача, ожидание завершения, синхронизированный блок. В одних заданиях выбери описание из пяти, в других собери его из квадратиков — лишние оставь.

Хочешь ещё?

Напиши наставнику: «Дай мне 3 головоломки по потокам, по одной. Для каждой я скажу, сколько там потоков, кто кого ждёт и есть ли общие данные».

Что тренирует этот набор

  • start против run, одноразовость потока, имя текущего потока.
  • Кто кого ждёт: join, Future.get, программа живёт, пока жив хоть один обычный поток.
  • Гонки: count++, volatile — не лекарство, замок должен быть общим.
  • Deadlock: разный порядок замков.
  • Правила компилятора: «фактически final» в лямбдах, InterruptedException, Runnable не возвращает значение.
