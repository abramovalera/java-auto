ExecutorService: пул потоков

Создавать поток на каждую задачу — как нанимать нового официанта на каждого гостя. В настоящих программах работает смена из нескольких официантов. Знакомимся с пулом потоков, Callable и Future.

Повторение

Почему не создавать Thread вручную

Поток — дорогая штука: операционная система выделяет ему память под стек (обычно около мегабайта) и следит за ним. Создай поток на каждую из 10 000 задач — программа потратит больше времени на наём и увольнение, чем на работу, а то и упадёт от нехватки памяти.

Аналогия: смена официантов

В ресторане не нанимают нового официанта на каждого гостя. Работает смена из четырёх человек. Заказы копятся в очереди на кухне; освободился официант — берёт следующий. Гостей сто, а официантов по-прежнему четыре. Это и есть пул потоков (thread pool).

ExecutorService: submit и shutdown

Пул в Java — интерфейс ExecutorService (executor — «исполнитель»). Готовые пулы возвращают статические методы класса Executors:

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Waiters {
    public static void main(String[] args) {
        ExecutorService pool = Executors.newFixedThreadPool(3);
        for (int i = 1; i <= 5; i++) {
            int order = i;
            pool.submit(() -> System.out.println("Заказ " + order
                    + " несёт " + Thread.currentThread().getName()));
        }
        pool.shutdown();
        System.out.println("Приём заказов закрыт");
    }
}
Executors.newFixedThreadPool(3)

Вызов статического метода newFixedThreadPool с аргументом 3: метод возвращает пул ровно из трёх потоков — смена из трёх официантов.

int order = i;

Лямбда-выражение может использовать только «фактически final» локальные переменные, а i меняется. Поэтому объявляем переменную order и инициализируем её текущим значением i — на каждой итерации своя.

pool.submit(задача)

Вызываем метод submit у пула и передаём ему аргументом задачу (здесь — лямбда-выражение): она встаёт в очередь. Метод не ждёт выполнения задачи — возвращает управление сразу.

pool.shutdown()

Вызов shutdown() — «новых заказов не принимаем». Уже принятые задачи доделываются, потом потоки пула завершаются.

Что будет, если забыть pool.shutdown()?

Все заказы разнесут, но программа не завершится: потоки пула стоят и ждут новых задач, а Java не выключается, пока работает хоть один обычный поток. В IDEA красный квадратик ■ так и будет гореть. Правило: создал пул — закрой.

🔎 Для любопытных: подождать окончания и try-with-resources

shutdown() не ждёт. Чтобы главный поток дождался всех задач, после него вызывают pool.awaitTermination(10, TimeUnit.SECONDS) — «жду не дольше 10 секунд». shutdownNow() — «бросайте всё»: потокам пула отправляется interrupt().

С Java 19 пул можно закрывать как файл из модуля 15 — через try-with-resources. Метод close() сам вызовет shutdown() и дождётся всех задач:

try (ExecutorService pool = Executors.newFixedThreadPool(3)) {
    pool.submit(() -> System.out.println("Работаю"));
}   // здесь пул закрыт, все задачи выполнены

Callable и Future: задача с результатом

Задача Runnable ничего не возвращает (void run()). А если задача должна посчитать что-то? Для этого есть функциональный интерфейс Callable<V> с методом V call() — задача с результатом: метод возвращает значение типа V. Если тело лямбда-выражения, переданного аргументом в submit, возвращает значение, компилятор сам поймёт, что это Callable, а submit вернёт объект Future.

Аналогия: номерок в бургерной

Сделал заказ — получил чек с номером. Бургера ещё нет, но есть обещание. Можно пока сходить за салфетками. Потом подходишь к стойке и ждёшь, пока не выдадут заказ по номеру. Чек — это Future («будущий результат»), а ожидание у стойки — метод get().

import java.util.concurrent.*;

public class BurgerOrder {
    public static void main(String[] args)
            throws InterruptedException, ExecutionException {
        ExecutorService kitchen = Executors.newFixedThreadPool(2);

        Future<String> ticket = kitchen.submit(() -> {
            Thread.sleep(300);              // готовим
            return "бургер";
        });

        System.out.println("Взял салфетки");
        String food = ticket.get();         // ждём у стойки
        System.out.println("Получил: " + food);
        kitchen.shutdown();
    }
}

Этот вывод всегда одинаковый: вызов get() не вернёт управление главному потоку, пока результат не готов. Сравни с первым уроком, где порядок был случайным.

Пока он не вызвал get() — ничего: исключение тихо лежит внутри Future. На get() вылетит ExecutionException, причина — ArithmeticException. Поэтому результат задач всегда забирают через get(), иначе ошибки потеряются.

Мастерская: делим работу на части

Задача. Сервер интернет-магазина записал, за сколько миллисекунд он ответил на каждый запрос. Нужно посчитать, сколько запросов медленные (дольше 1000 мс), разделив массив на k частей и посчитав каждую часть в своей задаче пула. Идём по шаблону.

Шаг 1. Вход и выход. Вход — массив times длины n и число частей k. Выход — число медленных запросов. Примеры:

timeskОтветЗачем этот пример
[300, 1500, 800, 2000, 1200, 100, 900, 5000, 50, 1001]35обычный, части разного размера
[1500, 20]41частей больше, чем элементов
[]20граничный: пустой массив

Шаг 2. Руками. Как поделить 10 элементов на 3 части? 10 / 3 не делится нацело. Удобная формула: часть номер i начинается с индекса i * n / k и заканчивается перед (i + 1) * n / k. Деление целочисленное (модуль 3). Посчитаем:

ifrom = i·10/3to = (i+1)·10/3ИндексыЭлементыМедленных
0030, 1, 2300, 1500, 8001
1363, 4, 52000, 1200, 1002
26106 … 9900, 5000, 50, 10012

Части не пересекаются и покрывают весь массив: где кончилась одна, там началась следующая. Для [1500, 20] и k = 4 границы 0, 0, 1, 1, 2 — первая и третья части пустые, и это нормально: цикл по пустой части просто не выполнится.

Шаг 3. Роли переменных.

i
Шагающая: номер части, 0 … k − 1.
from, to
Временные границы. Объявляются заново на каждой итерации — поэтому их можно использовать в лямбда-выражении.
slow
Счётчик внутри задачи. У каждой задачи свой — никакой гонки.
parts
Список «чеков» Future — по одному на часть.
total
Накопитель в главном потоке: складывает результаты частей.

Шаг 4. Псевдокод.

создать пул из k потоков, пустой список чеков
для i от 0 до k-1:
    from ← i*n/k, to ← (i+1)*n/k
    отдать пулу задачу: посчитать медленных в times[from..to), вернуть число
    положить чек в список
total ← 0
для каждого чека: total ← total + чек.get()
закрыть пул, напечатать total

Шаг 5. Код — строка в строку:

int[] times = {300, 1500, 800, 2000, 1200, 100, 900, 5000, 50, 1001};
int n = times.length;
int k = 3;

ExecutorService pool = Executors.newFixedThreadPool(k);
List<Future<Integer>> parts = new ArrayList<>();
for (int i = 0; i < k; i++) {
    int from = i * n / k;
    int to = (i + 1) * n / k;
    parts.add(pool.submit(() -> {
        int slow = 0;
        for (int j = from; j < to; j++) {
            if (times[j] > 1000) slow++;
        }
        return slow;
    }));
}
int total = 0;
for (Future<Integer> part : parts) {
    total += part.get();
}
pool.shutdown();
System.out.println("Медленных запросов: " + total);

Шаг 6. Трассировка. Главный поток раздаёт части — посчитай границы сам.

Заметь: части ничего не пишут в общие переменные. Каждая считает своё и возвращает через Future, а складывает один главный поток. Нет общих изменяемых данных — нет гонки, и synchronized не нужен. Это самый надёжный способ писать многопоточный код.

Проверь себя

🔎 Для любопытных: виртуальные потоки (Java 21)

Обычный поток Java — это поток операционной системы, их тысячи, не миллионы. В Java 21 появились виртуальные потоки — лёгкие, их можно создать миллион. Пока виртуальный поток ждёт (сеть, база, sleep), он не занимает настоящий поток. Пул для них: Executors.newVirtualThreadPerTaskExecutor() — по новому виртуальному потоку на каждую задачу. Код с submit и Future остаётся тем же. Для учёбы сейчас это не нужно, но слово на собеседовании могут упомянуть.

Поговори с наставником

Напиши: «Я прошёл урок 16.3. Объясню своими словами, что такое Future и зачем shutdown, — проверь меня. А потом дай задачу m16-t04».

Коротко

  • Пул потоков — смена официантов: несколько потоков разбирают очередь задач. В Java — ExecutorService, создаётся через Executors.newFixedThreadPool(n).
  • submit ставит задачу в очередь и сразу возвращает Future. shutdown закрывает приём задач — без него программа не завершится.
  • Задача Callable возвращает результат (метод call()) и может бросать проверяемые исключения; задача Runnable — нет.
  • Вызов future.get() ждёт и возвращает результат задачи; ошибку задачи приносит как ExecutionException.
  • Лучший многопоточный код — без общих изменяемых данных: каждая задача считает своё, главный поток собирает.
