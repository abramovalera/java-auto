Как выбрать: class, abstract class, interface, enum или record

Пять инструментов в одном ящике. Сведём всё в одну схему выбора и соберём из них маленькую игру с заданиями, где каждый на своём месте.

⏱ 15 минут🧭 схема выбора⚡ 2 проверки

Повторение

Пять инструментов

🧱

class

Обычный класс: состояние + поведение. Корзина, игровой персонаж, счёт. Инструмент по умолчанию.

🍕

abstract class

Заготовка для родственников: общие поля и код, а деталь — у каждого своя. Delivery, Shape.

🔌

interface

Контракт «умеет делать» для кого угодно; класс может реализовать много интерфейсов. Payment, Comparator, Runnable.

🚦

enum

Фиксированный список вариантов, возможно с данными. Статусы, роли, языки.

🧾

record

Неизменяемые данные с готовыми equals/toString. Товар, точка, пользователь форума.

Схема выбора

Задавай вопросы сверху вниз. Первый ответ «да» — и инструмент найден.

Предскажи: «день недели», «координаты точки на карте», «умеет сохраняться в файл» — что для каждого?

День недели — enum (семь вариантов, и всё). Координаты — record (просто два числа, одинаковые координаты — одна и та же точка). «Умеет сохраняться» — interface: это умение может понадобиться документу, картинке, настройкам.

Не зубри таблицу построчно. Каждая клетка выводится из смысла: enum — «список готовых объектов», значит, new нельзя. record — «неизменяемые данные», значит, поля final и наследников нет. Спроси себя «зачем этот инструмент» — и клетка заполнится сама.

Все вместе: игрушечная игра с заданиями

Настоящие игры устроены сложнее, но кирпичики у них те же. Найди в коде каждый из пяти инструментов:

enum Status { DONE, FAILED }

record Result(String quest, Status status) { }

interface Reporter {
    void report(Result r);
}

abstract class Quest {
    abstract String name();
    abstract boolean play();                     // своя деталь каждого задания

    Result start() {                             // общая часть для всех заданий
        System.out.println("▶ " + name());
        Status st = play() ? Status.DONE : Status.FAILED;
        return new Result(name(), st);
    }
}

class DragonQuest extends Quest {
    String name() { return "dragon"; }
    boolean play() { return true; }
}

class RiddleQuest extends Quest {
    String name() { return "riddle"; }
    boolean play() { return 2 + 2 == 5; }
}

class ConsoleReporter implements Reporter {
    public void report(Result r) {
        System.out.println("  " + r);
    }
}

// в main:
Quest[] quests = { new DragonQuest(), new RiddleQuest() };
Reporter reporter = new ConsoleReporter();
for (Quest q : quests) {
    reporter.report(q.start());
}
Предскажи вывод программы 
▶ dragon
  Result[quest=dragon, status=DONE]
▶ riddle
  Result[quest=riddle, status=FAILED]

Цикл работает только с переменными типов Quest и Reporter. start() — общий шаблон, play() — своя деталь, результат — неизменяемый record, статус — enum, печать — через интерфейс (завтра можно подставить «отчёт в файл»).

🔎 Для любопытных: sealed — закрытый список наследников

Иногда хочется сказать: «Фигуры бывают только круги и квадраты, и никто больше не может добавить свою». Для этого в Java 17 появилось слово sealed («запечатанный»):

sealed interface Shape permits Circle, Square { }

record Circle(double r) implements Shape { }
record Square(double side) implements Shape { }

// class Triangle implements Shape { }   ✗ ошибка: Triangle нет в списке permits

Это что-то среднее между enum и интерфейсом: вариантов фиксированное количество, но каждый вариант — полноценный класс со своими данными. В новых версиях Java такие иерархии красиво разбирают через switch. В учебных программах это редкость, а на собеседованиях иногда спрашивают «что такое sealed».

Проверь себя

Поговори с наставником

Напиши: «Опиши мне маленькую программу (библиотека, кафе, магазин), а я разложу её на class, abstract class, interface, enum и record».

Коротко

  • Фиксированный список → enum. Неизменяемые данные → record.
  • Умение для разных классов → interface. Общие поля и код + своя деталь → abstract class.
  • Всё остальное (состояние меняется, есть поведение) → обычный class.
  • В реальном коде их комбинируют: enum внутри record, интерфейс + абстрактный класс с общей частью.
