Абстрактные классы

Бывают классы-заготовки: общий план есть, а одной детали не хватает. Учимся писать такие «полуфабрикаты» — и разбираемся, почему Java не даёт создать из них объект.

Какая площадь у «фигуры вообще»?

Пишем программу для геометрии. У всех фигур есть название и площадь, поэтому общий родитель напрашивается сам:

class Shape {
    double area() {
        return 0;     // ??? а какая площадь у «просто фигуры»?
    }
}

class Circle extends Shape { … area() считает π·r² … }
class Triangle extends Shape { … про area() забыли … }

Вот и проблема. Площадь «фигуры вообще» посчитать невозможно — это не круг, не квадрат, а просто идея. Мы написали return 0, потому что Java требует тело метода. Но это враньё, и оно опасно.

Предскажи: что напечатает new Triangle().area(), если в Triangle забыли переопределить area()?

0.0 — и никакой ошибки! Треугольник молча взял «враньё» родителя. Это логическая ошибка: программа работает, но считает неправильно, и компилятор ничего не заметил. Хочется, чтобы Java заставила каждого наследника написать свою площадь.

Нам нужен способ сказать: «Площадь есть у каждой фигуры, но как её считать — решит конкретная фигура. А “просто фигуру” создавать вообще нельзя». Именно это и умеет слово abstract.

abstract: метод без тела, класс-заготовка

abstract class Shape {
    abstract double area();   // только заголовок и ; — тела нет
}

class Circle extends Shape {
    private final double r;

    Circle(double r) {
        this.r = r;
    }

    @Override
    double area() {           // наследник ОБЯЗАН написать тело
        return Math.PI * r * r;
    }
}
abstract class Shape

Абстрактный класс — класс-заготовка. Из него нельзя создать объект (экземпляр), его можно только наследовать через extends.

abstract double area();

Абстрактный метод — метод без тела: есть заголовок (имя, параметры, тип возвращаемого значения), но нет фигурных скобок с телом — сразу ;. Это обещание: «у каждой фигуры будет area()».

@Override double area() { … }

Наследник выполняет обещание: переопределяет метод и пишет тело — то есть реализует абстрактный метод. Обычный (не абстрактный) класс ещё называют конкретным.

Аналогия: основа для пиццы

В пиццерии есть «основа»: тесто, соус, сыр — общая часть для всех пицц. Но продать «просто основу» нельзя: это ещё не пицца. Каждая пицца — «Маргарита», «Пепперони» — добавляет свою начинку. Абстрактный класс — основа: в нём всё общее и пустое место под начинку (абстрактный метод). Наследник — конкретная пицца.

Два правила, которые проверяет компилятор

Правило 1. Объект абстрактного класса создать нельзя.

Shape s = new Shape();     // ✗ ошибка компиляции
Main.java:3: error: Shape is abstract; cannot be instantiated
        Shape s = new Shape();
                  ^

Логично: если создать «просто фигуру» и вызвать s.area(), выполнять нечего — тела-то нет. Java защищает от этого заранее. Но обрати внимание: объявить переменную типа Shape — пожалуйста. Она будет хранить ссылку на объект-круг или объект-прямоугольник.

// ✓ переменная абстрактного типа, объект — конкретный
Shape s = new Circle(2);

Правило 2. Наследник обязан реализовать все абстрактные методы — или сам стать абстрактным.

class Triangle extends Shape {
    // забыли area()
}
Main.java:12: error: Triangle is not abstract and does not override abstract method area() in Shape
class Triangle extends Shape {
^

Вот она, защита от «вранья» с return 0: забыть площадь теперь невозможно — программа просто не скомпилируется. Ошибка компиляции лучше логической: её видно сразу, а не через месяц в отчёте.

Предскажи: а что если написать abstract class Triangle extends Shape { }?

Скомпилируется. Абстрактный наследник имеет право не реализовывать area() — он тоже заготовка. Обязанность просто переходит дальше: первый конкретный наследник (например, RightTriangle extends Triangle) должен будет написать тело.

Шаблон «общая часть + своя деталь»

В абстрактном классе можно держать не только абстрактные методы. В нём бывают поля, конструктор и обычные методы — всё общее, что не хочется копировать в каждого наследника. И самое интересное: обычный метод может вызывать абстрактный.

abstract class Shape {
    private final String name;

    // да, у абстрактного класса есть конструктор
    Shape(String name) {
        this.name = name;
    }

    abstract double area();

    String describe() {  // общая часть: одна на всех
        return name + ", площадь " + area();   // своя деталь: area() наследника
    }
}

class Rect extends Shape {
    private final double a;
    private final double b;

    Rect(double a, double b) {
        // конструктор Shape вызывается через super
        super("Прямоугольник");
        this.a = a;
        this.b = b;
    }

    @Override
    double area() {
        return a * b;
    }
}

class Circle extends Shape {
    private final double r;

    Circle(double r) {
        super("Круг");     // без этой строки — ошибка компиляции
        this.r = r;
    }

    @Override
    double area() {
        return Math.PI * r * r;
    }
}

Обрати внимание на super("Круг") в Circle. Теперь у Shape есть только конструктор с параметром Shape(String name), поэтому каждый наследник обязан вызвать его первой строкой своего конструктора. Забудешь — IDEA подчеркнёт конструктор: There is no parameterless constructor available in 'Shape' («у Shape нет конструктора без параметров»). Это правило ты уже видел в модуле 10.

У этого приёма есть имя

Когда общий метод родителя задаёт порядок действий, а отдельные шаги оставляет наследникам, это называют шаблонным методом (Template Method). На собеседованиях его любят спрашивать — и он повсюду в библиотеках Java.

Где это в настоящих программах

В больших программах почти всегда есть абстрактный «базовый» класс. Общие действия написаны там один раз, а каждый наследник добавляет свою деталь. Например, доставка в интернет-магазине: везут заказ все одинаково, а адрес у каждого вида доставки свой.

abstract class Delivery {
    abstract String address();                 // у каждой доставки свой адрес

    void deliver() {                           // везти умеют все одинаково
        System.out.println("Везу заказ: " + address());
        System.out.println("Отправляю SMS: заказ в пути…");
    }
}

class HomeDelivery extends Delivery {
    @Override
    String address() { return "ул. Лесная, 5"; }
}

class PickupDelivery extends Delivery {
    @Override
    String address() { return "пункт выдачи №12"; }
}
Везу заказ: ул. Лесная, 5
Отправляю SMS: заказ в пути…

Захотели добавить в deliver() фото посылки — правим одно место, и это работает для всех доставок. А новый вид доставки нельзя «забыть» снабдить адресом: компилятор не пустит.

Предскажи: можно ли написать Delivery d = new HomeDelivery(); d.deliver();? Что напечатается?

Можно: переменная абстрактного типа Delivery хранит ссылку на объект конкретного класса HomeDelivery. Напечатается «Везу заказ: ул. Лесная, 5» и «Отправляю SMS: заказ в пути…». deliver() унаследован от Delivery, а address() вызывается переопределённый — из HomeDelivery.

Что может быть в абстрактном классе

Можно ли?Ответ
Поля (в том числе private)✓ да
Конструктор✓ да — его вызывают наследники через super(...)
Обычные методы с телом✓ да
Абстрактные методы✓ сколько угодно, даже ни одного
Переменная этого типа, массив Shape[]✓ да
new Shape()✗ нет
Абстрактный метод в обычном (не abstract) классе✗ нет — класс с абстрактным методом обязан быть abstract
🔎 Для любопытных: странные сочетания слов, о которых спрашивают на собеседованиях
  • abstract final class — ошибка. final запрещает наследование, а абстрактный класс без наследников бесполезен.
  • private abstract void m(); — ошибка. Наследник не видит private-метод, значит, не сможет его реализовать.
  • static abstract void m(); — ошибка. Статический метод принадлежит классу и не переопределяется, а абстрактный только для того и существует.
  • abstract class Helper { } без единого абстрактного метода — законно. Так делают, когда хотят запретить создавать объекты «общего» класса.

Проверь себя

Поговори с наставником

Напиши: «Объясни мне на примере не из урока, зачем делать класс абстрактным, если можно просто не создавать его объекты». А потом попробуй сам ответить, почему return 0 в методе родителя — плохая идея.

Коротко

  • abstract class — заготовка: наследовать можно, создавать объект нельзя.
  • abstract-метод — только заголовок и ;. Каждый конкретный наследник обязан написать тело, иначе ошибка компиляции.
  • В абстрактном классе бывают поля, конструктор и обычные методы — вся общая часть.
  • Обычный метод может вызывать абстрактный: «общая часть + своя деталь» (шаблонный метод).
  • Переменные и массивы абстрактного типа — можно: они хранят ссылки на объекты конкретных классов.
