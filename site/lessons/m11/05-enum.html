Перечисления enum

PASSED, FAILED, SKIPPED. Понедельник… воскресенье. Лёгкий, средний, сложный. Когда вариантов ровно столько и не больше, Java даёт особый тип — перечисление.

⏱ 20 минут🚦 светофор⚡ 2 проверки

Повторение

Проблема: статус строкой

Ведём журнал экзамена. У каждого ученика три возможных результата: сдал, не сдал, пропустил. Первое, что приходит в голову, — хранить результат строкой:

String status = "PASED";  // опечатка — компилятор молчит
if (status.equals("PASSED")) {
    // не выполнится, и никто не поймёт почему
    System.out.println("Молодец!");
}
status = "банан";  // тоже можно — это же просто строка

Можно взять числа: 0 — сдал, 1 — не сдал, 2 — пропустил. Но status = 7 компилируется так же спокойно, а читать if (status == 1) — сплошное гадание.

Аналогия: светофор

У светофора ровно три сигнала: красный, жёлтый, зелёный. «Фиолетовый» или «красный с опечаткой» не бывает. Хочется тип, у которого заранее известен полный список значений — и чтобы компилятор не давал выйти за этот список.

enum — тип с фиксированным списком

enum ExamStatus {
    PASSED, FAILED, SKIPPED
}

ExamStatus s = ExamStatus.FAILED;
System.out.println(s);                   // FAILED

if (s == ExamStatus.FAILED) {
    System.out.println("Делаем скриншот");
}
enum ExamStatus

Объявление перечисления (enum, enumeration). Новый тип, как класс, только значения у него перечислены заранее.

PASSED, FAILED, SKIPPED

Константы перечисления. Пишут БОЛЬШИМИ_БУКВАМИ, через запятую. Других значений у типа ExamStatus не бывает (кроме null).

System.out.println(s)

Печатает имя константы: FAILED. Переопределять toString не нужно — у enum он уже возвращает имя.

s == ExamStatus.FAILED

Константы сравнивают через ==. Здесь это правильно, в отличие от строк (модуль 8). Почему — смотри схему.

Опечатка теперь ловится сразу: ExamStatus.PASED → error: cannot find symbol. И строку такой переменной не присвоить: ExamStatus s = "PASSED"; → incompatible types.

Предскажи: ExamStatus a = ExamStatus.FAILED; ExamStatus b = ExamStatus.FAILED; — что даст a == b?

true. Новых объектов константы не создают: ExamStatus.FAILED всегда указывает на один и тот же объект. Поэтому == для enum — норма. equals тоже работает, но == ещё и не выбросит NullPointerException, если слева null.

Что умеет любой enum

Каждый enum получает от Java готовые методы:

МетодЧто делаетПример → результат
values()массив всех констант по порядку объявленияExamStatus.values() → [PASSED, FAILED, SKIPPED]
ordinal()номер константы, считая с нуляExamStatus.SKIPPED.ordinal() → 2
name()имя константы строкойExamStatus.FAILED.name() → "FAILED"
valueOf(String)константа по её имени (буква в букву)ExamStatus.valueOf("PASSED") → PASSED
compareTo(…)сравнение по порядку объявленияPASSED.compareTo(SKIPPED) → отрицательное
for (ExamStatus st : ExamStatus.values()) {
    System.out.println(st.ordinal() + " " + st);
}
Предскажи вывод цикла 
0 PASSED
1 FAILED
2 SKIPPED

Порядок — как в объявлении. ordinal() начинается с 0, как индексы массива. Поэтому им удобно пользоваться как индексом: counts[st.ordinal()]++ — это пригодится в задаче про итоги сезона.

valueOf принимает аргументом текст (например, введённый с клавиатуры) и возвращает константу с таким именем. Но он строгий:

ExamStatus.valueOf("passed")
Exception in thread "main" java.lang.IllegalArgumentException: No enum constant ExamStatus.passed

Регистр важен. Если текст может прийти маленькими буквами, сначала вызови у строки toUpperCase(): "passed".toUpperCase().

ordinal — не для хранения

Номер зависит от порядка строк в коде. Вставил кто-то новую константу в середину — номера всех следующих сдвинулись. Пользуйся ordinal() внутри программы (как индексом), но не записывай его в файлы и базы как «код статуса».

switch по enum

enum и switch из модуля 4 — отличная пара. В case пишут просто имя константы, без ExamStatus. — тип и так известен:

static void printIcon(ExamStatus s) {
    switch (s) {
        case PASSED -> System.out.println("✔ сдал");
        case FAILED -> System.out.println("✘ не сдал");
        case SKIPPED -> System.out.println("⏭ пропустил");
    }
}

IDEA тоже помогает: напиши switch (s), нажми Alt+Enter — и она предложит создать ветки для всех констант.

Но не спеши писать switch по каждому поводу. Если для каждой константы нужно какое-то число или текст — цена, название, коэффициент — лучше положить его прямо в константу — в её поле. Смотри следующий шаг.

Поля, конструктор и методы в enum

enum — это настоящий класс. У него могут быть поля, конструктор и методы. Тогда каждая константа — объект со своими значениями полей:

enum Difficulty {
    EASY("Лёгкий", 1),
    MEDIUM("Средний", 2),
    HARD("Сложный", 3);  // ; обязательна, если дальше что-то есть

    private final String title;
    private final int multiplier;

    // конструктор: Java вызовет его сама
    Difficulty(String title, int multiplier) {
        this.title = title;
        this.multiplier = multiplier;
    }

    String getTitle() {
        return title;
    }

    int score(int base) {
        return base * multiplier;
    }
}

Difficulty d = Difficulty.HARD;
System.out.println(d.getTitle() + ": " + d.score(100));
Сложный: 300
HARD("Сложный", 3)

Константа с аргументами — это вызов конструктора с аргументами "Сложный" и 3. Java создаёт три объекта (по одному на константу) один раз, когда enum впервые понадобился.

HARD("Сложный", 3);

Список констант всегда первый и заканчивается ;, если после него идут поля и методы.

Difficulty(String title, …)

Конструктор enum всегда приватный (даже без слова private): new Difficulty(…) написать нельзя — ошибка enum classes may not be instantiated.

Предскажи: что напечатает System.out.println(Difficulty.EASY.score(50) + Difficulty.MEDIUM.score(50));?

150: 50 × 1 + 50 × 2. Обрати внимание — ни одного if и switch: каждая константа хранит свой множитель в поле multiplier. Добавишь уровень NIGHTMARE("Кошмар", 5) — остальной код менять не придётся.

enum в настоящих программах

В программах enum на каждом шагу: статусы заказов, размеры одежды, роли пользователей, языки приложения.

enum Language {
    RU("Привет"),
    EN("Hello");

    private final String greeting;

    Language(String greeting) {
        this.greeting = greeting;
    }

    String getGreeting() {
        return greeting;
    }
}

Language lang = Language.valueOf("EN");     // например, из настроек приложения
System.out.println(lang.getGreeting() + ", Аня!");
Hello, Аня!

Программа не хранит приветствия в if-ах — она вызывает getGreeting() у константы. Переключаем язык — меняем одно слово в настройках.

🔎 Для любопытных: enum — особый класс
  • Любой enum неявно наследует java.lang.Enum, поэтому extends у него писать нельзя. И сам он final: наследоваться от enum нельзя.
  • А вот implements — можно: enum Step implements Runnable — и каждая константа станет «работой», которую можно передать в метод.
  • У каждой константы может быть своё тело с переопределёнными методами: PLUS { int apply(int a, int b) { return a + b; } }.
  • Для словарей «константа → значение» в модуле 13 будет быстрый EnumMap.

Поговори с наставником

Напиши: «Почему для enum можно сравнивать через ==, а для строк нужно equals? Проверь, правильно ли я понимаю» — и объясни своими словами со схемой про кучу.

Коротко

  • enum — тип с заранее известным списком значений; опечатки и «левые» значения ловит компилятор.
  • Каждая константа — единственный объект, поэтому сравнение == — правильное.
  • values(), ordinal() (с нуля), name(), valueOf("ИМЯ") — строгий к регистру, иначе IllegalArgumentException.
  • switch по enum: в case только имя константы.
  • У enum бывают поля, конструктор (всегда приватный) и методы — данные лучше хранить в полях константы, а не в switch.
