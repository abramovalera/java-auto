record: неизменяемые данные в одну строку

Помнишь, сколько строк занимают конструктор, геттеры, equals, hashCode и toString? Для классов, которые «просто хранят данные», Java умеет написать всё это сама.

⏱ 20 минут🧠 память по шагам⚡ 2 проверки

Повторение

Сорок строк ради двух полей

Товар в магазине: название и цена. Чтобы это был «правильный» класс-данные, по правилам модуля 10 нужно написать:

public final class Product {
    private final String name;
    private final int price;

    public Product(String name, int price) {
        this.name = name;
        this.price = price;
    }

    public String getName() { return name; }
    public int getPrice() { return price; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Product)) return false;
        Product other = (Product) o;
        return price == other.price && name.equals(other.name);
    }

    @Override
    public int hashCode() { return 31 * name.hashCode() + price; }

    @Override
    public String toString() {
        return "Product[name=" + name + ", price=" + price + "]";
    }
}

Полезной информации тут — «название и цена». Остальное — однообразный шаблонный код, в котором легко ошибиться: добавил поле и забыл его в equals — получил хитрый баг. С Java 16 то же самое объявляется одной строкой — record (запись):

record Product(String name, int price) { }

Одна строка — и у тебя уже есть всё из большого класса выше. Это не сокращение для ленивых: компилятор генерирует ровно те же методы, только без ошибок.

Что Java пишет за тебя

Компоненты записи
То, что в круглых скобках после имени: String name, int price. По ним компилятор генерирует private final-поля.
Канонический конструктор
Конструктор, параметры которого — все компоненты по порядку. Он вызывается при создании объекта: new Product("Чай", 120).
Методы доступа
name() и price() — без «get»! Частая ошибка: p.getName() у record не существует.
Product tea = new Product("Чай", 120);
Product tea2 = new Product("Чай", 120);

System.out.println(tea);                  // Product[name=Чай, price=120]
System.out.println(tea.price());          // 120
System.out.println(tea == tea2);          // ?
System.out.println(tea.equals(tea2));     // ?
Предскажи: что напечатают две последние строки?

false и true. == по-прежнему сравнивает ссылки: объектов два. А equals record сравнивает по всем компонентам — название и цена совпали. Это ровно то поведение, ради которого в модуле 10 переопределяли equals.

Неизменяемость

Все поля record — final, сеттеров нет. Создал объект — он навсегда такой. Такие объекты называют неизменяемыми (immutable).

Product tea = new Product("Чай", 120);
tea.price = 100;          // ✗ ошибка: поле private final — снаружи не изменить
tea.setPrice(100);        // ✗ error: cannot find symbol — сеттеров нет

Нужна скидка? Не меняем старый объект, а создаём новый объект на его основе:

Product sale = new Product(tea.name(), tea.price() - 20);
System.out.println(tea);    // Product[name=Чай, price=120] — старый не тронут
System.out.println(sale);   // Product[name=Чай, price=100]
Аналогия: чек из магазина

Напечатанный чек не исправляют ручкой. Если ошиблись, пробивают новый чек. Зато любой, у кого в руках старый чек, может быть уверен: цифры в нём никто тайком не поменял. Так и record: передавай ссылку на него аргументом в любые методы — объект не изменится у тебя за спиной.

🔎 Для любопытных: неизменяемость «неглубокая»

Если компонент record — массив, то ссылку на массив поменять нельзя, а вот содержимое массива — можно: record Team(String[] names) → team.names()[0] = "Хакер" сработает. Поэтому компонентами record делают неизменяемые типы: числа, строки, enum, другие record. А ещё у record с массивом equals сравнивает массивы по ссылкам, а не по содержимому.

Компактный конструктор: проверка на входе

Товар с ценой −50 — бессмыслица. Проверить данные можно в особом компактном конструкторе: у него нет круглых скобок с параметрами — они и так известны из заголовка record.

record Product(String name, int price) {
    // компактный конструктор: без ( )
    Product {
        if (price < 0) {
            throw new IllegalArgumentException(
                    "Цена не может быть отрицательной: " + price);
        }
        name = name.strip();  // меняем ПАРАМЕТР, не поле
        // дальше Java сама сделает this.name = name; this.price = price;
    }
}
Product {

Компактный конструктор. Он выполняется перед тем, как Java присвоит значения параметров полям.

throw new IllegalArgumentException(…)

На опережение (модуль 12): создаём объект исключения с сообщением и throw выбрасывает его — если никто не перехватит, программа остановится с ошибкой. Объект с неверной ценой просто не будет создан.

name = name.strip();

Можно не только проверять, но и исправлять: убрать лишние пробелы, привести к нужному виду. Присваиваем параметру — а в поле уже попадёт исправленное.

Посмотри, в какой момент значения попадают в поля:

Частая ошибка

В компактном конструкторе нельзя писать this.name = … — будет ошибка компиляции: поля присвоит сама Java в конце. Меняй параметр: name = ….

А что будет, если цена всё-таки отрицательная? Вот что ты увидишь в консоли Run — это твой первый собственный «отказ», подробно разберём его в модуле 12:

record OrderLine(Product product, int qty) {
    int total() {
        return product.price() * qty;
    }
}

OrderLine line = new OrderLine(new Product("Чай", 120), 3);
System.out.println(line.total());    // 360
Предскажи: что напечатает System.out.println(line);?

OrderLine[product=Product[name=Чай, price=120], qty=3]. toString record вызывает toString у каждого компонента — а компонент сам record, у него тоже красивый toString.

В программах record — идеальная форма для данных о людях и вещах. Например, участники форума:

enum Role { ADMIN, MEMBER }

record ForumUser(String login, String email, Role role) { }

ForumUser admin = new ForumUser("admin", "admin@forum.ru", Role.ADMIN);
ForumUser anna = new ForumUser("anna", "anna@mail.ru", Role.MEMBER);
System.out.println("На форуме: " + admin.login() + " (" + admin.role() + ")");
На форуме: admin (ADMIN)

Видишь союз record и enum? Данные пользователя — record, а набор ролей — enum. А если что-то пошло не так, toString record сразу показывает, с какими данными работала программа.

Проверь себя

Поговори с наставником

Напиши: «Назови пять объектов из интернет-магазина, а я скажу, какие из них лучше сделать record, а какие — обычным классом, и почему».

Коротко

  • record Имя(тип a, тип b) { } — класс-данные: private final поля, канонический конструктор, a()/b(), equals, hashCode, toString.
  • Методы доступа — без «get»: p.price().
  • record неизменяем: «поменять» = создать новый объект.
  • Компактный конструктор Имя { … } проверяет и исправляет параметры; поля Java присвоит после него сама.
  • record — для данных (товары, пользователи форума, ответы сервера), class — для объектов с поведением и меняющимся состоянием.
