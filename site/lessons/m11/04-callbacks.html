Интерфейс как обратный вызов: Comparator и Runnable

До сих пор мы передавали в методы данные: числа, строки, массивы. Теперь научимся передавать поведение — «вот как сравнивать», «вот что делать». Это главный мостик к лямбдам.

⏱ 25 минут🧠 стек вызовов⚡ 2 проверки

Повторение

«Перезвоните мне, когда будет готово»

Ты заказываешь пиццу и оставляешь номер телефона. Пиццерия не знает, что ты будешь делать, когда пицца готова: побежишь к двери или попросишь соседа забрать. Она просто позвонит по номеру в нужный момент. Твой номер — это обратный вызов (по-английски callback).

В Java «номер телефона» — это объект класса, который реализует интерфейс. Мы передаём его аргументом, метод получает его в свой параметр и в нужный момент вызывает у него метод интерфейса. Та же пиццерия в коде: кухня готовит заказы и сообщает «слушателю» о каждом.

interface OrderListener {
    // «номер, по которому позвонят»
    void onReady(String order, boolean success);
}

class Kitchen {
    static void cookAll(String[] orders, OrderListener listener) {
        for (String o : orders) {
            boolean ok = !o.contains("burnt");       // будто бы испекли пиццу
            listener.onReady(o, ok);                 // ← обратный вызов
        }
    }
}

class ConsoleListener implements OrderListener {
    public void onReady(String order, boolean success) {
        System.out.println((success ? "✔ " : "✘ ") + order);
    }
}

// в main:
Kitchen.cookAll(new String[]{"margherita", "burnt-pepperoni"}, new ConsoleListener());
✔ margherita
✘ burnt-pepperoni

Пройди по шагам и посмотри на стек вызовов: в какой момент выполнение «возвращается» в твой класс?

Так устроены кнопки в программах

В программах с окнами нажатие кнопки работает точно так же: ты передаёшь кнопке «слушателя» — объект класса, который реализует интерфейс библиотеки. Библиотека не знает, что ты сделаешь, — она просто вызывает метод слушателя в момент клика. Так же устроены таймеры, будильники и уведомления.

Comparator: «вот как сравнивать»

Массив чисел или строк отсортировать просто — Arrays.sort(arr) из модуля 6. А как отсортировать массив игроков? По очкам? По имени? По убыванию или по возрастанию? Java угадать не может. Метод сортировки говорит: «Сортировать я умею. Ты только скажи, как сравнить двоих».

Для этого в JDK есть интерфейс java.util.Comparator с одним главным методом:

int compare(T a, T b);

Что за T? Это место для типа. Авторы JDK не знали, что ты будешь сравнивать — игроков, заказы или книги, — поэтому оставили пустое место. Ты заполняешь его сам, когда пишешь Comparator<Player>: вместо T подставится Player, и метод станет int compare(Player a, Player b).

import java.util.Arrays;
import java.util.Comparator;

class Player {
    final String name;
    final int score;

    Player(String name, int score) {
        this.name = name;
        this.score = score;
    }
}

class ByScoreDesc implements Comparator<Player> {
    @Override
    public int compare(Player a, Player b) {
        // b и a поменяны местами → по убыванию
        return Integer.compare(b.score, a.score);
    }
}

public class Ranking {
    public static void main(String[] args) {
        Player[] players = {
                new Player("Аня", 70),
                new Player("Боря", 95),
                new Player("Вика", 80)
        };
        // передаём «судью» в сортировку
        Arrays.sort(players, new ByScoreDesc());
        for (Player p : players) {
            System.out.println(p.name + " " + p.score);
        }
    }
}
Comparator<Player>

Читается «компаратор игроков». В угловых скобках — параметр типа: тип объектов, которые этот компаратор сравнивает. Как надпись на коробке «только игроки»: благодаря ей параметры compare сразу имеют тип Player, и внутри можно писать a.score. Такие угловые скобки называются generics (обобщения). Подробно — в модуле 13, а пока правило одно: в скобках пиши класс, объекты которого сортируешь.

Integer.compare(x, y)

Готовый судья для чисел: минус, если x < y, ноль, если равны, плюс, если больше. Для строк — s1.compareTo(s2) (по алфавиту).

Arrays.sort(players, new ByScoreDesc())

Создаём объект ByScoreDesc и передаём его аргументом. Метод sort сам много раз вызывает у него compare — это и есть обратный вызов.

Предскажи: что напечатает программа? 
Боря 95
Вика 80
Аня 70

По убыванию очков: в Integer.compare(b.score, a.score) аргументы переставлены. Было бы (a.score, b.score) — получилось бы по возрастанию.

Если очки равны, часто сравнивают по второму признаку:

public int compare(Player a, Player b) {
    if (a.score != b.score) {
        return Integer.compare(b.score, a.score);   // сначала по очкам
    }
    return a.name.compareTo(b.name);                // при равенстве — по имени
}
🔎 Для любопытных: почему не return a.score - b.score?

Так пишут часто, и для маленьких чисел это работает. Но при больших значениях вычитание может переполнить int (модуль 2): разница огромного положительного и огромного отрицательного числа «перевалит» через максимум и станет отрицательной. Сортировка молча сломается. Integer.compare такой ошибки не делает.

Comparator или Comparable — не перепутай

Слова похожи, роли разные. Comparable («сравнимый») — объект сам знает свой порядок: у строк и чисел он встроен, поэтому Arrays.sort(words) работает без судьи. Comparator («сравниватель») — судья со стороны: его передают в sort вторым аргументом, и для одного класса судей можно сделать сколько угодно — по очкам, по имени. У нашего Player встроенного порядка нет, поэтому Arrays.sort(players) без судьи упадёт при запуске с ClassCastException. Свой Comparable научимся писать в уроке 13.7.

Runnable: «вот что сделать»

Ещё один знаменитый интерфейс JDK — java.lang.Runnable. В нём один абстрактный метод без параметров и без возвращаемого значения: void run(). Это просто «кусок работы, который можно выполнить позже». Импортировать его не нужно — он из java.lang, как String. И угловых скобок у него нет: run() ничего не принимает и не возвращает, подставлять тип некуда.

class CallPizzeria implements Runnable {
    @Override
    public void run() {
        System.out.println("Звоню в пиццерию");
    }
}

public class Retry {
    static void repeat(int times, Runnable action) {
        for (int i = 1; i <= times; i++) {
            System.out.print(i + ": ");
            action.run();  // выполняем то, что передали
        }
    }

    public static void main(String[] args) {
        repeat(3, new CallPizzeria());
    }
}
1: Звоню в пиццерию
2: Звоню в пиццерию
3: Звоню в пиццерию

Метод repeat умеет повторять что угодно: звонить, отправлять сообщение, мигать лампочкой. Что именно — передают снаружи аргументом: объект класса, который реализует Runnable. Так делают «повтори действие, пока не получится» (например, переподключиться к интернету) и «выполни через минуту», а в модуле 16 Runnable станет работой для отдельного потока.

Предскажи: что напечатает repeat(0, new CallPizzeria())?

Ничего. Цикл не выполнится ни разу, и run() никто не вызовет. Передать поведение ≠ выполнить его: выполняет тот, кому передали, и тогда, когда сам решит.

Анонимный класс: объект «на месте»

Заводить отдельный класс ради одной строки — многовато: CallPizzeria, ByScoreDesc… Java позволяет создать объект класса без имени — анонимного класса — прямо там, где он нужен. Сначала на простом Runnable: тот же звонок, но без CallPizzeria:

repeat(3, new Runnable() {
    @Override
    public void run() {
        System.out.println("Звоню в пиццерию");
    }
});
new Runnable() {

«Создай объект безымянного класса, который реализует Runnable». Сразу после скобок () открывается тело этого класса.

public void run() { … }

Внутри — реализация метода интерфейса, как в обычном классе.

});

} закрывает тело класса, ) — вызов repeat, ; — инструкцию. Эта тройка часто путает новичков.

Обрати внимание: new Runnable() — это не создание объекта интерфейса (так нельзя!). Это создание объекта нового безымянного класса, который интерфейс реализует. Компилятор даже сделает для него файл вроде Retry$1.class.

С компаратором — точно так же, только после имени интерфейса, как и раньше, угловые скобки с типом:

Arrays.sort(players, new Comparator<Player>() {
    @Override
    public int compare(Player a, Player b) {
        return a.name.compareTo(b.name);            // по алфавиту
    }
});

Мостик к лямбдам

Заметил общее у OrderListener, Comparator и Runnable? В каждом один абстрактный метод. Такие интерфейсы называют функциональными: объект класса, который реализует такой интерфейс, — по сути «одна функция, завёрнутая в объект».

Анонимный класс для одной функции — это 5 строк, из которых важна одна. В модуле 14 ты узнаешь короткую запись — лямбду. Просто посмотри, писать так пока не нужно:

// сейчас:
Arrays.sort(players, new Comparator<Player>() {
    @Override
    public int compare(Player a, Player b) {
        return Integer.compare(b.score, a.score);
    }
});

// модуль 14 — то же самое лямбдой:
Arrays.sort(players, (a, b) -> Integer.compare(b.score, a.score));

IDEA об этом знает и, как только ты напишешь анонимный класс, начнёт намекать:

Почему сначала длинно

Лямбда — это не магия, а сокращённая запись того же анонимного класса. Кто понимает «длинную» форму, тот никогда не теряется в лямбдах: понятно, какой интерфейс реализуется, какой метод и откуда берутся a и b.

Проверь себя

Поговори с наставником

Напиши: «Дай мне массив объектов и попроси отсортировать его двумя разными компараторами — один отдельным классом, другой анонимным». А потом объясни ему своими словами, почему это называется «обратный вызов».

Коротко

  • Обратный вызов: передаёшь в метод аргументом объект класса, реализующего интерфейс, а метод в нужный момент вызывает у него метод интерфейса.
  • Comparator<T>: int compare(a, b) — минус, ноль или плюс. Arrays.sort(arr, компаратор).
  • Integer.compare(x, y) для чисел, s1.compareTo(s2) для строк; переставь аргументы — получишь обратный порядок.
  • Comparable — встроенный порядок самого объекта, Comparator — судья со стороны, его передают в sort.
  • Runnable — «работа на потом»: void run().
  • Анонимный класс new Интерфейс() { … } — объект безымянного класса прямо на месте. Интерфейсы с одним методом — функциональные, в модуле 14 анонимные классы для них заменят лямбды.
