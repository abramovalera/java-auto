Частые ошибки в условиях

В условиях прячутся ловушки, в которые попадает каждый новичок — а иногда и опытный программист. Одни компилятор ловит сам, другие проскакивают молча. Пройдём минное поле с картой в руках.

Повторение

Ловушка 1: = вместо ==

Ты помнишь из модуля 3: одно = — оператор присваивания («положи»), два == — оператор сравнения («спроси»). В условии нужно спрашивать. С числами компилятор тебя спасёт:

int x = 5;
// error: incompatible types: int cannot be converted to boolean
if (x = 5) {
    System.out.println("Пять!");
}

x = 5 — это присваивание, а его значение — число 5. Число условием быть не может, и javac останавливается. Хорошо.

А вот с boolean ловушка срабатывает молча:

boolean isPaid = false;
if (isPaid = true) {                     // компилируется!
    System.out.println("Заказ оплачен, отправляем");
}
Предскажи: что напечатает программа? Какое значение будет у isPaid после if?

Напечатает «Заказ оплачен, отправляем», а isPaid станет true. isPaid = true присваивает переменной значение true, и значение всего выражения присваивания — тоже true. Условие всегда истинно, и неоплаченный заказ уходит покупателю. Лекарство из урока 4.1: не сравнивай boolean с true вообще, пиши if (isPaid).

Ловушка 2: точка с запятой после if

Рука привыкла ставить ; в конце строки. Но после if (…) она всё ломает:

int balance = 100;
if (balance < 0); {
    System.out.println("Долг! Пополните счёт");
}

Запустим и введём положительный баланс:

Баланс положительный, а программа ругается. Почему? Точка с запятой сама по себе — это пустая инструкция: «ничего не делать». Java видит так: тело if — эта пустая инструкция, «если баланс меньше нуля — ничего не делай». Точка. А блок в фигурных скобках стоит уже отдельно и выполняется всегда.

Правило

После if (…), else и else if (…) точка с запятой не ставится никогда. Сразу открывай {.

Ловушка 3: if без фигурных скобок

Java разрешает не ставить скобки, если в теле if одна инструкция: if (x > 0) System.out.println("плюс");. Но стоит добавить вторую строку…

int age = 30;
if (age < 18)
    System.out.println("Доступ запрещён");
    System.out.println("Позовите родителей");
System.out.println("Конец проверки");
Предскажи: что напечатает программа для 30-летнего?

«Позовите родителей» и «Конец проверки». Без скобок телом if считается только одна следующая инструкция. Вторая строка стоит с отступом, но отступы для Java ничего не значат — это просто пробелы. На деле она находится вне if и выполняется всегда.

С else бывает ещё хитрее. К какому if относится этот else?

int a = 5, b = -1;
if (a > 0)
    if (b > 0)
        System.out.println("оба плюс");
else
    System.out.println("a не плюс");
Предскажи: что напечатает программа?

«a не плюс» — хотя a = 5! Правило Java: else относится к ближайшему if без пары, то есть к if (b > 0). Отступ обманывает глаз. Эта ловушка так знаменита, что у неё есть имя — «висячий else» (dangling else). Со скобками её не бывает.

Совет на всю жизнь: всегда ставь фигурные скобки, даже для одной строки. Так требуют правила оформления кода почти во всех компаниях — именно из-за этих двух ловушек.

Ловушка 4: строки через ==

Спросим у пользователя, продолжать ли:

Scanner scanner = new Scanner(System.in);
String answer = scanner.nextLine();      // пользователь ввёл: Да
if (answer == "Да") {
    System.out.println("Продолжаем!");
} else {
    System.out.println("Выходим");
}

Ввели «Да», а программа выходит. В модуле 3 мы уже видели причину: строка — объект в куче, а == у объектов сравнивает ссылки («это один и тот же объект?»), а не текст. Строка с клавиатуры — новый объект, у него другой адрес.

Текст сравнивают методом equals: вызываем его у одной строки и передаём другую как аргумент. Запомни пока как формулу:

if ("Да".equals(answer)) {               // сравнивает буквы — правильно
    System.out.println("Продолжаем!");
}
Почему «Да» слева

Можно написать и answer.equals("Да") — тоже сработает. Но вариант "Да".equals(answer) надёжнее: он не упадёт, даже если в answer вдруг не окажется никакой строки. Что такое «не окажется» и что такое equals на самом деле — разберём в модуле 8 «Строки». А для регистра есть родственник: "да".equalsIgnoreCase(answer) примет и «Да», и «ДА».

Ловушка 5: сравнение дробей

Тоже знакомая по модулю 3 история, но в if она особенно больно бьёт:

double total = 0.1 + 0.2;
if (total == 0.3) {
    System.out.println("Сумма сошлась");
} else {
    System.out.println("Ошибка в расчётах!");   // напечатается это
}

0.1 + 0.2 на самом деле 0.30000000000000004: дробные числа хранятся с крошечной погрешностью. Поэтому дроби сравнивают «с допуском» — проверяют, что разница очень мала:

if (Math.abs(total - 0.3) < 0.000001) {
    System.out.println("Сумма сошлась");
}

А вот < и > с дробями работают нормально — проблема только с точным равенством == и !=.

Ловушка 6: двойное сравнение как в математике

В математике пишут 0 < x < 10. Попробуем так же в Java:

if (0 < x < 10) { … }    // error: bad operand types for binary operator '<'

Java вычисляет выражение слева направо: сравнение 0 < x даёт true или false, а дальше получается true < 10 — операнды оператора < оказались boolean и числом, а так сравнивать нельзя. Двойное условие собирают из двух вопросов через «и»:

if (x > 0 && x < 10) { … }    // «больше нуля И меньше десяти»

Где прячутся баги

Самые опасные — строки «молчит». Программа запускается и выглядит рабочей, а ошибка всплывает только на определённых данных. Поэтому свою программу всегда проверяют на граничных и «неудобных» значениях — как это делать, разберём в мастерской, урок 4.6.

Коротко

  • В условии — ==, не =. boolean не сравнивай с true: if (ok).
  • Никакой ; после if (…). Всегда фигурные скобки — иначе вторая строка и else уезжают не туда.
  • else без скобок привязывается к ближайшему if.
  • Строки сравнивай через "Да".equals(answer), дроби — с допуском через Math.abs.
  • 0 < x < 10 пишется как x > 0 && x < 10.
