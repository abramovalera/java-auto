Программа принимает решения: if

До сих пор твои программы были как поезд на рельсах: строка за строкой, всегда одно и то же. Сегодня у поезда появится стрелка — и программа сама решит, куда ехать.

⏱ 20 минут🔀 первая развилка🔍 трассировка

Повторение: вопросы с ответом «да» или «нет»

Весь этот модуль стоит на одном фундаменте из модуля 3: на сравнениях и типе boolean. Освежим.

Зачем программе решать

Почти любая полезная программа ведёт себя по-разному в разных ситуациях:

🏧

Банкомат

Денег на счёте хватает — выдать купюры. Не хватает — показать «Недостаточно средств».

🔐

Вход на сайт

Пароль верный — пустить в личный кабинет. Неверный — показать ошибку.

🎮

Игра

Жизни закончились — показать «Игра окончена». Остались — играть дальше.

Аналогия: светофор

Подходишь к переходу и задаёшь себе вопрос: «Горит зелёный?» Если да — переходишь дорогу. Если нет — просто ничего не делаешь и ждёшь. Ты не переходишь «на всякий случай» и не стоишь вечно — ты проверяешь условие и в зависимости от ответа выполняешь действие или пропускаешь его.

В Java для этого есть слово if — по-английски «если». Это условный оператор: он проверяет условие (вопрос с ответом true или false) и выполняет кусок кода, только если условие истинно.

Как записывается if

public class Weather {
    public static void main(String[] args) {
        int temp = 32;
        if (temp > 30) {
            System.out.println("Жарко! Возьми воду.");
        }
        System.out.println("Хорошего дня!");
    }
}
Жарко! Возьми воду.
Хорошего дня!
if

Ключевое слово «если». Пишется маленькими буквами.

(temp > 30)

Условие — в круглых скобках, они обязательны. Внутри — выражение, которое даёт true или false.

{ … }

Тело if — блок в фигурных скобках. Выполняется, только если условие дало true. Строк в блоке может быть сколько угодно.

println("Хорошего дня!")

Стоит после закрывающей скобки — уже не в теле if, а следующая инструкция программы. Выполнится в любом случае.

Программисты рисуют такие развилки блок-схемой: прямоугольник — действие, ромб — вопрос с двумя выходами, «да» и «нет».

Предскажи: что напечатает программа, если в первой строке написать int temp = 30;?

Только «Хорошего дня!». 30 > 30 — неправда: тридцать не больше тридцати. Чтобы 30 тоже считалось жарой, нужно temp >= 30. Такие «пограничные» значения — главный источник ошибок в условиях, мы будем ловить их весь модуль.

Условие — это любое boolean-выражение

В круглые скобки после if можно поставить что угодно, лишь бы его значение было true или false. Всё, что ты делал в модуле 3, теперь работает внутри if:

if (balance >= price) { … }                  // сравнение
if (age >= 18 && hasTicket) { … }            // И: обе части правда
if (day == 6 || day == 7) { … }              // ИЛИ: хотя бы одна правда
if (!isBlocked) { … }                        // НЕ: «если не заблокирован»
if (n % 2 == 0) { … }                        // остаток: чётное число

boolean isVip = true;
if (isVip) { … }                             // boolean — уже готовое условие

Новички часто пишут if (isVip == true). Это работает, но звучит как «если правда, что VIP — правда». Пиши просто if (isVip), а для «если не VIP» — if (!isVip). Так пишут профессионалы.

А вот число условием быть не может — в Java нет правила «ноль значит ложь», как в некоторых других языках:

int count = 3;
// ошибка: incompatible types: int cannot be converted to boolean
if (count) { … }
// правильно: задаём вопрос явно
if (count > 0) { … }

Фигурные скобки — это блок

Всё, что между { и }, — один блок. У if этот блок и есть его тело, и работает он как дверь: условие истинно — заходим и выполняем все инструкции внутри по порядку; ложно — проходим мимо всей комнаты сразу.

int money = 500;
int price = 350;
if (money >= price) {
    money = money - price;
    System.out.println("Покупка прошла!");
    System.out.println("Осталось: " + money);
}
System.out.println("Касса закрыта.");

Внутри блока можно объявлять свои переменные. Но они живут только внутри этого блока: за закрывающей скобкой их уже нет. Это называется область видимости (по-английски scope).

if (money >= price) {
    int change = money - price;     // change родилась здесь
    System.out.println(change);     // работает
}
System.out.println(change);         // cannot find symbol: change «умерла»
Отступы

Строки внутри блока сдвигают на 4 пробела вправо. Компилятору всё равно, а человеку сразу видно, что «внутри», а что «снаружи». В IDEA Ctrl+Alt+L расставит отступы сам.

Предскажи: что напечатает пример с магазином, если money = 200?

Только «Касса закрыта.» Условие 200 >= 350 — false, поэтому всё тело if из трёх инструкций пропущено целиком: деньги не списаны, ничего не напечатано.

Решение по вводу с клавиатуры

Самое интересное начинается, когда условие зависит от того, что ввёл человек. Тогда при каждом запуске программа может пойти другой дорогой.

import java.util.Scanner;

public class Parking {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int minutes = scanner.nextInt();
        int price = 0;
        if (minutes > 15) {
            price = (minutes - 15) * 2;
        }
        System.out.println("К оплате: " + price);
    }
}

Запусти её в IDEA. Внизу откроется консоль Run — и ничего не произойдёт: программа остановилась на вызове метода nextInt() и ждёт числа. Щёлкни мышкой в консоль, набери число и нажми Enter:

Предскажи: сколько к оплате при вводе 15? А 16?

0 и 2. 15 > 15 — false, бесплатно. 16 > 15 — true, (16 − 15) × 2 = 2. Опытный программист обязательно проверил бы именно эти два числа — они стоят на самой границе условия.

Коротко

  • if (условие) { … } — условный оператор: выполнить тело (блок), только если условие true. Иначе тело пропускается целиком.
  • Условие — любое boolean-выражение: сравнение, &&, ||, !, переменная boolean. Число условием быть не может.
  • На блок-схеме if — ромб с двумя выходами.
  • Переменная, объявленная внутри блока, живёт только в нём.
  • Всегда проверяй граничные значения: > или >=?
