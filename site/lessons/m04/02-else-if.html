else, else if и вложенные условия

Один if умеет «сделать или пропустить». А жизнь чаще предлагает выбор: туда или сюда, а иногда — из пяти дорог. Учимся строить цепочки проверок и понимаем, почему в них важен порядок.

Повторение

else — «иначе»

Часто нужно сделать одно из двух: если условие верно — одно, если нет — другое. Для второй дороги есть ключевое слово else («иначе»). Получаются две ветки — два пути, по которым может пойти программа: тело if и ветка else.

int n = 7;
if (n % 2 == 0) {
    System.out.println(n + " — чётное");
} else {
    System.out.println(n + " — нечётное");
}
7 — нечётное
У else нет условия

Писать else (n % 2 != 0) нельзя — это ошибка компиляции. else означает «во всех остальных случаях», ему не нужен свой вопрос.

else if — цепочка вопросов

А если вариантов больше двух? Например, отметка по баллам за тест:

int score = 82;
if (score >= 90) {
    System.out.println("Отлично");
} else if (score >= 75) {
    System.out.println("Хорошо");
} else if (score >= 60) {
    System.out.println("Удовлетворительно");
} else {
    System.out.println("Пересдача");
}
Хорошо
Аналогия: сортировка посылок

Посылка едет по ленте мимо нескольких ворот. У первых ворот спрашивают: «Тяжелее 20 кг?» — если да, посылку снимают в грузовой отдел, и дальше она не едет. Если нет — едет к следующим воротам: «Тяжелее 5 кг?» И так далее. Последние ворота (else) забирают всё, что доехало до конца.

Главное правило цепочки: выполняется только первая подходящая ветка. 82 подходит и под «>= 75», и под «>= 60», но до «>= 60» Java даже не доходит. Поэтому во второй ветке не нужно писать score >= 75 && score < 90: раз мы здесь, значит, первая проверка уже ответила «нет», и score точно меньше 90.

else if — это не отдельное ключевое слово, а просто else, в ветке которого сразу стоит новый условный оператор if. Поэтому цепочка может быть любой длины.

Порядок проверок важен

Переставим ветки — вроде бы те же проверки, только снизу вверх:

int score = 95;
if (score >= 60) {
    System.out.println("Удовлетворительно");
} else if (score >= 75) {
    System.out.println("Хорошо");
} else if (score >= 90) {
    System.out.println("Отлично");
}
Предскажи: что напечатает программа для 95 баллов?

«Удовлетворительно»! 95 >= 60 — правда, первая ветка сработала, остальные Java даже не смотрит. Ветки «Хорошо» и «Отлично» теперь не выполнятся никогда: любое число ≥ 75 уже поймано первой проверкой. Компилятор такую ошибку не заметит — она логическая.

Правило порядка

Когда условия «вложены» друг в друга (каждое следующее шире предыдущего), проверяй от самого узкого к самому широкому: «>= 90» → «>= 75» → «>= 60» → всё остальное. Или наоборот, снизу: «< 60» → «< 75» → «< 90». Главное — чтобы каждая ветка могла хоть когда-нибудь сработать.

Нужен ли последний else?

Цепочка может заканчиваться и без else. Тогда, если ни одно условие не подошло, не выполнится ни одна ветка:

int place = 7;
if (place == 1) {
    System.out.println("Золото");
} else if (place == 2) {
    System.out.println("Серебро");
} else if (place == 3) {
    System.out.println("Бронза");
}
// для 7-го места не напечатается ничего — и это нормально

Предскажи: что напечатает этот код? Чем он отличается от цепочки? 
int score = 95;
if (score >= 90) { System.out.println("Отлично"); }
if (score >= 75) { System.out.println("Хорошо"); }
if (score >= 60) { System.out.println("Удовлетворительно"); }

Три строки: «Отлично», «Хорошо», «Удовлетворительно». Без else это три независимых вопроса, и каждый задаётся заново. Слово else как раз и связывает проверки в цепочку «только одна».

Вложенные if

Внутри тела if может стоять другой if — вложенный. Это как вопрос, который имеет смысл задавать только после «да» на первый. Пример: вход в систему.

boolean userExists = true;
boolean passwordOk = false;
if (userExists) {
    if (passwordOk) {
        System.out.println("Добро пожаловать!");
    } else {
        System.out.println("Неверный пароль");
    }
} else {
    System.out.println("Пользователь не найден");
}
Неверный пароль

Условие внешнего if — «есть ли такой пользователь?». Внутренний if проверяется, только если есть: он стоит в теле внешнего. Каждая ветка else относится к своему if — это видно по скобкам и отступам.

Иногда вложенность можно заменить на &&. Эти два варианта делают одно и то же:

// вариант 1: вложенные if
if (age >= 12) {
    if (height >= 140) {
        System.out.println("Проходи на аттракцион!");
    }
}

// вариант 2: одно условие с &&
if (age >= 12 && height >= 140) {
    System.out.println("Проходи на аттракцион!");
}
Что выбрать

Если в «промежуточном» случае ничего не надо делать — бери &&, так короче. Если на каждый вопрос нужен свой ответ («пользователь не найден» и «неверный пароль» — разные сообщения), — вложенные if. Глубже 2–3 уровней лучше не залезать: код становится «лесенкой», в которой легко заблудиться.

Проверь себя

Поговори с наставником

Напиши: «Дай мне цепочку else if с ошибкой в порядке веток — я найду ветку, которая никогда не сработает».

Коротко

  • if … else — ровно одна из двух веток. У else нет условия.
  • else if строит цепочку: проверки сверху вниз, выполняется первая подходящая ветка, остальные пропускаются.
  • Порядок важен: широкое условие сверху «съест» все узкие под ним.
  • Несколько отдельных if — независимые вопросы, могут сработать все.
  • Вложенный if — вопрос внутри ответа «да». Иногда его заменяет &&.
