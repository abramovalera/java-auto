Задача 1, разбор целиком: отметка по баллам

Условие. Программа читает баллы за тест (от 0 до 100) и печатает отметку: 90 и выше — «5», от 75 — «4», от 60 — «3», меньше 60 — «2». Если баллы вне диапазона — «Ошибка».

① Пойми задачу

Вход — одно целое число. Выход — одна строка: цифра или слово «Ошибка». Уточняем вопросы, которые условие оставило «на потом»: 90 — это уже «5»? Да, «90 и выше». А 100? Тоже «5». А 101 и −1 — «Ошибка».

② Реши руками

95 → смотрю, ≥ 90? да → «5». 80 → ≥ 90? нет. ≥ 75? да → «4». 30 → ни одно «≥» не подошло → «2». Что я делал? Сравнивал с порогами сверху вниз и останавливался на первом подходящем — это ровно цепочка else if.

③ Таблица случаев и граничные значения

Числа от 0 до 100 распадаются на диапазоны, внутри которых ответ одинаковый. Проверять каждое число не нужно — берём по одному из середины и обязательно числа на краях каждого диапазона: ошибки прячутся именно там (> вместо >=).

④ Псевдокод

прочитать баллы
если баллы < 0 или баллы > 100 → «Ошибка»
иначе если баллы >= 90 → «5»
иначе если баллы >= 75 → «4»
иначе если баллы >= 60 → «3»
иначе → «2»

Проверку на ошибку ставим первой: иначе 500 баллов попадёт в «>= 90» и получит пятёрку.

⑤ Код — перевод псевдокода строка в строку

import java.util.Scanner;

public class SchoolMark {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int score = scanner.nextInt();
        if (score < 0 || score > 100) {
            System.out.println("Ошибка");
        } else if (score >= 90) {
            System.out.println("5");
        } else if (score >= 75) {
            System.out.println("4");
        } else if (score >= 60) {
            System.out.println("3");
        } else {
            System.out.println("2");
        }
    }
}

Задача 2: високосный год — порядок проверок

Правило. Год високосный, если делится на 4. Но годы, кратные 100, — не високосные. Но годы, кратные 400, — всё-таки високосные. В модуле 3 ты записывал это одним логическим выражением. Теперь — цепочкой условий, и главный вопрос здесь — в каком порядке проверять.

Видишь «лесенку»? Каждое следующее правило — исключение из предыдущего. А в цепочке else if побеждает первая подходящая ветка. Значит, самое узкое исключение (на 400) надо проверить первым, а самое широкое правило (на 4) — последним. Это то же «от узкого к широкому», что в уроке 4.2.

Код по этому плану ты напишешь сам — это задача в практике. Подсказка: «делится на 400» в Java — это выражение year % 400 == 0.

Задача 3: тип треугольника — что проверять первым

Условие. Даны три стороны. Нужно сказать, какой это треугольник: равносторонний (все стороны равны), равнобедренный (ровно две равны) или разносторонний. А если из таких палочек треугольник не сложить — «Не существует».

① Пойми задачу: когда треугольник существует?

Возьми палочки 2, 2 и 5. Положи длинную, а две короткие попробуй соединить над ней — не дотянутся: 2 + 2 меньше 5. Правило: каждая сторона меньше суммы двух других. А при 1, 2, 3 палочки лягут в одну линию (1 + 2 = 3) — это уже не треугольник. И конечно, сторона не может быть нулём или отрицательной.

Предскажи: программист сначала проверил «все равны?», потом «две равны?», а существование — в самом конце. Что получат стороны 2 2 5? А 0 0 0?

2 2 5 → «Равнобедренный», 0 0 0 → «Равносторонний». Оба ответа неверны! Проверка «существует ли?» должна стоять первой: про форму треугольника имеет смысл спрашивать, только когда он есть. Это общее правило: сначала отсекай некорректные случаи, потом разбирай нормальные. Как в задаче 1 с «Ошибкой».

Код — снова в практике. Запиши сначала псевдокод: одна ветка на «не существует» (какие условия соединишь через ||?), потом «все три равны», потом «хотя бы две равны» — сколько тут пар сторон?

Задача 4: максимум и минимум — роль «рекордсмен»

Найти наибольшее из трёх чисел можно лесенкой вложенных if: «a больше b? если да, a больше c?…». Получается запутанно. Есть приём проще — переменная в роли рекордсмена.

Аналогия: таблица рекордов

На соревнованиях по прыжкам первый участник прыгнул — его результат пока рекорд. Каждый следующий прыгает, и судья спрашивает одно: «Побил рекорд?». Если да — записывает новый. В конце на табло — лучший результат. Сравнивать всех со всеми не нужно.

В игре «Раннер» тот же шаблон работает на каждом ходу: на входе — радар, на выходе — команда Джавику, а таблица случаев — «жук близко», «летучая ошибка близко», «впереди пусто». И порядок проверок решает, добежит ли он. Открыть урок «Раннер».

Поговори с наставником

Перед любой задачей с условиями напиши: «Вот моя таблица случаев и псевдокод для задачи …, проверь, не пропустил ли я граничные значения» — и только потом садись за код.

Коротко

  • Шесть шагов: пойми → руками → таблица случаев → псевдокод → код → проверка по таблице.
  • Таблица случаев: диапазоны с одинаковым ответом + числа на границах каждого диапазона.
  • В цепочке — сначала некорректные случаи, потом от узкого условия к широкому.
  • Рекордсмен (max / min) инициализируется первым реальным значением, а новый рекорд ему присваивают в отдельных if.
