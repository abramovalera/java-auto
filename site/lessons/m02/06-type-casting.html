Преобразования типов

Что будет, если сложить int и double? Как превратить 3.9 в целое число, букву — в её код, а текст «42» — в настоящее число? Разберёмся, когда Java меняет тип сама, а когда нужно попросить её явно.

Повторение

Когда типы встречаются

Тип переменной выбирается навсегда, но данные постоянно приходится переводить из одного типа в другой: цена товара в рублях (double) нужна целым числом; пользователь ввёл текст «42», а считать нужно с числом; в файле с прайс-листом цена — это текст «1299», а сложить её с другими надо как число.

Аналогия: переливаем воду

Из маленького стакана в большую банку переливать безопасно — всё поместится. Java делает это сама. А из большой банки в маленький стакан — часть может пролиться. Тут Java требует, чтобы ты сказал явно: «я понимаю, что часть пропадёт».

Автоматическое расширение

int count = 5;
long big = count;          // int → long, сама
double d = count;          // int → double: 5.0
double sum = 10 + 2.5;     // int + double → double: 12.5

Правило для выражений: если встретились два разных типа, меньший подтягивается к большему, и результат получается большего типа. int + long → long, int + double → double.

Коротко про деление целых

А если оба числа целые, то и результат — целый. Дробная часть при делении отбрасывается:

System.out.println(7 / 2);       // 3   — int / int = int
System.out.println(7 / 2.0);     // 3.5 — int / double = double
double half = 7 / 2;
System.out.println(half);        // 3.0 — сначала 7 / 2 = 3, потом 3 → 3.0

Последний пример коварный: переменная double, а результат всё равно без половинки. Java сначала вычисляет выражение справа по правилам int, получает 3, и только потом этим значением инициализирует переменную double — кладёт 3.0 в double-коробку. Деление и остаток подробно разберём в модуле 3.

Вспомни урок 2.2. Почему long seconds = days * 24 * 60 * 60; может дать отрицательное число, если days — int, равный 30 000?

Выражение справа вычисляется в int — все числа в нём int. 30 000 × 86 400 = 2 592 000 000 — больше предела int. Переполнение случается до того, как результат присвоится переменной long. Починка — сделать хотя бы одно число long с самого начала: days * 24L * 60 * 60. Тогда всё выражение считается в long.

Явное приведение: (тип)

Присвоить значение double переменной int напрямую нельзя — компилятор не даст потерять дробную часть молча:

int a = 3.99;          // ошибка компиляции

«Возможна потеря при преобразовании». Если ты согласен на потерю, напиши нужный тип в скобках перед значением. Это явное приведение типа (англ. cast):

int a = (int) 3.99;         // 3 — дробная часть отброшена
int b = (int) -3.99;        // -3 — тоже отброшена, а не «вниз»
int c = (int) 3_000_000_000L;  // -1294967296 — не влезло в int
(int) не округляет

(int) 3.99 — это 3, а не 4. Приведение просто отрезает всё после точки. Нужно округление по правилам математики — есть метод Math.round(3.99), он вернёт 4 (результат типа long).

Приведение — это ты говоришь компилятору «я знаю, что делаю». Компилятор верит на слово. Если число не помещается, как в третьей строке, значение молча испортится, как при переполнении.

🔎 Для любопытных: что выведет (byte) 200?

−56. В byte помещаются числа от −128 до 127. 200 туда не влезает, и счёт уходит по кругу: 200 − 256 = −56. Тот же «счётчик пробега», что у int, только круг маленький — на 256 значений.

Приведение и деление: где стоят скобки

Приведение работает и в обратную сторону — из int в double. Пригождается, когда делим две целые переменные, а нужен дробный ответ, например средний балл. Но важно, к чему относится (double): оно действует только на то, что стоит сразу справа от него.

int sum = 10;
int count = 4;
double good = (double) sum / count;    // 2.5
double bad = (double) (sum / count);   // 2.0
  • (double) sum / count — сначала sum становится 10.0, потом 10.0 / 4. Одно число дробное — значит, и деление дробное: 2.5.
  • (double) (sum / count) — сначала выполняется то, что в скобках: 10 / 4 = 2 (int / int, дробь уже отброшена). Потом 2 превращается в 2.0. Поздно — половинка потерялась: 2.0.
Что выведет программа?
int a = 7;
int b = 2;
System.out.println((double) a / b);
System.out.println((double) (a / b));

3.5 и 3.0. В первой строке к double приводится a до деления — деление дробное. Во второй сначала целое деление 7 / 2 = 3, и только готовая тройка становится 3.0.

Аккуратный вывод дробных: Math.round

Дробные числа компьютер хранит в двоичном виде, и многие «круглые» для нас числа (0.1, 1.8) записываются в нём лишь приблизительно — как 1/3 в десятичной записи: 0.3333… Обычно этого не видно, но иногда вылезает «хвост»:

System.out.println(0.1 + 0.2);              // 0.30000000000000004
double fahrenheit = 37 * (9.0 / 5) + 32;
System.out.println(fahrenheit);             // 98.60000000000001

Это не ошибка в твоём коде, так устроены все дробные числа в компьютере. Чтобы напечатать красиво, число округляют до нужного знака методом Math.round (класс Math — набор математических методов, лежит в java.lang, import не нужен):

double rounded = Math.round(fahrenheit * 10) / 10.0;   // 98.6 — один знак после точки
double tidy = Math.round((0.1 + 0.2) * 100) / 100.0;   // 0.3  — два знака после точки
  1. Сдвигаем точку: умножаем на 10 (один знак) или на 100 (два знака): 98.60000000000001 × 10 = 986.0000000000001.
  2. Округляем до целого: Math.round(...) возвращает целое число (типа long) — 986. В отличие от (int), он округляет по правилам математики: Math.round(3.7) = 4.
  3. Возвращаем точку: делим на 10.0 — именно с точкой! 986 / 10 — это целое деление, получится 98.
Что выведет System.out.println(Math.round(2.0 / 3 * 100) / 100.0);?

0.67. 2.0 / 3 = 0.6666…, ×100 = 66.66…, округление даёт 67, а 67 / 100.0 = 0.67.

Поэтому в задачах курса дробный ответ либо подобран так, что «хвоста» нет, либо в условии прямо сказано округлить через Math.round.

Символы — это числа

Помнишь секрет из урока 2.2? Внутри char лежит код символа из таблицы Unicode. Поэтому char легко превращается в int, и обратно:

char letter = 'A';
int code = letter;                  // 65 — автоматически
char next = (char) (letter + 1);    // 'B' — явно
System.out.println(code);           // 65
System.out.println(next);           // B
System.out.println('A' + 1);        // 66 — char + int = int
System.out.println('A' + 'B');      // 131 — два кода сложились
System.out.println("" + 'A' + 'B'); // AB — строка в начале: склейка
'7' — не 7

char digit = '7'; хранит код 55. Поэтому '7' + 1 = 56, а не 8. Превратить символ-цифру в число можно так: digit - '0' → 55 − 48 = 7.

Что выведет System.out.println('a' - 'A');?

32. 97 − 65 = 32. Маленькие латинские буквы стоят в таблице ровно на 32 позиции дальше больших. На этом трюке раньше делали перевод букв в верхний регистр.

Строки и числа

Строка «42» и число 42 для Java — совсем разные вещи. Перевести одно в другое помогают готовые методы:

int n = Integer.parseInt("42");            // строка → int
double d = Double.parseDouble("3.14");     // строка → double
long big = Long.parseLong("9000000000");   // строка → long

String s1 = String.valueOf(42);            // число → строка "42"
String s2 = "" + 42;                       // тоже "42" — короткий трюк

System.out.println("42" + 1);              // 421 — склейка
System.out.println(n + 1);                 // 43  — сложение

Если строка не похожа на число, программа упадёт с ошибкой NumberFormatException:

  • Integer.parseInt("abc") — не число;
  • Integer.parseInt("3.5") — для int дробь не подходит;
  • Integer.parseInt(" 42") — пробел тоже мешает;
  • Integer.parseInt("") — пустая строка — не число.

Заметь: Double.parseDouble всегда ждёт точку, в отличие от Scanner, который смотрит на язык системы.

Второй способ обойти ловушку Scanner

Помнишь ловушку nextInt + nextLine? Можно читать всё через nextLine() и переводить сам: int age = Integer.parseInt(scanner.nextLine()); Здесь строку, которую вернул nextLine(), мы передаём аргументом методу Integer.parseInt, а его результатом инициализируем age. Enter съедается вместе со строкой, и ловушки нет.

В реальных программах это на каждом шагу: всё, что приходит из поля ввода, из файла или из интернета, — текст. Цена «1299», количество «3» — чтобы сравнить или сложить, сначала Integer.parseInt.

Поговори с наставником

Напиши: «Дай мне 5 выражений с разными типами — я скажу тип результата и значение, а ты проверь».

Коротко

  • Расширение (byte → short → int → long → float → double, char → int) Java делает сама.
  • В выражении меньший тип подтягивается к большему. int / int = int, дробь отбрасывается: 7 / 2 = 3.
  • Сужение — только явно: (int) 3.99 = 3. Не округляет! Не влезло — значение испортится.
  • (double) a / b — дробное деление; (double) (a / b) — сначала целое деление, дробь уже потеряна.
  • У дробных бывает «хвост» (0.1 + 0.2 = 0.30000000000000004). Округлить до одного знака: Math.round(x * 10) / 10.0.
  • char ↔ int: 'A' + 1 = 66, (char) 66 = 'B'. Цифра '0' — это код 48.
  • Строка → число: Integer.parseInt, Double.parseDouble, Long.parseLong. Число → строка: String.valueOf(x) или "" + x.
  • Не похоже на число — NumberFormatException.
