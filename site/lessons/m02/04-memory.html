Память изнутри: стек и куча

Где на самом деле лежат твои переменные? Почему число хранится прямо в коробке, а строка — где-то далеко, и в коробке только стрелка? Заглянем в память JVM — это один из любимых вопросов на собеседованиях.

Повторение

Две части памяти: стек и куча

Когда программа запускается, JVM получает от операционной системы кусок оперативной памяти и делит его на области. Нам важны две:

🗂️

Стек (stack)

Рабочий стол с ящичками. Здесь лежат переменные методов — например, всё, что ты объявил в main. Маленький, очень быстрый, всё по порядку.

🏭

Куча (heap)

Большой склад. Здесь живут объекты — строки, сканеры, а потом и твои собственные. Места много, порядок свободный, убирает сборщик мусора.

Слово «стек» по-английски значит «стопка». Представь стопку тарелок: новую кладут сверху, и снимают тоже сверху. Каждый запущенный метод получает свою «тарелку» — фрейм (англ. frame — рамка) со своими переменными. Сейчас у нас один метод — main, значит, и фрейм один. Когда начнём писать свои методы (модуль 7), тарелок станет больше.

Правило, которое стоит выучить наизусть: примитивы лежат прямо в переменной, а объекты — в куче, и в переменной лежит только ссылка на объект. Дальше разберём, что это значит.

Примитивы: значение прямо в коробке

int age = 25;
double price = 9.99;
boolean ok = true;

У каждого примитивного типа точный размер: int — 4 байта, double — 8, и так далее. JVM заранее знает, сколько места нужно, поэтому при инициализации кладёт значение прямо в ячейку на стеке. Заглянул в коробку — увидел число.

Объекты: в коробке — номерок

int age = 25;
String name = "Аня";

Строка — объект. Объекты бывают любого размера: строка может быть из трёх букв, а может хранить текст целой книги. Таскать такое по стеку неудобно, поэтому объект создаётся в куче, а переменная инициализируется ссылкой — адресом, по которому этот объект можно найти.

Аналогия: гардероб в театре

Ты сдаёшь пальто в гардероб и получаешь номерок. Пальто (объект) висит на вешалке (в куче), а у тебя в руке только номерок (ссылка). Номерок маленький и всегда одного размера — неважно, сдал ты лёгкую куртку или огромную шубу. Захотел пальто — показал номерок и получил его.

Стек
Область памяти для переменных методов. У каждого метода свой фрейм.
Куча
Область памяти для объектов.
Ссылка
Адрес объекта в куче. Переменная типа String хранит ссылку, а не сам текст. Типы, переменные которых хранят ссылки, называют ссылочными.

Копируем: значение или стрелку?

Разница между примитивами и объектами сильнее всего видна при копировании. int b = a; инициализирует b копией числа, как ксерокопией записки. String s2 = s1; инициализирует s2 копией ссылки: теперь две стрелки ведут к одному и тому же объекту. Посмотри по шагам — слева стек, справа куча, стрелки — ссылки.

Что выведет программа?
String city = "Москва";
String home = city;
city = "Казань";
System.out.println(home);

Москва. Инициализация home = city скопировала стрелку на объект «Москва». Потом переменной city присвоили ссылку на новый объект «Казань» — её стрелку перевесили, но стрелка home осталась на месте. Перевесить одну стрелку — не значит перевесить другую.

🔎 Для любопытных: а можно ли поменять сам объект «Аня»?

У строк — нет: объекты String неизменяемые (англ. immutable). Любой метод, который будто бы меняет строку (toUpperCase() и другие), на самом деле создаёт новый объект. Поэтому с двумя стрелками на одну строку ничего плохого случиться не может.

А вот объекты, которые можно менять, бывают: например, массивы (модуль 6) и твои собственные классы (модуль 9). Там две стрелки на один объект — источник сюрпризов: поменял через одну переменную — изменилось и «у другой». Картинка со стрелками тебе тогда очень пригодится.

null — номерок без пальто

null — особое значение для ссылочных переменных: «ни на что не указывает». Коробка есть, а стрелки нет. Это не то же самое, что пустая строка:

String empty = "";       // объект есть, в нём 0 символов
String nothing = null;   // объекта нет вообще
int zero = 0;            // примитив: просто число 0

System.out.println(empty.length());    // 0
System.out.println(nothing.length());  // программа падает!

Вызвать метод у объекта, которого нет, нельзя: nothing.length() — это как прийти в гардероб с пустой рукой и требовать пальто. JVM бросает ошибку NullPointerException (сокращённо NPE). Это самая частая ошибка в Java: например, когда ждали, что программа что-то найдёт и вернёт (скажем, клиента по номеру карты), а она вернула null.

Примитив не бывает null

int x = null; — ошибка компиляции. В примитивной коробке всегда лежит число (или true/false, или символ), стрелок там нет, поэтому и «нет стрелки» быть не может.

Кто убирает память

Стек и кучу убирают по-разному:

  • Стек убирается сам и мгновенно. Метод закончился — его фрейм снимается со стопки целиком, со всеми переменными. Закончился main — исчезли a, b, s1, s2.
  • Кучу убирает сборщик мусора (англ. garbage collector, GC). Время от времени он проходит по куче и ищет объекты, до которых не ведёт ни одна стрелка — ни со стека, ни из других объектов. Их память освобождается. Именно это ты делал в игре в уроке 1.1, только теперь знаешь, что «ниточки» — это ссылки из переменных на стеке.
Две знаменитые ошибки

StackOverflowError — стопка тарелок выросла до потолка: методов вызвано слишком много одновременно (встретишь в модуле 7 про рекурсию). Отсюда, кстати, название сайта Stack Overflow. OutOfMemoryError — склад забит: объектов столько, что даже после уборки места не хватает.

🔎 Для любопытных: пул строк — вопрос с собеседований

Если написать String x = "Аня"; и String y = "Аня";, объект в куче будет один, и обе стрелки укажут на него. Java хранит строки, написанные прямо в коде (литералы), в особом месте кучи — пуле строк — и не создаёт одинаковые дважды: зачем, если строки всё равно не меняются? Из-за этого сравнение строк в Java полно ловушек. Разберём в модуле 8.

Честное уточнение к трассировке выше: строки-литералы из пула на практике живут, пока загружен класс, — на них ссылается сам пул. Мы упростили картинку, чтобы показать главное правило: объект, до которого не дотянуться ни по одной ссылке, — мусор. Для обычных объектов, которые ты будешь создавать сам, оно работает ровно так.

И ещё уточнение для собеседований: «примитивы — на стеке» верно для переменных внутри методов. Если примитив — часть объекта (поле класса, модуль 9), он живёт внутри этого объекта, в куче.

Коротко

  • Память JVM: стек — переменные методов (у каждого метода свой фрейм), куча — объекты.
  • Примитив хранит значение прямо в переменной. Объектная переменная хранит ссылку на объект в куче.
  • Присваивание b = a для примитивов копирует число, для объектов — стрелку: две переменные смотрят на один объект.
  • null — «стрелки нет». Вызов метода у null — NullPointerException. Примитив не бывает null.
  • Стек чистится сам, когда метод заканчивается. Объекты без ссылок убирает сборщик мусора.
