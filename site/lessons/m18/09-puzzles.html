Автотесты: найдёт ли? пройдёт ли? что выведется?

Вопросы в духе собеседования на автоматизатора: локаторы, проверки Selenide, ожидания, Page Object и жизненный цикл JUnit. Запускать нельзя — только думать и объяснять.

Как решать

Сначала скажи ответ вслух и объясни почему, потом кликай. Для локаторов помогает нарисовать дерево элементов, для JUnit — вспомнить, что на каждый тест создаётся новый объект класса.

Какой локатор найдёт элемент?

1. Какой локатор не найдёт эту кнопку?

<button class="btn btn-primary" data-test-id="pay">Оплатить</button>
  • .btn-primary
  • [data-test-id='pay']
  • //button[@class='btn']
  • //button[text()='Оплатить']

2. На странице есть <input id="email" name="email">. Что сделает тест?

$("email").setValue("anna@mail.ru");
  • Введёт адрес в поле email
  • Будет искать тег <email>, не найдёт и упадёт через таймаут
  • Ошибка компиляции

3. Сколько элементов найдёт .menu .active li?

<ul class="menu">
  <li>Книги</li>
  <li class="active">Новинки</li>
  <li>Акции</li>
</ul>
  • 1
  • 0
  • 3

4. ★ Для того же меню: сколько найдёт //li[contains(text(),'книги')]?

  • 1
  • 0
  • 3

Хрупкий или стабильный?

5. Дизайнеры перенесли кнопку «Выйти» из шапки в боковое меню и перекрасили её. Какой локатор переживёт редизайн?

  • .header .btn-blue
  • /html/body/header/div[2]/button
  • [data-test-id='logout']
  • (//button)[3]

Что проверяет shouldHave?

6. Значок корзины должен показывать 1, а из-за бага показывает 12. Что будет с тестом?

$("[data-test-id='cart-count']").shouldHave(text("1"));
  • Упадёт: 12 ≠ 1
  • Пройдёт — баг останется незамеченным
  • Ошибка: text() не работает с числами

7. В итоговой строке написано «Итого: 1 290 ₽». Какая проверка упадёт?

  • shouldHave(text("1 290"))
  • shouldHave(text("итого"))
  • shouldHave(exactText("1 290"))

Ожидания и sleep

8. Результат поиска появляется через 0,3 с. Что не так с тестом?

$("[data-test-id='search-button']").click();
Thread.sleep(2000);
$("[data-test-id='results']").shouldBe(visible);
  • Тест упадёт
  • Пройдёт, но sleep лишний: каждый раз теряем время
  • Всё правильно: без sleep Selenide не дождётся

9. ★★ Блок результатов виден сразу с текстом «Ищем…», а «Найдено: 5» появляется в нём через 3 с. Что будет?

$("[data-test-id='search-button']").click();
Thread.sleep(2000);
assertThat($("[data-test-id='results']").getText()).isEqualTo("Найдено: 5");
  • Пройдёт: AssertJ подождёт
  • Упадёт: проверка выполнится один раз, когда текста ещё нет
  • Будет то проходить, то падать

Page Object: что вернёт и скомпилируется ли

10. Скомпилируется ли последняя строка?

public class SearchPage {
    public SearchPage typeQuery(String q) { /* … */ return this; }
    public ResultsPage submit() { /* … */ return new ResultsPage(); }
}
public class ResultsPage {
    public int count() { /* … */ }
}

new SearchPage().typeQuery("java").submit().typeQuery("kotlin");
  • Да, это обычная цепочка
  • Нет: у ResultsPage нет метода typeQuery
  • Да, но упадёт при запуске

11. ★★★ Скомпилируется ли класс страницы? (Есть import static com.codeborne.selenide.Selenide.*;)

public class LoginPage {
    public LoginPage open() {
        open("/login");
        return this;
    }
}
  • Да: вызовется Selenide.open("/login")
  • Нет: внутри класса open — это метод самого LoginPage, а он не принимает аргументов
  • Да, но будет бесконечная рекурсия

Независимость тестов и JUnit

12. Что напечатают два теста (в любом порядке)?

class CounterTest {
    int calls = 0;

    @Test void first()  { calls++; System.out.print(calls); }
    @Test void second() { calls++; System.out.print(calls); }
}
  • 12
  • 11
  • 00

13. ★ А если поле сделать static int calls = 0;?

  • 11
  • 12
  • Ошибка компиляции

14. ★★ Что напечатает запуск единственного теста t?

abstract class BaseTest {
    @BeforeEach void baseBefore() { System.out.print("B"); }
    @AfterEach  void baseAfter()  { System.out.print("b"); }
}

class LoginTest extends BaseTest {
    @BeforeEach void loginBefore() { System.out.print("L"); }
    @AfterEach  void loginAfter()  { System.out.print("l"); }
    @Test       void t()           { System.out.print("T"); }
}
  • LBTlb
  • BLTlb
  • BLTbl

15. Скомпилируется, но что будет при запуске?

class CatalogTest {
    @BeforeAll
    void configure() {
        Configuration.baseUrl = "https://nook-shop.test";
    }

    @Test
    void catalogOpens() { /* … */ }
}
  • Всё отработает как обычно
  • JUnit откажется запускать: метод @BeforeAll должен быть static
  • Ошибка компиляции

Читаем код

Строки автотестов тоже читаем вслух правильными словами: локатор, элемент страницы, действие, проверка состояния, метод страницы, ожидаемое и фактическое значение. В одних заданиях выбери верное описание из пяти, в других собери его из квадратиков — лишние оставь на месте.

Что тренирует этот набор

  • Как CSS и XPath находят элементы: пробел — «внутри», класс в XPath сравнивается целиком, XPath различает регистр.
  • Почему стабильный локатор опирается на тестовый атрибут, а не на место, цвет и номер.
  • Разницу text / exactText и почему getText + sleep — путь к падениям.
  • Как типы возвращаемых значений методов страниц (Page Object) описывают переходы между страницами.
  • Жизненный цикл JUnit: новый объект на тест, порядок @BeforeEach/@AfterEach, static у @BeforeAll.
