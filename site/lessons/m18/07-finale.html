Финал курса: что дальше

Курс «Java с нуля» позади. Оглянемся на весь путь, выберем пет-проект и составим план, что учить дальше.

Весь курс на одной карте

Остановись на минуту и посмотри назад. Ты начинал с вопроса «что такое программа», а заканчиваешь отладчиком, Git, тестами и паттернами. Вот что теперь умеешь — по модулям. Щёлкни по названию, если хочешь освежить модуль.

Это и есть Java Core — фундамент, который спрашивают на собеседовании Java junior и на котором стоит всё остальное: базы данных, веб, Spring. Дальше ты не начинаешь с нуля, а достраиваешь этажи.

Что дальше: план на 2–3 месяца

Почти любая вакансия Java junior — это бэкенд: программа на сервере, которая хранит данные в базе и отвечает другим программам по сети. Чтобы до неё дорасти, учи темы именно в этом порядке — каждая опирается на предыдущую. Темп — около часа в день; быстрее — отлично, медленнее — тоже нормально.

  1. Недели 1–3. SQL и базы данных. Как хранят данные по-настоящему: таблицы, SELECT, WHERE, ORDER BY, JOIN, GROUP BY, INSERT/UPDATE/DELETE, первичный и внешний ключ. Бери PostgreSQL — её чаще всего встречают в вакансиях.
    Бесплатно: «Интерактивный тренажёр по SQL» на Stepik (задачи с автопроверкой прямо в браузере) · руководство по PostgreSQL на metanit (установка, pgAdmin, все запросы по порядку) · SQLBolt (то же на английском, очень коротко).
    Практика: придумай таблицы для своего пет-проекта (например, clients и accounts для мини-банка) и напиши к ним 10 запросов: «все счета клиента», «сумма по всем счетам», «клиенты без счетов».
  2. Недели 4–5. JDBC: Java разговаривает с базой. Подключение к базе из своей программы: Connection, PreparedStatement, ResultSet. Драйвер базы подключаешь как зависимость в Gradle — урок 17.4 тебе здесь уже пригодится.
    Бесплатно: «Работа с базами данных» на metanit (там MySQL, для PostgreSQL меняется только драйвер и адрес подключения) · JDBC Basics от Oracle (английский).
    Практика: твой пет-проект хранит данные в PostgreSQL вместо файла.
  3. Недели 6–7. HTTP и REST. Как программы общаются по сети: запрос и ответ, методы GET/POST/PUT/DELETE, коды ответа 200, 404, 500, формат JSON. REST — договорённость, как по этим правилам устроить API.
    Бесплатно: «Обзор протокола HTTP» на MDN (на русском) · встроенный в Java HttpClient (пакет java.net.http) — найди пример в документации JDK или спроси ИИ «объясни по шагам».
    Практика: из Java-программы получи JSON у любого открытого API (погода, курсы валют) и выведи пару полей.
  4. Недели 8–12. Spring Boot. Главный фреймворк Java-бэкенда. Собираешь проект на start.spring.io (выбираешь Gradle — он тебе знаком), пишешь контроллер с @RestController, подключаешь базу через Spring Data JPA, тестируешь на JUnit — тех же, что в модуле 17.
    Бесплатно: официальные пошаговые гайды «Building a RESTful Web Service» и «Accessing Data with JPA» (английский, каждый — на вечер).
    Практика: пет-проект как REST-сервис — например, у мини-банка GET /accounts отдаёт счета, а POST /transfers делает перевод.
Git — заодно и глубже

Всё, что делаешь по плану, сразу храни в Git и выкладывай на GitHub. Захочешь разобраться в Git глубже — бесплатная книга Pro Git на русском и игра-тренажёр Learn Git Branching с ветками на картинках.

Почему не начать сразу со Spring Boot — он же главный в вакансиях?

Spring Boot прячет под собой и SQL, и JDBC, и HTTP. Пока работает — кажется магией, а когда сломается, ты не поймёшь, что именно: запрос к базе, код ответа или твой класс. Знаешь, что «под капотом», — чинишь за минуты. Это тот же принцип, что в курсе: сначала println изнутри, потом удобные обёртки.

Идеи пет-проектов

Пет-проект (pet project, «домашний проект») — программа, которую пишешь для себя, без заказчика. Именно такие проекты показывают на собеседовании, когда опыта работы ещё нет. Выбери одну идею и развивай её вместе с планом выше: сначала консоль и файлы, потом база данных, потом REST на Spring Boot.

💰

Трекер расходов

Записываешь траты с категорией и датой, смотришь итоги за месяц и «куда ушли деньги». Пригодятся record, коллекции, стримы (группировка по категориям), файл CSV, тесты на подсчёт сумм.

📚

Домашняя библиотека

Книги, авторы, отметка «прочитано», поиск по автору и названию, статистика за год. Хороший первый проект для таблиц с JOIN: книги ↔ авторы.

✅

Список дел со сроками

Задачи с приоритетом и датой (LocalDate), сортировка, «что горит сегодня». Позже — REST API: добавить, отметить выполненной, удалить.

🏦

Мини-банк

Клиенты, счета, пополнение с комиссией, переводы с проверками, история операций. Всё, что было в курсе, ложится сюда: классы и инкапсуляция, исключения для «не хватает денег», коллекции, файлы, тесты на переводы.

🌦️

Погодный помощник

Программа спрашивает город, запрашивает открытый API погоды по HTTP, разбирает JSON и советует, брать ли зонт. Тренирует HTTP, Gradle-зависимости (библиотека для JSON) и обработку ошибок сети.

Как сделать проект «показательным»

Маленькие коммиты с понятными сообщениями, ветка под каждую фичу, тесты на главную логику, файл README.md: что умеет программа, как её запустить, пример работы. Работодатель смотрит не на размер, а на то, как проект сделан.

Свой проект — на GitHub, «Тренинг код» — каждый день

Выбрал идею из списка выше? Заведи под неё проект и сразу выложи на GitHub — это первая строчка твоего портфолио:

  1. Создай проект в IDEA с галочкой Create Git repository (урок 1.3) и проверь .gitignore: out/, .idea/workspace.xml — в истории им не место (урок 17.2).
  2. Добавь в корень файл README.md: пара строк о том, что умеет программа и как её запустить. Закоммить.
  3. ☰ → Git → GitHub → Share Project on GitHub (урок 17.3) — и проект на GitHub.
  4. Дальше развивай: тесты на JUnit для главной логики, перевод на Gradle, хранение в базе по плану выше. Каждый шаг — коммит и push.
🏋️

«Тренинг код» каждый день

Раздел «Тренинг код» никуда не делся. Решай 2–3 задачи в день, 20–30 минут. Каждый день понемногу работает лучше, чем три часа раз в неделю: синтаксис перестаёт быть препятствием, и голова свободна для новых тем.

🗣️

Объясняй вслух

Перед собеседованием пройдись по шпаргалке всех модулей и отвечай на вопросы вслух, своими словами. Не можешь объяснить — вернись к уроку.
