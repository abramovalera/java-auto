Файлы и пути

До сих пор всё, что знала программа, исчезало, как только она завершалась. Файлы — это память, которая переживает запуск. Но сначала научимся объяснять Java, где файл лежит.

Чтобы что-то прочитать или записать, Java должна знать, где лежит файл. Адрес файла называется путь (path). С него и начнём — на путях спотыкаются почти все новички.

Путь — адрес файла

Файлы на диске разложены по папкам (их ещё называют каталогами, directory), папки лежат в папках — получается дерево. Путь — это список папок, через которые надо пройти, чтобы добраться до файла.

Абсолютный путь
Полный адрес от самого корня: на Windows начинается с буквы диска (C:\…), на Linux и macOS — с косой черты (/home/…). Работает откуда угодно.
Относительный путь
Адрес «от того места, где я стою»: notes.txt, data/users.csv. Без диска и без косой черты в начале.
Рабочая папка
То самое «место, где стоит программа» (working directory). Относительные пути Java отсчитывает от неё.
Аналогия: как объяснить дорогу

Абсолютный путь — полный почтовый адрес: «Россия, Москва, ул. Ленина, д. 5, кв. 12». Письмо дойдёт, откуда бы его ни отправили.

Относительный — «вторая дверь налево». Удобно и коротко, но работает, только если ты знаешь, откуда считать. Встанешь в другом коридоре — попадёшь не туда.

Разделитель папок на Windows — обратный слэш \, на Linux и macOS — прямой /. Хорошая новость: Java понимает прямой слэш / на всех системах, так что пиши data/users.csv и не думай.

Предскажи: что напечатает System.out.println("C:\new\table.txt");?

Вспомни модуль 1: внутри строки \n — перевод строки, а \t — табуляция. Напечатается C:, новая строка, ew, табуляция, able.txt. Обратный слэш в Java-строке нужно удваивать: "C:\\new\\table.txt". Или просто писать "C:/new/table.txt" — так проще.

Где «стоит» твоя программа

Самый частый вопрос новичка: «Я записал файл notes.txt — где он?». Ответ: в рабочей папке. Узнать её можно прямо из программы:

import java.nio.file.Path;

public class WhereAmI {
    public static void main(String[] args) {
        Path here = Path.of("").toAbsolutePath();
        System.out.println("Рабочая папка: " + here);
        System.out.println("Файл будет тут: "
                + Path.of("notes.txt").toAbsolutePath());
    }
}
import java.nio.file.Path;

Всё современное про файлы живёт в пакете java.nio.file (nio — «new input/output», новый ввод-вывод). Его надо импортировать, как Scanner из java.util.

Path.of("")

Вызов статического метода of у класса Path (статический — значит, вызываем у самого класса, а не у объекта) с аргументом — пустой строкой. Метод возвращает объект Path с пустым путём — «прямо здесь», то есть рабочая папка.

.toAbsolutePath()

Вызываем метод toAbsolutePath у полученного объекта Path. Он возвращает новый, абсолютный путь: приклеивает впереди рабочую папку. Этим результатом инициализируется переменная here. Отличный способ узнать, куда на самом деле смотрит программа.

Ловушка IDEA: файл не в папке модуля!

Класс лежит в module-15, но рабочая папка при запуске из IDEA — корень проекта (workspace). Поэтому notes.txt появится рядом с папками module-01…module-15, а не внутри module-15.

Посмотреть и поменять рабочую папку: меню Run → Edit Configurations… → твой класс → поле Working directory. Обычно там $MODULE_WORKING_DIR$ или путь к проекту — оставь как есть.

Не видно нового файла?

IDEA иногда не замечает файл, созданный программой. Нажми File → Reload All from Disk (Ctrl+Alt+Y) — и он появится в дереве проекта. Текстовый файл можно открыть двойным кликом прямо в IDEA.

А сайт курса запускает твою программу в пустой временной папке. Поэтому в задачах модуля программа сначала сама создаёт нужный файл, а потом с ним работает. И мусор после проверки не остаётся.

Path.of — делаем путь

Путь в Java — объект класса Path. Создание объекта Path идёт не через new, а через вызов статического метода Path.of(…): этот метод-«фабрика» сам создаёт объект и возвращает его. Аргументом можно передать строку целиком или по кусочкам — Java сама вставит нужный разделитель:

Path config = Path.of("config.properties");             // файл в рабочей папке
Path users  = Path.of("data/users.csv");                // в подпапке data
Path photo  = Path.of("photos", "summer", "sea.png");   // по частям
Path abs    = Path.of("C:/Users/Misha/report.txt");     // абсолютный

System.out.println(photo);
System.out.println(photo.isAbsolute() + " " + abs.isAbsolute());
photos\summer\sea.png
false true

На Windows путь печатается с \, на Linux — с /. Сам объект один и тот же.

Важно: Path — только адрес

Создать объект Path.of("nope.txt") можно, даже если такого файла нет и никогда не было. Path — это бумажка с адресом, а не сам дом. Ошибка случится позже — когда попробуешь по этому адресу что-то прочитать.

🔎 Для любопытных: Paths.get и класс File

В старом коде и в статьях (в том числе на metanit) встречаются два «предка»:

  • Paths.get("a", "b") — то же самое, что Path.of("a", "b"). Path.of появился в Java 11 и короче, поэтому пишем его.
  • new File("notes.txt") — класс java.io.File, старейший способ (с Java 1.0). Умеет меньше и сообщает об ошибках хуже: например, метод delete() просто возвращает false, не объясняя причину. Встретишь File — знай, что file.toPath() превращает его в Path, а path.toFile() — обратно.

Разомнись: какие из этих путей абсолютные, а какие — относительные?

Что умеет Path

У объекта Path есть методы, чтобы разбирать и собирать адреса. Они не трогают диск — просто работают с текстом адреса. Вызываем такой метод у объекта Path, и он возвращает новый объект Path; исходный не меняется (Path, как и строка, неизменяемый).

Path save = Path.of("games/saves/slot1/save.dat");

System.out.println(save.getFileName());   // имя последней части
System.out.println(save.getParent());     // всё, кроме последней части
System.out.println(save.getNameCount());  // сколько частей

Path photos = Path.of("photos", "summer");
Path photo = photos.resolve("sea.png");                   // приклеить к папке
System.out.println(photo);
System.out.println(photo.resolveSibling("beach.png"));     // сосед по папке

Path messy = Path.of("data/../config/./app.properties");
System.out.println(messy.normalize());                    // убрать . и ..

Предскажи: что вернёт Path.of("notes.txt").getParent()?

null! В пути всего одна часть, «родителя» в самом адресе не записано. Это не значит, что у файла нет папки на диске — просто Path работает только с текстом адреса. Если вызвать метод у результата — получишь NullPointerException. Нужна настоящая папка — сначала toAbsolutePath().

Предскажи: на Windows Path.of("photos").resolve("C:/tmp/x.png") — что получится?

Просто C:\tmp\x.png. Если передать в метод resolve аргументом абсолютный путь, он побеждает: «зайти в папку» по полному адресу нельзя, поэтому метод возвращает сам этот адрес.

Проверь себя

Поговори с наставником

Напиши: «Я прошёл урок 15.1. Объясню своими словами, чем абсолютный путь отличается от относительного и где моя программа ищет notes.txt, — поправь меня».

Коротко

  • Файл живёт на диске и переживает завершение программы. В программах это данные, настройки, картинки, отчёты, сохранения игр.
  • Абсолютный путь — от корня диска, относительный — от рабочей папки. В IDEA рабочая папка — корень проекта, а не папка модуля.
  • Вызов статического метода Path.of("a", "b.txt") создаёт объект Path. Это только адрес: файла может и не быть.
  • Прямой слэш / работает везде; обратный в строке надо удваивать \\.
  • getFileName, getParent, resolve, toAbsolutePath, normalize — методы объекта Path: возвращают новый путь, не трогая диск.
