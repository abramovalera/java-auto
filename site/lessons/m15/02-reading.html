Чтение текстовых файлов

Адрес файла мы знаем. Теперь достанем, что внутри: целиком, по строкам или конвейером-стримом. И разберёмся, почему компилятор вдруг требует какой-то IOException.

⏱ 20 минут📖 Files.readString / readAllLines / lines🔍 трассировка

Повторение

Три способа прочитать файл

Для чтения есть класс-помощник Files (с s на конце) из того же пакета java.nio.file. Все его методы статические: вызываем их прямо у класса, объект Files создавать не нужно — Files.что-то(путь). Путь передаём аргументом, а метод возвращает прочитанное. Для текста — три главных:

МетодЧто возвращаетКогда брать
Files.readString(p)String — весь текст с переводами строк внутрифайл небольшой и нужен целиком: шаблон письма, JSON-ответ для сравнения
Files.readAllLines(p)List<String> — по строке в элементе, без \nнужно пройтись по строкам, знать их количество, взять строку по номеру
Files.lines(p)Stream<String> — строки по одной, ленивофайл большой (лог на гигабайт) или хочется сразу filter/map

Первое чтение

Создай файл руками: правый клик по корню проекта workspace → New → File → имя users.txt. Впиши три строки: anna, boris, vera. Теперь программа в module-15:

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public class ReadUsers {
    public static void main(String[] args) throws IOException {
        Path file = Path.of("users.txt");

        String all = Files.readString(file);
        System.out.println(all);

        List<String> users = Files.readAllLines(file);
        System.out.println("Пользователей: " + users.size());
        for (int i = 0; i < users.size(); i++) {
            System.out.println((i + 1) + ". " + users.get(i));
        }
    }
}
throws IOException

Метод main объявляет, что может выбросить IOException. Это обещание компилятору: «если при работе с файлом что-то пойдёт не так, я не ловлю ошибку здесь, а пропускаю её наверх». Без этих слов программа не скомпилируется — почему, разберём в следующем шаге.

Files.readString(file)

Вызываем статический метод readString у класса Files и передаём аргумент file. Метод открывает файл, читает всё, закрывает его и возвращает текст — этим значением инициализируется переменная all. Одна строчка вместо десяти, как писали раньше.

System.out.println(all)

Внутри строки all лежат и буквы, и символы перевода строки \n — поэтому она печатается в три строчки. А в списке из readAllLines переводы строк уже отрезаны.

Files.readAllLines(file)

Метод возвращает знакомый по модулю 13 List<String>, им инициализируется переменная users: size(), get(i), for-each — всё как обычно.

Предскажи: в файле в конце есть пустая строка (ты нажал Enter после vera ещё раз). Что покажет users.size()?

4: последний элемент списка — пустая строка "". Один Enter после последней строки — это просто конец строки, а второй создаёт ещё одну, пустую. В файлах с данными пустые строки — частая причина странных падений, поэтому их обычно пропускают: if (line.isBlank()) continue;.

Почему компилятор требует IOException

Убери throws IOException и нажми ▶. IDEA подчеркнёт readString красным, а компилятор скажет:

Вспомни модуль 12: IOException — checked-исключение. Компилятор видит, что метод readString объявлен с throws IOException, и требует от тебя решения: перехватить исключение в catch или объявить его в throws и передать дальше.

Аналогия: курьер

Ты заказываешь доставку. Курьер может не найти дом, дверь может быть заперта, лифт сломан — и курьер в этом не виноват, это внешний мир. Поэтому служба заранее спрашивает: «Если не застанем — оставить у соседей или вернуть?» Отказаться отвечать нельзя.

С файлом так же: его могли удалить, у программы может не быть прав, флешку выдернули. Это не ошибка в твоём коде (как NullPointerException), а ситуация, к которой надо быть готовым. Поэтому исключение checked.

Два способа ответить компилятору:

// Способ 1: передать наверх — подходит для учебных программ и тестов
public static void main(String[] args) throws IOException {
    List<String> users = Files.readAllLines(Path.of("users.txt"));
    System.out.println(users);
}

// Способ 2: поймать и сказать по-человечески
public static void main(String[] args) {
    try {
        List<String> users = Files.readAllLines(Path.of("users.txt"));
        System.out.println(users);
    } catch (IOException e) {
        System.out.println("Не удалось прочитать файл: " + e.getMessage());
    }
}

Набирать руками не обязательно: поставь курсор на красное и нажми Alt+Enter — IDEA предложит оба способа.

А если файла нет? При запуске (не при компиляции!) метод выбросит исключение — наследника IOException:

Сообщение NoSuchFileException: users.txt почти всегда значит одно: файл лежит не там, где его ищет программа. Не спорь с ней — напечатай Path.of("users.txt").toAbsolutePath() и сравни с тем, где файл на самом деле.

🔎 Для любопытных: в тестах обычно пишут throws

В JUnit-тесте (модуль 17) метод с файлами обычно объявляют так: void readsUsers() throws IOException. Если файл не прочитался, тест просто упадёт красным с понятным stack trace — это и нужно. Ловить исключение и печатать «ой» в тесте — плохая идея: тест станет зелёным, хотя проверка не прошла.

Обходим строки

Типичная задача: в файле список заказов магазина, надо посчитать отменённые. Пройди программу по шагам и впиши значение счётчика сам.

Files.lines — файл как стрим

readAllLines загружает весь файл в память. Для лога на пару гигабайт это плохо: памяти не хватит. Files.lines возвращает стрим: строки идут по одной, как по конвейеру, — и к нему сразу добавляются промежуточные операции filter, map и терминальные count, toList из модуля 14.

Path log = Path.of("run.log");

try (Stream<String> lines = Files.lines(log)) {
    List<String> errors = lines
            .filter(line -> line.contains("ERROR"))
            .map(String::trim)
            .toList();
    System.out.println("Ошибок: " + errors.size());
    errors.forEach(System.out::println);
}
Аналогия: грузовик и конвейер

readAllLines — привезти на склад весь грузовик коробок и только потом разбирать. Files.lines — конвейерная лента: коробки едут по одной, ненужные сразу сбрасываешь, а склад не переполняется.

Стрим из файла нужно закрыть

Пока стрим жив, файл открыт. Поэтому Files.lines вызывают в try-с-ресурсами (try-with-resources): ресурс — здесь стрим — объявляется и инициализируется в круглых скобках после try: try (Stream<String> lines = …) { … }. После закрывающей фигурной скобки Java закроет его автоматически, а с ним и файл. У readString и readAllLines такой заботы нет: они закрывают файл до того, как вернут результат. Подробно про «закрывать» — в уроке 15.4.

Предскажи: что выведет Files.lines(p).count() для файла из трёх строк — и что тут не так?

Выведет 3, но стрим не закрыт: файл останется открытым, пока программа работает. В маленькой программе незаметно, а в программе, которая работает сутками (например, на сервере), незакрытые файлы копятся, и однажды система скажет «слишком много открытых файлов». Правильно: try (var s = Files.lines(p)) { … s.count() … }.

Кодировка: почему бывают кракозябры

На диске нет букв — только байты (числа от 0 до 255). Кодировка — таблица, по которой байты превращаются в буквы. Сегодня почти везде UTF-8: латиница в ней занимает 1 байт, кириллица — 2.

  • Методы Files.readString, readAllLines, lines, writeString всегда работают в UTF-8, если не сказать иначе.
  • Можно указать кодировку явно вторым аргументом: Files.readAllLines(p, StandardCharsets.UTF_8). Так делают в рабочем коде, чтобы никто не гадал.
  • Если файл пришёл из старой Windows-программы в кодировке Windows-1251, читать его надо с Charset.forName("windows-1251"), иначе readString выбросит MalformedInputException («байты не похожи на UTF-8»).
В IDEA

Кодировка открытого файла видна в правом нижнем углу окна IDEA (UTF-8). Если там другое — щёлкни и выбери UTF-8.

Проверь себя

Поговори с наставником

Напиши: «Я прошёл урок 15.2. Спроси меня, когда брать readAllLines, а когда Files.lines, и почему IOException — checked».

Коротко

  • Files.readString — весь текст строкой, readAllLines — список строк, lines — ленивый стрим (закрывать в try-с-ресурсами). Все три — статические методы класса Files.
  • IOException — checked: файл зависит от внешнего мира. Нужно throws IOException или try-catch, иначе не скомпилируется.
  • NoSuchFileException — файл не там, где ищет программа. Смотри toAbsolutePath().
  • Файл — это байты, кодировка превращает их в буквы. По умолчанию Files работает с UTF-8.
