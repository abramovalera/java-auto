Работа с папками

Проверить, есть ли файл, найти все фотографии в папке, скопировать отчёт в архив, убрать за собой временные файлы. Всё это — снова класс Files и немного стримов.

⏱ 20 минут📂 exists, list, walk, copy, move, delete🧩 сборка кода

Повторение

Есть ли файл?

Перед чтением данных полезно проверить, что они на месте, — и упасть с понятным сообщением, а не со стектрейсом на полэкрана.

Path data = Path.of("data", "users.csv");

if (Files.notExists(data)) {
    System.out.println("Нет файла с данными: " + data.toAbsolutePath());
    return;
}
System.out.println("Это файл? " + Files.isRegularFile(data));
System.out.println("Это папка? " + Files.isDirectory(data));
System.out.println("Размер: " + Files.size(data) + " байт");
МетодОтвет
Files.exists(p) / Files.notExists(p)есть ли что-то по этому адресу
Files.isRegularFile(p)это обычный файл (не папка)
Files.isDirectory(p)это папка
Files.size(p)размер в байтах (выбрасывает IOException, если файла нет)

Все эти статические методы, кроме size, не выбрасывают исключений: если файла нет, они просто возвращают false.

Предскажи: папка reports существует. Что вернёт Files.exists(Path.of("reports"))? А Files.isRegularFile?

true и false. exists отвечает «есть ли хоть что-то» — папка тоже считается. Поэтому если нужен именно файл, проверяй isRegularFile.

Что лежит в папке: list и walk

Два статических метода, оба возвращают Stream<Path>, оба надо закрывать — поэтому их вызывают в try-с-ресурсами:

Path photos = Path.of("photos", "summer");

try (Stream<Path> files = Files.list(photos)) {
    List<String> names = files
            .filter(Files::isRegularFile)
            .map(p -> p.getFileName().toString())
            .filter(name -> name.endsWith(".png"))
            .sorted()
            .toList();
    System.out.println("Фотографий: " + names.size());
    names.forEach(System.out::println);
}
.filter(Files::isRegularFile)

Передаём в промежуточную операцию filter ссылку на статический метод Files.isRegularFile (модуль 14): остаются только файлы, папки отбрасываются.

p.getFileName().toString()

Тело лямбда-выражения с параметром p внутри map. В стриме лежат полные пути photos/summer/sea.png: вызываем у p метод getFileName() — он возвращает только имя, — а затем toString() превращает Path в String.

.sorted()

Промежуточная операция sorted обязательна, если важен порядок. list и walk возвращают файлы в том порядке, в каком их хранит система, — на твоём компьютере и на сервере он может быть разным.

Files.walk(папка) работает так же, только спускается во все подпапки. Глубину можно ограничить: Files.walk(папка, 2). Типичный пример — найти все .csv с данными в проекте, где бы они ни лежали.

Копировать и перемещать

Path report = Path.of("report.html");
Path archive = Path.of("archive");
Files.createDirectories(archive);

Path copy = archive.resolve(report.getFileName());        // archive/report.html
Files.copy(report, copy, StandardCopyOption.REPLACE_EXISTING);

Files.move(Path.of("draft.txt"), Path.of("final.txt"));  // переименовать
archive.resolve(report.getFileName())

Вызываем у archive метод resolve и передаём аргументом имя файла — метод возвращает путь archive/report.html. Вторым аргументом copy всегда указывают полный путь нового файла, а не папку. Скопировать «в папку archive» = скопировать в archive/report.html.

REPLACE_EXISTING

Без этой опции copy и move откажутся затирать существующий файл и выбросят FileAlreadyExistsException. Защита от случайной потери данных.

Files.move

Статический метод move переносит файл: первый аргумент — откуда, второй — куда. Если папка та же, а имя другое — это переименование. Отдельного метода rename нет.

Предскажи: запускаешь Files.copy(report, copy) без опций второй раз. Что будет?

Первый раз — успех. Второй раз archive/report.html уже есть — метод выбросит FileAlreadyExistsException. В IDEA, где программу запускают много раз, это классика. Лечение — REPLACE_EXISTING или удаление старой копии перед копированием.

Удалять

Без корзины

Files.delete удаляет насовсем, мимо корзины. Перед запуском программы, которая удаляет, дважды проверь путь — особенно если он абсолютный.

🗑️

Files.delete(p)

Нет файла — NoSuchFileException. Папка не пустая — DirectoryNotEmptyException.

🧹

Files.deleteIfExists(p)

Нет файла — не ошибка, вернёт false. Удобно для уборки «на всякий случай».

Удалить папку с содержимым одной командой нельзя. Приём: обойти дерево через walk и удалять с конца — сначала файлы, потом опустевшие папки. Обратная сортировка путей как раз ставит вложенное раньше родителя:

Предскажи: почему не написать короче — walk.sorted(…).forEach(Files::delete);?

Не скомпилируется. Терминальная операция forEach принимает аргументом лямбда-выражение (или ссылку на метод) функционального интерфейса Consumer, а его метод accept не объявлен с throws IOException. Выбросить checked-исключение из тела лямбды наружу нельзя. Компилятор скажет incompatible thrown types IOException in functional expression (а для лямбды p -> Files.delete(p) — знакомое unreported exception java.io.IOException). Либо try-catch внутри лямбды, либо обычный цикл, как выше. Это частый вопрос на собеседованиях: «почему checked-исключения плохо дружат с лямбдами».

Временные файлы

Программе часто нужен файл «на минутку»: записать, проверить, выкинуть. Класть его в проект — мусорить. Для этого есть системная папка временных файлов:

Path tmpFile = Files.createTempFile("report-", ".txt");
Path tmpDir  = Files.createTempDirectory("import-");

System.out.println(tmpFile);
System.out.println(tmpDir);

Files.writeString(tmpFile, "черновик отчёта");
Files.deleteIfExists(tmpFile);
C:\Users\Misha\AppData\Local\Temp\report-8135520926471530811.txt
C:\Users\Misha\AppData\Local\Temp\import-4417932013577349002
  • Java сама придумывает уникальное имя: приставка + случайное число + окончание. Две программы, запущенные одновременно, не помешают друг другу.
  • Где эта папка, подскажет System.getProperty("java.io.tmpdir").
  • Сама по себе временная папка не чистится — убирать за собой всё равно надо.

Именно так работает проверка задач на сайте: сервер создаёт временную папку, запускает в ней твою программу, а потом удаляет папку целиком. А в JUnit (модуль 17) есть аннотация @TempDir: тест получает чистую временную папку и уборку за собой — бесплатно.

Коротко

  • exists, isRegularFile, isDirectory — проверки без исключений; size — размер в байтах.
  • Files.list — один уровень, Files.walk — всё дерево вместе с самой папкой. Оба — стримы: закрывать и сортировать.
  • copy/move: второй аргумент — полный путь нового файла; затереть — REPLACE_EXISTING.
  • delete — насовсем; непустую папку — через walk в обратном порядке и цикл.
  • Checked-исключение нельзя выбросить из тела лямбды наружу — поэтому файловые операции часто пишут обычным циклом.
  • createTempFile/createTempDirectory — уникальные временные файлы «на минутку».
