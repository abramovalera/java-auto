Не путай: три разных «потока»

Слово «поток» в Java означает три совсем разные вещи. По-английски у двух из них одно и то же слово stream, а третье — thread, но по-русски все три часто зовут «потоком». Разведём их сразу, иначе дальше будет каша:

Поток ввода-вывода — труба, по которой на кухню поступают продукты. Стрим — конвейер, на котором продукты моют, режут и сортируют. Поток выполнения — повар; когда поваров несколько, они готовят одновременно.

В этом уроке «поток» — всегда труба ввода-вывода. Подсказка — имя класса: …InputStream, …OutputStream, …Reader, …Writer из пакета java.io.

Поток ввода-вывода — это труба

Поток ввода-вывода (I/O stream) — это последовательность байтов, которая течёт по одному, как вода по трубе. С одной стороны — источник (файл, сеть, клавиатура), с другой — программа. Или наоборот: программа → приёмник (файл, экран).

Ты уже пользовался потоками ввода-вывода, не зная этого:

  • System.in — это InputStream: байты с клавиатуры. new Scanner(System.in) — создание объекта Scanner: конструктору передаём аргументом System.in, и сканер подключается к трубе как удобный «кран».
  • System.out — PrintStream, наследник OutputStream: байты в консоль.

Прочитаем файл hi.txt с текстом Hi! по одному байту:

try (InputStream in = Files.newInputStream(Path.of("hi.txt"))) {
    int b;
    while ((b = in.read()) != -1) {
        System.out.print(b + " ");
    }
}
72 105 33

Буквы H, i, ! на диске — просто числа 72, 105, 33. Метод read() возвращает следующий байт, а когда труба кончилась — −1. Поток in объявлен в скобках после try — это try-с-ресурсами, ниже разберём, зачем.

🔎 Для любопытных: почему read() возвращает int, а не byte

Байт принимает 256 значений (0…255), и все они могут встретиться в файле. Нужен 257-й сигнал «конец» — поэтому тип шире: int, а конец — -1, которого среди байтов нет. Классический вопрос с собеседования.

Байты и символы

Байты — это хорошо для картинок, фото, архивов. Но текст удобнее читать символами: кириллическая буква в UTF-8 занимает 2 байта, и собирать её из байтов вручную никто не хочет. Поэтому в пакете java.io две пары классов:

Запомни одно правило: …Stream — байты, …Reader и …Writer — символы. Для текста почти всегда нужны Reader и Writer — например, BufferedWriter из урока 15.3 и BufferedReader из следующего шага.

🔎 Для любопытных: трубы с насадками (декоратор)

Между семьями есть мост: класс InputStreamReader берёт трубу с байтами и по таблице кодировки собирает из них символы. Например, так Scanner превращает байты клавиатуры в буквы.

В старом коде потоки собирают как сантехнику: берут основную трубу и навинчивают на неё насадки:

new BufferedReader(new InputStreamReader(new FileInputStream("a.txt"), StandardCharsets.UTF_8))

Объекты создаются изнутри наружу, и каждый передаётся аргументом в конструктор следующего: труба из файла → переходник «байты → символы» → накопительный бак с readLine(). Такой приём называется обёртка, или паттерн декоратор: каждая насадка добавляет одну способность. Тебе писать так не нужно — Files.newBufferedReader(путь) собирает ту же цепочку за тебя.

BufferedReader: ведром, а не каплями

Каждое обращение к диску — дорогое: это как сходить к колодцу. Если брать воду по капле, будешь ходить вечность. Буфер — ведро: поток зачерпывает сразу кусок (обычно 8 КБ), а программа берёт из ведра сколько нужно. Ведро кончилось — новый поход к колодцу. BufferedWriter из урока 15.3 работает так же, только в обратную сторону: копит текст в ведре и выливает на диск целиком.

BufferedReader вдобавок умеет читать строку целиком — метод readLine(). Когда строки кончились, он возвращает null.

try (BufferedReader br = Files.newBufferedReader(Path.of("users.csv"))) {
    String line;
    int n = 0;
    while ((line = br.readLine()) != null) {
        n++;
        System.out.println(n + ": " + line);
    }
}
Files.newBufferedReader(путь)

Современный способ: вызов статического метода newBufferedReader открывает файл и возвращает объект BufferedReader, сразу в UTF-8. Им инициализируется переменная br, объявленная в скобках после try. В старом коде объект создают вручную: new BufferedReader(new FileReader("users.csv")) — результат тот же.

(line = br.readLine()) != null

Два дела в одном условии: вызываем br.readLine(), присваиваем возвращённую строку переменной line и сравниваем результат присваивания с null. Скобки обязательны. Идиома, которую встретишь в любом старом коде.

Закрывай кран

Открытый поток держит файл: операционная система выделила под него ресурс. Пока поток не закрыт:

  • на Windows такой файл нельзя удалить или переименовать — «файл занят другой программой»;
  • открытых файлов у программы ограниченное число — в программе, которая работает сутками, незакрытые копятся, и всё падает с Too many open files;
  • при записи через буфер данные лежат в «ведре» и попадают на диск только при flush() или close(). Не закрыл — файл может остаться пустым.
Аналогия: кран

Открыл кран, набрал воды — закрой. Иначе течёт вода и растёт счёт, а соседи снизу (другие программы) страдают. try-с-ресурсами (try-with-resources) — кран с датчиком: отошёл от раковины — закрылся сам, даже если ты убежал в панике (выброшено исключение).

BufferedWriter w = Files.newBufferedWriter(Path.of("report.txt"));
w.write("Все заказы оплачены");
// забыли w.close()

Программа завершится, а report.txt окажется пустым: текст остался в буфере. Правильно — объявить ресурс в круглых скобках после try (try-с-ресурсами): при выходе из блока Java сама вызовет у него close():

try (BufferedWriter w = Files.newBufferedWriter(Path.of("report.txt"))) {
    w.write("Все заказы оплачены");
    // на выходе из блока Java сама вызовет w.close():
    // буфер сбросится на диск, файл закроется
}

В скобках после try можно объявить любой объект, класс которого реализует интерфейс AutoCloseable — то есть у него есть метод close(). Все потоки, читатели, писатели и Scanner такие, а, например, String — нет. Ресурсов можно объявить несколько через ; — тогда запомни два правила, их любят спрашивать на собеседованиях:

  1. закрываются они в обратном порядке: последний открытый — первым;
  2. закрытие происходит до блока catch: когда исключение перехвачено, краны уже закрыты.
🔎 Для любопытных: свой «кран» с AutoCloseable — проверим порядок закрытия

Сделаем класс, который реализует AutoCloseable и печатает, когда его открыли и закрыли:

class Tap implements AutoCloseable {
    private final String name;
    Tap(String name) { this.name = name; System.out.println("открыт " + name); }
    @Override
    public void close() { System.out.println("закрыт " + name); }
}

public class TapDemo {
    public static void main(String[] args) {
        try (Tap a = new Tap("A"); Tap b = new Tap("B")) {
            System.out.println("работаем");
            throw new IllegalStateException("авария");
        } catch (IllegalStateException e) {
            System.out.println("поймали: " + e.getMessage());
        }
    }
}

работаем

закрыт A
поймали: авария

Видно оба правила: B закрыт раньше A (как матрёшку: сначала закрываешь внутреннюю), и оба закрыты ещё до catch.

Старые классы: FileReader, FileWriter и FileNotFoundException

В старом коде и в статьях файлы открывают не через Files, а создают объекты классов из java.io оператором new. Узнать их стоит — встретишь обязательно:

// чтение построчно — как Files.newBufferedReader
try (BufferedReader br = new BufferedReader(new FileReader("users.txt"))) {
    System.out.println(br.readLine());
}

// запись — старое содержимое стирается
try (FileWriter w = new FileWriter("log.txt")) {
    w.write("новый журнал\n");
}

// дописывание: второй аргумент true — «пиши в конец»
try (FileWriter w = new FileWriter("log.txt", true)) {
    w.write("заказ 1: оплачен\n");
}
new FileWriter("log.txt")

Создаём объект FileWriter, конструктору передаём имя файла. Как writeString без опций: файла нет — создаст, есть — сотрёт старое.

new FileWriter("log.txt", true)

Второй аргумент конструктора — append («дописывать»). true — то же самое, что пара CREATE, APPEND из урока 15.3: файла нет — создаст, есть — допишет в конец. С false — перезапишет.

w.write("…\n")

Метод write у FileWriter, как и у BufferedWriter, пишет текст как есть — перевод строки ставим сами.

Предскажи: программу с new FileWriter("log.txt", true), которая пишет одну строку, запустили три раза. А если без true?

С true в файле три строки — по одной от каждого запуска. Без второго аргумента — одна: каждый запуск стирает файл и пишет заново.

Если файла нет, старые классы бросают не NoSuchFileException, а своё исключение — FileNotFoundException:

  • FileNotFoundException (старые классы) и NoSuchFileException (класс Files) — оба наследники IOException. Поэтому catch (IOException e) поймает любое из них.
  • FileWriter тоже бросает FileNotFoundException — когда нет папки для файла (лечится тем же Files.createDirectories) или файл нельзя открыть на запись.
  • Лечение то же, что в уроке 15.2: напечатай toAbsolutePath() и проверь, где на самом деле лежит файл.

Scanner для файла — и чем он отличается от BufferedReader

Знакомый Scanner умеет читать не только клавиатуру, но и файл: при создании объекта передаём конструктору аргументом объект Path. Удобно, когда в файле числа: nextInt сам разберёт их.

// в файле steps.txt: 340 1250 87 410
// (шаги за четыре прогулки, через пробелы или по строкам)
try (Scanner sc = new Scanner(Path.of("steps.txt"))) {
    int total = 0;
    while (sc.hasNextInt()) {
        total += sc.nextInt();
    }
    System.out.println("Всего: " + total + " шагов");
}
Всего: 2087 шагов

Предскажи: в файле steps.txt одна строка 340 1250. Что вернёт br.readLine(), а что — sc.nextInt()?

readLine() вернёт всю строку "340 1250" — это String, сложить его с числом не выйдет: придётся сделать split(" ") и Integer.parseInt. А nextInt() вернёт int 340, следующий вызов — 1250.

А Scanner(System.in) закрывать не надо

Вызов close() у Scanner закрывает и трубу под ним. Для файла — то, что нужно. А закроешь Scanner(System.in) — закроется сама клавиатура для программы, и новый Scanner уже ничего не прочитает. Правило: закрывай то, что сам открыл. System.in открывал не ты.

🔎 Для любопытных: ресурсы — файлы внутри программы

Ресурс — это файл с данными (настройки, картинка, список городов), который лежит не где-то на диске, а внутри самого проекта, рядом с кодом, и при сборке упаковывается вместе с программой. В проекте со сборщиком Gradle (модуль 17) для них есть папка src/main/resources.

По обычному пути Path.of(…) ресурс не найти: программу могут запустить из любой папки, а файл лежит внутри собранного архива. Поэтому его просят у самой программы: getClass().getResourceAsStream("/users.csv"). Метод возвращает InputStream — трубу с байтами (или null, если ресурса нет). Дальше как обычно: обернуть в BufferedReader через InputStreamReader с UTF-8 и закрыть в try-с-ресурсами.

🔎 Для любопытных: сериализация — объект в байты

Есть потоки, которые пишут в файл целый объект: ObjectOutputStream.writeObject(obj) и обратно ObjectInputStream.readObject(). Класс должен реализовать пустой интерфейс-метку Serializable, а поля, которые сохранять не надо (пароль, кеш), помечают словом transient.

Сегодня встроенную сериализацию почти не используют (она медленная и небезопасная), объекты сохраняют в JSON. Но вопрос «что такое transient» на собеседованиях ещё бывает.

Поговори с наставником

Напиши: «Я прошёл урок 15.4. Спроси меня, чем стрим, поток ввода-вывода и поток выполнения отличаются друг от друга, зачем закрывать потоки и в каком порядке закрывает try-with-resources».

Коротко

  • «Поток» в Java — три разные вещи: стрим (конвейер из модуля 14), поток ввода-вывода (труба к файлу — этот урок) и поток выполнения (Thread, модуль 16).
  • Поток ввода-вывода — труба с байтами: InputStream в программу, OutputStream из неё. Для текста — Reader/Writer.
  • read() возвращает −1 в конце, readLine() — null.
  • Буфер — ведро: меньше походов к диску. BufferedReader.readLine() читает строку целиком.
  • Потоки надо закрывать: try-с-ресурсами закрывает сам, в обратном порядке и до catch. Не закрыл буферизованную запись — файл может остаться пустым.
  • Старые классы: new FileWriter(файл, true) дописывает в конец; нет файла — FileNotFoundException.
  • Scanner разбирает числа и слова (удобно для клавиатуры и маленьких файлов), BufferedReader быстро читает строки (для больших файлов). System.in не закрывай.
