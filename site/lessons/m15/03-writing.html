Запись в файл

Программа научилась читать. Теперь пусть оставляет следы: отчёт за день, журнал, результат расчёта. Главное — не стереть случайно то, что уже было в файле.

⏱ 20 минут✍️ writeString / write / APPEND🧩 сборка кода

Повторение

writeString и write

Запись — зеркало чтения. Тот же класс Files, два главных статических метода:

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;

public class SaveReport {
    public static void main(String[] args) throws IOException {
        Path summary = Path.of("summary.txt");
        Files.writeString(summary, "Заказов: 12, отменено 2\n");

        Path cancelled = Path.of("cancelled.txt");
        List<String> names = List.of("кофемашина", "пылесос");
        Files.write(cancelled, names);

        System.out.println(Files.readString(summary));
        System.out.println(Files.readAllLines(cancelled));
    }
}
Files.writeString(путь, текст)

Вызов статического метода writeString: первым аргументом передаём путь, вторым — текст, и метод записывает эту строку в файл. Файла нет — создаст. Есть — сотрёт старое содержимое и запишет новое. Перевод строки сам не добавляет: нужен — пиши \n.

Files.write(путь, список)

Статический метод write получает аргументами путь и список и записывает список строк: каждая строка — на своей строчке файла, после каждой Java ставит перевод строки. Удобно для коллекций из модуля 13.

throws IOException

Запись тоже может сорваться: диск полон, нет прав, папки нет. Поэтому методы записи тоже объявлены с throws IOException — исключение снова checked.

Предскажи: почему в выводе после «отменено 2» пустая строка?

В файле текст заканчивается на \n, а println добавляет ещё один перевод строки. Два перевода подряд — одна пустая строка.

Перезапись или дописывание

Запусти программу ниже дважды и загляни в log.txt. Сколько там строк?

Path log = Path.of("log.txt");
Files.writeString(log, "заказ 1: оплачен\n");
Files.writeString(log, "заказ 2: отменён\n");

Одна: заказ 2: отменён. Каждый writeString по умолчанию начинает файл с чистого листа. Первая запись стёрта второй.

Аналогия: доска и тетрадь

Обычная запись — школьная доска: перед новой темой её вытирают целиком. APPEND — тетрадь: каждая новая запись идёт на следующую строку, старое остаётся.

Чтобы дописывать, передай методу дополнительными аргументами опции открытия — константы из StandardOpenOption:

import java.nio.file.StandardOpenOption;
…
Path log = Path.of("log.txt");
Files.writeString(log, "заказ 1: оплачен\n",
        StandardOpenOption.CREATE, StandardOpenOption.APPEND);
Files.writeString(log, "заказ 2: отменён\n",
        StandardOpenOption.CREATE, StandardOpenOption.APPEND);
ОпцияСмысл
CREATEфайла нет — создать
APPENDписать в конец, не стирая
TRUNCATE_EXISTINGобрезать файл до нуля перед записью (по умолчанию)
CREATE_NEWсоздать новый, а если файл уже есть — ошибка FileAlreadyExistsException. Защита от случайной перезаписи

Без опций Java подставляет CREATE, TRUNCATE_EXISTING, WRITE — отсюда и «доска».

Предскажи: файла log.txt нет, пишем с одной опцией APPEND (без CREATE). Что будет?

Метод выбросит исключение NoSuchFileException. Как только ты передал опции сам, Java больше ничего не подставляет — а APPEND умеет только дописывать в существующий файл. Поэтому пара CREATE, APPEND — устойчивое выражение.

Ловушка в IDEA: лог растёт с каждым запуском

Программа дописывает в log.txt с APPEND. Запустил 5 раз — в файле строки от всех пяти запусков. Если нужен лог только этого запуска, в начале программы очисти файл: Files.writeString(log, "") — обычная запись без опций как раз обнуляет его.

Собери журнал заказов

Программа должна начать журнал с чистого листа, дописать в него две строки (сначала про чайник, потом про утюг) и напечатать, сколько строк получилось. Расставь строки по порядку.

Заметил? Здесь APPEND без CREATE работает: файл к этому моменту уже создан первой строкой writeString(log, "").

Нет папки — нет файла

Программы любят раскладывать файлы по папкам: photos/summer/sea.png, reports/2026-11-27/summary.txt. Но writeString не создаёт папки. Папки reports нет — метод выбросит NoSuchFileException.

Path report = Path.of("reports", "shop", "summary.txt");

// reports/shop — со всеми родителями
Files.createDirectories(report.getParent());
Files.writeString(report, "Заказов: 5, все оплачены\n");

System.out.println("Записано: " + report.toAbsolutePath());
report.getParent()

Вызываем метод getParent у объекта report; он возвращает папку, где должен лежать файл: reports/shop. Это возвращаемое значение сразу передаём аргументом в createDirectories. Метод Path из урока 15.1 пригодился.

Files.createDirectories(…)

Статический метод получает путь аргументом и создаёт папку и всех недостающих родителей. Если папка уже есть — спокойно ничего не делает. Можно вызывать хоть каждый раз.

📁

createDirectory

Ровно одну папку. Родителя нет — NoSuchFileException. Папка уже есть — FileAlreadyExistsException.

🗂️

createDirectories

Всю цепочку. Уже есть — не ошибка. На практике почти всегда берут его.

Предскажи: Files.createDirectories(Path.of("notes.txt").getParent()) — что будет?

getParent() у пути из одной части — null, и вызов createDirectories(null) выбросит NullPointerException. Если файл пишется прямо в рабочую папку, создавать ничего не нужно — она уже есть.

Переводы строк и PrintWriter

Мелочь, о которой спотыкаются: на Windows конец строки в файле — два символа \r\n, на Linux и macOS — один \n.

  • Files.write(путь, список) ставит после каждой строки System.lineSeparator() — перевод строки той системы, где запущена программа.
  • Files.writeString пишет ровно то, что дали. Написал \n — будет \n.
  • При чтении разницы нет: readAllLines и lines понимают оба варианта.

Если строк много и их удобно печатать как в консоль — есть старый знакомый println, только в файл. Это класс PrintWriter:

try (PrintWriter out = new PrintWriter(
        Files.newBufferedWriter(Path.of("table.txt")))) {
    out.println("Товар           | Цена");
    out.printf("%-15s | %d руб.%n", "чайник", 340);
    out.printf("%-15s | %d руб.%n", "кофемашина", 1250);
}

Те же println и printf, что у System.out, только текст уходит в файл. Объект PrintWriter создаётся в скобках try (…) — это уже знакомый try-с-ресурсами: после блока файл закроется автоматически. Подробнее про это и про BufferedWriter — в следующем уроке про потоки.

Кстати, System.out — это объект PrintStream, близкий родственник PrintWriter. Ты с первого урока пишешь в «файл», который называется консоль!

Коротко

  • Files.writeString(путь, текст) и Files.write(путь, список) — статические методы записи. По умолчанию файл перезаписывается.
  • Дописать в конец — StandardOpenOption.CREATE, StandardOpenOption.APPEND. Без CREATE на несуществующем файле — ошибка.
  • Папки сами не появляются: Files.createDirectories(file.getParent()) перед записью.
  • Files.write ставит системный перевод строки, writeString пишет ровно то, что дали.
  • PrintWriter — println/printf в файл.
