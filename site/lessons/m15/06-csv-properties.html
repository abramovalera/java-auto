Практика: CSV и properties

Два формата, которые в программах встречаются каждый день: таблица данных в CSV и файл настроек в .properties. Научимся разбирать оба — и решим задачу по шаблону Мастерской.

⏱ 25 минут🛠 Мастерская🔍 трассировка

Повторение

CSV — таблица в текстовом файле

CSV (comma-separated values, «значения через запятую») — самый простой формат таблицы. Каждая строка файла — строка таблицы, ячейки разделены запятой. Первая строка обычно — заголовок с названиями колонок. Такой файл открывается и в Excel, и в IDEA, и в Блокноте.

login,password,role
anna,qwerty1,admin
boris,secret22,manager
vera,pass333,user

Так хранят списки пользователей, товаров, оценок: программа читает файл и обрабатывает каждую строку. Добавил строку в файл — у программы появился ещё один пользователь, а код трогать не нужно.

Разбираем CSV в объекты

record User(String login, String password, String role) { }

public class LoadUsers {
    public static void main(String[] args) throws IOException {
        List<String> lines = Files.readAllLines(Path.of("users.csv"));

        List<User> users = lines.stream()
                .skip(1)                                // заголовок пропускаем
                .filter(line -> !line.isBlank())        // пустые строки тоже
                .map(line -> line.split(","))
                .map(c -> new User(c[0].trim(), c[1].trim(), c[2].trim()))
                .toList();

        System.out.println("Загружено: " + users.size());
        users.forEach(u -> System.out.println(u.login() + " → " + u.role()));
    }
}
.skip(1)

Промежуточная операция skip(1) пропускает первый элемент стрима. Первая строка — заголовок login,password,role. Если не пропустить, получится пользователь с логином «login».

.filter(line -> !line.isBlank())

Передаём в filter лямбда-выражение с параметром line: оно возвращает true только для непустых строк. Пустая строка в конце файла — частый гость. "".split(",") вернёт массив из одной ячейки, и обращение к c[1] выбросит ArrayIndexOutOfBoundsException.

c[0].trim()

Люди любят ставить пробелы после запятой: anna, qwerty1. Метод trim возвращает строку без пробелов по краям.

Здесь конвейер из модуля 14 работает со списком строк: промежуточные операции skip, filter, map и терминальная toList. То же самое можно сделать и через Files.lines в try-с-ресурсами.

Подводные камни CSV

Пустые ячейки в конце. "anna,,".split(",") вернёт массив длины 1: пустые хвосты split выбрасывает. Нужны все ячейки — split(",", -1).

Точка с запятой. Русский Excel сохраняет CSV с разделителем ;, потому что запятая у нас — в дробных числах. Посмотри на файл, прежде чем писать split.

Запятая внутри значения — "Иванов, Иван",admin — простым split не разобрать. Для таких файлов берут библиотеку (OpenCSV) или готовую поддержку в JUnit: @CsvFileSource.

Предскажи: что выведет System.out.println("a,b,,".split(",").length + " " + "a,b,,".split(",", -1).length);?

2 4. Без второго аргумента пустые строки в конце отбрасываются, с -1 — сохраняются все четыре ячейки: a, b, "", "".

Мастерская: сумма по колонке

Задача: в файле orders.csv заказы с колонками id,product,price,qty. Посчитать выручку — сумму price × qty по всем заказам. Решаем по шаблону Мастерской, а не сразу кодом.

  1. Пойми задачу. Вход — файл: заголовок и строки заказов. Выход — одно число. Примеры: два заказа 30×2 и 250×1 → 310. Граничный: файл только с заголовком → 0.
  2. Реши руками. Пропускаю первую строку. Беру строку 1,pen,30,2: режу по запятой, третья ячейка — цена 30, четвёртая — количество 2, 30 × 2 = 60, запоминаю. Следующая: 250 × 1 = 250, прибавляю к 60 → 310. Повторялось: «разрезать — взять две ячейки — перемножить — прибавить».
  3. Роли переменных. i — шагающая (номер строки, с 1, чтобы пропустить заголовок). total — накопитель. cells, price, qty — временные, живут один виток.
  4. Псевдокод. «прочитать все строки; total = 0; для каждой строки, кроме первой: разрезать по запятой, price = ячейка 2, qty = ячейка 3, total += price × qty; напечатать total».
  5. Код — перевод псевдокода строка в строку (ниже).
  6. Трассировка. Пройди код по шагам и впиши значения.

Заметь: Мастерская не про файлы. Файл дал нам список строк — дальше та же сумма в цикле, что в модулях 5–6. Сначала свести задачу к знакомой, потом решать.

config.properties — настройки без перекомпиляции

Адрес сервера, язык, громкость звука — плохая идея зашивать в код. Захотел другой язык — перекомпилируй программу? Нет: настройки кладут в файл properties, формат «ключ=значение»:

# настройки игры
server.url=https://game.example.com
language=ru
sound.volume = 10
player.name=Javik
  • Строки с # (или !) — комментарии, пустые строки пропускаются.
  • Пробелы вокруг = не важны: ключ sound.volume, значение 10.
  • Точки в ключах — просто договорённость для группировки (player.name, player.color), для Java это обычные символы.

Читает такой файл класс java.util.Properties — по сути словарь String → String, как HashMap из модуля 13:

Properties config = new Properties();
try (BufferedReader reader = Files.newBufferedReader(
        Path.of("config.properties"))) {
    config.load(reader);
}

String serverUrl = config.getProperty("server.url");
// "en" — значение по умолчанию
String language = config.getProperty("language", "en");
int volume = Integer.parseInt(config.getProperty("sound.volume", "5"));
String proxy = config.getProperty("proxy");

System.out.println("Сервер: " + serverUrl);
System.out.println("Язык: " + language + ", громкость " + volume);
System.out.println("Прокси: " + proxy);
Сервер: https://game.example.com
Язык: ru, громкость 10
Прокси: null
config.load(reader)

Вызываем у объекта config метод load и передаём аргументом reader: метод разбирает файл и складывает все пары в объект. Сам reader возвращает статический метод Files.newBufferedReader, а объявлен он в try-с-ресурсами — после блока файл закроется. Reader в UTF-8, кириллица в значениях не сломается.

getProperty("language", "en")

Второй аргумент — значение по умолчанию: нет такого ключа — метод вернёт его. Без второго аргумента метод вернёт null (как у proxy).

Integer.parseInt(…)

В properties всё — строки. Число нужно разобрать самому: вызываем статический метод Integer.parseInt, он возвращает int, и этим значением инициализируется переменная volume.

Аналогия: пульт от телевизора

Код программы — телевизор, конфиг — пульт. Чтобы переключить канал (язык ru → en), не разбирают телевизор, а нажимают кнопку: правят одну строку language.

Предскажи: в файле ключ записан дважды — language=ru, ниже language=en. Что вернёт getProperty("language")?

en. Как в Map.put: повторный ключ перезаписывает старое значение, побеждает последнее.

🔎 Для любопытных: как это устроено в настоящих проектах
  • Конфиг лежит в папке ресурсов проекта src/main/resources (появится в модуле 17 вместе со сборщиком Gradle) и читается так: getClass().getResourceAsStream("/config.properties") — это InputStream из урока 15.4.
  • Осторожно: Properties.load(InputStream) читает байты в старой кодировке ISO-8859-1, и кириллица превращается в кракозябры. Оборачивай поток в new InputStreamReader(in, StandardCharsets.UTF_8).
  • Часто значение из файла можно перебить при запуске: System.getProperty("server.url", config.getProperty("server.url")). Тогда ту же программу можно запустить с другим сервером флагом -Dserver.url=https://backup.example.com.
  • Записать настройки обратно — config.setProperty(…) и config.store(writer, "комментарий"). В начало файла store добавит строку с датой.

Напиши: «Я прошёл урок 15.6. Дай мне CSV-файл из 4 строк и задачу на него — я сначала распишу план по шаблону Мастерской, а код потом».

Коротко

  • CSV — таблица в тексте: строка → split(",") → ячейки → объект. Заголовок пропусти, пустые строки отфильтруй, значения trim.
  • Пустые хвосты split выбрасывает — split(",", -1). Сложные CSV (запятые в кавычках) — библиотекой.
  • Properties — файл «ключ=значение»; load(reader), getProperty(ключ) или getProperty(ключ, поУмолчанию). Всё — строки.
  • Настройки в файле — стандарт для любых программ: меняешь файл, а не код.
  • Задача с файлом = прочитать в список + знакомый алгоритм. Шаблон Мастерской работает и здесь.
