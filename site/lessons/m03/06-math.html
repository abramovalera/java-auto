Класс Math — калькулятор в кармане

Корень, степень, модуль, округление, случайное число — писать всё это самому не нужно. В Java есть готовый «инженерный калькулятор» — класс Math. Разбираемся, какие кнопки на нём есть и где он подкладывает свинью.

Как пользоваться Math

Math — это класс из стандартной библиотеки Java (из того самого пакета java.lang, что и System). Импортировать его не нужно — он доступен всегда. Внутри — готовые методы: маленькие программки, которые что-то считают и возвращают результат.

double root = Math.sqrt(16);      // 4.0
System.out.println(root);
System.out.println(Math.max(3, 8));   // 8 — можно сразу печатать
Math

Имя класса — «чей калькулятор».

.sqrt

Точка и имя метода — «какая кнопка». sqrt — square root, квадратный корень.

(16)

В скобках — аргументы: значения, которые передаём методу на вход. Если их несколько — через запятую.

double root =

Вызов метода — это выражение: метод возвращает значение (4.0). Им можно инициализировать переменную, как здесь root, напечатать его или подставить в другое выражение.

Аналогия: кофемашина

Кладёшь зёрна (аргументы), нажимаешь кнопку «эспрессо» (имя метода) — получаешь чашку кофе (возвращаемое значение). Как она устроена внутри, знать не обязательно. Свои такие «машины» — методы — научимся делать в модуле 7.

Ловушки типов

Самое коварное в Math — тип результата. Значки ⚠️ в таблице не просто так:

int power = Math.pow(2, 10);          // ошибка компиляции!
int power2 = (int) Math.pow(2, 10);   // так можно: 1024

int r = Math.round(2.7);              // ошибка компиляции!
long r2 = Math.round(2.7);            // так можно: 3
int r3 = (int) Math.round(2.7);       // и так: 3
Traps.java:3: error: incompatible types: possible lossy conversion from double to int
        int power = Math.pow(2, 10);
                            ^
Traps.java:6: error: incompatible types: possible lossy conversion from long to int
        int r = Math.round(2.7);
                          ^
2 errors

Это текст javac (его покажет проверка на сайте). Число после двоеточия — номер строки в целом файле: в полном файле ниже (с class и main) это строки 3 и 6. А в IDEA обе ошибки видны прямо в редакторе, ещё до запуска:

  • pow, sqrt, floor, ceil всегда возвращают double — даже если ответ «ровный». Поэтому Math.floor(2.9) печатается как 2.0.
  • round для double возвращает long. Присвоить значение long переменной int без приведения нельзя — вдруг не влезет (помнишь из модуля 2?).
  • abs, max, min возвращают тот же тип, что у аргументов: Math.max(3, 8) → int 8, а Math.max(3, 7.5) → double 7.5.
Что выведет System.out.println(Math.ceil(7 / 2)); ?

3.0, а не 4.0! Сначала вычисляется выражение-аргумент 7 / 2 — целочисленное деление, 3. Округлять вверх уже нечего: Math.ceil(3) = 3.0. Чтобы получить 4.0, нужно Math.ceil(7 / 2.0). Math не спасает от целочисленного деления — оно случается раньше.

Три способа округлить

round — к ближайшему, floor — всегда вниз, ceil — всегда вверх. «Вниз» значит к меньшему числу — и для отрицательных это сюрприз: вниз от −2.7 — это −3. А приведение (int) из модуля 2 вообще не округляет, а отрезает дробь — то есть двигается к нулю.

Округление до копеек

У round нет параметра «сколько знаков». Зато есть трюк: сдвинуть запятую, округлить, сдвинуть обратно.

double price = 3.14159;

Хотим 3.14.

price * 100

314.159 — сдвинули запятую на два знака вправо.

Math.round(price * 100)

314 (long) — округлили до целого.

Math.round(price * 100) / 100.0

3.14 — сдвинули обратно. Обязательно 100.0: с 100 было бы целочисленное деление long на int, и получилось бы 3.

Где пригодится

Цены, проценты, средние значения. В магазине — когда на ценнике должно быть «12.35 ₽», а твой код посчитал 12.3456: округли до копеек и только потом показывай и сравнивай.

Комбинируем: методы внутри выражений

Раз вызов метода — это выражение, его можно подставлять куда угодно: в арифметику, в сравнения и даже в аргумент другого метода.

int a = 7;
int b = 12;
int c = 9;
int biggest = Math.max(a, Math.max(b, c));         // 12 — максимум из трёх

double r = 5;
double area = Math.PI * r * r;                     // площадь круга ≈ 78.54
double hyp = Math.sqrt(3 * 3 + 4 * 4);             // гипотенуза 5.0

int distance = Math.abs(a - c);                    // расстояние между a и c: 2
boolean close = Math.abs(0.1 + 0.2 - 0.3) < 1e-9;  // true — помнишь урок 3.3?

Вложенный вызов Java выполняет изнутри наружу: сначала вызывается Math.max(b, c) и возвращает 12, это значение становится аргументом внешнего вызова Math.max(7, 12), и он возвращает 12. А 1e-9 — это научная запись числа 0.000000001 (единица, умноженная на 10 в степени −9).

Чему равно Math.min(Math.max(15, 0), 10)? А если вместо 15 подставить -4?

10 и 0. Это знаменитый приём «зажать в диапазон 0..10»: max не даёт опуститься ниже 0, min — подняться выше 10. Для 15: max(15, 0) = 15, min(15, 10) = 10. Для −4: max(−4, 0) = 0, min(0, 10) = 0. Так делают, например, громкость или здоровье персонажа в играх.

Math.random() и игральный кубик

Math.random() возвращает случайное дробное число от 0 до 1: ноль может выпасть, единица — никогда. Как превратить его в бросок кубика от 1 до 6? Растягиваем, отрезаем и сдвигаем:

А что даст int dice = (int) Math.random() * 6 + 1; — без внутренних скобок?

Всегда 1! Приведение типа — унарный оператор, он главнее умножения (урок 3.5). Значит, сначала (int) Math.random() — а число от 0 до 0.999 после отрезания дроби всегда 0. Дальше 0 * 6 + 1 = 1. Кубик, который никогда не врёт 🙂

Общая формула: случайное целое от min до max

У кубика min = 1, max = 6. А если нужно от 10 до 20? Или от −5 до 5? Формула одна:

int min = 10;
int max = 20;
int n = (int) (Math.random() * (max - min + 1)) + min;   // от 10 до 20 включительно
max - min + 1

Сколько всего вариантов. От 10 до 20 — это 11 чисел (10, 11, …, 20), а не 10: +1 нужен, чтобы max тоже мог выпасть. У кубика: 6 − 1 + 1 = 6.

(int) (Math.random() * 11)

Растянули и отрезали дробь: целое от 0 до 10.

… + min

Сдвинули: от 0 + 10 = 10 до 10 + 10 = 20.

Какой диапазон даст (int) (Math.random() * (max - min)) + min для min = 1, max = 6 — без «+ 1»?

От 1 до 5. Вариантов получилось 6 − 1 = 5: (int) (Math.random() * 5) даёт 0…4, плюс 1 — это 1…5. Шестёрка не выпадет никогда. Забытая «+ 1» — самая частая ошибка в этой формуле. Проверяй формулу на крайних значениях: может ли выпасть min? А max?

Случайность и повторяемость

Случайные числа помогают делать уникальные данные: например, промокод "SALE" + (int) (Math.random() * 100000) для покупателя. Но случайность мешает искать ошибки: если программа сломалась на одном случайном числе, при следующем запуске выпадет другое. Поэтому случайное значение обязательно печатают в лог — чтобы ошибку можно было повторить.

🔎 Для любопытных: четыре сюрприза Math
  • Math.round(-2.5) → -2, а не −3: round округляет «половинку» всегда в сторону большего числа (вправо по прямой).
  • Math.sqrt(-1) → NaN: корня из отрицательного числа нет, но программа не падает (как и с делением double на ноль).
  • Math.abs(Integer.MIN_VALUE) → -2147483648: Integer.MIN_VALUE — самое маленькое int (пара к Integer.MAX_VALUE из модуля 2). У него нет «положительной пары» — 2147483648 не помещается в int, и происходит переполнение.
  • Math.floorMod(-7, 3) → 2, хотя -7 % 3 → -1. floorMod всегда даёт неотрицательный остаток (для положительного делителя) — удобно для «часов», которые крутятся назад.

Проверь себя

Поговори с наставником

Напиши: «Дай мне 5 вызовов Math с подвохом по типу результата. Я скажу, что напечатается, а ты проверь».

Коротко

  • Math.имя(аргументы) — вызов готового метода: передаём аргументы, метод возвращает результат. Импорт не нужен.
  • pow, sqrt, floor, ceil → double; round → long; abs, max, min → тот же тип.
  • До сотых: Math.round(x * 100) / 100.0. Вверх: ceil, вниз: floor, к нулю: (int).
  • Кубик: (int) (Math.random() * 6) + 1 — скобки обязательны. В общем виде, от min до max включительно: (int) (Math.random() * (max - min + 1)) + min.
