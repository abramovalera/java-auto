Арифметика: деление и остаток

Плюс, минус и умножение ты знаешь со школы. А вот деление в Java умеет удивлять: 7 / 2 здесь равно 3, а у деления есть брат-близнец — остаток. Разберёмся, почему так и чем это полезно.

Сначала разомнёмся: вспомним переменные и типы. Без них сегодня никуда — все операторы работают со значениями в переменных.

Операторы — глаголы программы

Переменные — это «существительные» программы: в них лежат данные. А операторы — «глаголы»: они выполняют действие над значениями. Сложить, сравнить, увеличить на единицу. Весь модуль 3 — про них.

Оператор
Значок действия: +, -, *, /, % и другие.
Операнд
То, над чем действует оператор. В price * count операнды — price и count.
Выражение
Кусочек кода, у которого есть значение: 2 + 3, price * count + 300, даже просто 42. Java вычисляет выражение и получает одно значение определённого типа.

Пять арифметических операторов Java:

ОператорЧто делаетПримерРезультат

-вычитание7 - 25
*умножение (звёздочка, не «х»)7 * 214
/деление7 / 23 😳
%остаток от деления7 % 21

Да-да, 7 / 2 — это 3, а не 3.5. Это не ошибка Java, а правило. Сейчас разберём, откуда оно взялось.

Целочисленное деление

Правило простое: если оба операнда целые (int или long), то и результат целый. Дробная часть просто отбрасывается — не округляется, а отрезается.

Аналогия: печенье для детей

У тебя 17 печенек и 5 детей. Ломать печенье нельзя. Каждому достанется по 3 — это 17 / 5. Две печеньки останутся в коробке — это 17 % 5. Целочисленное деление отвечает на вопрос «сколько целых раз поместится».

System.out.println(17 / 5);   // 3
System.out.println(9 / 10);   // 0 — ноль целых раз!
System.out.println(-7 / 2);   // -3 — отрезаем дробь, а не «вниз»

А как получить честные 3.5? Нужно, чтобы хотя бы один операнд был дробным (double). Тогда Java сначала расширит второй до double и посчитает дробно:

7 / 2.0

3.5 — у 2.0 есть точка, значит, это double.

7.0 / 2

3.5 — неважно, какой из операндов дробный.

(double) 7 / 2

3.5 — сначала литерал 7 привели к double и получили 7.0 (приведение типа из модуля 2), потом поделили.

(double) (7 / 2)

3.0 — ловушка! Скобки заставили сначала поделить целые (получилось 3), и только потом 3 превратилось в 3.0. Дробную часть уже не вернуть.

int a = 5; int b = 2; double result = a / b; — что окажется в result?

2.0. Тип переменной слева ни на что не влияет: Java сначала вычисляет выражение справа от =. a / b — деление двух int, получается 2. И только потом целое 2 инициализирует переменную result типа double и становится 2.0. Чтобы получить 2.5, пиши (double) a / b.

Правило типов

int с int → int. Если в паре есть double → результат double. Если есть long (а double нет) → long. Java всегда «поднимает» меньший тип до большего, а не наоборот.

Остаток %: маленький, да удаленький

Оператор % (читается «остаток от деления», по-английски modulo) даёт в результате то, что не поместилось при целочисленном делении. Кажется мелочью, но программисты пользуются им постоянно:

⚖️

Чётность

n % 2 равно 0 — число чётное. Равно 1 (или −1 для отрицательных) — нечётное.

🔢

Последняя цифра

472 % 10 → 2. А 472 / 10 → 47: последнюю цифру «отрезали».

🕐

Часы и круги

Сейчас 22 часа, через 5 часов будет (22 + 5) % 24 → 3 часа ночи.

📦

«Каждый n-й»

Каждый третий покупатель получает подарок: номер покупателя % 3 равен 0.

Чему равно 25 % 24? А 24 % 24? А 3 % 24?

1, 0 и 3. 25 часов — это сутки и ещё 1 час. 24 % 24 = 0: ровно сутки, остатка нет. А если число меньше делителя (3 % 24), оно целиком и есть остаток: 24 в 3 не помещается ни разу.

Знак остатка

У остатка тот же знак, что у левого числа (делимого): -7 % 2 → -1, а 7 % -2 → 1. Поэтому проверка нечётности «остаток равен 1» сломается на отрицательных числах. Надёжнее проверять чётность: «остаток равен 0».

Трассировка: яйца по коробкам

Птицефабрика собрала 20 яиц. В коробку помещается 6. Сколько полных коробок и сколько яиц останется? Пройди программу по шагам и сам впиши значения переменных — так программисты проверяют код «в голове».

Проверка, которая всегда работает

Для целых чисел верно: (a / b) * b + a % b == a. Деление и остаток — две половинки одного действия: «сколько раз» и «сколько осталось».

Деление на ноль

В математике делить на ноль нельзя. А что сделает Java? Зависит от типа!

int apples = 10;
int people = 0;
System.out.println(apples / people);

Программа скомпилируется (компилятор не знает, что в переменной окажется ноль), но при запуске упадёт. Вот что ты увидишь в панели Run:

Exception (исключение) — это аварийная остановка программы. ArithmeticException — «арифметическая авария», / by zero — «деление на ноль», а строка с at подсказывает файл и номер строки. С % то же самое: 10 % 0 тоже падает. Подробно исключения пройдём в модуле 12.

А у double всё иначе — он не падает, а возвращает особые значения:

System.out.println(10.0 / 0);    // Infinity  — бесконечность
System.out.println(-10.0 / 0);   // -Infinity
System.out.println(0.0 / 0);     // NaN — «не число» (Not a Number)

Что опаснее? Как ни странно, double. Упавшую программу видно сразу. А Infinity или NaN тихо поедут дальше по программе и испортят все следующие вычисления. В интернет-магазинах такое иногда всплывает как «цена: NaN ₽» прямо на странице — и покупатели видят, что где-то поделили на ноль.

🔎 Для любопытных: переполнение — когда int «заворачивается»

У int есть предел: от −2 147 483 648 до 2 147 483 647 (примерно ±2.1 миллиарда). Если результат не помещается, Java не сообщает об ошибке — число «перескакивает» на другой край, как одометр старой машины после 999 999 км:

int max = 2147483647;
System.out.println(max + 1);                 // -2147483648

long big = 1_000_000 * 1_000_000;            // подчёркивания — для читаемости
System.out.println(big);                     // -727379968 (!)
System.out.println(1_000_000L * 1_000_000);  // 1000000000000

Вторая ловушка — классика собеседований. Переменная long, а результат всё равно испорчен. Почему? Java сначала вычисляет выражение справа от =: 1_000_000 * 1_000_000 — это int на int, значит, результат int, и он переполняется. Только потом испорченным числом инициализируется переменная типа long. Буква L у одного из множителей делает этот литерал типа long — и всё умножение идёт в long.

Коротко

  • Операторы + - * / % вместе с операндами образуют выражение, а выражение вычисляется в одно значение.
  • int / int → int: дробная часть отрезается. Нужна дробь — сделай хотя бы один операнд double до деления.
  • % — остаток: чётность, последняя цифра, часы и круги. Знак остатка — как у левого числа.
  • Целое на ноль → ArithmeticException. double на ноль → Infinity или NaN.
