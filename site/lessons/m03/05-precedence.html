Приоритет операций

Почему "2 + 2 = " + 2 + 2 печатает 22, а "Итог: " + 3 * 2 — честные 6? Всё решает порядок, в котором Java разбирает выражение. Научимся вычислять его по шагам, как компилятор.

Повторение

Как в школе, только операторов больше

В школе учили: сначала скобки, потом умножение и деление, потом сложение и вычитание. 2 + 3 * 4 — это 14, а не 20. В Java то же самое, просто операторов больше. У каждого есть приоритет — «старшинство»: чем выше, тем раньше выполняется.

Как запомнить

Сверху вниз: «действия с одной переменной → арифметика (сначала умножение) → сравнения → логика (сначала И) → присваивание в самом конце». Присваивание последнее — логично: сначала вычисли выражение справа, потом присвой результат переменной — положи в коробку.

Один приоритет — читаем слева направо

Если рядом стоят операторы одного уровня, Java выполняет их по очереди слева направо. Это называется ассоциативность.

100 / 10 / 5

(100 / 10) / 5 = 10 / 5 = 2. Не 100 / 2 = 50!

10 - 4 - 3

(10 − 4) − 3 = 3. Не 10 − 1 = 9.

7 / 2 * 2

(7 / 2) * 2 = 3 * 2 = 6. Целочисленное деление съело половинку, и умножение её не вернёт.

a = b = 5

Присваивание — справа налево: сначала переменной b присваивается 5, потом значение этого присваивания (5) присваивается переменной a. Обе переменные равны 5.

Загадка «2 + 2 = 22» — окончательно

Ещё в модуле 1 ты видел эту ловушку. Теперь можно объяснить её до конца. Оператор + умеет две вещи: складывать числа и склеивать строки. Что именно он сделает — решается в момент выполнения каждого плюса: если хотя бы один операнд — строка, это склейка.

Ещё несколько примеров — проверь себя, прежде чем читать пояснение:

1 + 2 + "3"

(1 + 2) — числа, 3. Потом 3 + "3" — склейка: "33".

"" + 1 + 2

"" + 1 = "1", потом "1" + 2 = "12". Пустая строка в начале превращает всё в склейку.

"Итог: " + 3 * 2

* главнее +: сначала 3 * 2 = 6, потом склейка: "Итог: 6".

"Итог: " + 3 * 2 + 1

"Итог: 6", потом + 1 — склейка: "Итог: 61".

'a' + 1

Строк нет! char — это число-код: 97 + 1 = 98. А (char) ('a' + 1) — это 'b'.

Скомпилируется ли System.out.println("Разница: " + 10 - 5); ?

Нет. + и − одного уровня, идём слева направо: "Разница: " + 10 = "Разница: 10" (строка). Потом строка − 5 — вычитать из текста нельзя: bad operand types for binary operator '-'. Лечится скобками: "Разница: " + (10 - 5).

🔎 Для любопытных: приоритет — это не порядок вычисления операндов

Приоритет решает, как расставить скобки. А сами операнды Java всегда вычисляет слева направо. Обычно это незаметно, но с ++ разница видна:

int i = 2;
int r = i + i++ * i;
System.out.println(r + " " + i);   // 8 3

Приоритет говорит: это i + (i++ * i). Но левый операнд i Java вычислит первым, когда он ещё 2. Потом i++ отдаст 2 и сделает i = 3, потом правое i — уже 3. Итого 2 + 2 × 3 = 8. Именно поэтому ++ внутри выражений — зло.

Скобки — лучший друг

Классическая ошибка — средний балл:

int a = 4;
int b = 5;
int c = 3;
double wrong = a + b + c / 3.0;     // 4 + 5 + 1.0 = 10.0 — средний балл 10?!
double right = (a + b + c) / 3.0;   // 12 / 3.0 = 4.0

Деление главнее сложения, поэтому на 3 поделилось только c. Компилятор не видит здесь ошибки — программа работает, просто считает не то. Это логическая ошибка, самая коварная.

Правило профи: не уверен в приоритете — ставь скобки. Лишние скобки ничего не стоят, а пропущенные стоят часов отладки. И да, в задачах этого модуля такая ошибка тебе ещё встретится 😉

Проверь себя

Поговори с наставником

Напиши: «Дай мне длинное выражение на приоритет, я распишу его вычисление по шагам, как в трассировке, а ты проверь каждый шаг».

Коротко

  • Порядок: унарные → * / % → + - → сравнения → == != → && → || → присваивание.
  • Один уровень — слева направо (кроме присваивания: справа налево).
  • + со строкой — склейка, и решается это на каждом плюсе отдельно: "2 + 2 = " + 2 + 2 → 22.
  • Не уверен — ставь скобки. (a + b + c) / 3.0, а не a + b + c / 3.0.
