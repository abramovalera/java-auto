Логические операции: И, ИЛИ, НЕ

Одного сравнения часто мало: «логин верный и пароль верный», «студент или пенсионер». Соединяем вопросы в один — и узнаём, почему Java иногда даже не смотрит на правую половину выражения.

Повторение

Три логических оператора

Логические операторы соединяют вопросы: их операнды — значения типа boolean, и результат тоже boolean. Их три:

🤝

&& — И

true, только если оба true. «Логин верный и пароль верный» — пускаем.

🔀

|| — ИЛИ

true, если хотя бы один true. «Студент или пенсионер» — скидка.

🔄

! — НЕ

Переворачивает: !true → false, !false → true. «Не заблокирован».

boolean loginOk = true;
boolean passwordOk = false;
boolean blocked = false;

boolean canEnter = loginOk && passwordOk && !blocked;
System.out.println(canEnter);     // false — пароль неверный
Аналогия: лампочка и выключатели

Представь электрическую цепь. Если два выключателя стоят друг за другом, лампа горит, только когда замкнуты оба — это &&. Если они стоят параллельно, хватит любого — это ||.

Таблицы истинности

Все возможные случаи для двух boolean-значений легко перечислить — их всего четыре. Такая табличка называется таблицей истинности:

Заучивать не нужно — достаточно помнить две фразы: «&& — true только когда всё true», «|| — false только когда всё false».

Теперь можно починить проверку диапазона из прошлого урока. «x от 1 до 10» — это «x не меньше 1 И x не больше 10»:

int x = 7;
boolean inRange = x >= 1 && x <= 10;      // true
boolean outside = x < 1 || x > 10;         // false — то же самое «наоборот»
boolean notBig = !(x > 5);                  // false — то же, что x <= 5
Температура t = 25. Что даст t < 0 || t > 40? А t > 20 && t < 30?

false и true. 25 не меньше 0 и не больше 40 — оба вопроса «нет», значит, ИЛИ даёт false (не экстремальная погода). 25 больше 20 и меньше 30 — оба «да», И даёт true (тепло).

Короткое замыкание

Java ленива — в хорошем смысле. Если по левой части уже понятен ответ, правую она не вычисляет вообще:

  • false && … — уже ясно, что false, что бы ни было справа.
  • true || … — уже ясно, что true.

Это называется короткое замыкание (short-circuit evaluation). Звучит как мелочь, но спасает от аварий:

int total = 50;
int count = 0;
// false, без ошибки
boolean good = count != 0 && total / count > 10;
// ArithmeticException: / by zero
boolean bad = total / count > 10 && count != 0;

В первой строке левый операнд count != 0 — false, и до опасного деления в правом операнде дело не доходит. Во второй делим сразу — и программа падает. Порядок проверок важен: сначала «можно ли», потом «что получится».

🔎 Для любопытных: & и | без короткого замыкания, ^ — «исключающее ИЛИ»

У && и || есть «полные» версии с одним символом: & и |. Для boolean они дают тот же результат, но всегда вычисляют обе части. false & ++x > 0 увеличит x. На практике почти всегда нужны двойные — про одинарные спрашивают на собеседованиях.

^ (XOR, «исключающее ИЛИ») — true, когда значения разные: true ^ false → true, true ^ true → false. «Либо чай, либо кофе, но не оба».

А ещё есть законы де Моргана: !(a && b) — то же, что !a || !b, а !(a || b) — то же, что !a && !b. «Неверно, что идёт дождь И холодно» = «нет дождя ИЛИ не холодно».

Кто главнее: && или ||

Как умножение главнее сложения, так и у логических операторов есть порядок: сначала !, потом сравнения, потом &&, и только потом ||.

boolean isStudent = true;
int age = 30;
boolean hasCard = false;

boolean discount = isStudent || age >= 65 && hasCard;
// Java читает так:  isStudent || (age >= 65 && hasCard)
// = true || (false && false) = true

Если бы задумка была «(студент или пенсионер) и при этом есть карта», результат был бы другим — (true || false) && false = false. Компьютер не угадывает мысли — он следует приоритетам.

Совет из реальной жизни: если в выражении есть и &&, и || — ставь скобки, даже когда они «не нужны». Код читают люди, и они не обязаны помнить таблицу приоритетов. Пригодится, например, в задаче про високосный год.

🔎 Для любопытных: поразрядные операции — & | ^ ~ << >> для чисел

Операторы &, |, ^ работают и с целыми числами — тогда они применяются к каждому биту (каждой двоичной цифре) отдельно. Число 6 в двоичной системе — 110, число 3 — 011:

ВыражениеВ битахРезультатСмысл
6 & 3110 & 011 = 0102бит 1, где 1 в обоих
6 | 3110 | 011 = 1117бит 1, где 1 хотя бы в одном
6 ^ 3110 ^ 011 = 1015бит 1, где биты разные
~5все биты наоборот-6«НЕ» для каждого бита
1 << 31 → 10008сдвиг влево = умножить на 2³
16 >> 210000 → 1004сдвиг вправо = разделить на 2²

Где это встречается: флаги и права доступа (каждый бит — отдельное «можно/нельзя»), быстрая проверка чётности (n & 1) == 0, хеш-функции. В обычном коде — редко, а на собеседованиях иногда спрашивают << и >>. Есть ещё >>> — сдвиг вправо, который не сохраняет знак минус.

Поговори с наставником

Напиши: «Дай мне 3 правила из жизни (скидка, вход на сайт, прогноз погоды) — я переведу их в логические выражения на Java, а ты проверь скобки и порядок».

Коротко

  • && — И (всё true), || — ИЛИ (хоть что-то true), ! — НЕ.
  • Диапазон: x >= 1 && x <= 10, а не 1 <= x <= 10.
  • Короткое замыкание: false && … и true || … не вычисляют правую часть. Сначала «можно ли», потом «что получится».
  • Приоритет: ! → сравнения → && → ||. Смешал && и || — поставь скобки.
