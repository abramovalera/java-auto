Зачем нужен отладчик

Ты уже встречал логические ошибки: программа компилируется, работает, но выдаёт не то. Компилятор их не видит, исключения нет. Как найти, где именно всё пошло не так?

📝

Способ 1: println

Вставить System.out.println("total = " + total) в десять мест, запустить, прочитать простыню вывода, потом не забыть всё удалить.

⏸️

Способ 2: отладчик

Поставить точку остановки, запустить программу в режиме отладки и выполнять её по одной строке, видя все переменные сразу. Код не меняется вообще.

Аналогия: видеоповтор в футболе

Обычный запуск — матч в прямом эфире: всё пролетает за секунду, и ты видишь только счёт. Отладчик — видеоповтор: можно поставить на паузу, прокрутить по кадру, приблизить любого игрока. Спорный момент сразу виден.

Отладчик (debugger)
Инструмент IDEA, который запускает программу под присмотром: останавливает её в нужном месте и показывает, что лежит в переменных.
Отладка (debugging)
Поиск и исправление ошибок. Слово «баг» (bug, жук) — с тех времён, когда в огромный компьютер залетела настоящая моль и сломала реле.
Брейкпоинт (breakpoint)
Точка остановки: строка, на которой программа замрёт перед её выполнением.

Для разработчика отладчик — инструмент номер один. Программа посчитала не ту сумму заказа? Запускаешь её через Debug, останавливаешься перед подозрительной строкой — и видишь, что на самом деле лежит в переменных и что пришло из файла или от сервера.

Брейкпоинт и кнопка Debug

Возьмём программу, которая считает очки в игре. Набери её в module-17 — будем на ней тренироваться.

public class GameScore {
    public static void main(String[] args) {
        int[] hits = {3, 5, 2};
        int score = 0;
        for (int i = 0; i < hits.length; i++) {
            score += points(hits[i]);
        }
        System.out.println("Очки: " + score);
    }

    static int points(int hitCount) {
        int base = hitCount * 10;
        return base + bonus(hitCount);
    }

    static int bonus(int hitCount) {
        return hitCount >= 5 ? 50 : 0;
    }
}
  1. Поставь брейкпоинт. Щёлкни мышью по серой полосе слева от номера строки 4 (int score = 0; — объявление переменной score с инициализацией). Появится красная точка. Щёлкнешь ещё раз — исчезнет. С клавиатуры: Ctrl+F8 на текущей строке.
  2. Запусти отладку. Не зелёный ▶, а жучок 🐞 Debug рядом с ним (или Shift+F9). Либо щёлкни по ▶ у main и выбери Debug 'GameScore.main()'.
  3. Программа замерла. Строка 4 подсвечена синим — она ещё не выполнена. Внизу открылась панель Debug.

А вот так это выглядит в самой IDEA:

Программа остановилась на строке 4. Почему в Variables нет переменной score?

Подсвеченная строка ещё не выполнена: отладчик останавливается перед ней. Переменная score будет объявлена и инициализирована, как только мы сделаем шаг. Это главное, что путают новички: «стою на строке» = «эта строка будет следующей».

Шагаем: Step Over, Step Into, Step Out

Теперь программа в твоих руках. Четыре главные кнопки:

КнопкаКлавишаЧто делает
Step Over — шаг с обходомF8Выполнить текущую строку целиком и встать на следующую. Если в строке вызов метода — метод отработает «за кадром».
Step Into — шаг внутрьF7Если в строке вызов твоего метода — зайти внутрь и встать на его первую строку.
Step Out — шаг наружуShift+F8Доделать текущий метод до конца и вернуться туда, откуда его вызвали.
Resume — продолжитьF9Бежать дальше без остановок — до следующего брейкпоинта или до конца программы.
Run to CursorAlt+F9Бежать до строки, где стоит курсор, — как одноразовый брейкпоинт.
Аналогия: рецепт со ссылкой

В рецепте пирога написано: «приготовь крем (см. стр. 40)». Step Over — веришь, что крем получится, делаешь его и идёшь к следующему пункту. Step Into — открываешь страницу 40 и выполняешь крем по пунктам. Step Out — дочитал страницу 40 до конца, вернулся к пирогу.

Пройди программу так, как прошёл бы её отладчик. Справа — то же, что в панелях Frames (стек вызовов) и Variables.

Вот четвёртый шаг трассировки — после F7 — в настоящей IDEA:

Ты стоишь на строке 6 и нажимаешь F8, а внутри points стоит ещё один брейкпоинт. Где остановится программа?

Внутри points, на брейкпоинте. Step Over не «перепрыгивает» брейкпоинты: если внутри вызываемого метода есть красная точка, отладчик на ней остановится.

Variables, Evaluate Expression и подсказки в коде

Когда программа стоит на паузе, у тебя есть три способа узнать любое значение:

  • Панель Variables. Все переменные текущего метода. У массивов и объектов есть стрелочка ▸ — раскрой и увидишь элементы и поля. Правый клик → Set Value (F2) меняет значение прямо на ходу: «а что, если бы тут было 5?»
  • Подсказки в коде. IDEA пишет значения серым прямо в строках (hits: [3, 5, 2]). Наведи мышь на переменную — всплывёт её значение.
  • Evaluate Expression (Alt+F8). Окно-калькулятор: напиши любое выражение Java, и IDEA вычислит его в текущем состоянии программы: hitCount * 10, bonus(7), hits.length - 1. Можно выделить кусок кода в редакторе и нажать Alt+F8 — он подставится сам.
Приём: дробим подозрительное выражение

Длинное выражение считает не то? Выделяй его по кусочкам и вычисляй каждый через Evaluate. Ошибка почти всегда прячется в одном маленьком кусочке — например, в целочисленном делении или в скобках не на месте.

Программа стоит на строке return price * (15 / 100);, где price = 200. Что покажет Evaluate Expression для 15 / 100? А для всего выражения?

15 / 100 = 0: оба операнда — целочисленные литералы, деление целочисленное (модуль 3). Значит, и всё выражение — 0, скидка пропала. Evaluate сразу показывает, какой кусок «съел» значение. Починка: price * 15 / 100 — сначала умножение, потом деление.

Осторожно с Evaluate

Evaluate по-настоящему выполняет код. Вычислишь вызов метода list.remove(0) — элемент действительно удалится, и программа дальше пойдёт уже с изменённым списком. Для «посмотреть» используй выражения без побочных эффектов.

Условный брейкпоинт

Представь цикл на 365 дней, и ошибка только в 200-й день. Жать F8 двести раз? Нет: поставь брейкпоинт с условием.

for (int day = 1; day <= 365; day++) {
    int steps = stepsForDay(day);
    total += steps;          // ← брейкпоинт с условием day == 200
}
  1. Поставь обычный брейкпоинт на строку внутри цикла.
  2. Щёлкни по красной точке правой кнопкой — появится окошко.
  3. В поле Condition напиши логическое выражение Java: day == 200. Нажми Done. На точке появится знак вопроса.
  4. Запусти Debug — программа пролетит 199 кругов и остановится ровно на двухсотом.

Условие — любое выражение типа boolean: steps < 0, name.equals("Аня"), total > 1_000_000. Так ловят «тот самый» случай, на котором всё ломается.

🔎 Для любопытных: остановка на исключении и брейкпоинт без остановки

Exception Breakpoint. Ctrl+Shift+F8 → «+» → Java Exception Breakpoints → например, NullPointerException. Программа остановится в момент, когда исключение бросается, — и ты увидишь все переменные прямо перед падением, а не только stack trace после.

Логирующий брейкпоинт. В том же окошке брейкпоинта сними галочку Suspend и включи Evaluate and log: "day=" + day + " total=" + total. Программа не останавливается, а печатает в консоль — это println без правки кода.

Frames — это стек вызовов

В модуле 7 ты узнал про стек вызовов: каждый вызов метода кладёт сверху новый «лист» со своими переменными, а return его снимает. Панель Frames показывает этот стек вживую. Щёлкни по нижнему фрейму — и Variables покажет переменные того метода, который вызвал текущий.

А помнишь из модуля 9, что System.out.println(…) — это вызов метода println у объекта System.out класса PrintStream, за которым прячется целая цепочка? Отладчик позволяет провалиться в неё самому:

  1. Поставь брейкпоинт на строку с println и запусти Debug.
  2. Обычный Step Into (F7) в классы JDK не заходит — IDEA бережёт тебя от чужого кода. Нужен Force Step Into: Alt+Shift+F7.
  3. Ты внутри исходника PrintStream.java. Ещё пара Force Step Into — и в Frames уже несколько этажей:

Имена внутренних методов немного отличаются от версии к версии JDK — это нормально.

Вот он, «под капотом println», только теперь не на картинке, а в настоящем исходнике JDK! Можешь дойти до самого низа, где Java передаёт байты операционной системе. Вернуться к себе — Shift+F8 несколько раз или F9.

Отладчик или вывод в лог?

Отладчик не всегда лучше. Если программа работает на сервере, ночью, или ошибка возникает только при одновременной работе нескольких потоков (модуль 16), остановить её не получится — нужны записи о том, что происходило: лог. Разложи ситуации:

🔎 Для любопытных: чем лог лучше println

В рабочих проектах вместо System.out.println используют логгер — библиотеку вроде SLF4J + Logback: log.info("Заказ {} оплачен", id). Отличия: у каждой записи есть время, имя класса и уровень (DEBUG, INFO, WARN, ERROR); подробные DEBUG-записи можно выключить настройкой, не трогая код; записи можно писать в файл. Когда программа сломалась на сервере, где отладчик не подключишь, лог — первое, что читают.

Порядок поиска проблемы
  1. Прочитай сообщение об ошибке и stack trace. Найди первую строку со своим классом (модуль 12).
  2. Повтори ошибку стабильно: на каких данных она появляется.
  3. Отладчик: брейкпоинт перед подозрительным местом, шаги, Variables.
  4. Логи, если остановить программу нельзя.
  5. Перечитай код глазами или объясни его вслух построчно (хоть резиновой уточке). Ошибка часто находится на середине объяснения.
  6. Крайняя мера — пересобрать проект. Если IDEA показывает странное (красный код, который компилируется; старое поведение после правки), выполни Build → Rebuild Project. Не помогло — File → Invalidate Caches… → Invalidate and Restart: IDEA сотрёт свои кеши и перечитает проект с нуля.

Поговори с наставником

Напиши: «Я прошёл урок 17.1. Дай мне маленькую программу с логической ошибкой — я найду её отладчиком и расскажу, на каком шаге увидел проблему».

Коротко

  • Брейкпоинт — щелчок по полосе слева от строки; запуск — 🐞 Debug (Shift+F9). Программа замирает перед строкой.
  • F8 — шаг с обходом, F7 — внутрь метода, Shift+F8 — наружу, F9 — дальше.
  • Variables — значения, Evaluate (Alt+F8) — любое выражение, условный брейкпоинт — остановка на нужном круге.
  • Frames — живой стек вызовов; stack trace — его снимок в момент исключения.
  • Отладчик — для «здесь и сейчас», лог — для сервера, ночных прогонов и потоков.
