Аналогия: сохранения в игре

Перед боссом ты сохраняешься. Проиграл — загрузился. Git делает то же для кода, только сохранения никогда не перезаписываются: у тебя вся цепочка с первого дня, и у каждого есть подпись «что тут было».

Git — система контроля версий: программа, которая хранит историю изменений проекта. Её придумал в 2005 году Линус Торвальдс, автор Linux. Сегодня Git используют почти все команды разработчиков в мире: банковские системы, игры, мобильные приложения — весь их код живёт в Git.

Репозиторий, коммит и три зоны

Репозиторий (repository, «репо»)
Папка проекта, за которой следит Git. Вся история хранится в скрытой подпапке .git. Удалишь её — проект останется, а история пропадёт.
Коммит (commit)
Снимок проекта в какой-то момент + подпись: автор, время и сообщение «что и зачем сделано». У каждого коммита уникальный номер — хеш, например 4b7d201.
Индекс (staging area)
«Подготовка к коммиту»: сюда ты складываешь изменения, которые войдут в следующий снимок. Не всё, что ты поменял, обязано попасть в один коммит.
Ты поменял два файла: в одном починил баг, в другом начал новую фичу, которая ещё не работает. Как сделать аккуратный коммит?

Добавить в индекс только файл с исправлением и закоммитить его с сообщением «Почини …». Недоделанную фичу оставить в рабочей папке — она уйдёт в отдельный коммит, когда будет готова. Ради этого индекс и придуман.

История проекта

Вот как выглядит история маленького проекта. Пролистай её, как машину времени: у каждого коммита хеш, сообщение и что в нём изменилось.

Хорошее сообщение коммита

Коротко, по делу, отвечает на вопрос «что сделает этот коммит?»: Почини расчёт доставки для суммы 2000, Добавь тесты на пароль. Плохо: fix, правки, asdf, сделал. Во многих командах есть свой формат, например fix: … / feat: … — смотри, как принято у них.

Git в IntelliJ IDEA

Основной путь — через интерфейс IDEA. Git обычно уже установлен вместе с IDEA или ставится одной кнопкой: IDEA сама предложит скачать его, если не найдёт.

  1. Создать репозиторий: меню VCS → Create Git Repository… (в новых версиях — Version Control в главном меню) → выбрать папку проекта. Появится вкладка Git внизу.
  2. Цвета файлов: красный — Git этот файл ещё не знает (untracked); зелёный — новый, добавлен; синий — изменён с прошлого коммита; обычный — без изменений.
  3. Коммит: Ctrl+K. Слева откроется окно Commit: галочками отмечаешь файлы (это и есть индекс), внизу пишешь сообщение, жмёшь Commit.
  4. Посмотреть разницу: в окне Commit двойной щелчок по файлу или Ctrl+D — Diff: слева было, справа стало; зелёным — добавлено, синим — изменено, серым — удалено.
  5. История: вкладка Git (Alt+9) → Log. Все коммиты, ветки, авторы. Щелчок по коммиту — какие файлы он поменял.
  6. Откатить незакоммиченные правки файла: правый клик → Git → Rollback (Ctrl+Alt+Z). Файл вернётся к состоянию последнего коммита.

🔎 Для любопытных: Local History — страховка даже без Git

IDEA сама запоминает изменения файлов на несколько дней: правый клик по файлу → Local History → Show History. Спасает, если что-то удалил до коммита. Но это память только твоего компьютера и только твоей IDEA — Git она не заменяет.

Ты поменял файл и сразу написал git commit -m "Почини баг", без git add. Что будет?

Коммит не создастся: Git скажет no changes added to commit. Изменения есть только в рабочей папке, а коммит собирается из индекса — а он пуст. Сначала git add. (IDEA делает add сама, когда ты ставишь галочки.)

Ветки — параллельные вселенные

Ветка (branch) — отдельная линия истории. Главная обычно называется main (в старых проектах — master): в ней рабочий код. Для каждой задачи создают свою ветку, работают в ней, а когда всё готово и проверено — сливают (merge) обратно в main.

Аналогия: черновик

Пишешь сочинение: чистовик лежит на столе, а смелую новую концовку пробуешь на черновике. Получилось — переписываешь в чистовик. Нет — выбрасываешь черновик, чистовик цел.

В IDEA: внизу справа (или вверху слева в новом интерфейсе) написано имя текущей ветки. Щёлкни по нему: New Branch — создать ветку и перейти в неё; щелчок по ветке → Checkout — перейти; Merge into Current — влить выбранную ветку в текущую.

git branch
* main
git switch -c feature/login
Switched to a new branch 'feature/login'
git switch main
git merge feature/login

git branch — список веток (звёздочка — текущая); git switch -c имя — создать и перейти; git switch имя — перейти; git merge имя — влить ветку в текущую. В старых инструкциях вместо switch встретишь git checkout — делает то же самое.

.gitignore — что не хранить

Не всё в папке проекта нужно истории. Скомпилированные .class, папки сборки, личные настройки IDEA, а главное — пароли и ключи. Список того, что Git должен игнорировать, лежит в файле .gitignore в корне репозитория:

# результаты сборки — их всегда можно собрать заново
out/
build/
.gradle/
*.class

# личные настройки IDEA
.idea/workspace.xml

# секреты — никогда в Git!
.env
*.key
Пароль, попавший в Git, считай утёкшим

Даже если удалить файл следующим коммитом, пароль останется в истории — любой, у кого есть копия репозитория, его найдёт. Пароли от базы данных, ключи платёжных сервисов и другие секреты держат в переменных окружения или в файле, который внесён в .gitignore.

Папка out/ уже попала в коммит, и только потом ты добавил её в .gitignore. Исчезнет ли она из репозитория?

Нет. .gitignore действует только на файлы, которые Git ещё не отслеживает. Уже закоммиченное надо явно убрать из отслеживания: git rm -r --cached out и закоммитить. Файлы на диске останутся, а Git про них забудет.

Проверь себя

Практика с наставником

Напиши: «Я прошёл урок 17.2. Дай мне Git-практику из модуля 17: создам репозиторий, сделаю несколько коммитов и ветку, а потом покажу тебе git log».

Коротко

  • Git хранит историю проекта: коммит = снимок + сообщение + автор + хеш.
  • Путь изменения: рабочая папка → add (индекс) → commit (история).
  • В IDEA: Ctrl+K — коммит, Git → Log — история, Ctrl+D — Diff, Rollback — откат.
  • Ветка — параллельная линия истории; задачу делают в ветке и сливают в main через merge.
  • .gitignore — что не хранить: сборку, личные настройки и особенно пароли.
