Шаблон решения — снова с нами

LeetCode (литкод) — сайт с тысячами задач на программирование: на них тренируются перед собеседованиями, решение пишут прямо в браузере, и сайт сам проверяет его на разных входных данных. Там задача «разверни массив» пугает не кодом, а пустым экраном: с чего начать? Начинать надо не с кода. Шесть шагов, одинаковых для любой задачи:

  1. Пойми задачу. Что на входе, что на выходе? 2–3 примера, обязательно граничные: один элемент, все одинаковые, отрицательные.
  2. Реши руками на бумаге и запиши, что ты делал. Какие действия повторялись?
  3. Найди роли переменных: шагающая, накопитель, счётчик, максимум, флаг, временная.
  4. Псевдокод на русском — план без синтаксиса.
  5. Код — перевод псевдокода строка в строку.
  6. Трассировка: таблица «шаг | переменные» руками или отладчиком IDEA, потом граничные случаи.

Сначала соберём пять базовых приёмов — коротко, по одной идее. Потом разворот массива — подробно, по всем шести шагам.

Приём 1–2: сумма, среднее, максимум

Сумма и среднее

Роль: накопитель sum, инициализируем нулём. Обход: for-each, индексы не нужны.

int sum = 0;
for (int x : a) {
    sum += x;
}
double avg = (double) sum / a.length;
Почему не просто sum / a.length? Что будет для массива {1, 2}?

3 / 2 — деление двух операндов типа int, дробная часть отбрасывается: получится 1, а не 1.5. Поэтому один из операндов приводим к double (приведение типа): (double) sum / a.length = 1.5. Ловушка из модуля 3 никуда не делась.

Максимум и его позиция

Роли: максимум max («лучшее из увиденного») и maxIndex — где мы его видели. Руками это так: смотришь на первое число — пока оно самое большое. Идёшь дальше: встретил больше — запоминаешь новое и его место.

Главная ловушка: int max = 0

Если начать с нуля, а все числа отрицательные (температуры зимой: −4, −9, −1), ни одно не окажется больше нуля — и программа гордо скажет, что максимум 0. Которого в массиве нет! Инициализируй max первым элементом: int max = a[0];

Но у пустого массива (new int[0]) первого элемента нет: a[0] уронит программу с ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0. Если массив может оказаться пустым, сначала проверь это: if (a.length == 0) { … } — и сообщи «чисел нет». У пустого массива максимума просто не бывает. В задачах модуля сказано «N ≥ 1» — там такой проверки не нужно.

В массиве {3, 8, 8, 2} два максимума. Какой индекс найдёт этот код? А если заменить > на >=?

С > — 1: вторая восьмёрка не больше первой, и maxIndex ничего не присваивается. С >= — 2: равный тоже «перебивает» рекорд. Один оператор решает, какой из одинаковых максимумов ты найдёшь — первый или последний. Минимум ищется так же, только со знаком <.

Два рекордсмена: второй по величине

Частый вопрос на собеседовании: найти второе по величине число за один проход, без сортировки. Нужны два рекордсмена: max («чемпион») и second («серебро»). Ответь на вопрос ниже, прежде чем открывать, — это ключ к задаче «Второй по величине».

Массив {5, 9, 1, 7}. Сначала max = 5, потом приходит 9 — новый чемпион. Что должно случиться со старым рекордом 5?

Он не пропадает, а переходит в серебро: сначала second = max (5), потом max = 9. Порядок важен: поменяешь строки местами — потеряешь пятёрку. Дальше приходит 1 — меньше обоих, ничего не меняем. Приходит 7 — меньше чемпиона, но больше серебра: обновляем только second = 7. Ответ: 7.

Ещё два случая проверь руками сам: число, равное max, — не «второе различное», его пропускаем; а если серебра ещё нет вовсе (было одно число или все одинаковые) — пригодится флаг hasSecond, «серебро уже нашлось».

Приём 3–4: подсчёт и поиск

Подсчёт по условию

Роль: счётчик (инициализируем нулём, увеличиваем инкрементом). «Сколько чётных?», «сколько оценок ниже 3?», «сколько товаров дороже 1000?» — один шаблон, меняется только условие в if.

int count = 0;
for (int x : a) {
    // условие — единственное, что меняется от задачи к задаче
    if (x % 2 == 0) {
        count++;
    }
}

Поиск элемента: есть или нет?

Роли: флаг found и позиция index. Нашли — присвоили index значение счётчика и сразу вышли из цикла через break: дальше смотреть незачем.

int target = 7;
int index = -1;                 // -1 = «пока не нашли»: такого индекса нет
for (int i = 0; i < a.length; i++) {
    if (a[i] == target) {
        index = i;
        break;                  // первое вхождение найдено — выходим
    }
}
if (index != -1) {
    System.out.println("Нашёл на позиции " + index);
} else {
    System.out.println("Нет такого");
}

Тут флаг спрятан внутрь index: «−1» значит «не нашли». Этот приём ты встретишь в самой Java: метод indexOf, который вызывают у строк (модуль 8), возвращает −1, если ничего не нашёл.

Частая ошибка: else внутри цикла 
for (int i = 0; i < a.length; i++) {
    if (a[i] == target) {
        System.out.println("Нашёл");
    } else {
        // ❌ печатается для КАЖДОГО неподходящего элемента
        System.out.println("Нет такого");
    }
}

«Нет» можно сказать, только посмотрев все элементы, то есть после цикла. На одной итерации ты знаешь лишь «этот элемент не подходит».

Приём 5: массив-счётчик

Задача: в классе поставили оценки, сколько вышло единиц, двоек… пятёрок? Пять счётчиков c1, c2… и пять if — та же беда, что сто переменных в уроке 1. Решение — массив-счётчик: значение элемента само становится индексом, а в ячейке копится, сколько раз оно встретилось.

int[] grades = {5, 4, 5, 3, 5, 2, 4};
int[] count = new int[6];          // индексы 0…5: ячейка на каждую оценку
for (int g : grades) {
    count[g]++;                    // встретили оценку g — +1 в ячейку g
}
for (int g = 1; g <= 5; g++) {
    System.out.println(g + ": " + count[g]);
}
1: 0
2: 1
3: 1
4: 2
5: 3

Строка count[g]++ читается так: «обращаемся к элементу массива count по индексу g и увеличиваем его инкрементом». Почему new int[6], а не new int[5]? Оценка 5 должна стать индексом, а у массива длины 5 последний индекс — 4. Ячейку count[0] просто не используем: так проще, чем сдвигать каждую оценку на единицу (count[g - 1]++ — тоже рабочий вариант).

Аналогия: ящики для голосования

Пять ящиков с номерами на крышке. Каждый бюллетень с цифрой кладёшь в ящик с тем же номером, ничего не сравнивая. В конце считаешь, сколько в каждом ящике.

Что будет, если в grades по ошибке окажется оценка 7?

count[7]++ обратится к индексу 7, а у массива длины 6 последний индекс 5 — программа упадёт с ArrayIndexOutOfBoundsException: Index 7 out of bounds for length 6. Массив-счётчик работает, только когда значения — небольшие целые числа в известных пределах: оценки, цифры, кубик, номера дней недели.

Разворот массива. Шаги 1–3: понять, руками, роли

Задача (классика собеседований и LeetCode): развернуть массив на месте — переставить элементы в обратном порядке в том же массиве, без второго массива.

Шаг 1. Вход и выход, примеры:

ВходВыходЗачем этот пример
[1, 2, 3, 4, 5][5, 4, 3, 2, 1]обычный, нечётная длина
[1, 2, 3, 4][4, 3, 2, 1]чётная длина: середины нет
[7][7]граничный: один элемент
[][]граничный: пустой массив, код не должен упасть

Шаг 2. Руками. Положи пять карточек 1 2 3 4 5 на стол. Как развернуть, не беря новых карточек? Поменять местами крайние: 1 и 5. Потом следующие с краёв: 2 и 4. Тройка в середине стоит на месте. Пальцы двигаются навстречу друг другу, пока не встретятся.

Шаг 3. Роли переменных.

left
Шагающая слева направо: инициализируем индексом 0, потом 1, 2…
right
Шагающая справа налево: инициализируем последним индексом a.length - 1, потом на один меньше…
tmp
Временная. Без неё обмен не сделать: присваивание a[left] = a[right]; затрёт старое значение a[left] навсегда.
Аналогия: два стакана

В одном стакане сок, в другом молоко. Поменять содержимое, не смешав, можно только через третий, пустой стакан: сок → в пустой, молоко → в стакан из-под сока, сок из третьего → в стакан из-под молока. tmp — это третий стакан.

Разворот. Шаги 4–6: псевдокод, код, трассировка

Шаг 4. Псевдокод:

left ← первая позиция, right ← последняя
пока left левее right:
    поменять местами a[left] и a[right] (через tmp)
    left сдвинуть вправо, right сдвинуть влево

Шаг 5. Код — строка в строку:

int left = 0;
int right = a.length - 1;
while (left < right) {
    int tmp = a[left];
    a[left] = a[right];
    a[right] = tmp;
    left++;
    right--;
}

Шаг 6. Трассировка. Пройди сам и предскажи значения — так проверяют любой алгоритм, прежде чем ему поверить.

То же самое можно сделать в IDEA с настоящей программой. Поставь точку останова на строку left++; и запусти жуком 🐞. Программа остановится после первого обмена — и отладчик покажет те же значения, что и таблица выше:

Граничные случаи проверь в голове: [7] — left = 0, right = 0, условие 0 < 0 ложно сразу, массив не меняется. Пустой [] — right инициализируется значением −1, 0 < -1 ложно, тело цикла не выполнится ни разу и ничего не упадёт. Отлично.

Новичок написал for (int i = 0; i < a.length; i++) и меняет a[i] с a[a.length - 1 - i]. Что получится?

Массив не изменится! Первая половина цикла развернёт массив, а вторая — развернёт его обратно: каждую пару поменяют дважды. Идти нужно только до середины — условие i < a.length / 2. Это та же логика «пока пальцы не встретились», записанная через один индекс.

Сдвиги: по кругу, удаление, вставка

Задача: сдвинуть элементы на одну позицию вправо по кругу: последний становится первым. [1, 2, 3, 4, 5] → [5, 1, 2, 3, 4].

Руками: пятёрку убираем «в карман» (временная переменная tmp, инициализированная последним элементом), остальные сдвигаем вправо, освободившееся первое место занимает пятёрка из кармана.

Двигаться нужно с конца

Если идти слева направо (a[1] = a[0], потом a[2] = a[1]…), единица «протечёт» по всему массиву: получится [1, 1, 1, 1, 1]. Каждое присваивание затирает число, которое ещё не перенесено. Идём справа налево: a[4] = a[3], a[3] = a[2]… — затирается только то, что уже скопировано.

Почему в условии i > 0, а не i >= 0?

В теле цикла есть обращение a[i - 1]. При i = 0 это a[-1] — ArrayIndexOutOfBoundsException. Да и не нужно: элементу с индексом 0 мы присваиваем tmp после цикла.

Удаление и вставка со сдвигом

Размер массива не меняется, поэтому «удалить» элемент — значит сдвинуть хвост влево на его место, а «вставить» — сдвинуть хвост вправо и освободить ячейку. Как в очереди: один ушёл — все за ним шагнули вперёд; кто-то встал в середину — все за ним отступили назад.

int[] a = {10, 20, 30, 40, 50};

// удаляем элемент с индексом k = 1 (число 20)
int k = 1;
for (int i = k; i < a.length - 1; i++) {
    a[i] = a[i + 1];               // каждый занимает место левого соседа
}
a[a.length - 1] = 0;               // последняя ячейка освободилась
System.out.println(Arrays.toString(a));   // [10, 30, 40, 50, 0]

// вставляем 25 на индекс k = 2
k = 2;
for (int i = a.length - 1; i > k; i--) {
    a[i] = a[i - 1];               // сдвиг вправо — с конца, как в задаче выше
}
a[k] = 25;
System.out.println(Arrays.toString(a));   // [10, 30, 25, 40, 50]

Последнюю ячейку при вставке занять некуда: её значение (здесь 0) вытесняется. В настоящих программах рядом с массивом заводят переменную size — сколько ячеек реально занято. Так устроен список ArrayList из модуля 13: внутри у него массив и счётчик.

Почему при удалении цикл идёт слева направо, а при вставке — справа налево?

Каждое присваивание затирает ячейку, куда пишем. При удалении пишем в ячейку слева, а её старое значение и так удаляется или уже скопировано. При вставке пишем в ячейку справа — если идти слева, затрём ещё не перенесённое число, и оно «протечёт», как в ловушке со сдвигом.

🔎 Для любопытных: System.arraycopy — сдвиг одной строкой

В Java есть готовый метод копирования куска массива: System.arraycopy(откуда, сИндекса, куда, вИндекс, сколько). Он правильно работает, даже когда «откуда» и «куда» — один и тот же массив, поэтому сдвиги из примера выше можно записать так:

System.arraycopy(a, k + 1, a, k, a.length - 1 - k);   // удаление: хвост влево
System.arraycopy(a, k, a, k + 1, a.length - 1 - k);   // вставка: хвост вправо

Именно этим методом внутри пользуются Arrays.copyOf и ArrayList. Но сначала научись писать сдвиг циклом: на собеседовании просят именно его, а в аргументах arraycopy легко ошибиться на единицу.

Проверь себя

Тренируй план, а не код

Напиши наставнику: «Дай задачу на массивы уровня собеседования. Я сначала напишу только примеры, роли переменных и псевдокод — проверь план до того, как я начну кодить».

Коротко

  • Сумма — накопитель; среднее — выражение (double) sum / a.length с приведением типа.
  • Максимум и позиция: инициализируем значением a[0] и индексом 0, никогда не нулём. > найдёт первый из равных, >= — последний.
  • Подсчёт: счётчик + условие. Поиск: инициализируем index = -1, нашли — присвоили индекс и break; «нет» говорим только после цикла.
  • Разворот на месте: два указателя навстречу, обмен через tmp, пока left < right.
  • Второй по величине: два рекордсмена; новый максимум отправляет старый в second.
  • Массив-счётчик: count[x]++ — значение становится индексом; длина массива — наибольшее значение + 1.
  • Сдвиг вправо: спрятать последний, двигать с конца, положить спрятанный в начало. Удаление — хвост влево (цикл слева), вставка — хвост вправо (цикл с конца).
