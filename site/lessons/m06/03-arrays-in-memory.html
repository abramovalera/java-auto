Массив в памяти: стек, куча и стрелки

Почему, поменяв массив b, ты вдруг поменял и a? Заглянем в память и увидим: переменная хранит не массив, а стрелку на него.

⏱ 20 минут🧠 стек и куча⚖️ == и Arrays.equals

Повторение

Загадка

Прежде чем читать дальше — честно предскажи:

int[] a = {1, 2, 3};
int[] b = a;
b[0] = 99;
System.out.println(a[0]);
Что напечатается: 1 или 99?

99. Мы ни разу не присваивали ничего через a, а a[0] изменился. Почему так — весь этот урок. Если ты ответил 1 — не страшно, так отвечает почти каждый новичок. И многие на собеседовании.

С переменными примитивного типа всё было бы иначе:

int x = 1;
int y = x;
y = 99;
System.out.println(x);   // 1 — x не изменился

Почему с int копия независимая, а с int[] — нет? Ответ в том, что именно лежит в переменной.

Переменная хранит ссылку, массив живёт в куче

Вспомни две области памяти:

  • Стек — переменные метода main. Маленькие ячейки, у каждой своё имя.
  • Куча — большой склад для объектов. Всё, что создаётся через new, появляется там.

Массив — объект. Строка int[] a = new int[3]; — объявление с инициализацией — делает две вещи: в куче создаёт сам массив (три ячейки плюс записанная длина), а в стеке — переменную a, в которой лежит ссылка: адрес массива в куче. На схемах ссылку рисуют стрелкой.

Аналогия: номерок в гардеробе

Ты сдал куртку — тебе дали номерок №1. Куртка висит в гардеробе (это куча), а в кармане у тебя только номерок (это переменная). Строка int[] b = a; — объявляем b и инициализируем её значением a, то есть ссылкой: это второй номерок с тем же номером, а не вторая куртка. Друг по своему номерку возьмёт твою куртку и пришьёт пуговицу — ты свою куртку получишь уже с пуговицей.

Смотрим по шагам: b = a — это не копия

Слева код, справа память: стек с переменными и куча с объектами. Стрелка показывает, куда смотрит ссылка. Сначала — обычные int, потом массив.

Правило на всю жизнь в Java

Оператор присваивания = всегда копирует то, что лежит в переменной. У примитивов (int, double, boolean, char…) там значение — копируется значение. У массивов и других объектов там ссылка — копируется ссылка. В модулях про классы и коллекции это правило будет работать точно так же.

Где это бьёт в реальной работе: тест сохранил «ожидаемый» массив присваиванием expected = actual;, потом программа поменяла элементы actual — и тест сравнивает массив сам с собой. Он всегда зелёный и ничего не проверяет.

Как сделать настоящую копию

Нужен второй, независимый массив — значит, нужен второй объект в куче. Три способа:

import java.util.Arrays;
…
int[] a = {1, 2, 3};

int[] c1 = Arrays.copyOf(a, a.length);   // 1. готовый метод класса Arrays
int[] c2 = a.clone();                    // 2. «клонировать» массив

int[] c3 = new int[a.length];            // 3. руками: новый массив + цикл
for (int i = 0; i < a.length; i++) {
    c3[i] = a[i];
}

Во всех трёх случаях в куче появляется новый массив с теми же числами. В первых двух мы вызываем метод (copyOf у класса Arrays, clone у массива a), и метод возвращает ссылку на новый массив — ею инициализируется переменная. Arrays.copyOf умеет ещё и менять длину — второй аргумент задаёт длину копии: Arrays.copyOf(a, 5) даст [1, 2, 3, 0, 0] (лишние ячейки — нули), а Arrays.copyOf(a, 2) — [1, 2]. Так и «увеличивают» массив: создают новый побольше.

Аналогия: ссылка на документ и копия документа

Ты отправил другу ссылку на свой Google-документ (b = a). Друг дописал строчку — ты видишь её у себя: документ-то один. А если нажать «Создать копию» (Arrays.copyOf), у друга будет свой документ, и его правки тебя не касаются.

Сравнение: == или Arrays.equals

Раз в переменных лежат ссылки, то a == b сравнивает ссылки: «ведут ли стрелки в один и тот же объект?». Совпадение содержимого == не интересует. Чтобы сравнить содержимое поэлементно, есть Arrays.equals(a, b): одинаковая длина и одинаковые элементы на тех же местах.

Что выведет: System.out.println(new int[]{1} == new int[]{1});

false. Два new — два разных объекта в куче, два разных адреса. Содержимое одинаковое, но == на него не смотрит.

Стрелку можно перевесить

Переменной-ссылке можно присвоить ссылку на другой массив. Старый при этом никуда не копируется — просто стрелка начинает вести в другое место:

int[] a = {1, 2, 3};
int[] b = a;          // a и b → #1
a = new int[5];       // a → #2 (новый массив из нулей), b по-прежнему → #1
System.out.println(b[0] + " " + a.length);   // 1 5

А если на старый массив не смотрит ни одна стрелка, до него больше никак не добраться. Такой объект — мусор, и его рано или поздно уберёт сборщик мусора (garbage collector) — помнишь его по модулю 1? Освобождать память руками в Java не нужно.

🔎 Для любопытных: null — ссылка в никуда

Переменной-массиву можно присвоить null — «стрелки нет».

int[] a = null;
System.out.println(a);        // null — печатать можно
System.out.println(a.length); // 💥 NullPointerException

Пойти по стрелке, которой нет, нельзя — программа падает с NullPointerException (NPE). Это самое частое исключение в Java вообще, ты ещё не раз его встретишь. Не путай: new int[0] — это настоящий массив длины 0 (пустой шкаф без ячеек), его length равен 0 и ничего не падает.

Проверь себя

Поговори с наставником

Напиши: «Нарисую словами память для кода int[] b = a; b[0] = 5; — проверь, правильно ли я понимаю стрелки». Объяснить это вслух — лучший способ понять ссылки навсегда.

Коротко

  • Массив — объект в куче. Переменная в стеке хранит ссылку (адрес) на него.
  • int[] b = a; — b инициализируется копией ссылки: два имени, один массив. Изменения видны через оба.
  • Настоящая копия: Arrays.copyOf(a, a.length), a.clone() или новый массив + цикл.
  • == сравнивает ссылки, Arrays.equals(a, b) — содержимое, поэлементно. a.equals(b) у массивов = ==.
  • На объект без единой ссылки придёт сборщик мусора. null — ссылки нет, обращение даст NullPointerException.
