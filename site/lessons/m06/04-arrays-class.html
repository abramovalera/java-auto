Класс Arrays: ящик с инструментами

Печать, сортировка, заполнение, копирование, сравнение — всё это уже написано за тебя. Учимся пользоваться готовым и понимать, что оно делает с массивом.

Попробуй напечатать массив целиком:

int[] a = {3, 1, 2};
System.out.println(a);

Это не ошибка и не мусор. Мы вызвали println и передали аргументом ссылку на массив — а метод не умеет красиво печатать массивы и выводит «паспорт» объекта:

Чтобы увидеть содержимое, вызываем метод Arrays.toString и передаём ему массив — метод возвращает строку с элементами:

// как import java.util.Scanner — подключаем класс из JDK
import java.util.Arrays;

public class PrintArray {
    public static void main(String[] args) {
        int[] a = {3, 1, 2};
        System.out.println(Arrays.toString(a));   // [3, 1, 2]
    }
}
Привычка, которая сэкономит часы

Не понимаешь, что лежит в массиве? Вставь строку System.out.println(Arrays.toString(a)); и запусти. Так программисты «подсматривают» в данные при отладке.

Что лежит в ящике

Arrays — готовый класс из пакета java.util, как Scanner. Это ящик с инструментами для массивов, и каждый инструмент — метод класса Arrays. Все они вызываются одинаково: Arrays.имяМетода(массив, …) — в скобках передаём аргументы.

ВызовЧто делаетПример результата
Arrays.toString(a)Возвращает строку с элементами"[3, 1, 2]"
Arrays.sort(a)Меняет сам массив: сортирует по возрастаниюa стал [1, 2, 3]
Arrays.fill(a, 7)Меняет сам массив: присваивает 7 всем элементамa стал [7, 7, 7]
Arrays.copyOf(a, n)Возвращает новый массив длины n[3, 1] при n = 2
Arrays.copyOfRange(a, from, to)Новый массив из куска: с from включительно до to не включаяcopyOfRange(a, 1, 3) → [1, 2]
Arrays.equals(a, b)Сравнивает содержимое, возвращает true/falsetrue

Обрати внимание на два вида методов. Одни меняют массив, переданный аргументом (sort, fill), и ничего не возвращают. Другие массив не трогают, а возвращают новое значение (toString, copyOf, equals). Путать их — частая ошибка.

Arrays.sort — сортировка на месте

int[] prices = {300, 120, 990, 45};
Arrays.sort(prices);
System.out.println(Arrays.toString(prices));   // [45, 120, 300, 990]

String[] names = {"Оля", "Борис", "Аня"};
Arrays.sort(names);
System.out.println(Arrays.toString(names));    // [Аня, Борис, Оля]
Две ловушки sort

1) int[] sorted = Arrays.sort(prices); — не скомпилируется: метод sort ничего не возвращает (в Java это называется void), инициализировать переменную нечем — он меняет сам массив.

2) Исходный порядок пропадает. Нужен и старый, и отсортированный — сначала сделай копию и отсортируй её: int[] sorted = Arrays.copyOf(prices, prices.length); Arrays.sort(sorted);

Первая ловушка в IDEA выглядит так:

Что выведет: int[] a = {3, 1, 2}; int[] b = a; Arrays.sort(b); System.out.println(a[0]);

1. Вспомни урок 3: b и a — две стрелки на один массив. Вызвали sort и передали аргумент b — отсортировался общий массив, и a видит его отсортированным.

А по убыванию? Для int[] простого «sort наоборот» нет. Самый понятный способ сейчас: отсортировать по возрастанию и обойти массив циклом с конца — счётчик инициализируем последним индексом: for (int i = a.length - 1; i >= 0; i--).

🔎 Для любопытных: почему «Яна» окажется раньше «аист»

Строки сортируются по кодам символов. У всех заглавных букв коды меньше, чем у строчных, поэтому {"аист", "Яна"} после сортировки станет [Яна, аист]. А буква «Ё» стоит отдельно от алфавита — вообще перед «А». Сортировку «как в словаре» делают другими средствами — разберём в модуле про строки и коллекции.

fill, copyOfRange и equals в деле

fill нужен, когда элементы нужно инициализировать не нулём. Например, кинотеатр: в ячейке — номер проданного билета, а -1 значит «место свободно». Не путай: индекс ячейки — это её положение в ряду (с нуля), а значение в ней — номер билета.

int[] seats = new int[6];
Arrays.fill(seats, -1);                        // все места свободны
seats[2] = 1042;                               // индекс 2 = третье место: продано, билет 1042
System.out.println(Arrays.toString(seats));    // [-1, -1, 1042, -1, -1, -1]

int[] firstRow = Arrays.copyOfRange(seats, 0, 3);
System.out.println(Arrays.toString(firstRow)); // [-1, -1, 1042]

Аргументы-границы copyOfRange(a, from, to) устроены как в цикле for (int i = from; i < to; i++): левая включается, правая — нет. Поэтому длина куска всегда to - from. Так же устроены многие методы в Java — например, вырезание кусочка строки в модуле 8.

И сравнение, уже знакомое по уроку 3: метод Arrays.equals сравнивает содержимое поэлементно и возвращает boolean. Так проверяют, что результат совпал с ожиданием, — например, что сортировка сработала:

int[] actual = {5, 3, 9};
Arrays.sort(actual);
int[] expected = {3, 5, 9};
System.out.println(Arrays.equals(expected, actual)); // true
System.out.println(expected == actual);              // false — разные объекты

Собери программу

Программа читает N чисел и печатает их по возрастанию, а потом самое маленькое и самое большое. После сортировки минимум и максимум искать не нужно — они на краях: обращаемся к элементам по индексам 0 и a.length - 1. Расставь строки по порядку:

Что выведет эта программа на ввод «4 9 -2 7 0»?

[-2, 0, 7, 9] и Мин: -2, макс: 9. Первое число 4 — это N, размер массива, в сам массив оно не попадает.

Коротко

  • import java.util.Arrays; — и готовые методы под рукой: Arrays.метод(аргументы).
  • println(a) печатает «паспорт» [I@…; содержимое — Arrays.toString(a).
  • sort и fill меняют массив, переданный аргументом, и ничего не возвращают (void).
  • copyOf, copyOfRange возвращают новый массив; у copyOfRange правая граница не включается.
  • Arrays.equals сравнивает содержимое, == — ссылки.
