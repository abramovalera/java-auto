Зачем копать так глубоко

Программы почти целиком состоят из текста: имена, адреса, сообщения об ошибках, ответы сервера. Программа то и дело получает строку и сравнивает её с ожидаемой — например, интернет-магазин проверяет статус заказа:

String city = order.getCity();         // «Казань»
String status = order.getStatusText(); // «Доставлен»
if (!status.equals("Доставлен")) {
    System.out.println("Заказ ещё в пути");
}

Этот код пока условный — методы getCity и getStatusText придумали для примера: вызываем метод у объекта заказа, он возвращает строку, ею инициализируем переменную. Но смысл верный: программист целыми днями достаёт строки, режет их, чистит от пробелов и сравнивает. Чтобы делать это без сюрпризов, надо понимать, как строка устроена.

Строка в памяти: номерок и пальто

Вспомни гардероб из модуля 2. Ты сдаёшь пальто (объект) — оно висит на вешалке в зале (в куче). В руке у тебя только номерок (ссылка). Со строкой ровно так же: объявляем переменную name типа String и инициализируем её строковым литералом "Мурзик" — в переменную попадает ссылка:

String name = "Мурзик";
int age = 3;

Внутри объект String похож на массив символов: ряд пронумерованных ячеек плюс записанная длина. Отсюда и знакомые тебе вызовы методов charAt(0) и length(). Но есть важное отличие от массива — о нём следующий шаг.

Почему у String тип пишется с большой буквы, а у int — с маленькой?

int, double, char, boolean — примитивы, встроенные в язык «коробочки» со значением. String — это класс, чертёж объекта (вспомни урок 1.1). Имена классов в Java пишут с большой буквы. Строка — объект, поэтому и тип у неё «объектный».

🔎 Для любопытных: что на самом деле внутри объекта String

Если открыть исходник класса String в IDEA (Ctrl+клик по слову String), увидишь поле private final byte[] value — обычный массив байтов. С Java 9 строки из латиницы хранятся по одному байту на символ, а с кириллицей — по два. Это называется «компактные строки» (compact strings) и экономит память. Снаружи ничего не меняется: charAt и length работают с символами, а не с байтами.

Слово final у поля и отсутствие методов, которые меняли бы этот массив, — как раз то, что делает строку неизменяемой.

Строки неизменяемы (immutable)

Массив можно поменять — присвоить элементу новое значение: a[0] = 99. А у строки такого способа нет. Ни одного метода, который поменял бы символы готового объекта String. Это свойство называется неизменяемость (англ. immutable — «не подлежащий изменению»).

Аналогия: табличка на двери

Строка — как табличка, выгравированная на металле. Исправить на ней букву нельзя. Хочешь другую надпись — заказываешь новую табличку и вешаешь её вместо старой. Старая отправляется в мусор, если её никто не забрал.

Но ведь у строки есть toUpperCase(), replace(), trim()… Они не меняют строку? Нет. Мы вызываем метод у объекта строки, и каждый такой метод возвращает новую строку, а исходная остаётся как была:

String word = "кот";
word.toUpperCase();              // новая строка "КОТ" создана… и сразу потеряна
System.out.println(word);        // кот

String loud = word.toUpperCase(); // а вот так результат сохранили
System.out.println(loud);        // КОТ
System.out.println(word);        // кот — исходная по-прежнему маленькими

word = word.toUpperCase();       // меняем переменную: присваиваем новую строку
System.out.println(word);        // КОТ
word.toUpperCase();

Вызываем метод toUpperCase у объекта word. Метод честно создал новую строку «КОТ» и вернул ссылку на неё. Но возвращаемое значение мы никуда не сохранили — оно пропало. IDEA подсветит такую строку жёлтым: «Result of String.toUpperCase() is ignored».

String loud = word.toUpperCase();

Объявляем переменную loud и инициализируем её результатом вызова метода. Теперь в куче две строки: «кот» и «КОТ».

word = word.toUpperCase();

Объект «кот» не изменился! Это присваивание: переменной word присвоили ссылку на новую строку — номерок от новой вешалки.

Вот как это выглядит в IDEA. Код компилируется и запускается, но строка с потерянным возвращаемым значением подсвечена:

Ошибка «вызвал метод и не сохранил возвращаемое значение» — одна из самых частых у новичков. Её любят на собеседованиях: вызов s.trim(); — и удивляются, почему пробелы остались. Запомни: у строки любые «изменения» — через присваивание.

Смотрим по шагам: s = s + "!"

Самое коварное место — склейка. Кажется, что присваивание s = s + "!" дописывает восклицательный знак в конец строки. На самом деле в куче появляется новый объект. Пройди по шагам и следи за стрелками.

Сравни с массивом: int[] a = {1}; int[] b = a; a[0] = 2; — что в b[0]? А с String s = "a"; String t = s; s = s + "b"; — что в t?

В b[0] будет 2: массив изменяемый, а a и b ссылаются на один объект. В t останется "a": строку нельзя изменить, склейка создала новый объект, и переставилась только стрелка s. Поэтому со строками «эффект двух имён» не страшен — именно ради этого их и сделали неизменяемыми.

Зачем Java так сделала

Неизменяемость кажется неудобной: зачем плодить новые объекты? Но у неё три больших плюса.

🛡️

Безопасно делиться

Передал строку аргументом в чужой метод — и точно знаешь, что твою строку там не испортят. С массивом так не получится (вспомни урок 7.4).

Можно переиспользовать

Одинаковые литералы "Java" в разных местах программы — это один объект. Раз его никто не поменяет, делить его безопасно. Это пул строк — следующий урок.

🔑

Надёжные ключи

Строки часто служат ключами: логин, id, название. Ключ, который может тихо поменяться, — источник страшных багов. Подробнее — в модуле 13 (коллекции).

Цена неизменяемости

Каждая склейка — новый объект. Одна-две — не страшно. А присваивание result = result + c в теле цикла на 100 000 итераций создаст 100 000 строк, и каждая следующая длиннее предыдущей. Для таких случаев есть изменяемый «черновик» — StringBuilder (урок 8.5).

Строка, которой нет: null и пустая строка

Раз в переменной номерок, номерка может и не быть: String s = null; — переменная объявлена и инициализирована литералом null, а объекта нет. А пустая строка "" — это настоящий объект, просто в нём ноль символов.

String a = "";String b = null;

Аналогияномерок от пустой вешалкиномерка нет вообще
String s = null; System.out.println(s + "!"); — упадёт программа или нет?

Не упадёт! Напечатает null!. При склейке Java превращает null в текст «null». А вот вызовы s.length() или s.toUpperCase() упадут с NullPointerException: нельзя вызвать метод у объекта, которого нет.

Так выглядит падение в IDEA. Это исключение — ошибка выполнения, как деление на ноль из урока 1.7: программа скомпилировалась, запустилась и упала посреди работы.

Как читать NPE

Смотри на то, что в кавычках после because: это переменная, в которой оказался null. Дальше вопрос один — почему туда не попал объект. А если проверишь эту же программу кнопкой на сайте, вместо имени может быть написано because "<local1>" is null — «локальная переменная № 1». Так бывает, когда программу компилируют без отладочной информации и имена переменных в .class не сохраняются. IDEA их сохраняет, поэтому в ней видно настоящее имя.

Коротко

  • String — класс, строка — объект в куче. В переменной лежит ссылка (номерок).
  • Строки неизменяемы: ни один метод не меняет готовую строку — вызов метода у строки возвращает новую строку.
  • Чтобы «поменять» строку, присвой переменной возвращаемое значение: s = s.trim();
  • s = s + "!" создаёт новый объект; старый, если на него нет ссылок, уберёт сборщик мусора.
  • "" — пустой объект, null — нет объекта. null.length() → NullPointerException.
