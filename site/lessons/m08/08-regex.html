Регулярные выражения: шаблоны для текста

Как проверить, что строка похожа на email или телефон? Как одной строчкой оставить в тексте только цифры? Для этого есть мини-язык шаблонов — регулярные выражения. Урок необязательный, но в реальных проектах регулярки встречаются постоянно: проверка форм, поиск по логам, чистка данных.

Повторение

Зачем нужен шаблон

Задача из жизни: пользователь вводит телефон в форме регистрации. Надо проверить, что он в правильном формате — «+7» и ровно 10 цифр. Конкретный номер мы заранее не знаем (каждый вводит свой), значит, equals не подходит. Можно написать цикл с вызовами charAt и десятком проверок… или одну строчку — объявить переменную ok и инициализировать её результатом вызова matches:

String phone = "+79991234567";
boolean ok = phone.matches("\\+7\\d{10}");   // true

"\\+7\\d{10}" — аргумент метода, это регулярное выражение (regular expression, коротко regex или «регулярка»): строка-шаблон, описывающая, как должен выглядеть текст. Читается так: «плюс, семёрка, потом ровно 10 цифр».

Аналогия: трафарет

Обычный equals — это сравнение с готовой надписью: совпадает буква в букву или нет. Регулярка — трафарет: «здесь любая цифра, здесь любая буква, тут повтори три раза». Под трафарет подходит много разных строк одинакового вида.

✅

Проверить формат

Метод matches возвращает boolean: email, телефон, дата, индекс, номер заказа.

Азбука регулярок

Большинство символов в шаблоне означают сами себя: "кот" подходит только под «кот». Особый смысл есть у немногих:

ШаблонОзначаетПодходит
\dлюбая цифра0 … 9
\Dчто угодно, кроме цифрыa, пробел, +
\wлатинская буква, цифра или _a, Z, 7, _ (кириллицу — нет!)
\sпробельный символпробел, табуляция, перевод строки
.один любой символa, 5, !, пробел
[abc]один из перечисленныхa, b или c
[а-яё]один из диапазоналюбая маленькая русская буква
[^0-9]любой, кроме перечисленныхвсё, что не цифра

После символа можно указать, сколько раз он повторяется:

СколькоОзначаетПример
+1 или больше\d+ — «число из одной и более цифр»
*0 или больше\s* — «пробелы, а может, их нет»
?0 или 1 (необязательный)colou?r — color и colour
{n}ровно n раз\d{6} — почтовый индекс
{n,m} / {n,}от n до m / от n и больше[a-z]{2,} — 2+ латинские буквы
Двойной обратный слэш в Java

В регулярках пишут \d. Но в строковом литерале Java обратный слэш — спецсимвол (помнишь \n и \\ из модуля 1?). Чтобы в строку попал один \, его надо написать в литерале дважды. Поэтому в коде всегда "\\d", "\\s+", "\\.". А чтобы найти сам особый символ — точку, плюс, скобку — его экранируют: \\. — «именно точка», \\+ — «именно плюс».

matches: подходит ли строка под шаблон

Вызов s.matches(regex) — шаблон передаём аргументом — возвращает true, если под шаблон подходит вся строка целиком — от первого до последнего символа.

"ivan.petrov@mail.ru".matches("[\\w.-]+@[\\w-]+\\.[a-z]{2,}")   // true
// нет точки и зоны
"ivan@mail".matches("[\\w.-]+@[\\w-]+\\.[a-z]{2,}")             // false

// телефон в привычной записи
"+7 (999) 123-45-67".matches("\\+7 \\(\\d{3}\\) \\d{3}-\\d{2}-\\d{2}")  // true
// дата ДД.ММ.ГГГГ
"27.11.2026".matches("\\d{2}\\.\\d{2}\\.\\d{4}")                // true

"123456".matches("\\d{6}")    // true — индекс
"abc".matches("b")            // false! нужна вся строка
"abc".matches(".*b.*")        // true — «что угодно, b, что угодно»
"иван@mail.ru".matches("[\\w.-]+@[\\w-]+\\.[a-z]{2,}") — true или false?

false. \w в Java по умолчанию — только латиница, цифры и подчёркивание, кириллицу не берёт. Хочешь русские буквы — пиши диапазон явно: [а-яёА-ЯЁ]. Такие мелочи и есть причина, почему регулярки обязательно проверяют на примерах — в том числе на «плохих».

Как проверять свою регулярку

Составь таблицу «строка → должно подойти?» с хорошими и плохими примерами (это же шаг 1 Мастерской!) и для каждой вызови matches. Ещё удобно на сайте regex101.com — выбери там вариант Java, и он подсветит, какая часть шаблона что «съела».

replaceAll: найти по шаблону и заменить

replaceAll(regex, замена) — два аргумента, как у replace, только метод ищет не точный кусок, а всё, что подходит под шаблон, и возвращает новую строку.

// убрать всё, кроме цифр
"+7 (999) 123-45-67".replaceAll("\\D", "")        // "79991234567"
"  много    пробелов  ".trim().replaceAll("\\s+", " ")  // "много пробелов"
// цена из чека → в число
"1 299 ₽".replaceAll("[^0-9]", "")                 // "1299"
"Заказ №123 от 27.11".replaceAll("\\d", "#")       // "Заказ №### от ##.##"

Типичная задача: пользователь ввёл телефон как «+7 (999) 123-45-67», а в базе лежит «79991234567». Сравнивать их как есть бесполезно. Приводим оба к одному виду — вызов replaceAll("\\D", "") — и уже потом сравниваем по содержимому через equals. То же с текстом, скопированным из документа: в нём бывают лишние пробелы и переводы строк, а replaceAll("\\s+", " ") их схлопнет.

Ловушка: replace против replaceAll

replace понимает аргумент буквально, replaceAll — как шаблон. Поэтому "a.b".replace(".", "*") → «a*b», а "a.b".replaceAll(".", "*") → «***»: точка в регулярке — «любой символ», и заменилось всё. Не нужен шаблон — бери replace.

split по шаблону — теперь понятно, что за \\s+

Открою секрет: параметр метода split — это всегда регулярка. Поэтому:

// \\s+ — «один или больше пробелов»
"  кот   пёс  ".trim().split("\\s+")      // ["кот", "пёс"]
// запятая или ;, потом пробелы, если есть
"яблоко, груша;слива".split("[,;]\\s*")  // ["яблоко", "груша", "слива"]
// пусто! точка = любой символ, всё ушло в разделители
"a.b.c".split(".")                        // []
"a.b.c".split("\\.")                      // ["a", "b", "c"] — именно точка

Классика багов: вызов version.split(".") для «1.2.3» возвращает пустой массив, а следующая строчка с обращением по индексу [0] падает с ArrayIndexOutOfBoundsException. Точка, плюс, звёздочка, скобки, вертикальная черта | в split — особые символы. Экранируй.

Меру знай

  • Регулярки — мощный, но плохо читаемый инструмент. Если хватает contains, startsWith, replace — бери их.
  • «Настоящая» проверка email по стандарту занимает страницу. Для обычной программы хватает упрощённой — главное, честно понимать, что именно она проверяет.
  • Сложную регулярку подпиши комментарием: // +7 и 10 цифр. Через месяц ты сам её не прочитаешь.
🔎 Для любопытных: группы и перестановка кусков

Круглые скобки делают группу — запоминают, что совпало. В замене на группу ссылаются через $1, $2… Так можно переставить части даты:

"2026-11-27".replaceAll("(\\d+)-(\\d+)-(\\d+)", "$3.$2.$1")   // "27.11.2026"

Для серьёзной работы с регулярками в Java есть классы Pattern и Matcher — они умеют искать все совпадения в тексте по очереди. Понадобятся, когда будешь доставать, например, все номера заказов из длинного лога.

Коротко

  • Регулярка — шаблон вида текста. В строковом литерале Java слэши удваиваются: "\\d", "\\s+", "\\.".
  • \d цифра, \s пробел, \w латиница/цифра/_, . любой, […] один из, [^…] кроме; + * ? {n} {n,m} — сколько раз.
  • matches возвращает boolean — подходит ли вся строка. replaceAll возвращает новую строку с заменой по шаблону. split — тоже по шаблону, возвращает массив.
  • Не нужен шаблон — бери replace, contains. Точку в split экранируй.
