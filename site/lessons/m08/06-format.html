Форматирование: printf, String.format и текстовые блоки

Склеивать текст плюсами — как писать письмо, вырезая буквы из газеты. Есть способ удобнее: шаблон с «дырками», куда Java сама подставит значения. Заодно научимся ровнять столбики и писать многострочный текст.

Сравни два способа напечатать одно и то же:

String name = "Аня";
int age = 17;
double avg = 4.5666;

System.out.println("Привет, " + name + "! Тебе " + age
        + " лет, средний балл " + avg);
System.out.printf("Привет, %s! Тебе %d лет, средний балл %.2f%n",
        name, age, avg);
Привет, Аня! Тебе 17 лет, средний балл 4.5666
Привет, Аня! Тебе 17 лет, средний балл 4,57

Метод printf (print formatted — «напечатать по шаблону») вызывают с несколькими аргументами: первый — шаблон, строка с метками %…, дальше — значения через запятую. Первую метку метод заменяет первым значением, вторую — вторым, и так далее.

Аналогия: бланк с пропусками

Помнишь бланки «Я, ________, проживающий по адресу ________»? Шаблон — это бланк, метки %s, %d — пропуски, а аргументы после шаблона — то, что вписывают. Причём на каждом пропуске написано, что туда можно вписать: текст, целое число, дробь.

МеткаЧто подставляетПример → результат
%sстроку (а вообще — что угодно, превратив в текст)"%s", "кот" → кот
%dцелое число (int, long)"%d шт.", 5 → 5 шт.
%fдробное число (по умолчанию 6 знаков)"%f", 1.5 → 1,500000
%.2fдробное, ровно 2 знака после запятой, с округлением"%.2f", 4.5666 → 4,57
%cодин символ"%c", 'Ж' → Ж
%bboolean"%b", true → true

printf не переводит строку сам

Это print с шаблоном, а не println. Хочешь новую строку — ставь %n в конце шаблона. Забудешь — вывод следующего вызова приклеится к этому.

Запятая вместо точки: ловушка локали

Заметил, что выше напечаталось 4,57, а не 4.57? Это не ошибка. printf и String.format учитывают локаль — языковые настройки компьютера. На русской Windows дробная часть отделяется запятой, как принято в России. А вызов println(4.57) с литералом-аргументом всегда печатает точку.

Где это кусается

Твоя программа на русской Windows печатает «4,57», а на сервере (там обычно английская локаль) та же программа печатает «4.57». Проверка, которая ждёт одно, на другой машине не пройдёт. Поэтому задачи на сайте не проверяют вывод %.2f. А в реальном коде, где нужна именно точка, локаль передают явно — первым аргументом:

import java.util.Locale;
…
System.out.printf(Locale.US, "%.2f%n", 4.5666);   // 4.57 — везде одинаково
Как напечатается String.format("%.1f", 2.25)? А String.format("%.0f", 2.5)?

2,3 и 3 (на русской локали). Формат округляет «по-школьному»: пятёрка округляется вверх. Значение переменной при этом не меняется — метод возвращает новую строку, округляется только она.

Ширина и выравнивание: ровные столбики

Между % и буквой можно указать ширину — сколько символов минимум займёт значение. Не хватает — дополнится пробелами.

System.out.printf("%-10s%5d%10.2f%n", "Хлеб", 2, 45.5);
System.out.printf("%-10s%5d%10.2f%n", "Молоко", 1, 89.9);
System.out.printf("%-10s%5d%10.2f%n", "Сыр", 3, 312.0);
System.out.printf("%-15s%10.2f%n", "ИТОГО:", 1116.9);
Хлеб          2     45,50
Молоко        1     89,90
Сыр           3    312,00
ИТОГО:            1116,90
%-10s

Название — в поле из 10 символов, прижато влево (минус). Тексты обычно ровняют по левому краю.

%5d

Количество — 5 символов, прижато вправо. Числа ровняют по правому краю, чтобы разряды стояли друг под другом.

%10.2f

Цена — 10 символов, 2 знака после запятой, вправо.

Ещё пара полезных трюков: %05d дополняет нулями: 42 → 00042 (номера заказов, время «09:05» — "%02d:%02d"). Если значение длиннее ширины — оно не обрезается, столбик просто «поедет».

String.format — то же самое, но в переменную

printf сразу печатает. А String.format с теми же метками возвращает строку — ею можно инициализировать переменную, передать аргументом в метод, сравнить в тесте.

String time = String.format("%02d:%02d", 9, 5);          // "09:05"
String msg = String.format("Заказ №%05d на сумму %d руб.", 42, 1500);
// "Заказ №00042 на сумму 1500 руб."

// так собирают текст сообщения, чтобы показать или сохранить
String expected = String.format("Товаров в корзине: %d", 3);
// то же, короче (Java 15+)
String alt = "Товаров в корзине: %d".formatted(3);

Что бывает, если шаблон и значения не совпали

Компилятор шаблон не проверяет — шаблон для него обычный строковый литерал, и ошибка всплывёт только при запуске:

КодЧто будет
String.format("%d", 3.5)💥 IllegalFormatConversionException: %d — для целых, а аргумент типа double
String.format("%s и %s", "a")💥 MissingFormatArgumentException: меток две, аргумент один
String.format("%s", 3.5)"3.5" — %s принимает всё
String.format("%d", "5")💥 "5" — строка, а не число

IDEA подсвечивает несовпадение меток и аргументов жёлтым ещё до запуска. Видишь жёлтое в printf — наведи мышку и прочитай.

Текстовые блоки """ (Java 15+)

Многострочный текст плюсами и \n — мучение. Особенно JSON для запроса к серверу, где ещё и кавычки надо экранировать:

String json = "{\n" +
              "  \"login\": \"ivan\",\n" +
              "  \"age\": 25\n" +
              "}\n";

Текстовый блок (text block) — строковый литерал в тройных кавычках. Пишешь как есть: переводы строк сохраняются, обычные кавычки экранировать не нужно.

String json = """
        {
          "login": "%s",
          "age": %d
        }
        """.formatted("ivan", 25);
System.out.print(json);
{
  "login": "ivan",
  "age": 25
}
  • После открывающих """ обязательно новая строка — текст начинается со следующей.
  • Общий отступ слева Java убирает: ориентир — самая левая строка (или закрывающие """). Поэтому блок можно красиво отступить в коде, а в строке лишних пробелов не будет.
  • Если закрывающие """ на отдельной строке — в конце текста будет перевод строки. Поставишь их сразу после текста — не будет.
  • Это обычная String: у неё можно вызывать все методы — formatted, equals.
String t = """
        Строка 1
        Строка 2""";
System.out.println("[" + t + "]");
Что напечатает этот код? Сколько строк будет между квадратными скобками?

Две строки: [Строка 1 и Строка 2]. Перевод строки сразу после открывающих """ в текст не попадает, общий отступ убран, а после «Строка 2» перевода нет — закрывающие кавычки стоят вплотную.

Проверь себя

Мини-проект

Напиши наставнику: «Хочу напечатать таблицу умножения 1–9 ровными столбиками через printf. Дай подсказку, какую ширину выбрать, но код не пиши».

Коротко

  • printf(шаблон, аргументы…) печатает, String.format — возвращает строку. "шаблон".formatted(…) — короткая форма.
  • Метки: %s строка, %d целое, %.2f дробь с 2 знаками, %n перевод строки, %% знак процента.
  • Ширина: %5d вправо, %-10s влево, %05d с нулями.
  • Дроби форматируются по локали: на русской Windows — запятая. Нужна точка — Locale.US.
  • Неверный тип аргумента или нехватка аргументов — исключение при запуске.
  • Текстовый блок """…""" — многострочный текст без \n и экранирования кавычек (Java 15+).
