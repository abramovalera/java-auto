do-while, break и continue

Третий цикл, который сначала делает и только потом спрашивает. И два «пульта управления»: выйти из цикла досрочно и перейти к следующей итерации.

Повторение

do-while: сначала делай, потом спрашивай

while и for — осторожные: сначала проверяют условие, потом выполняют тело. Это циклы с предусловием (условие стоит перед телом). Иногда так неудобно. Например, программа просит ввести возраст и должна переспрашивать, пока не введут нормальное число. Спросить нужно хотя бы один раз — проверять ещё нечего.

Аналогия: суп и соль

Ты не решаешь, солить ли суп, пока его не попробовал. Сначала пробуешь (действие), потом думаешь: «Пресно? — посолю и попробую ещё». Хотя бы одна ложка будет всегда.

Scanner scanner = new Scanner(System.in);
int age;
do {
    System.out.print("Сколько тебе лет? ");
    age = scanner.nextInt();
} while (age <= 0);
System.out.println("Записал: " + age);
do { … }

«Делай» [ду]. Тело цикла выполняется сразу, без проверки.

while (age <= 0);

Условие — после тела, поэтому do-while называют циклом с постусловием. Условие true — выполняется ещё одна итерация. Обрати внимание на точку с запятой в конце: в do-while она обязательна.

int age;

Переменную age объявили до цикла, а значение ей присваивается в теле. Объяви её внутри do { } — условие while её бы уже не увидело: она живёт только внутри фигурных скобок. Подробно — в уроке 5.7.

Что напечатает: int i = 10; do { System.out.println(i); i++; } while (i < 5);?

10 — один раз. Тело цикла выполнилось до проверки условия, потом 11 < 5 оказалось ложью. С обычным while не напечаталось бы ничего.

break: нашёл — выходи

Ищешь ключи по карманам. Нашёл во втором — остальные проверять не станешь. В Java для этого есть инструкция break [брейк] («прервать»): выход из цикла — немедленно, не дожидаясь, пока условие станет ложным. Ты уже встречал break в switch из модуля 4 — там он выходил из switch, здесь — из цикла.

Задача: найти первое число от 1 до 100, которое делится на 7 и заканчивается на 3.

for (int i = 1; i <= 100; i++) {
    if (i % 7 == 0 && i % 10 == 3) {
        System.out.println("Нашёл: " + i);
        break;
    }
}
System.out.println("Поиск окончен");
Нашёл: 63
Поиск окончен

Без break цикл делал бы итерации до сотни впустую: ответ уже найден, а он всё крутится. А если бы подходящих чисел было несколько, напечатал бы все, хотя нужно только первое. С break — первое найденное, и сразу на выход. Остаток % 10 — это последняя цифра числа; этот трюк станет главным героем урока 5.6.

В реальных программах

Классика — «повторить попытку»: связь с сервером иногда пропадает, поэтому приложение банка пробует отправить платёж до 5 раз и выходит из цикла через break, как только получилось. Похожий цикл крутится в любом мессенджере: он раз за разом спрашивает сервер, пока не придёт новое сообщение.

continue: переходи к следующей итерации

На конвейере рабочий видит бракованную деталь, откладывает её — и сразу берёт следующую. Конвейер не останавливается. Это инструкция continue [континью] («продолжай»): переход к следующей итерации — остаток тела пропускается, цикл продолжается.

for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) {
        continue;            // кратные 3 пропускаем
    }
    System.out.print(i + " ");
}
1 2 4 5 7 8 10

В for после continue программа прыгает на шаг (i++), а потом на условие. Разницу между break и continue проще всего увидеть по шагам:

Ловушка: continue в while

В while шаг написан в теле цикла. Если continue стоит выше шага, шаг пропускается — и цикл зависает:

int i = 0;
while (i < 10) {
    if (i % 3 == 0) {
        continue;      // i++ ниже не выполнится!
    }
    System.out.println(i);
    i++;
}

При i = 0 срабатывает continue, i так и остаётся нулём — бесконечный цикл. В for такого нет: там continue ведёт прямо на шаг.

Коварство в том, что такой цикл ничего не печатает. В панели Run пусто, и кажется, будто программа просто долго думает:

while (true) + break: «пока не скажут стоп»

Иногда условие выхода удобнее проверить в середине тела. Тогда пишут «вечный» цикл с условием-литералом true и выходят из него через break. Пример: пользователь вводит числа, ноль означает «хватит».

Scanner scanner = new Scanner(System.in);
int sum = 0;
while (true) {
    int x = scanner.nextInt();
    if (x == 0) {
        break;
    }
    sum += x;
}
System.out.println("Сумма: " + sum);

Ноль здесь — стоп-сигнал: само число в сумму не идёт, оно только говорит «конец». Такой приём встречается часто: «введи пустую строку, чтобы закончить», «нажми q для выхода».

Что будет, если убрать break из этой программы?

Программа даже не скомпилируется! Из while (true) без break выйти нельзя, и компилятор это видит: строка с итоговой суммой после цикла не выполнится никогда. Такой код Java считает ошибкой — недостижимый код:

А если бы после цикла ничего не было, программа скомпилировалась бы — и стала по-настоящему бесконечной: даже после нуля ждала бы новых чисел, а выйти можно было бы только кнопкой Stop. Вывод: у while (true) обязательно должен быть путь к break.

Коротко

  • do { … } while (условие); — цикл с постусловием: сначала тело, потом проверка. Тело выполнится хотя бы раз. Точка с запятой в конце обязательна.
  • break — немедленный выход из цикла. «Нашёл — выходи».
  • continue — переход к следующей итерации: остаток тела пропускается. В while следи, чтобы он не перепрыгнул шаг.
  • while (true) + break — цикл с выходом из середины, например по стоп-сигналу 0.
  • Число итераций известно — for; «пока не случится» — while; «хотя бы раз» — do-while.
