Ошибка на единицу (off-by-one)

Самая частая ошибка в циклах во всём мире. У неё даже есть имя: off-by-one [оф-бай-уан] — «промах на единицу». Цикл делает на одну итерацию больше или меньше, чем нужно.

Задачка про забор

Забор длиной 5 метров, столбы ставят через каждый метр. Сколько нужно столбов? Хочется сказать «5», но правильно — 6: пролётов 5, а столбов на один больше. Программисты так и называют эту ошибку — «ошибка заборного столба».

В коде это выглядит так. Задача — напечатать числа от 1 до 10:

for (int i = 1; i < 10; i++) {     // ❌ последнее — 9
    System.out.print(i + " ");
}
for (int i = 0; i <= 10; i++) {    // ❌ лишний 0 в начале
    System.out.print(i + " ");
}
for (int i = 1; i <= 10; i++) {    // ✅ ровно 1…10
    System.out.print(i + " ");
}
Как не промахнуться

Проверь крайние итерации: какое значение будет у счётчика на первой и на последней? Подставь последнее в условие: при i = 10 выполнится ли i < 10? Нет — значит, 10 не напечатается. Количество итераций для i от a до b включительно с шагом 1 — это b − a + 1.

Сколько звёздочек напечатает for (int i = 5; i >= 0; i--) System.out.print("*");?

6: i = 5, 4, 3, 2, 1, 0. По формуле: 5 − 0 + 1 = 6. Знак >= пропускает и ноль.

Бесконечный цикл: четыре лица

В уроке 5.1 ты видел самую простую причину — забыли шаг. Но у вечного цикла есть и другие маски:

// 1. Шаг уводит от границы
for (int i = 10; i > 0; i++) { … }      // i растёт, а условие ждёт убывания
// 2. continue перепрыгнул шаг (урок 5.3)
int i = 0;
while (i < 10) {
    if (i % 2 == 0) continue;
    i++;
}
// 3. Шагнули мимо: условие через !=
for (int i = 1; i != 10; i += 2) { … }  // 1, 3, 5, 7, 9, 11… — мимо 10
// 4. Коварная точка с запятой
int i = 0;
while (i < 5); {
    i++;
}

Четвёртый — самый подлый. Точка с запятой сразу после заголовка while (…) — это пустое тело цикла. Java читает код так: «пока i < 5 — ничего не делай». i не меняется, цикл крутится вечно, а блок { i++; } ниже — просто отдельный блок кода, до которого программа никогда не дойдёт.

IDEA иногда подсвечивает такие места жёлтым и пишет предупреждение. Не игнорируй жёлтое! Наведи мышку и прочитай — это бесплатная подсказка.

Что напечатает for (int k = 0; k < 3; k++); { System.out.println("Hi"); }?

Hi — один раз. Точка с запятой снова дала пустое тело: цикл сделал три итерации, ничего не выполнив. Потом выполнился блок с вызовом println — как обычный код после цикла. Программа не зависла, но работает не так, как задумано: это логическая ошибка, компилятор её не заметит.

Правило безопасности

Для счётчиков цикла пиши условие через <, <=, >, >=, а не через !=: «перешагнуть» границу неравенства невозможно. И помни, как останавливать зависшую программу: красный квадрат Stop или Ctrl+F2.

Переменная живёт в своих скобках

Задача: сумма чисел от 1 до 3. Найди проблему, прежде чем читать дальше:

for (int i = 1; i <= 3; i++) {
    int sum = 0;
    sum += i;
}
System.out.println(sum);
ScopeBug.java:5: error: cannot find symbol
        System.out.println(sum);
                           ^
  symbol:   variable sum

Это текст javac — его покажет проверка на сайте. А IDEA подчеркнёт проблему ещё до запуска:

Ошибок тут сразу две, и обе из-за области видимости — участка кода, где переменная существует. Правило Java простое: переменная живёт от объявления до закрывающей скобки } блока, в котором её объявили.

  1. Не видна снаружи. sum объявлена внутри тела цикла — после } её область видимости кончилась. Компилятор честно говорит: cannot find symbol — «не знаю такого имени».
  2. Рождается заново на каждой итерации. Даже если бы печать была внутри цикла, на каждой итерации выполнялось бы объявление с инициализацией int sum = 0 — накопитель обнулялся бы, и сумма никогда не накопилась бы.
Аналогия: гостиничный номер

Тело цикла — номер в отеле, а каждая итерация — новые сутки. Каждое утро номер убирают: всё, что ты в нём оставил (переменные из тела), исчезает. Хочешь что-то копить между сутками — держи это в своей сумке, то есть объявляй до цикла.

Исправленная версия — накопитель объявлен и инициализирован до цикла:

int sum = 0;
for (int i = 1; i <= 3; i++) {
    sum += i;
}
System.out.println(sum);   // 6
Иногда «внутри» — как раз правильно

Нужна сумма каждой строки таблицы отдельно? Тогда накопитель строки объявляют внутри внешнего цикла: на каждой новой строке он честно обнуляется. Правило выбора: «как долго должно жить значение?» Всю программу — объявляй до цикла. Одну итерацию — в теле цикла.

for (int row = 1; row <= 3; row++) {
    int rowSum = 0;                    // новая сумма для каждой строки
    for (int col = 1; col <= 4; col++) {
        rowSum += row * col;
    }
    System.out.println("Строка " + row + ": " + rowSum);
}
Скомпилируется ли for (int i = 0; i < 3; i++) { } System.out.println(i);?

Нет: i объявлена в заголовке for и живёт только внутри цикла. Если значение счётчика нужно после цикла, его объявляют заранее, а в заголовке только присваивают начальное значение: int i; for (i = 0; i < 3; i++) { } — тогда после цикла i равно 3.

Отладчик IDEA: трассировщик по-настоящему

Трассировщик на сайте показывал переменные по шагам. В IntelliJ IDEA есть то же самое для твоей настоящей программы — отладчик (debugger [дибáггер], от bug — «жучок», ошибка). Когда цикл ведёт себя странно, не гадай — посмотри.

  1. Поставь точку останова. Щёлкни по серому полю слева от номера строки внутри цикла — появится красный кружок (breakpoint [брейкпойнт]). Здесь программа остановится.
  2. Запусти в режиме отладки. Вместо зелёного ▶ нажми на кнопку с жучком 🐞 Debug (или Shift+F9). Программа дойдёт до точки и замрёт, строка подсветится.
  3. Смотри переменные. Внизу откроется панель Debug: в окне Variables видны все переменные и их текущие значения — как таблица в трассировщике. IDEA ещё и пишет значения серым прямо рядом с кодом.
  4. Шагай. F8 (Step Over) — выполнить одну строку. Жми и следи, как меняются i и накопитель. F9 (Resume) — бежать до следующей остановки, то есть до следующей итерации.
  5. Останови отладку красным квадратом, когда всё понял.

Проверь себя: охота на баги

Поговори с наставником

Напиши: «Покажи мне 3 цикла с ошибками — off-by-one, вечный цикл и область видимости — вперемешку. Я найду ошибку и объясню, почему так получилось».

Коротко

  • Off-by-one: лишняя или недостающая итерация. Проверяй первое и последнее значение счётчика; от a до b включительно — b − a + 1 итераций.
  • Вечный цикл: нет шага, шаг не туда, continue перед шагом, != вместо <, ; после заголовка while (…).
  • Область видимости: переменная живёт до } своего блока. То, что копится между итерациями, объявляй до цикла.
  • Отладчик: точка останова, Debug 🐞, F8 — шаг, F9 — дальше, окно Variables — значения.
