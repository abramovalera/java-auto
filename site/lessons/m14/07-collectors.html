Collectors: склеить, сгруппировать, посчитать

Список — не единственное, во что можно собрать стрим. Строка через запятую, Map «оценка → студенты», «сдали/не сдали», «слово → сколько раз» — всё это делает одна операция collect с нужным коллектором.

Повторение

collect и «упаковщики» Collectors

Ты уже встречал collect(Collectors.toList()) в уроке 14.5. Терминальная операция collect(…) говорит: «собери всё, что доехало». А как собрать — решает коллектор: объект-«упаковщик», который ты передаёшь в collect аргументом. Готовые коллекторы возвращают статические методы класса Collectors (import java.util.stream.Collectors;).

КоллекторЧто получитсяПример результата
toList()список[Аня, Вика]
toSet()множество без повторов[Аня, Вика]
joining(", ")одна строка"Аня, Вика"
groupingBy(ключ)Map<ключ, List<…>>{4=[Борис], 5=[Аня, Вика]}
groupingBy(ключ, counting())Map<ключ, Long>{4=1, 5=2}
partitioningBy(условие)Map<Boolean, List<…>>{false=[…], true=[…]}
toMap(ключ, значение)Map<K, V>{Чай=200, Кофе=350}
Аналогия: склад и упаковщики

Конвейер привёз на склад товары. Дальше зависит от упаковщика: один сложит всё в одну коробку (toList), другой нанижет на нитку, как бусы (joining), третий разложит по полкам с табличками (groupingBy), четвёртый — на две полки «годные/брак» (partitioningBy).

joining: бусы из строк

List<String> missing = List.of("Хлеб", "Молоко", "Сыр");

// ХлебМолокоСыр
String a = missing.stream().collect(Collectors.joining());
// Хлеб, Молоко, Сыр
String b = missing.stream().collect(Collectors.joining(", "));
// [Хлеб, Молоко, Сыр]
String c = missing.stream().collect(Collectors.joining(", ", "[", "]"));

System.out.println("Не хватает: " + b);
  • Один аргумент — разделитель: ставится только между элементами, не после последнего. Вручную в цикле с этим вечно мучаешься.
  • Три аргумента — разделитель, начало и конец строки.
  • joining работает только со строками. Числа сначала превращай промежуточной операцией .map(String::valueOf).
Что даст Stream.of(1, 2, 3).map(String::valueOf).collect(Collectors.joining(" + "))?

Строку 1 + 2 + 3. Разделитель « + » стоит только между элементами.

groupingBy: разложить по полкам

Классика: разбить студентов по оценкам. groupingBy принимает аргументом Function (лямбду или ссылку на метод) — «как вычислить ключ (табличку полки)» для каждого элемента. Элементы с одинаковым ключом попадают в один список.

record Student(String name, int grade) { }

List<Student> students = List.of(
        new Student("Аня", 5), new Student("Борис", 4), new Student("Вика", 5),
        new Student("Гоша", 3), new Student("Дима", 4));

Map<Integer, List<Student>> byGrade = students.stream()
        .collect(Collectors.groupingBy(Student::grade));

System.out.println(byGrade.get(5));
// [Student[name=Аня, grade=5], Student[name=Вика, grade=5]]

У groupingBy есть второй аргумент — что делать внутри каждой полки (его называют downstream-коллектор, «коллектор ниже по течению»). Самые полезные:

Map<Integer, Long> countByGrade = students.stream()
        .collect(Collectors.groupingBy(Student::grade, Collectors.counting()));
System.out.println(countByGrade);   // {3=1, 4=2, 5=2}

Map<Integer, List<String>> namesByGrade = students.stream()
        .collect(Collectors.groupingBy(Student::grade,
                Collectors.mapping(Student::name, Collectors.toList())));
// {3=[Гоша], 4=[Борис, Дима], 5=[Аня, Вика]}
System.out.println(namesByGrade);
Collectors.counting()

Вместо списка на полке — количество элементов. Тип значения — Long.

Collectors.mapping(Student::name, …)

Перед тем как положить на полку, превратить студента в имя — ссылкой на метод Student::name. Это map, но внутри группы.

Порядок ключей: просим TreeMap

groupingBy по умолчанию кладёт результат в HashMap, а он не обещает порядок ключей. С маленькими числами порядок обычно выходит «удачный», а со строками — какой придётся. Для отчёта или для проверки вывода в задачах нужен предсказуемый порядок. Решение — третий вариант groupingBy: «ключ, какую Map создать, что делать в группе».

String text = "to be or not to be";

Map<String, Long> freq = Arrays.stream(text.split(" "))
        .collect(Collectors.groupingBy(
                w -> w,                    // ключ — само слово
                TreeMap::new,              // Map с ключами по алфавиту
                Collectors.counting()));   // на полке — количество

freq.forEach((word, n) -> System.out.println(word + ": " + n));

Посмотри на лямбду-ключ w -> w: она возвращает свой же параметр, то есть «ключом будет сам элемент». Так считают частоту чего угодно — слов, символов, статусов ответов сервера. Вместо этой лямбды можно передать готовую — её возвращает статический метод Function.identity().

Подсчёт слов «по-взрослому»

В настоящем тексте есть заглавные буквы и знаки препинания. Перед группировкой их обычно приводят к одному виду: .map(String::toLowerCase) и разбивают по "\\s+". Иначе «Кот» и «кот» окажутся на разных полках.

partitioningBy: две полки «да» и «нет»

Если ключ — это просто true/false, бери partitioningBy. Он принимает аргументом Predicate и всегда создаёт обе полки — даже если одна пустая.

record ExamResult(String student, boolean passed) { }

List<ExamResult> exam = List.of(
        new ExamResult("Аня", true), new ExamResult("Борис", false),
        new ExamResult("Вика", true), new ExamResult("Гоша", false));

Map<Boolean, List<String>> report = exam.stream()
        .collect(Collectors.partitioningBy(ExamResult::passed,
                Collectors.mapping(ExamResult::student, Collectors.toList())));

System.out.println("Сдали: " + report.get(true));
System.out.println("Не сдали: " + report.get(false));
Сдали: [Аня, Вика]
Не сдали: [Борис, Гоша]
Экзамен сдали все. Что вернёт report.get(false) — null или []?

[] — пустой список. partitioningBy всегда создаёт обе полки. А вот у groupingBy полки для отсутствующего ключа нет — там get вернул бы null.

toMap: ключ → значение

Когда у каждого элемента свой уникальный ключ, Map собирают через toMap: ему передают два аргумента-функции (обычно ссылки на методы) — «как получить ключ» и «как получить значение».

record Product(String title, int price) { }

List<Product> catalog = List.of(
        new Product("Чай", 200),
        new Product("Кофе", 350));

Map<String, Integer> priceByTitle = catalog.stream()
        .collect(Collectors.toMap(Product::title, Product::price));

System.out.println(priceByTitle.get("Кофе"));   // 350
Одинаковые ключи → исключение

Если два элемента дадут один и тот же ключ, toMap выбросит исключение: IllegalStateException: Duplicate key Чай. Он не знает, какое значение оставить. Подскажи третьим аргументом — как объединить: toMap(Product::title, Product::price, (old, now) -> old + now) сложит цены одинаковых товаров. Или подумай, не нужен ли тут groupingBy.

Так это выглядит в консоли. Стек получился длинный — стримы внутри устроены многослойно. Не пугайся: читаешь первую строку и ищешь свой файл.

Поговори с наставником

Напиши: «Урок 14.7. Дай мне список record-ов, а я сгруппирую его тремя разными способами: groupingBy, groupingBy + counting и partitioningBy — и объясню, где какой нужен».

Коротко

  • collect(коллектор) — собрать результат; готовые коллекторы — в Collectors.
  • joining(разделитель[, начало, конец]) — склеить строки.
  • groupingBy(ключ) → Map<K, List<T>>; второй аргумент — что делать в группе: counting(), mapping(…).
  • Нужен порядок ключей — groupingBy(ключ, TreeMap::new, коллектор).
  • partitioningBy(условие) — две полки true/false; toMap(ключ, значение) — выбрасывает исключение на одинаковых ключах без функции слияния.
