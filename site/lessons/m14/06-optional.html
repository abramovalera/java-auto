Optional: коробка, в которой может быть пусто

NullPointerException — самое частое исключение в Java. Optional — способ прямо в типе сказать: «результата может не быть, проверь». Научимся открывать эту коробку правильно.

⏱ 20 минут📦 Optional🧩 2 проверки

Повторение

Чем плох null

Представь метод из программы интернет-магазина: найти пользователя по email. А если такого нет? Раньше возвращали null:

static String findUserName(String email) {
    if (email.equals("anna@mail.ru")) {
        return "Анна";
    }
    return null;                         // не нашли — молча вернули «ничего»
}

String name = findUserName("boris@mail.ru");
System.out.println(name.toUpperCase());  // 💥 NullPointerException

Беда не в том, что пользователя нет, — это нормальная ситуация. Беда в том, что по типу String этого не видно. Тот, кто вызывает метод, легко забудет проверить на null, и программа упадёт где-то далеко от места, где всё началось.

Optional<T> — это класс-обёртка: объект Optional («коробка») либо содержит один объект типа T, либо пуст. Если метод возвращает Optional<String>, сам тип возвращаемого значения кричит: «тут может быть пусто — разберись».

Как создать Optional

Optional<String> full = Optional.of("Анна");          // точно не null
Optional<String> empty = Optional.empty();            // точно пусто
// name может быть null — тогда будет пусто
Optional<String> maybe = Optional.ofNullable(name);
Optional.of(x)
Вызов статического метода of с аргументом x возвращает коробку с x. Если x окажется null — метод сразу выбросит NullPointerException. Бери, когда уверен, что значение есть.
Optional.empty()
Возвращает пустой Optional — пустую коробку.
Optional.ofNullable(x)
«Мост» из старого мира: если аргумент x — null, метод возвращает пустую коробку, иначе — коробку с x.

Перепишем поиск пользователя:

static Optional<String> findUserName(String email) {
    if (email.equals("anna@mail.ru")) {
        return Optional.of("Анна");
    }
    return Optional.empty();
}

Но чаще всего Optional ты не создаёшь руками, а получаешь как возвращаемое значение терминальных операций стрима: findFirst(), min, max.

Optional<String> anna = findUserName("anna@mail.ru");

System.out.println(anna.orElse("гость"));     // Анна
System.out.println(nobody.orElse("гость"));   // гость

// напечатает: Пользователь не найден
nobody.ifPresentOrElse(
        n -> System.out.println("Привет, " + n),
        () -> System.out.println("Пользователь не найден"));

if (anna.isPresent()) {
    System.out.println("Есть такой пользователь");
}

Склад: «найди товар или сообщи понятную ошибку»

Иногда пустой результат означает ошибку в данных: товар обязан быть в каталоге. Тогда не нужно запасное значение — нужно сразу выбросить исключение и написать в его сообщении, что именно не нашлось:

record Product(String title, boolean inStock) { }

List<Product> products = List.of(
        new Product("Чайник", true),
        new Product("Тостер", false));

Product toaster = products.stream()
        .filter(p -> p.title().equals("Тостер"))
        .findFirst()
        .orElseThrow(() -> new IllegalStateException(
                "Товар «Тостер» не найден в каталоге"));

System.out.println(toaster.inStock());   // false — в каталоге есть, но закончился

Сравни с null: там программа упала бы где-то дальше с безликим NPE. А тут сообщение сразу говорит, что сломалось. Хорошая программа падает понятно.

map и filter — прямо в коробке

Optional похож на маленький стрим из нуля или одного элемента. У него тоже есть методы map и filter: им передают аргументом лямбда-выражение, они работают с содержимым, если оно есть, и ничего не делают с пустой коробкой.

record Student(String name, int score) { }

List<Student> group = List.of(
        new Student("Аня", 72),
        new Student("Борис", 91),
        new Student("Вика", 95));

String first = group.stream()
        .filter(s -> s.score() > 90)
        .findFirst()           // Optional[Student[name=Борис, score=91]]
        .map(Student::name)    // Optional[Борис]
        .orElse("Не найден");  // "Борис"

String none = group.stream()
        .filter(s -> s.score() > 100)
        .findFirst()           // Optional.empty
        .map(Student::name)    // Optional.empty — map пропущен
        .orElse("Не найден");  // "Не найден"
Аналогия: курьер и пустая коробка

map — сотрудник, который «открывает коробку, перекладывает содержимое в новую упаковку и закрывает». Если коробка пустая, он ничего не делает и передаёт дальше пустую. В конце orElse — получатель: «если пусто — дайте мне вот это».

Что вернёт Optional.of(" ").filter(s -> !s.isBlank()).orElse("пусто")?

"пусто". В коробке была строка из пробелов, filter её не пропустил и вернул пустую коробку — orElse вернул запасное значение.

Как не надо

❌ get() без проверки

Вызов opt.get() возвращает значение, а если пусто — выбрасывает NoSuchElementException: No value present. Это тот же NPE, только в профиль. Вместо get() бери orElse, orElseThrow, map. (В новых версиях Java orElseThrow() без аргументов делает то же, что get(), но по имени честно предупреждает: «может выбросить исключение».)

Optional<String> nobody = Optional.empty();

nobody.get();                          // ❌ NoSuchElementException
if (nobody.isPresent()) {              // 🤔 работает, но это тот же if != null,
    System.out.println(nobody.get());  //    только длиннее
}
nobody.ifPresent(System.out::println); // ✅ коротко и безопасно

// ❌ NullPointerException — для null есть ofNullable
Optional<String> x = Optional.of(null);
// ❌ сам Optional не должен быть null — проверяй isEmpty()
if (nobody == null) { … }

Голый get() IDEA ловит сама — подсвечивает жёлтым. Вот предупреждение и то, что будет, если его проигнорировать:

  • Optional — для возвращаемых значений. Не объявляй поля и параметры методов типа Optional — так не принято, это усложняет код.
  • Не заворачивай коллекции. Вместо Optional<List<…>> возвращай пустой список.
Ловушка с собеседования: что напечатает Optional.of("A").orElse(make()), если make() печатает «make» и возвращает «B»?

Сначала make, потом A. Аргумент orElse вычисляется всегда — до вызова метода, как у любого метода Java. Значение «B» просто выбрасывается. А orElseGet(() -> make()) вызовет make() только для пустой коробки. Если запасное значение дорогое (запрос к базе, чтение большого файла) — бери orElseGet.

Проверь себя

Поговори с наставником

Напиши: «Урок 14.6. Объясню своими словами, зачем нужен Optional и почему get() без проверки — плохо. А потом дай мне метод, который возвращает null, — я перепишу его на Optional».

Коротко

  • Optional<T> — объект-обёртка («коробка»): либо один объект, либо пусто. Тип возвращаемого значения сам предупреждает «может не быть».
  • Создать: Optional.of, Optional.empty(), Optional.ofNullable. Чаще — получить из findFirst, min, max.
  • Открыть: orElse, orElseGet, orElseThrow, ifPresent, ifPresentOrElse; преобразовать: map, filter.
  • Не надо: get() без проверки, Optional.of(null), Optional в полях и параметрах.
  • orElse вычисляет аргумент всегда, orElseGet — только для пустой коробки.
