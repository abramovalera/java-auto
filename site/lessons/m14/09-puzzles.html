🔎 map и flatMap: «список списков» в один поток

map превращает каждый элемент ровно в один. А если каждый элемент сам содержит несколько — например, у каждого заказа список товаров? Тогда map даст «поток списков», а нужен поток товаров. Для этого есть промежуточная операция flatMap: её лямбда возвращает для каждого элемента стрим, а flatMap «расплющивает» все стримы в один.

List<List<Integer>> orders = List.of(List.of(1, 2), List.of(3));

// [2, 1]
System.out.println(orders.stream().map(List::size).toList());
// [1, 2, 3]
System.out.println(orders.stream().flatMap(List::stream).toList());

Классический пример — все слова из нескольких строк: lines.stream().flatMap(l -> Arrays.stream(l.split(" "))). На собеседовании любят спросить: «чем map отличается от flatMap?» Ответ: map — один в один, flatMap — один во много (0, 1, 2…), и всё сливается в общий поток.

🔎 Подвох: Stream.of(new int[]{1, 2, 3}).count()

Ответ — 1, а не 3. Stream.of принимает аргументами объекты, а массив int[] — это один объект. Получается стрим из одного элемента-массива. Для примитивного массива нужен Arrays.stream(arr) или IntStream.of(1, 2, 3). С Integer[] такой проблемы нет: Stream.of(new Integer[]{1, 2, 3}) даст три элемента.

🔎 Параллельные стримы: parallelStream()

Если вместо stream() написать parallelStream(), Java разобьёт данные на части и обработает их на нескольких ядрах процессора одновременно. Звучит как бесплатное ускорение, но:

  • на маленьких списках (а в учебных задачах они почти всегда маленькие) параллельный стрим медленнее: на разделение и сборку уходит больше времени, чем на работу;
  • forEach в параллельном стриме печатает в непредсказуемом порядке — для порядка есть forEachOrdered;
  • лямбды, которые меняют общие данные (например, добавляют в один ArrayList), в параллельном стриме ломаются — это тема многопоточности (модуль 16).

Правило: пиши обычные stream(). Параллельные — только когда данных очень много, операции независимы и ты измерил, что стало быстрее.

Читаем код

Теперь не «что выведется», а «что здесь написано». Прочитай каждую строку вслух правильными словами: лямбда-выражение, параметр и тело лямбды, ссылка на метод, промежуточная и терминальная операция, Optional. В одних заданиях выбери описание из пяти, в других собери его из квадратиков — лишние оставь на месте.

Напиши: «Дай мне ещё 5 головоломок по стримам: что выведется, скомпилируется ли, что при запуске. По одной, с разбором после моего ответа». У наставника в запасе банк из двадцати с лишним задачек по этому модулю.

Коротко

  • Без терминальной операции конвейер ничего не делает.
  • Элементы идут по одному через всю цепочку; limit/findFirst/anyMatch обрывают конвейер, sorted ждёт все элементы.
  • Поток одноразовый; toList() неизменяемый; toMap выбрасывает исключение на одинаковых ключах.
  • Optional.get() на пустом — NoSuchElementException; аргумент orElse вычисляется всегда.
  • В теле лямбды — только effectively final локальные переменные снаружи; count() — это long.
