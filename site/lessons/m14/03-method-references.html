Ссылки на методы: ::

Иногда лямбда ничего не придумывает сама, а просто вызывает готовый метод. Тогда её можно сжать ещё сильнее — до имени этого метода через два двоеточия.

Повторение

Лямбда-«передатчик»

Посмотри на эти лямбды. Что у них общего?

names.forEach(n -> System.out.println(n));
Function<String, Integer> parse = s -> Integer.parseInt(s);
Function<String, String> upper = s -> s.toUpperCase();

Каждая только передаёт свой параметр аргументом в вызов уже существующего метода — и больше ничего не делает. Для таких лямбд есть короткая запись — ссылка на метод (method reference): Где::какойМетод. Это имя готового метода, которое передают вместо лямбда-выражения.

names.forEach(System.out::println);
Function<String, Integer> parse = Integer::parseInt;
Function<String, String> upper = String::toUpperCase;
Аналогия: «Переключаю на специалиста»

Звонишь в поддержку, а оператор говорит: «Соединяю с бухгалтерией» — и всё, сам ничего не решает. Такой оператор и есть лямбда-передатчик. Проще сразу дать номер бухгалтерии: Бухгалтерия::ответить.

Важно: ссылка на метод не вызывает метод прямо сейчас — после имени нет скобок. Это «адрес» метода, который вызовут потом, когда понадобится, — точно как с лямбдой.

Скомпилируется ли names.forEach(System.out::println());?

Нет. Скобки после имени в ссылке на метод не пишут: System.out::println. Со скобками это выглядело бы как вызов метода, а :: так не работает.

Четыре вида ссылок

Слева от :: может стоять класс, конкретный объект или даже new. От этого зависит, куда пойдут параметры лямбды:

ВидЗаписьКуда идёт параметр лямбды
① статический методInteger::parseInt, Math::absв аргументы метода: Integer.parseInt(s)
② метод конкретного объектаSystem.out::printlnв аргументы метода этого объекта: System.out.println(x)
③ метод «любого объекта» типаString::length, Student::nameпараметр сам становится объектом, у которого вызывают метод: s.length(), st.name()
④ конструкторArrayList::newв конструктор: new ArrayList<>()

Вид ③ — самый хитрый и самый частый. String::length выглядит как вызов статического метода, но length не статический! Java понимает так: «возьми пришедшую строку и вызови у неё length()». Именно поэтому для record-ов пишут Student::name — это «у каждого студента спроси имя».

Где это в настоящих программах

Ссылки на методы делают цепочки вызовов читаемыми почти как обычный текст. Вот как может выглядеть обработка корзины интернет-магазина:

record CartItem(String title, int price) { }

List<CartItem> cart = new ArrayList<>(List.of(
        new CartItem("Монитор", 20000),
        new CartItem("Мышь", 1500),
        new CartItem("Коврик", 300)));

cart.sort(Comparator.comparing(CartItem::price));   // по цене
cart.forEach(System.out::println);                   // печать каждого
CartItem[title=Коврик, price=300]
CartItem[title=Мышь, price=1500]
CartItem[title=Монитор, price=20000]

Заметь: System.out::println печатает record целиком — через его автоматический toString() из модуля 11.

Какой тип подойдёт для CartItem::title?

Function<CartItem, String>: параметр — товар, возвращаемое значение — его название. Это вид ③ — параметр сам становится объектом, у которого вызывают title().

Сортировка по двум полям — одной строкой

Вернёмся к студентам из урока 14.2 — дописывай в тот же файл SortStudents.java, новый record Student не объявляй. Там мы сортировали «по баллу от большего, при равенстве — по имени» через переменную byScore. Со ссылками на методы это одна цепочка вызовов:

students.sort(Comparator.comparing(Student::score).reversed()
        .thenComparing(Student::name));

students.forEach(s -> System.out.println(s.name() + " " + s.score()));
Борис 90
Вика 90
Аня 75
Comparator.comparing(Student::score)

Вызов статического метода comparing с аргументом — ссылкой на метод Student::score (вид ③: «у каждого студента спроси балл»). Возвращает компаратор «по баллу, по возрастанию».

.reversed()

Возвращает новый компаратор — по убыванию.

.thenComparing(Student::name)

Второй судья: при равных баллах — по имени.

Ловушка: comparing(лямбда).reversed()

Почему не написать то же самое лямбдой, без переменной? Comparator.comparing(s -> s.score()).reversed() не скомпилируется: cannot find symbol: method score(). Компилятор выводит тип параметра лямбды из того, что от неё ждут. Но здесь результат comparing сразу уходит в .reversed(), и подсказки «это студенты» у компилятора нет — он считает s просто Object. В уроке 14.2 подсказкой был тип переменной Comparator<Student> byScore. Лечится ссылкой на метод Student::score (в ней класс назван явно) или явным типом параметра (Student s) -> s.score().

Скомпилируется ли students.sort(Comparator.comparing((Student s) -> s.score()).reversed());?

Да. Тип параметра указан явно — компилятору больше нечего выводить, s точно студент.

Когда ссылку не сделать

Правило: ссылка на метод возможна, если лямбда только передаёт свои параметры в один метод — в том же порядке, ничего не добавляя. Если она что-то делает сама, нужна обычная лямбда:

ЛямбдаМожно ссылкой?Почему
s -> s.trim()✅ String::trimтолько вызывает метод у параметра
s -> s.substring(1)❌добавляет своё число 1
x -> x * 2❌это оператор, а не вызов метода
s -> "Привет, " + s❌склеивает сама
(a, b) -> a.compareTo(b)✅ String::compareToпервый параметр — объект, второй — аргумент
s -> System.out.println("> " + s)❌меняет аргумент перед передачей
IDEA подскажет сама

Если лямбду можно заменить ссылкой, IDEA подсветит её серым. Нажми Alt+Enter → Replace lambda with method reference. И наоборот: на ссылке Alt+Enter → Replace method reference with lambda — удобно, когда не понимаешь, что она делает.

Не увлекайся

Ссылка нужна для читаемости, а не ради краткости любой ценой. Если s -> s.getAddress().getCity() понятнее — оставь лямбду. Ссылкой это всё равно не записать: тут два вызова подряд.

Коротко

  • Ссылка на метод Класс::метод — сокращение лямбды, которая только передаёт параметры в один метод.
  • Четыре вида: статический (Integer::parseInt), метод объекта (System.out::println), метод параметра (String::length, Student::name), конструктор (ArrayList::new).
  • Скобок после имени нет: ссылка указывает на метод, а не вызывает его.
  • Лямбда что-то добавляет сама (число, склейку, оператор) — ссылкой её не заменить.
  • Сортировка по двум полям: Comparator.comparing(Student::score).reversed().thenComparing(Student::name). С лямбдой comparing(s -> s.score()).reversed() не скомпилируется — компилятор не узнает тип s.
  • Alt+Enter в IDEA переводит лямбду в ссылку и обратно.
