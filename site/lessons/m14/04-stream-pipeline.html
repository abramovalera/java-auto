Stream API: конвейер для данных

Отфильтровать, преобразовать, отсортировать, взять первые три — раньше на это уходил цикл с кучей переменных. Стрим делает то же самое цепочкой из понятных шагов, которая читается как рецепт.

Повторение

Одна задача — два способа

Задача из интернет-магазина: есть товары из каталога. Нужны названия товаров в наличии дешевле 1000 ₽, по алфавиту. Сначала — как ты бы написал раньше, циклом:

record Product(String title, int price, boolean inStock) { }

List<Product> catalog = List.of(
        new Product("Чай", 200, true),
        new Product("Кофе", 900, true),
        new Product("Торт", 1500, true),
        new Product("Сок", 150, false),
        new Product("Вафли", 300, true));

List<String> result = new ArrayList<>();
for (Product p : catalog) {
    if (p.inStock() && p.price() < 1000) {
        result.add(p.title());
    }
}
Collections.sort(result);
System.out.println(result);

А теперь то же самое стримом:

List<String> result = catalog.stream()
        .filter(p -> p.inStock())
        .filter(p -> p.price() < 1000)
        .map(Product::title)
        .sorted()
        .toList();
System.out.println(result);

Прочитай стрим вслух: «возьми каталог, оставь те, что в наличии, оставь дешевле тысячи, возьми названия, отсортируй, собери в список». Это что нужно сделать. А цикл — это как: заведи список, пройди, проверь, добавь… Стрим описывает результат, а не процесс.

А правильными словами так: у списка catalog вызываем метод stream(), дальше идут промежуточные операции filter, filter, map, sorted, а терминальная операция toList() собирает результат в список — им инициализируется переменная result. Что значат эти слова, разберём в следующем шаге.

Три части конвейера

Stream (поток) — это не коллекция и не хранилище. Это конвейер, по которому элементы из источника едут один за другим через станки-операции. У любого стрима три части:

Источник
Откуда берутся элементы: список, массив, набор значений. Сам источник стрим не меняет.
Промежуточная операция
filter, map, sorted, distinct, limit, skip… Каждая возвращает новый Stream, поэтому их можно писать цепочкой вызовов через точку. Аргументом им обычно передают лямбда-выражение или ссылку на метод.
Терминальная операция
toList, count, forEach… Завершает конвейер и возвращает результат — уже не Stream. Она одна и всегда последняя.
Аналогия: завод по разливу сока

Яблоки (источник) едут по ленте. Сортировщик выбрасывает гнилые (filter), пресс делает из яблока сок (map), упаковщик разливает в коробки (терминальная операция). Пока упаковщик не пришёл на смену, лента стоит: никто не будет давить сок, который некуда налить.

Последняя строка пригодится в задачах: ввод с клавиатуры приходит одной строкой, а нужно поработать с каждым числом или словом.

Scanner sc = new Scanner(System.in);
String line = sc.nextLine();               // "  3 10   7 "

List<Integer> numbers = Arrays.stream(line.trim().split("\\s+"))
        .map(Integer::parseInt)
        .toList();
System.out.println(numbers);               // [3, 10, 7]
line.trim()

Вызов trim() возвращает новую строку без пробелов по краям. Без него split вернул бы в начале пустую строку, и вызов parseInt("") выбросил бы исключение.

.split("\\s+")

Вызов split возвращает массив кусков: режет по «одному или нескольким пробельным символам» — даже если между числами три пробела, лишних кусков не будет.

.map(Integer::parseInt)

Промежуточная операция map со ссылкой на метод Integer::parseInt: каждую строку-кусочек превращает в число.

Пустая строка

"".split("\\s+") возвращает не пустой массив, а массив из одной пустой строки [""]. Если ввод может быть пустым, добавь перед map промежуточную операцию filter с лямбда-выражением: .filter(s -> !s.isEmpty()).

Шесть главных промежуточных операций

List<Integer> nums = List.of(5, 3, 8, 3, 1, 9, 5);

// оставить подходящие: [5, 8, 9, 5]
nums.stream().filter(n -> n > 4).toList();
// превратить каждый: [50, 30, 80, 30, 10, 90, 50]
nums.stream().map(n -> n * 10).toList();
// по возрастанию: [1, 3, 3, 5, 5, 8, 9]
nums.stream().sorted().toList();
// по убыванию: [9, 8, 5, 5, 3, 3, 1]
nums.stream().sorted(Comparator.reverseOrder()).toList();
// без повторов: [5, 3, 8, 1, 9]
nums.stream().distinct().toList();
// первые 3: [5, 3, 8]
nums.stream().limit(3).toList();
// пропустить 5: [9, 5]
nums.stream().skip(5).toList();
ОперацияАргументЧто делает
filterPredicateпропускает только элементы, для которых условие true
mapFunctionпревращает каждый элемент в другой (можно в другой тип: товар → название)
sortedничего или Comparatorестественный порядок или по твоему правилу
distinct—убирает повторы (сравнивает через equals)
limit(n)числопропускает только первые n элементов
skip(n)числовыбрасывает первые n элементов

skip + limit = страница. Таблица на сайте магазина показывает по 10 строк; вторая страница — это skip(10).limit(10). Так программа и выбирает, какие записи показать на странице N.

Что даст Stream.of(3, 1, 3, 2, 1).distinct().sorted().toList()?

[1, 2, 3]. distinct оставит 3, 1, 2 (первые появления), sorted расставит по возрастанию.

А что даст IntStream.rangeClosed(1, 10).skip(2).limit(3), если собрать в список?

[3, 4, 5]. rangeClosed включает обе границы: 1…10. Пропускаем 1 и 2, берём три следующих.

Ленивость: конвейер работает по одному элементу

Две вещи, о которых спрашивают на собеседованиях:

  1. Пока нет терминальной операции, не происходит ничего. Промежуточные операции только описывают конвейер. Это называется ленивость (lazy evaluation).
  2. Элементы идут «вертикально»: первый элемент проходит все станки до конца, потом второй, потом третий. А не «сначала все через filter, потом все через map».

Пройди конвейер по шагам и угадывай, что происходит с каждым элементом:

Из «вертикальности» следует приятный бонус: limit, findFirst, anyMatch могут остановить конвейер раньше — остальные элементы даже не будут проверяться.

List<Integer> result = Stream.of(1, 2, 3, 4, 5)
        .peek(x -> System.out.println("взял " + x))  // «подглядеть», не меняя
        .filter(x -> x > 1)
        .limit(2)
        .toList();
System.out.println(result);
взял 1
взял 2
взял 3
[2, 3]

Элементы 4 и 5 не понадобились — конвейер их даже не взял. (peek — промежуточная операция для отладки, о ней подробнее в Мастерской.)

sorted — «стоп-кран»

Исключение из вертикального правила — sorted. Нельзя отдать первый по порядку элемент, пока не увидел все. Поэтому sorted сначала собирает все элементы, сортирует, а уже потом пускает их дальше по одному.

Что выведет Stream.of(1, 2, 3).peek(System.out::println).map(x -> x * 2); — и больше ничего?

Ничего. Терминальной операции нет — значит, конвейер не запускается и peek ни разу не вызывается. Это самая частая ловушка: «я написал map, почему ничего не произошло?»

Поток одноразовый и не трогает источник

Ещё два свойства, которые надо помнить:

List<String> names = new ArrayList<>(List.of("Вика", "Ян"));

List<String> upper = names.stream().map(String::toUpperCase).toList();
System.out.println(names);   // [Вика, Ян]   — источник не изменился
System.out.println(upper);   // [ВИКА, ЯН]   — результат — новый список

Stream<String> s = names.stream();
System.out.println(s.count());   // 2
System.out.println(s.count());   // 💥 IllegalStateException

Стрим — как билет на один проезд: прокомпостировал (вызвал терминальную операцию) — и он больше не действует. Нужно ещё раз — возьми новый: снова names.stream(). Поэтому стримом почти никогда не инициализируют переменную, а пишут цепочку вызовов от источника до результата.

Как записывать цепочку

Каждую операцию — на новой строке, точкой в начале. Так видно каждый шаг, и IDEA подскажет справа, какой тип у потока после каждой строки.

Коротко

  • Конвейер стрима = источник → промежуточные операции → одна терминальная операция.
  • Источники: list.stream(), Arrays.stream(arr), Stream.of(…), IntStream.range.
  • Промежуточные: filter, map, sorted, distinct, limit, skip — возвращают новый Stream.
  • Ленивость: без терминальной операции ничего не выполняется. Элементы едут по одному; limit может остановить конвейер раньше, sorted ждёт все элементы.
  • Поток одноразовый и не меняет источник.
