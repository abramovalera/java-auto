Мастерская: цикл или стрим?

Решим одну задачу двумя способами — по шаблону Мастерской. Увидишь, как каждая часть цикла превращается в операцию стрима, когда стрим понятнее, когда лучше цикл, и как отлаживать конвейер, если он врёт.

⏱ 25 минут🛠 Мастерская🔍 трассировка

Повторение

Шаг 1. Пойми задачу

В интернет-магазине накопились заказы за день:

record Order(String item, int price, boolean paid) { }

List<Order> orders = List.of(
        new Order("чайник", 1200, true),
        new Order("утюг", 3400, false),
        new Order("кружка", 800, true),
        new Order("пылесос", 5100, false),
        new Order("лампа", 900, false));

Задача: вывести строку Не оплачены: … — товары из неоплаченных заказов через запятую, от самого дорогого к самому дешёвому (о дорогих заказах напоминают первыми — они важнее всего). Если неоплаченных нет — Все заказы оплачены.

ВходВыход
пример вышеНе оплачены: пылесос, утюг, лампа
все paid = trueВсе заказы оплачены
пустой списокВсе заказы оплачены (неоплаченных нет)
один неоплаченныйНе оплачены: утюг — без запятой в конце!

Шаги 2–4. Руками, роли, псевдокод

Руками. Иду по списку и выписываю неоплаченные: утюг (3400), пылесос (5100), лампа (900). Расставляю по цене от большей: пылесос, утюг, лампа. Беру названия, пишу через запятую.

Что я делал? Три разных действия: отобрал, упорядочил, склеил. Запомни это — дальше пригодится.

Роли переменных для решения циклом:

  • order — шагающая: по очереди каждый заказ;
  • unpaid — накопитель: список неоплаченных;
  • sb — ещё один накопитель: строка ответа;
  • i — шагающая по отсортированному списку, нужна, чтобы не ставить запятую перед первым названием.

Псевдокод:

  1. для каждого заказа: если не оплачен — добавь в unpaid;
  2. отсортируй unpaid по цене, от большей к меньшей;
  3. если unpaid пуст — выведи «Все заказы оплачены» и закончи;
  4. для каждого в unpaid: если не первый — допиши «, »; допиши название;
  5. выведи «Не оплачены: » + строка.

Шаг 5. Код — двумя способами

Циклом — перевод псевдокода строка в строку:

List<Order> unpaid = new ArrayList<>();
for (Order order : orders) {
    if (!order.paid()) {
        unpaid.add(order);
    }
}
unpaid.sort(Comparator.comparingInt(Order::price).reversed());

if (unpaid.isEmpty()) {
    System.out.println("Все заказы оплачены");
} else {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < unpaid.size(); i++) {
        if (i > 0) {
            sb.append(", ");
        }
        sb.append(unpaid.get(i).item());
    }
    System.out.println("Не оплачены: " + sb);
}

Стримом — те же три действия «отобрал, упорядочил, склеил»: промежуточные операции filter, sorted, map и терминальная collect с коллектором joining:

String unpaid = orders.stream()
        .filter(o -> !o.paid())
        .sorted(Comparator.comparingInt(Order::price).reversed())
        .map(Order::item)
        .collect(Collectors.joining(", "));

System.out.println(unpaid.isEmpty() ? "Все заказы оплачены" : "Не оплачены: " + unpaid);

Ты заметил, куда делись переменные i, unpaid, sb? Их больше нет — меньше мест, где можно ошибиться. Особенно с запятой: в цикле её вечно ставят лишний раз в конце, а joining так не умеет ошибаться.

Шаг 6. Трассировка конвейера

Пройди конвейер по шагам. Обрати внимание на промежуточную операцию sorted: он копит элементы, пока не увидит все, — и только потом пускает их дальше.

Когда стрим, а когда цикл

Стримы — не замена циклам во всём. Это инструмент для одного типа задач: «взять набор данных → отобрать → преобразовать → собрать результат». Вот честное сравнение:

🌊

Стрим понятнее

Фильтр + преобразование + сбор. Подсчёт, группировка, проверки «все/хоть один/ни одного». Склейка через запятую. Цепочка читается как рецепт.

🔁

Цикл понятнее

Нужен индекс или соседний элемент (a[i] и a[i + 1]). Меняется несколько переменных сразу. Сложная логика с break в середине. Изменение элементов на месте.

⚠️

Стрим — плохая идея

Когда в теле лямбды хочется менять локальные переменные снаружи (count++ не скомпилируется — и это подсказка), или когда в цепочке 15 операций и никто её не понимает.

Правило большого пальца

Если, читая стрим вслух, ты получаешь понятное предложение — стрим хорош. Если приходится расшифровывать — перепиши циклом или разбей стрим на несколько шагов с понятными именами переменных.

Задача: найти в массиве цен два соседних товара с самой большой разницей цен. Стрим или цикл?

Цикл. Нужны соседи a[i] и a[i + 1] — а стрим видит элементы по одному и не знает «соседа». Стримом можно извернуться через IntStream.range по индексам, но цикл здесь читается проще.

Отладка: стрим врёт — что делать?

Стрим выдал не то, а точку останова внутрь цепочки так просто не поставишь. Три приёма:

1. peek — подглядеть. Промежуточная операция, которая ничего не меняет: ей передают аргументом Consumer — действие с каждым проходящим элементом. Вставь её между шагами:

String unpaid = orders.stream()
        .peek(o -> System.out.println("до filter: " + o.item()))
        .filter(o -> !o.paid())
        .peek(o -> System.out.println("после filter: " + o.item()))
        .map(Order::item)
        .collect(Collectors.joining(", "));

2. Разбить на шаги. Объяви переменную с говорящим именем, инициализируй её промежуточным результатом — списком — и посмотри на него — глазами или в отладчике:

List<Order> unpaidOrders = orders.stream().filter(o -> !o.paid()).toList();
System.out.println(unpaidOrders);      // правильно ли отфильтровали?
List<Order> sorted = unpaidOrders.stream()
        .sorted(Comparator.comparingInt(Order::price).reversed())
        .toList();
System.out.println(sorted);            // правильный ли порядок?

3. Отладчик IDEA. Поставь точку останова на строку со стримом, запусти Debug, а на панели отладчика нажми кнопку Trace Current Stream Chain (иконка со стрелками-волнами). IDEA покажет каждую операцию отдельной вкладкой: какие элементы вошли и какие вышли. Это та же трассировка, что выше, только для твоего кода.

peek — только для отладки

Не пиши «полезную работу» в peek: Java вправе его пропустить, если результат можно получить и без него. Например, в list.stream().peek(System.out::println).count() современная Java вообще не напечатает ничего — размер списка и так известен. Отладил — убери peek.

Коротко

  • Шаблон Мастерской работает и для стримов: пойми → руками → роли → псевдокод → код → трассировка.
  • Действия «отобрал, преобразовал, упорядочил, склеил, посчитал» = filter, map, sorted, joining, count.
  • Стрим — для «набор → отбор → преобразование → результат»; цикл — для индексов, соседей, сложных break и нескольких меняющихся переменных.
  • Порядок операций важен: sorted перед limit, distinct перед limit.
  • Отладка: peek, разбиение на шаги, Trace Current Stream Chain в отладчике IDEA.
