Терминальные операции: чем закончить конвейер

Конвейер запускается только тогда, когда в конце стоит «упаковщик». Упаковщики бывают разные: один собирает список, другой считает, третий отвечает «да/нет», четвёртый сворачивает всё в одно число.

Повторение

Карта терминальных операций

Терминальная операция завершает конвейер и возвращает уже не Stream, а результат: список, число, boolean, Optional — или вообще ничего. Удобно делить их по тому, что получаешь на выходе:

Собрать, посчитать, сделать с каждым

List<String> titles = List.of("Чай", "Кофе", "Торт", "Сок");

List<String> longOnes = titles.stream()
        .filter(t -> t.length() > 3)
        .toList();  // [Кофе, Торт]

long count = titles.stream().filter(t -> t.length() > 3).count();  // 2

titles.stream()
        .map(String::toUpperCase)
        .forEach(System.out::println);  // ЧАЙ, КОФЕ, ТОРТ, СОК — по строке
toList()

Терминальная операция: собирает элементы в список и возвращает его. Появилась в Java 16. Возвращает неизменяемый список — добавить в него ничего нельзя.

count()

Сколько элементов доехало до конца. Тип возвращаемого значения — long, а не int.

forEach(…)

Принимает аргументом Consumer (обычно лямбда-выражение) и делает что-то с каждым элементом. Ничего не возвращает (void).

toList() или collect(Collectors.toList())?

В старом коде (до Java 16) встретишь .collect(Collectors.toList()). Разница: он возвращает обычный изменяемый список (на практике ArrayList), а toList() — неизменяемый. Попробуешь вызвать add у списка, который вернул toList(), — метод выбросит UnsupportedOperationException. Если список нужно менять дальше — бери collect(Collectors.toList()) или new ArrayList<>(…).

Можно ли написать int n = list.stream().count();?

Нет, ошибка компиляции: count() возвращает long, а long в int автоматически не влезает — возможна потеря данных (модуль 2). Объявляй переменную типа long: long n = ….

Проверки: anyMatch, allMatch, noneMatch

Это любимые операции для проверок: узнать что-то про все элементы сразу. Все три принимают аргументом Predicate (лямбда-выражение с условием) и возвращают boolean.

List<Integer> prices = List.of(500, 1200, 90);

// true: все цены > 0
boolean allPositive = prices.stream().allMatch(p -> p > 0);
// true: хотя бы одна > 1000
boolean anyExpensive = prices.stream().anyMatch(p -> p > 1000);
// true: ни одной бесплатной
boolean noneFree = prices.stream().noneMatch(p -> p == 0);

List<String> messages = List.of("OK", "OK", "ERROR: timeout");
if (messages.stream().anyMatch(m -> m.startsWith("ERROR"))) {
    System.out.println("Внимание: в журнале есть ошибка");
}
ОперацияВопросКак в жизниОстанавливается, когда…
anyMatchесть ли хоть один подходящий?«есть кто-нибудь старше 18?»нашёл первый подходящий → true
allMatchвсе подходят?«все пристегнулись?»нашёл первый неподходящий → false
noneMatchни один не подходит?«никто не опоздал?»нашёл первый подходящий → false

Все три — «короткого замыкания»: как && и || из модуля 3, они не смотрят дальше, если ответ уже ясен.

Пустой стрим: allMatch → true

Для пустого стрима anyMatch вернёт false (подходящих нет), а allMatch и noneMatch — true. Логика: «все драконы в этой комнате зелёные» — правда, потому что нет ни одного незелёного дракона. Это ловушка: проверка «все цены > 0» пройдёт, даже если список товаров вообще не загрузился и цен ноль. Поэтому хорошая проверка сначала убеждается, что список не пустой.

Что вернёт List.of().stream().allMatch(x -> false)?

true. Условие ни разу не проверялось — элементов нет. А нарушителей нет, значит, «все подходят».

Найти один: findFirst, min, max

Иногда нужен не список, а один элемент: первый подходящий, самый дешёвый, самый длинный. Но что вернуть, если элементов нет? null — источник NullPointerException. Поэтому эти операции возвращают Optional — объект-обёртку («коробку»), в которой элемент может быть, а может и не быть.

List<Integer> prices = List.of(500, 1200, 90);

// Optional[1200]
System.out.println(prices.stream().filter(p -> p > 1000).findFirst());
// Optional.empty
System.out.println(prices.stream().filter(p -> p > 5000).findFirst());
// Optional[90]
System.out.println(prices.stream().min(Comparator.naturalOrder()));
// Optional[1200]
System.out.println(prices.stream().max(Integer::compare));

min и max принимают аргументом Comparator — тот же, что и sort. Например, самый дорогой товар: products.stream().max(Comparator.comparing(Product::price)).

Как достать значение из коробки правильно — тема следующего урока. Пока запомни: Optional печатается как Optional[…] или Optional.empty.

Числовые стримы: sum, average, max

Посчитать сумму цен хочется так: prices.stream().sum(). Но такого метода у Stream<Integer> нет: Stream не знает, что внутри числа (там мог бы быть и Stream<String>). Для чисел есть специальные стримы: IntStream, LongStream, DoubleStream. Перейти к ним — через промежуточную операцию mapToInt:

record Product(String title, int price) { }

List<Product> cart = List.of(
        new Product("Чай", 200),
        new Product("Торт", 1500),
        new Product("Сок", 150));

// 1850
int total = cart.stream().mapToInt(Product::price).sum();
// OptionalDouble[616.666…]
OptionalDouble avg = cart.stream().mapToInt(Product::price).average();
// OptionalInt[1500]
OptionalInt max = cart.stream().mapToInt(Product::price).max();

System.out.println(total);
System.out.println(avg.getAsDouble());
System.out.println(IntStream.rangeClosed(1, 100).sum());  // 5050
mapToInt(Product::price)

Промежуточная операция, как map, но возвращает IntStream с примитивными int. У него есть «числовые» методы.

sum()

Терминальная операция: сумма. Для пустого стрима — 0. Возвращает просто int.

average()

Среднее — OptionalDouble: у пустого стрима среднего нет, делить на ноль нельзя. Достать число — вызвать getAsDouble() (только если не пусто!) или orElse(0).

🔎 Для любопытных: всё сразу — summaryStatistics() (можно пропустить)

IntSummaryStatistics st = cart.stream().mapToInt(Product::price).summaryStatistics(); за один проход считает и количество, и сумму, и минимум, и максимум, и среднее: st.getMax(), st.getAverage()… Удобно, когда нужно всё и сразу. А обратно из IntStream в Stream<Integer> переходят через boxed().

reduce: свернуть всё в одно

sum, max, count — частные случаи общей идеи: взять все элементы и свернуть их в один результат. Общий инструмент для этого — reduce («уменьшить», «свести»).

int total = prices.stream().reduce(0, (acc, p) -> acc + p);
//                                  ↑  └── как добавить следующий к накопленному
//                                  начальное значение (identity)

Узнаёшь? Это роль накопителя из Мастерской: int sum = 0; for (…) sum = sum + x; Только цикл пишет за тебя Java. Пройди сам:

ЗадачаreduceПочему такое начальное значение
суммаreduce(0, Integer::sum)x + 0 = x
произведениеreduce(1, (a, b) -> a * b)x · 1 = x (с нулём всё стало бы 0!)
склейка строкreduce("", (a, b) -> a + b)"" + s = s
максимумreduce(Integer::max)без начального — результат Optional: у пустого стрима максимума нет
Что вернёт Stream.of(1, 2, 3).reduce(10, Integer::sum)?

16, а не 6. Начальное значение участвует в сумме: 10 + 1 + 2 + 3. Поэтому для суммы identity — строго 0.

Когда брать reduce

Для суммы, среднего, максимума есть готовые sum(), average(), max() — они понятнее. reduce бери, когда готового нет: перемножить, склеить по особому правилу, найти «лучший» элемент по хитрому условию. И знай его для собеседований.

Коротко

  • Собрать: toList() (неизменяемый) или collect(Collectors.toList()). Посчитать: count() → long. Сделать с каждым: forEach.
  • Проверить: anyMatch, allMatch, noneMatch. На пустом стриме allMatch = true!
  • Найти один: findFirst, min, max → Optional.
  • Числа: mapToInt → sum(), average() (OptionalDouble), max().
  • reduce(identity, (acc, x) -> …) — накопитель в одну строку; identity — значение, которое ничего не меняет.
