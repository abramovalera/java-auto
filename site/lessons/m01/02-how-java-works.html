Как Java запускает программу

Ты пишешь обычный текст, а компьютер почему-то начинает что-то делать. Пройдём этот путь своими руками — на игрушечной фабрике Java.

Компьютер не знает Java

Сердце компьютера — процессор. Он невероятно быстрый, но понимает только простейшие команды вроде «сложи два числа» или «запомни число вот сюда». Записаны они нулями и единицами. Это машинный код.

Писать нулями и единицами — мучение, поэтому придумали языки программирования. Но процессору они непонятны. Значит, программу нужно перевести. Переводить можно двумя способами:

📖

Перевод книги целиком

Переводчик заранее переводит всю книгу, а потом её читают. Это компиляция.

🎧

Синхронный переводчик

Переводит фразу за фразой прямо во время разговора. Это интерпретация.

А Java хитрая — она использует оба способа. Сначала программу целиком, заранее переводят на промежуточный язык — это как перевод книги. А потом специальная программа на твоём компьютере переводит этот промежуточный язык на ходу — как синхронный переводчик. Сейчас увидишь это на конвейере.

Фабрика Java

Любая программа на Java проходит один и тот же конвейер. Две команды — javac и java — запускают его. Поиграй: скомпилируй, запусти, а потом попробуй сломать.

javac
Компилятор (java compiler). Проверяет текст и переводит его в байт-код — это «перевод книги целиком». Нашёл ошибку — останавливается и говорит где.
.class
Файл с байт-кодом: уже не текст для людей, но ещё и не машинный код процессора.
JVM
Виртуальная машина Java. Читает байт-код и выполняет его на твоём компьютере, переводя на ходу, — это «синхронный переводчик». Запускается командой java.

Набирать javac и java руками тебе не придётся: в IntelliJ IDEA весь этот конвейер запускает одна зелёная кнопка ▶. Но знать, что происходит под ней, — это и отличает программиста от того, кто «просто нажимает кнопку».

Зачем нужен байт-код

Почему бы сразу не переводить программу в машинный код? Потому что у разных компьютеров он разный. Программа, переведённая для Windows, не запустится на Mac — пришлось бы собирать отдельную версию под каждую систему.

Аналогия: ноты

Композитор записывает музыку нотами. Сыграть по ним может любой музыкант на любом инструменте — композитору не нужно писать отдельную версию для пианиста и для гитариста.

Байт-код — это ноты. JVM — музыкант, который умеет играть на конкретном инструменте: на Windows, на Mac, на Linux.

Проверь на практике: попробуй запустить один и тот же файл на трёх компьютерах.

Пасхалка: любой .class-файл начинается с байтов CA FE BA BE — «кафе бэйби». Я же говорил, они любили кофе!

🔎 Для любопытных: как выглядит байт-код и почему Java быстрая (можно пропустить)

Вот как выглядит байт-код программы, которая печатает «Hello, World!». Учить это не нужно — руками его никто не пишет.

javap -c Main
  public static void main(java.lang.String[]);
    Code:
       0: getstatic     #7    // Field java/lang/System.out
       3: ldc           #13   // String Hello, World!
       5: invokevirtual #15   // Method java/io/PrintStream.println
       8: return

Видишь знакомые слова System.out, println, Hello, World!? Это та же программа, разложенная на крошечные шаги для машины.

А перевод на ходу — это не медленно? Нет: JVM замечает куски программы, которые выполняются часто, и один раз переводит их прямо в машинный код. Как переводчик, который выучил частые фразы и больше не лезет в словарь. Эта часть JVM называется JIT-компилятор.

Коротко

  • Процессор понимает только машинный код, поэтому программу нужно переводить.
  • javac проверяет Main.java и переводит его в байт-код — Main.class.
  • java Main запускает JVM, она выполняет байт-код. Под каждую систему своя JVM — поэтому Java работает везде.
  • JDK ⊃ JRE ⊃ JVM. Программисту нужен JDK.
  • Поменял код — перекомпилируй, иначе запустится старая версия.
