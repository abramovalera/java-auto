## Цели модуля и вопросы

Формат: вопрос → **суть правильного ответа** → типичные заблуждения.

### О1. Зачем методы, объявление и вызов
- «Зачем вообще нужны методы? Две причины.» → **не повторять код (поменял в одном месте — поменялось везде); давать куску кода понятное имя и делить задачу на части.**
- «Чем объявление отличается от вызова?» → **объявление — рецепт (заголовок + тело), само ничего не делает; вызов `имя(…);` выполняет тело и возвращается на следующую строку.**
- «Можно ли объявить метод внутри main? А ниже main?» → **внутри — нет (`illegal start of expression`); ниже/выше — можно, порядок методов в классе не важен.**
- Заблуждение: «метод выполняется, когда Java доходит до него в файле».
- Заблуждение: «`printLine;` без скобок — тоже вызов» (`not a statement`).

### О2. `public static void main(String[] args)` по словам
- «Разбери заголовок main по словам.» → **public — виден всем, JVM вызывает снаружи; static — можно вызвать без объекта; void — ничего не возвращает; main — имя, которое ищет JVM; `String[] args` — параметр, массив строк — аргументы запуска.**
- «Что лежит в args, если запустить без аргументов? Как задать аргументы в IDEA?» → **пустой массив (length 0, не null); Run → Edit Configurations → Program arguments.**
- Глубину про static/public не требовать — это модуль 9. Достаточно «без объекта» и «виден всем».

### О3. Параметры, аргументы, return
- «Чем параметр отличается от аргумента?» → **параметр — переменная в объявлении (графа бланка), аргумент — значение при вызове (что вписали).**
- «Как Java раскладывает аргументы по параметрам?» → **по порядку; количество и типы должны совпасть, иначе `cannot be applied to given types` (required/found).**
- «Что делает return? Можно ли несколько return?» → **отдаёт значение вызвавшему и сразу завершает метод; можно, в разных ветках.**
- «Что значит `missing return statement`? А `unreachable statement`?» → **есть путь без return у не-void метода; код сразу после return никогда не выполнится.**
- «Чем метод, который печатает, хуже метода, который возвращает?» → **возвращённое значение можно использовать дальше (сложить, сравнить, передать в другой метод); напечатанное — нет.**
- «Что значит `'void' type not allowed here`?» → **пытаемся использовать результат void-метода (например, `println(printSquare(3))`), а он ничего не возвращает. Либо метод должен возвращать значение, либо вызывать его отдельной строкой.**
- «Может ли метод вернуть массив? Как передать в метод Scanner?» → **да: `static int[] readArray(Scanner sc, int n)` с `return arr;`. Scanner создаём один раз в main и передаём параметром — несколько `new Scanner(System.in)` могут «съесть» ввод друг у друга.**
- Заблуждение: «результат метода обязательно надо сохранить в переменную» (можно использовать в выражении или выбросить).
- Заблуждение: «`return` выходит только из цикла/if» — нет, из всего метода.

### О4. Стек вызовов (главная цель модуля)
- «Что такое фрейм и что в нём лежит?» → **«рабочий стол» одного вызова: параметры, локальные переменные, место возврата.**
- «main → a → b. Нарисуй стек в момент, когда работает b. Что будет при return из b?» → **снизу main, a, сверху b; работает только верхний; при return фрейм b снимается со всеми переменными, a продолжает с той же строки, подставив результат.**
- «Почему стек — LIFO?» → **последний вызванный метод должен закончиться первым: те, кто ниже, ждут его ответа.**
- «`System.out.println` — это что?» → **вызов метода println из стандартной библиотеки JDK; внутри он тоже вызывает другие методы. Ctrl+клик / Ctrl+B открывает объявление.** Имена фреймов JDK, их число и Force Step Into — «для любопытных» в уроке 7.3, не требовать. Что такое System и out — подробно в модуле 9.
- «Прочитай stack trace» (дай любой из урока 3 или свой) → **первая строка — тип ошибки и сообщение; верхняя `at` — где упало; ниже — кто вызывал; ищем свою строку и идём вниз, откуда пришло плохое значение.**
- «Где в IDEA увидеть стек вживую?» → **Debug → панель Frames; F8 — Step Over, F7 — Step Into, Shift+F8 — Step Out.** (Alt+Shift+F7 — Force Step Into в код JDK — только для любопытных, не требовать.)
- Заблуждение: «после return переменные метода ещё живы».
- Заблуждение: «одинаковые имена переменных в разных методах — одна переменная».

### О5. Передача аргументов (вопрос с собеседований)
- «Как Java передаёт аргументы — по значению или по ссылке?» → **всегда по значению (копия значения переменной). У переменной-массива значение — ссылка, поэтому копируется ссылка, массив в куче один.**
- «Почему метод не может изменить int из main, а элемент массива — может?» → **в первом случае меняется копия числа в своём фрейме; во втором по копии ссылки меняется общий массив в куче.**
- «Метод сделал `arr = new int[3]`. Что увидит main?» → **ничего: перенаправлена только копия ссылки во фрейме метода.**
- «Можно ли написать swap(int a, int b)?» → **нет, поменяются копии.**
- «Как тогда вернуть новое значение int?» → **return + присвоить в вызывающем: `a = addTen(a)`.**
- Заблуждение: «массивы передаются по ссылке» — формулировка неточная; добиться правильной: «передаётся копия ссылки».
- Заблуждение: «при передаче массива он копируется».

### О6. Перегрузка
- «Что такое перегрузка? Пример из JDK.» → **методы с одним именем и разными параметрами; println(int), println(String), println(double)…**
- «Что входит в сигнатуру?» → **имя + типы параметров по порядку. Не входят имена параметров и тип результата.**
- «Можно ли `int f(int)` и `double f(int)`?» → **нет, already defined: по вызову `f(5);` не понять, какой нужен.**
- «Как компилятор выбирает перегрузку?» → **по типам аргументов, на этапе компиляции: точное совпадение, потом расширение (int → long → double; char → int — символ становится своим кодом, `show('B')` при единственном `show(int)` напечатает 66).**
- «Можно ли перегрузить main?» → **да, main — обычный метод: `static void main(int n)` рядом с настоящим компилируется. Но JVM запускает только `public static void main(String[] args)`; перегрузку надо вызвать самому.**
- Для любопытных (не требовать): varargs `int... nums` — внутри метода это массив, параметр только последний.
- Заблуждение: «перегрузку выбирает JVM при запуске».

### О7. Область видимости
- «Почему метод не видит переменную из main?» → **она локальная, живёт во фрейме main; видна от объявления до конца своего блока `{ }`.**
- «Видна ли `i` из `for (int i…)` после цикла?» → **нет.**
- «Можно ли в двух соседних циклах объявить i? А `int x` внутри if, если x уже объявлена выше в том же методе?» → **да; нет — `already defined`.**
- «Как передать данные между методами?» → **параметрами туда, return обратно (поля — модуль 9).**

### О8. Рекурсия
- «Что такое рекурсия? Из каких двух частей состоит рекурсивный метод?» → **метод вызывает сам себя для задачи поменьше; базовый случай (ответ сразу) + рекурсивный шаг, приближающий к базовому.**
- «Нарисуй стек для factorial(3). Когда выполняются умножения?» → **вниз: 3 фрейма + main, умножения отложены; вверх: 1 → 2·1 = 2 → 3·2 = 6.**
- «Откуда StackOverflowError?» → **нет базового случая или он недостижим (n проскакивает 0) — фреймы копятся, пока не кончится ограниченная память стека; это ошибка выполнения, не компиляции.**
- «Код до рекурсивного вызова и после — когда выполняется?» → **до — по пути вниз, после — по пути вверх, в обратном порядке.**
- «Рекурсия или цикл для факториала?» → **цикл проще и не тратит стек; рекурсия хороша для вложенных структур (папки, HTML-дерево).**
- «Чем Фибоначчи `fib(n - 1) + fib(n - 2)` отличается от факториала? Сколько вызовов у fib(5)?» → **два рекурсивных вызова — дерево, а не цепочка; сначала целиком считается левый; 9 вызовов; одни и те же значения считаются много раз, поэтому fib(45) — секунды, а цикл — мгновенно. Стек при этом не переполняется (глубина ≤ n).**

### О9. Декомпозиция и имена (Мастерская)
- «Как понять, что кусок кода пора вынести в метод?» → **его можно назвать коротким глаголом и описать вход/выход; повторяется; метод не помещается на экран; в имени просится «и».**
- «Как назвать метод, который отвечает да/нет? Который считает? Который печатает?» → **is/has/can + что (boolean); calculate/count/find + что; print/show + что. По-английски, camelCase.**
- «Почему маленькие методы легче проверять?» → **каждый можно вызвать отдельно на разных входах — так устроены юнит-тесты.**

## Банк головоломок

Давай по одной. Сначала ответ и «почему», потом разбор. ★★★ — предупреждай, что с подвохом.

### Что выведется?
1. ```java
   static void inc(int x) { x++; }
   // main: int a = 1; inc(a); inc(a); System.out.println(a);
   ```
   → `1` (копия примитива)
2. ```java
   static void zero(int[] arr) { arr[0] = 0; }
   // main: int[] a = {5, 6}; zero(a); System.out.println(a[0] + a[1]);
   ```
   → `6` (копия ссылки, ячейка изменилась; сложение int, не склейка)
3. ```java
   static void change(int[] arr) { arr = new int[]{7, 7}; arr[0] = 9; }
   // main: int[] a = {1, 2}; change(a); System.out.println(a[0]);
   ```
   → `1` (перенаправлена копия ссылки)
4. ★★★ `show(int)` и `show(String)`, вызов `show('A')` → `int: 65` (char расширяется до int, не до String)
5. ★★ Есть только `print(double d)`, вызов `print(7 / 2)` → `3.0` (сначала целочисленное деление, потом расширение)
6. ```java
   static void hello(int n) { if (n <= 0) return; System.out.print("Hi "); hello(n - 2); }
   // hello(5)
   ```
   → `Hi Hi Hi ` (5, 3, 1)
7. ★★ `p(n)`: печать n, `p(n - 1)`, печать n; базовый n == 0. `p(3)` → `321123`
8. `find(n)` с `return` внутри for (до 10) и `return "нет"` после: `find(3)`, `find(20)` → `нашёл 3`, `нет`
9. ★★★ `say(n)` печатает `n + " "` и возвращает n. `System.out.println(say(1) + say(2) * say(3));` → `1 2 3 7` (операнды слева направо, потом приоритет)
10. ```java
    static int twice(int n) { return n * 2; }
    // System.out.println(twice(twice(3)) + twice(1));
    ```
    → `14`
11. Цепочка с печатью входа/выхода: main → a (печатает «a:начало», вызывает b, печатает «a:конец»), b печатает «b». → `a:начало`, `b`, `a:конец` — спросить, в какой момент на стеке три фрейма.
12. ```java
    static int triple(int count) { count = count * 3; return count; }
    // main: int count = 1; int result = triple(count + 1); System.out.println(count + " " + result);
    ```
    → `1 6` (одинаковые имена — разные переменные)
13. ★★ `up(n)`: базовый n == 0 → return; `up(n - 1)`; печать n. `up(4)` → `1 2 3 4` по строкам. А если печать перенести до вызова? → `4 3 2 1`.
14. ```java
    static int sum(int n) { if (n == 0) return 0; return n + sum(n - 1); }
    // sum(4) — сколько вызовов sum и какой результат?
    ```
    → 5 вызовов (4, 3, 2, 1, 0), результат `10`

### Скомпилируется ли?
15. `static int one() { return 1; System.out.println("после"); }` → **нет**, `unreachable statement`.
16. `static int sign(int n) { if (n > 0) return 1; else if (n < 0) return -1; }` → **нет**, `missing return statement` (n == 0). А с `else return -1;` вместо `else if` — **да**.
17. `static int getValue()` и `static double getValue()` в одном классе → **нет**, `already defined`.
18. Метод `spend()` меняет `coins`, объявленную в main → **нет**, `cannot find symbol`.
19. `int x = printLine();`, где printLine — void → **нет**, `incompatible types: void cannot be converted to int`. А `System.out.println(printLine());` → **нет**, `'void' type not allowed here`.
20. `static void f(int a, double b)` и `static void f(double a, int b)`, вызов `f(1, 2)` → **нет**, `reference to f is ambiguous`.
21. `static void area(double r)` и `static void area(double side)` → **нет**: имена параметров не различают методы.
22. `for (int i = 0; i < 3; i++) { } System.out.println(i);` → **нет**: i видна только в цикле.

### Скомпилируется, но что будет при запуске?
23. ★★ `static int f(int n) { if (n == 0) return 0; return f(n - 2); }`, вызов `f(5)` → `StackOverflowError` (n проскакивает 0).
24. Метод `factorial` с базовым случаем `n == 1`, вызов `factorial(0)` → `StackOverflowError` (0, −1, −2…).
25. `int` факториал, `factorial(13)` → **неверное число** (переполнение int, 1932053504), не исключение.
26. ★★ `fib(n)` = `fib(n - 1) + fib(n - 2)`, базовый `n <= 2`. Вызов `fib(50)` → **ответ будет, но очень долго** (миллиарды вызовов, около минуты) и с переполнением int — не StackOverflowError: глубина стека всего 50.
27. Метод `average(total, count)` с `total / count`, вызов с count = 0 → `ArithmeticException: / by zero`; попросить прочитать stack trace и сказать, кто «виноват».

### Найди ошибку
28. ```java
    static int max(int a, int b) {
        if (a > b) {
            System.out.println(a);
        }
        return b;
    }
    ```
    → печатает вместо `return a` — при a > b вернёт не тот результат (логическая ошибка, компилируется).
29. ```java
    static void reverse(int[] arr) {
        for (int i = 0; i < arr.length; i++) {
            int t = arr[i]; arr[i] = arr[arr.length - 1 - i]; arr[arr.length - 1 - i] = t;
        }
    }
    ```
    → цикл до конца, а не до середины: каждая пара меняется дважды, массив остаётся прежним.

## Джавик-курьер, часть 4 — подсказки по уровням (без кода)

Урок `m07-courier` (`/lessons/m07/50-courier.html`), задачи `m07-c1…m07-c3`, у каждого уровня свой класс в `workspace/module-07/`. Главная мысль части: из команд робота собираем свои методы, и `run` читается как план. Джавик — объект: свой метод получает его параметром `CourierRobot robot`, потому что параметр `run` — локальная переменная и другому методу не виден; в параметр копируется ссылка, объект один.

На `/check` сначала спроси план словами («что делает Джавик, когда…?»), потом разберите поездку: на какой карте ✗, на каком ходу, что ответили датчики. Свои методы в журнале поездки не видны — только команды робота. Если ученик не понимает, где ошибка, пусть напечатает промежуточные значения через `System.out.println` — они появятся в блоке «Программа напечатала».

### ★ «Челнок» (`CourierShuttle`, `m07-c1`)
Карта: прямая улица 5–12 клеток, на складе 3 посылки, адрес в конце, за раз берётся одна. Проверка требует минимум два своих метода с параметром `CourierRobot`.
1. **С чего начать.** «Что Джавик делает в одной поездке? Какие куски повторяются?» → взять, до стены, отдать, развернуться, до стены, развернуться; повторяются «до стены» и «разворот». Сначала одна поездка целиком, потом повтор.
2. **Методы.** Разворот — 180°, одна команда — 90°: два поворота в одну сторону. «До стены» — цикл «пока впереди не стена — шаг».
3. **План на русском.** Пока на складе есть посылка (или ровно 3 раза): взять, до стены, отдать, развернуться, до стены, развернуться.
Ошибки: нет разворота на складе → Джавик смотрит в стену, «до стены» не едет, `drop` на складе — ошибка; вызов без аргумента или через `robot.`; методы без `static` (`Non-static method … cannot be referenced from a static context`).

### ★★ «Квартал» (`CourierHouses`, `m07-c2`)
Карта: улица на восток 10–14 клеток, 3–4 дома в нишах слева (соседних домов нет); Джавик уже везёт по посылке на каждый дом; `houses()` — номера клеток от склада по возрастанию. Проверка требует метод с параметрами `(CourierRobot robot, int steps)` и вызов `houses()`.
1. **С чего начать.** «houses() = [2, 5, 9]: сколько клеток проехать перед каждым домом?» → 2, 3, 4. Пусть сначала доставит только в первый дом.
2. **Откуда ехать.** Переменная «где я сейчас» (0 на складе): ехать `дом − где я`, после доставки обновить. Ниша: налево, вперёд, отдать, разворот, вперёд и один поворот налево — снова лицом на восток.
3. **План на русском.** Для каждого дома из массива: проехать (дом − где я) клеток; где я = дом; заехать в нишу, отдать, вернуться на улицу лицом на восток.
Ошибки: едут от склада каждый раз; после ниши смотрят на юг или запад; ищут `turnAround` из класса «Челнока» — у каждого уровня свой класс, метод надо объявить заново.

### ★★★ «Середина улицы» (`CourierMiddle`, `m07-c3`)
Карта: прямая улица 6–14 клеток, Джавик уже везёт посылку; адрес на клетке `(клеток − 1) / 2` от склада (при чётном числе клеток — середина, ближняя к складу); `atTarget()` здесь бросает ошибку и запрещён проверкой. Проверка требует метод, который возвращает `int`.
1. **С чего начать.** «Сколько шагов от склада до стены на улице из 7 клеток?» → 6, шагов на 1 меньше клеток. Пусть напишет `int driveToWall` и напечатает результат на трёх картах.
2. **Сколько назад.** Таблица на бумаге для 6, 7, 8, 9 клеток: метод вернул n = 5, 6, 7, 8 → адрес на клетке 2, 3, 3, 4 → назад 3, 3, 4, 4. «Каким действием с n получается номер клетки адреса?»
3. **План на русском.** n = до стены; развернуться; проехать от стены до клетки адреса; отдать.
Ответ для наставника: клетка адреса `n / 2`, назад `n − n / 2` (то же, что `(n + 1) / 2`). Типичная ошибка — назад `n / 2`: при нечётном n Джавик не доезжает одну клетку.
