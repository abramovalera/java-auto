## Цели модуля и вопросы

Формат: вопрос → **суть правильного ответа** → типичные заблуждения.

### О1. Абстрактный класс и абстрактный метод
- «Зачем делать класс абстрактным? Почему не написать в родителе `return 0`?» → **абстрактный метод заставляет каждого конкретного наследника написать свою реализацию; `return 0` — враньё, которое молча унаследует забывчивый наследник (логическая ошибка вместо ошибки компиляции).**
- «Два правила компилятора про abstract?» → **нельзя `new` абстрактного класса; конкретный наследник обязан реализовать все абстрактные методы (иначе сам должен быть abstract).**
- «Что может быть в абстрактном классе?» → **поля, конструктор, обычные методы, абстрактные методы (0 и больше).**
- Заблуждение: «у абстрактного класса нет конструктора». Есть, его вызывают наследники через `super(...)`.
- Заблуждение: «в абстрактном классе все методы абстрактные».
- Заблуждение: «раз объект создать нельзя, то и переменную `Shape s` объявить нельзя». Можно — в ней лежит конкретный объект.

### О2. Шаблон «общая часть + своя деталь» (шаблонный метод)
- «Обычный метод `describe()` абстрактного класса вызывает абстрактный `area()`. Чей `area()` выполнится?» → **реального объекта (наследника) — полиморфизм.**
- «Где такое бывает в реальных программах?» → **доставка с общим расчётом и своей ценой у курьера/почты; квест в игре с общим ходом и своей наградой; уведомления (SMS, email, push) с общей шапкой и своим текстом.**

### О3. Интерфейс: контракт «умеет делать»
- «Зачем интерфейс, если есть абстрактный класс?» → **у класса один родитель, а умений много; умение нужно классам из разных «семей» (птица, самолёт, супермен).**
- «Почему реализация метода интерфейса обязана быть `public`?» → **методы интерфейса неявно `public abstract`, реализация не может сузить доступ (weaker access privileges).**
- «`Flyable f = new Plane(); f.refuel();` — скомпилируется?» → **нет: через переменную интерфейса видны только методы контракта.**
- «Что значит “программировать на уровне интерфейсов”? Пример из реальной программы?» → **методы принимают интерфейс (Payment, Logger, List), реализацию меняют одной строкой: оплата картой ↔ СБП, ArrayList ↔ LinkedList.**
- Заблуждение: «`implements` можно только один». Сколько угодно, через запятую; `extends` — один и первым.

### О4. default, static, константы; проблема ромба
- «Зачем придумали default-методы?» → **добавить метод в интерфейс, не сломав все существующие реализации (Java 8).**
- «Как из своей реализации позвать версию по умолчанию?» → **`ИмяИнтерфейса.super.метод()`.**
- «Класс реализует A и B с одинаковым default `hello()`. Что будет?» → **ошибка компиляции (inherits unrelated defaults); надо переопределить и выбрать, например `A.super.hello()`.**
- «Как вызвать static-метод интерфейса?» → **только через имя интерфейса; реализации его не наследуют.**
- «Какие модификаторы у поля интерфейса?» → **`public static final` — константа.**

### О5. Интерфейс или абстрактный класс
- «Назови 3 отличия» → **один extends vs много implements; у абстрактного класса есть состояние (поля) и конструктор, у интерфейса только константы; смысл «кто ты» vs «что умеешь».**
- Дай 2–3 ситуации (счета в банке с балансом; «умеет сохраняться в файл»; персонажи игры с общим здоровьем и своей атакой) — ученик выбирает и объясняет.
- Хороший ответ упоминает комбинацию: интерфейс-контракт + абстрактный класс с общей частью (пример Toy → BatteryToy → ToyCar/ToyDuck в уроке 11.3, задача «Умный дом»).
- «Абстрактный класс реализует интерфейс, но написал не все его методы. Скомпилируется?» → **да: абстрактный класс имеет право; недописанные методы обязан написать первый конкретный наследник. Без слова abstract — ошибка `is not abstract and does not override abstract method`.**
- «Почему называется “ромб”?» → **классическая схема: общий предок наверху, два наследника по бокам, внизу класс, унаследовавший обоих, — четыре угла.**

### О6. Интерфейс как обратный вызов: Comparator, Runnable, анонимный класс
- «Что такое обратный вызов? Аналогия?» → **передаём объект-реализацию интерфейса в метод, а метод сам вызывает его в нужный момент («оставь номер — перезвоним»).**
- «Что возвращает `compare(a, b)` и что значит знак?» → **int: минус — a раньше, 0 — равны, плюс — b раньше; важен только знак.**
- «Как сделать сортировку по убыванию?» → **переставить аргументы: `Integer.compare(b.x, a.x)`.**
- «Почему лучше `Integer.compare`, а не `a.x - b.x`?» → **вычитание может переполнить int.** (★, не обязательно)
- «`new Comparator<Player>() { … }` — это создание объекта интерфейса?» → **нет, объект безымянного (анонимного) класса, который реализует интерфейс.**
- «Чем Comparator отличается от Comparable?» → **Comparable — встроенный порядок самого объекта (у String, чисел); Comparator — отдельный судья, его передают в sort, судей может быть много.**
- «Что будет, если вызвать `Arrays.sort(players)` без компаратора?» → **скомпилируется, но ClassCastException: Player не Comparable.** (★)
- «Что общего у Comparator, Runnable, OrderListener?» → **один абстрактный метод — функциональный интерфейс; в модуле 14 — лямбды.**
- Заблуждение: «передать Runnable в метод = выполнить его».

### О7. enum
- «Зачем enum, если можно хранить статус строкой?» → **фиксированный список: опечатки и «левые» значения ловит компилятор.**
- «Почему константы enum можно сравнивать `==`?» → **каждая константа — единственный объект на всю программу.**
- «Что вернут `ordinal()`, `values()`, `valueOf("x")`?» → **номер с нуля; массив по порядку объявления; константу по имени — строго по регистру, иначе IllegalArgumentException.**
- «Почему ordinal не стоит сохранять в файл/базу?» → **номера сдвигаются при вставке новой константы.**
- «Как в case у switch писать константу?» → **просто `PASSED`, без имени enum.**
- «Нужен ли `default` в switch-выражении по enum?» → **нет, если перечислены все константы; пропустишь одну — ошибка `the switch expression does not cover all possible input values`.**
- «Можно ли `new` у enum? Какой у него конструктор?» → **нет; конструктор всегда приватный, объекты создаёт Java по одному на константу.**
- «Зачем поля в enum?» → **данные живут в константе; не нужен switch/if на каждый вариант; новая константа не требует правок в остальном коде.**

### О8. record
- «Что Java генерирует для `record Product(String name, int price)`?» → **private final поля, канонический конструктор, методы `name()`/`price()`, equals/hashCode по всем компонентам, toString `Product[name=…, price=…]`.**
- «Как “изменить” цену у record?» → **никак: создать новый объект на основе старого.**
- «Что такое компактный конструктор и когда в нём присваиваются поля?» → **конструктор без скобок для проверки/исправления параметров; поля Java присваивает после его тела; `this.name = …` в нём — ошибка.**
- «Чего нельзя в record?» → **extends (уже наследует Record), дополнительные поля объекта, сеттеры; сам record final.**
- Заблуждение: `p.getName()` у record.
- ★ «Почему неизменяемость “неглубокая”?» → **компонент-массив можно менять изнутри.**

### О9. Как выбрать тип
- Дай описание мини-системы (кафе, библиотека, магазин) — ученик раскладывает на class / abstract class / interface / enum / record и объясняет каждый выбор.
- «Из чего нельзя создать объект через `new`?» → **abstract class, interface, enum.**
- ★ Для любопытных: «что такое sealed?» → **закрытый список наследников `permits`**. Не требовать.

## Банк головоломок

Давай по одной. Сначала ответ и «почему», потом разбор. ★★★ — с подвохом, честно предупреждай.

### Что выведется?
1. ```java
   abstract class Report {
       String build() { return "[" + body() + "]"; }
       abstract String body();
   }
   class Brief extends Report { String body() { return "ok"; } }
   Report r = new Brief();
   System.out.println(r.build() + r.body());
   ```
   → `[ok]ok`
2. `enum Level { LOW, MEDIUM, HIGH }` → `System.out.println(Level.HIGH.ordinal() + " " + Level.values()[0]);` → `2 LOW`
3. `Status a = Status.valueOf("OK"); System.out.println(a == Status.OK);` → `true` (единственный объект-константа)
4. `record Point(int x, int y)`: `a == b`, `a.equals(b)`, `println(b)` для двух `new Point(0, 5)` → `false`, `true`, `Point[x=0, y=5]`
5. `Logger.super.log(m.toUpperCase()) + "!"` при default `"LOG: " + m` и аргументе `"привет"` → `LOG: ПРИВЕТ!`
6. Компаратор `Integer.compare(b.length(), a.length())` для слов `{"кот", "бегемот", "ёж"}` → по убыванию длины, `words[0] + " " + words[2]` → `бегемот ёж`
7. ★★★ Конструктор абстрактного родителя вызывает переопределённый `name()`, который читает поле наследника `n = "Ребёнок"` → `Создаю: null` (поля наследника инициализируются после super()).
8. ```java
   record Item(String name, int qty) { Item { if (qty < 1) qty = 1; } }
   System.out.println(new Item("Чай", 0));
   System.out.println(new Item("Чай", 1).equals(new Item("Чай", 0)));
   ```
   → `Item[name=Чай, qty=1]`, `true`
9. `Difficulty.EASY.score(50) + Difficulty.MEDIUM.score(50)` при множителях 1 и 2 → `150`
10. `record OrderLine(Product product, int qty)` → `println(line)` → `OrderLine[product=Product[name=Чай, price=120], qty=3]` (вложенный toString)
11. `interface Config { int TIMEOUT = 5; } class A implements Config { void show() { System.out.println(TIMEOUT * 2); } }` → `10` (константа видна в реализации)
12. `Flyable[] squad = new Flyable[3]; System.out.println(squad[0]);` → `null` (массив ссылок, объектов интерфейса нет)

### Скомпилируется ли?
13. `abstract class Shape { abstract double area(); }` → `new Shape()` → **нет**: `Shape is abstract; cannot be instantiated`.
14. `Shape s = new Circle(1);` → **да**.
15. `abstract String voice() { return "..."; }` → **нет**: у абстрактного метода нет тела.
16. `class Fish extends Animal { }` без реализации абстрактного `voice()` → **нет**: `Fish is not abstract and does not override abstract method voice()`.
17. `abstract class Helper { }` без абстрактных методов → **да** (так запрещают создавать объекты «общего» класса).
18. `abstract final class X` → **нет** (final запрещает наследование). `private abstract void m();` → **нет**. `static abstract void m();` → **нет**.
19. Ромб: `class CatDog implements Cat, Dog { }`, у обоих `default String sound()` → **нет**: `types Cat and Dog are incompatible`.
20. `class Ru implements Greeter { String hello() { … } }` → **нет**: `attempting to assign weaker access privileges; was public`.
21. `interface Flyable { static int max() {…} }` → `Bird.max()` → **нет** (`cannot find symbol`): static-методы интерфейса не наследуются.
22. `Limits.MAX_RETRIES = 5;` → **нет**: поле интерфейса — `final`.
23. `record Money(int amount)`, `m.amount = 200;` → **нет**: `amount has private access` (и оно final).
24. `record P(String name) { P { this.name = name; } }` → **нет**: `cannot assign a value to final variable name` — в компактном конструкторе меняют параметр.
25. `record R(int x) extends Object { }` → **нет**: record не может extends.
26. `enum Level { LOW(1), HIGH(10); … }` → `new Level(5)` → **нет**: `enum classes may not be instantiated`.
27. `class Duck extends Animal, Bird` → **нет**. `class Duck implements Flyable extends Animal` → **нет** (порядок). `class Duck extends Animal implements Flyable, Swimmable` → **да**.
28. `Runnable r = new Runnable();` → **нет**. `Runnable r = new Runnable() { public void run() { } };` → **да** (анонимный класс).

### Скомпилируется, но что будет при запуске?
29. `Status.valueOf("passed")` при константе `PASSED` → `IllegalArgumentException: No enum constant Status.passed`.
30. `Arrays.sort(players)` для массива своих объектов без компаратора → `ClassCastException: … cannot be cast to class java.lang.Comparable`.
31. `return a.score - b.score;` при `a.score = Integer.MAX_VALUE`, `b.score = -1` → переполнение, знак «не тот», сортировка молча ломается. (★★★)

### Найди ошибку
32. ```java
    interface Device { void turnOn(); }
    enum Color { RED, GREEN }
    record Lamp(Color color) implements Device {
        public void turnOn() { System.out.println(color + " горит"); }
    }
    Device d = new Device();
    Color c = new Color();
    ```
    → две последние строки: `new` интерфейса и `new` enum. Record, реализующий интерфейс, — законно.
33. ```java
    enum Coffee {
        SMALL(200), LARGE(400)
        private final int ml;
        Coffee(int ml) { this.ml = ml; }
    }
    ```
    → нет `;` после списка констант.

### Почему здесь ошибка?

36. `error: class Android inherits unrelated defaults for hello() from types Robot and Human`
37. `error: enum classes may not be instantiated`
