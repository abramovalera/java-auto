## Цели модуля и вопросы

Формат: вопрос → **суть правильного ответа** → типичные заблуждения.

### О1. Что такое программа и зачем её переводить
- «Почему компьютер не может выполнить файл `HelloWorld.java` напрямую?» → **процессор понимает только машинный код; исходник — текст для людей, его надо перевести.**
- «Чем компиляция отличается от интерпретации? Аналогия?» → **перевод книги целиком заранее или синхронный переводчик по ходу.** Java использует оба подхода.

### О2. Путь программы: javac → .class → JVM
- «Нарисуй стрелками, что происходит от `.java` до вывода на экран» → **.java → javac → .class (байт-код) → JVM → выполнение.**
- «Что лежит в `.class`?» → **байт-код: не текст и не машинный код, а промежуточный язык для JVM.**
- Заблуждение: «javac запускает программу». Нет, javac только компилирует.
- Заблуждение: «.class — это машинный код». Нет, байт-код.

### О3. JDK / JRE / JVM, «write once, run anywhere»
- «Другу на Mac отправили `.class`, собранный на Windows. Запустится?» → **да, если у друга есть Java; JVM под Mac переведёт байт-код.**
- «Что нужно поставить, чтобы писать программы? А чтобы только запускать?» → **JDK; для запуска хватит JRE (JVM + библиотека).**
- «Что такое LTS и почему мы взяли 21?» → **версия с долгой поддержкой, её используют в реальных проектах.**

### О4. Что делает кнопка ▶
- «Ты нажал ▶. Что произошло по шагам?» → **IDEA вызвала javac, байт-код лёг в папку out, IDEA запустила JVM, вывод показан в панели Run.**
- «Где лежит `HelloWorld.class`, который получился после ▶?» → **в папке out — её создаёт IDEA.**
- «Если бы ты запускал без IDEA и поменял текст, но не скомпилировал заново — что бы вывелось?» → **старый текст: JVM запускает .class, а не .java** (это было в мини-игре «Фабрика Java»).

### О5. IntelliJ IDEA
- «Где в IDEA увидеть, что в коде ошибка, ещё до запуска?» → **красное подчёркивание.**
- «Зачем папку помечают Sources Root? Где взяли JDK?» → **чтобы IDEA знала, где код; JDK скачали через Project Structure → SDK → Download JDK.**
- «Что делает сокращение `sout`? А `psvm`?»
- «Чем IDE лучше Блокнота? Назови две вещи.»

### О6. Анатомия программы
- «Зачем нужен метод `main`?» → **точка входа: выполнение начинается с него.**
- «Почему файл называется `HelloWorld.java`, а не `hello.java`?» → **имя public-класса должно совпадать с именем файла, регистр тоже важен.**
- «Что значат фигурные скобки?» → **границы блока: класса, метода; коробки в коробках.**
- «Зачем `;`?» → **конец инструкции, как точка в конце предложения.**
- «`System` и `system` — одно и то же?» → **нет, Java различает регистр.**
- `public static void`, `String[] args` — полного понимания **не требовать**. Достаточно «это обязательная форма main, разберём позже».

### О7. print / println / спецсимволы
- «Чем `print` отличается от `println`?» → **println после текста переводит строку.**
- «Как напечатать кавычку внутри строки? А обратный слэш? А табуляцию?» → **`\"`, `\\`, `\t`.**

### О8. Строки, числа, склейка
- «Что выведет `System.out.println(2 + 2);` и `System.out.println("2 + 2");`?» → **4 и текст «2 + 2».**
- «Почему `"2 + 2 = " + 2 + 2` даёт 22 и как починить?» → **вычисление слева направо: строка + число = строка; починка — скобки `(2 + 2)`.**

### О9. Ошибки компиляции
- «Из чего состоит сообщение javac?» → **файл : номер строки : error : описание, строка кода, ^ под местом ошибки.**
- «Ошибок 5. С какой начинать?» → **с первой; остальные часто исчезают сами.**
- Назови 3 частые ошибки и их причины: `';' expected`, `cannot find symbol`, `unclosed string literal`, `reached end of file while parsing`, `class X is public, should be declared in a file named X.java`.
- «Чем ошибка компиляции отличается от логической?» → **логическая: программа запускается, но делает не то, компилятор её не видит.**

### О10. Комментарии и читаемость
- «Попадают ли комментарии в программу?» → **нет, компилятор их пропускает, они для людей.**
- «Компилятору важны отступы? А людям?»

## Банк головоломок

Давай по одной. Сначала ответ и «почему», потом разбор. ★★★ — со звёздочкой, честно предупреждай, что это на опережение.

### Что выведется?
1. `System.out.println("2 + 2 = " + 2 + 2);` → `2 + 2 = 22`
2. `System.out.println(1 + 2 + "3" + 4 + 5);` → `3345` (1+2=3 как числа, дальше склейка строк)
3. ```java
   System.out.print("A");
   System.out.println("B");
   System.out.print("C");
   ```
   → `AB`, на следующей строке `C`
4. `System.out.println("Hello" /* , World */ + "!");` → `Hello!` (комментарий внутри выражения)
5. `System.out.println("Путь: C:\new\table");` → **компилируется!** `\n` и `\t` — настоящие спецсимволы: `Путь: C:`, новая строка, `ew`, табуляция, `able`
6. `System.out.println("Раз\nДва\n\nТри");` → 4 строки, третья пустая
7. ★★★ `System.out.println(7 / 2);` → `3` (целочисленное деление, модуль 3)
8. ★★★ `System.out.println('A' + 'B');` → `131` (символы в одинарных кавычках — числа-коды: 65 + 66; модуль 2)

### Скомпилируется ли?
9. `System.out.println('Hello');` → **нет**: одинарные кавычки — для одного символа (char), строки пишутся только в двойных.
10. `System.out.print();` → **нет**: `print` без аргумента не бывает. А `System.out.println();` — **да**, это пустая строка.
11. Файл `Main.java`, внутри `public class main { … }` → **нет**: имя public-класса не совпадает с именем файла (регистр важен).
12. Файл `Test.java`, внутри `class Hello { public static void main(String[] args) { … } }` (без `public` у класса) → **да!** Не-public класс может лежать в файле с любым именем. javac создаст `Hello.class`, запускать надо `java Hello`.
13. `System.out.println("Привет")` без `;` в последней строке main → **нет**, `';' expected`.

### Скомпилируется, но что будет при запуске?
14. `public static void Main(String[] args)` (Main с большой буквы) → **компилируется**, но при запуске «Main method not found»: это обычный метод с похожим именем, а точку входа Java ищет по точному имени `main`.
15. Скомпилировали `HelloWorld.java`, запускаем `java helloworld` → «Could not find or load main class helloworld»: имя класса при запуске тоже чувствительно к регистру.

И ещё одна на «скомпилируется ли»:
13a. `System.out.println("Ответ: " + 10 - 5);` → **нет!** Слева направо: `"Ответ: " + 10` = строка `"Ответ: 10"`, а вычесть из строки число нельзя (`bad operand types for binary operator '-'`). Починка: `"Ответ: " + (10 - 5)`.

### Найди ошибку
16. ```java
    public class Greeting {
        public static void main(String[] args) {
            System.out.println("Привет!")
            System.Out.println("Как дела?");
        }
    }
    ```
    → нет `;` в строке 3, `Out` вместо `out`.
17. ```java
    public class Box {
        public static void main(String[] args) {
            System.out.println("Коробка");
        }
    ```
    → не хватает закрывающей `}` класса: `reached end of file while parsing`.
18. ```java
    public class Quote {
        public static void main(String[] args) {
            System.out.println("Он сказал "привет"");
        }
    }
    ```
    → кавычки внутри строки не экранированы, нужно `\"`.
19. Кавычки-ёлочки: `System.out.println(«Привет»);` → `illegal character`: в коде нужны прямые `"`.

### Почему здесь ошибка?
Покажи код и сообщение javac, попроси объяснить причину своими словами:
20. `error: cannot find symbol … symbol: variable system` → `system` с маленькой буквы.
21. `error: unclosed string literal` → строка не закрыта кавычкой.
22. `error: class, interface, enum, or record expected` → лишняя `}` или код за пределами класса.
