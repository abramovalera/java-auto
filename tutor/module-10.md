## Цели модуля и вопросы

Формат: вопрос → **суть правильного ответа** → типичные заблуждения.

### О1. Три кита ООП
- «Назови три кита ООП и объясни каждого одним предложением с примером» → **инкапсуляция — данные спрятаны, доступ через методы с проверками (счёт); наследование — новый класс на основе готового, отношение «является» (Cat extends Animal); полиморфизм — один вызов, разное поведение по реальному объекту (zoo[i].speak()).**
- Заблуждение: «инкапсуляция — это private». Нет, private — инструмент; суть — защита правил объекта.
- Заблуждение: «полиморфизм — это перегрузка». На собеседовании ждут переопределение + динамическую диспетчеризацию (перегрузку иногда называют «статическим полиморфизмом» — можно упомянуть, но не как главный ответ).

### О2. Инкапсуляция
- «Почему `public int balance` — плохо?» → **любой код может записать что угодно, правило «≥ 0» некому охранять; ошибку ищешь по всему проекту.**
- «Все поля private, к каждому геттер и сеттер без проверок — это инкапсуляция?» → **формально да, по сути нет: сеттер без проверки = открытое поле.**
- «Что такое инвариант? Пример» → **правило, всегда верное для объекта: баланс ≥ 0, возраст 0..150.**
- «Как инкапсуляция выглядит в кофемашине из урока?» → **настройки (температура, граммы зёрен) private, наружу — действия (`makeLatte`); поменялся рецепт — правим один класс.**
- ★ «Геттер возвращает внутренний массив. Что не так?» → **отдаёт ссылку, массив можно изменить снаружи; отдавать копию.**

### О3. Наследование и конструкторы
- «Когда уместно наследование?» → **когда честно «A является B» и A можно подставить везде вместо B.**
- «Сколько родителей у класса? А у Animal без extends?» → **один; у Animal — Object.**
- «Почему в Java нельзя `extends A, B`?» → **проблема ромба: два родителя с одинаковым методом (или общий прародитель с полем) — непонятно, чья версия/сколько копий поля у наследника. Java запретила двух родителей; несколько «умений» — через интерфейсы (модуль 11).** Заблуждение: «просто так решили» — нужен пример конфликта.
- «Что делает `super(name)`? Где он должен стоять?» → **вызывает конструктор родителя; первой строкой конструктора.**
- «Что будет, если super(...) не написать?» → **Java вставит `super()`; если у родителя нет конструктора без параметров — ошибка компиляции `constructor X cannot be applied to given types`.**
- «В каком порядке работают конструкторы при `new Kitten()`?» → **Animal → Cat → Kitten, от старшего к младшему.**
- «Видит ли наследник private-поле родителя?» → **поле в объекте есть, но обратиться напрямую нельзя; через геттер или protected.**
- «Чем protected отличается от private? Подвох?» → **виден наследникам; подвох — ещё и всему пакету.**

### О4. Переопределение и final
- «Переопределение и перегрузка — в чём разница?» → **override: в наследнике, те же параметры, выбор при запуске по объекту; overload: другие параметры, выбор при компиляции по типам аргументов.**
- «Зачем @Override, если работает и без неё?» → **компилятор проверит, что метод действительно переопределяет; ловит опечатки (`speek`) и неверные параметры.**
- «Правила переопределения?» → **та же сигнатура, тот же (или более узкий) тип результата, доступ не строже; private/static/final не переопределяются.**
- «Как дополнить метод родителя, а не заменить?» → **`super.method()` внутри переопределённого.**
- «Три значения final?» → **переменная — нельзя переприсвоить; метод — нельзя переопределить; класс — нельзя наследовать.**
- «Почему String — final?» → **неизменяемость строк, пул строк, безопасность (строки — пароли, пути, ключи); наследник мог бы подменить поведение.**
- «Зачем cook() в базовом рецепте делать final?» → **порядок prepare → mainStep → cleanUp не должен ломаться наследниками (шаблонный метод).**
- «Как сделать класс неизменяемым? Зачем?» → **final class; поля private final; всё в конструкторе; без сеттеров; «изменяющий» метод возвращает новый объект (Money.plus, как String.toUpperCase); изменяемые поля (массивы) — защитная копия. Зачем: объект можно отдавать куда угодно, никто не испортит.** Пусть напишет `Money` с `plus` и предскажет вывод `a.plus(b)` для `a`.

### О5. Полиморфизм
- «`Animal a = new Cat(); a.speak();` — чей метод? Почему?» → **Cat: версия переопределённого метода выбирается по объекту во время работы (динамическая диспетчеризация).**
- «Почему `a.meow()` не компилируется?» → **компилятор смотрит на тип переменной Animal, у Animal нет meow().**
- «Что выбирается по типу переменной, а что по объекту?» → **по переменной: доступные методы, поля, static, private, перегрузка; по объекту: версия переопределённого метода.**
- «Зачем полиморфизм в реальной программе?» → **один метод `checkout(Payment p)` для всех способов оплаты; игра запускает все уровни как «уровни», выполняется код конкретного уровня; новый класс — без правки старого кода.**
- Заблуждение: «JVM выбирает метод по типу переменной». Нет — по объекту.

### О6. Object: toString, equals, hashCode
- «Что напечатает объект без своего toString?» → **`ИмяКласса@шестнадцатеричное_число`.**
- «Зачем свой toString?» → **при отладке и в сообщениях об ошибках объекты печатаются; читаемый toString экономит время.**
- «`==` и `equals` — разница? Что делает equals из Object?» → **== — та же ссылка; equals — равенство по смыслу; в Object equals = ==.**
- «Напиши equals для Point» → **параметр Object; this == o; null и getClass; приведение; сравнение полей.**
- «Контракт equals?» → **рефлексивность, симметричность, транзитивность, постоянство, x.equals(null) = false.**
- «Контракт hashCode? Объясни своими словами, с аналогией» → **равные по equals → равные hashCode; обратное не обязательно (коллизия); постоянство. Аналогия: номерок в гардеробе / номер полки на складе — hashCode выбирает полку, equals сравнивает на полке.**
- «Что сломается, если переопределить только equals?» → **равные объекты получат разные hashCode, HashMap/HashSet ищут не на той полке: set из двух «одинаковых» точек имеет размер 2, map.get(равный ключ) вернёт null.** (Коллекции — модуль 13; достаточно идеи.)
- «`return 42;` в hashCode — корректно?» → **по контракту да, но все объекты на одной полке — поиск медленный.**
- «Что такое getClass()?» → **реальный класс объекта (`Object o = new Cat(...)` → `Cat`).** ★ «Чем getClass() в equals отличается от instanceof?» → **getClass — точное совпадение класса; instanceof — «является», учитывает наследников, с наследником легко нарушить симметричность.** В уроке это «для любопытных» — не требовать.
- «Что генерирует record?» → **equals, hashCode, toString по всем полям (плюс конструктор и геттеры).**
- ★ «clone() — что знаешь?» → **копия объекта; по умолчанию поверхностная; на практике чаще конструктор копирования.** Глубоко не требовать.

### О7. Приведение типов и instanceof
- «Восходящее и нисходящее приведение — что это, когда явно?» → **вверх (Cat → Animal) само и безопасно; вниз (Animal → Cat) только явно `(Cat) a`.**
- «Когда ClassCastException, а когда ошибка компиляции?» → **CCE — при запуске, если объект не того класса (Animal-переменная с собакой → (Cat)); компиляции — если типы неродственные (переменная Cat → (Dog)).**
- «`a instanceof Cat` для котёнка? Для null?» → **true (является котом); false.**
- «Что такое `if (a instanceof Cat c)`?» → **pattern matching (Java 16+): проверка и приведение сразу; c видна только там, где проверка прошла.**
- «Почему `a instanceof Dog d || d.isGuard()` не компилируется?» → **при || правая часть работает, когда a не собака, переменной d нет.**
- «Цепочка instanceof на каждого зверя — что не так?» → **поведение должно быть в переопределённом методе; instanceof — для отбора/подсчёта, equals, чужих классов.**

### О8. Композиция против наследования
- «is-a и has-a — пример каждого» → **Cat is-a Animal → extends; Car has-a Engine → поле.**
- «Что такое делегирование?» → **объект поручает работу своей части: car.start() → engine.start().**
- «Почему "предпочитай композицию"? Три причины» → **жёсткая связь (хрупкий базовый класс), наследуешь всё, один родитель, нельзя заменить на ходу.**
- «В игре рюкзак с вещами есть у каждого героя — как сделать?» → **поле Inventory в герое (композиция), а не «божественный» родитель со всем подряд и не extends Inventory.**
- ★ «Квадрат — наследник прямоугольника: в чём проблема?» → **при изменяемых setWidth/setHeight квадрат нельзя подставить вместо прямоугольника — нарушение принципа подстановки Лисков.**

### О9. Мостик к модулю 11
- «Утка летает и плавает, самолёт летает. Как выразить общее?» → **не наследованием (один родитель, они не родня), а «умеет» — интерфейсы (модуль 11).** Достаточно идеи.

## Банк головоломок

Давай по одной. Сначала ответ и «почему», потом разбор. ★★★ — со звёздочкой, честно предупреждай, что это с подвохом или на опережение. Головоломки 1–18 со страницы модуля ученик мог видеть — на экзамене бери из этого банка другие или меняй значения.

### Что выведется?
1. Шаблонный метод:
   ```java
   class Report {
       void print() { System.out.print("[" ); body(); System.out.println("]"); }
       void body() { System.out.print("пусто"); }
   }
   class SalesReport extends Report {
       @Override void body() { System.out.print("продажи"); }
   }
   Report r = new SalesReport(); r.print();
   ```
   → `[продажи]` — print() у родителя, body() выбирается по объекту.
2. ```java
   class A { void f() { System.out.println("A"); } }
   class B extends A { void f() { System.out.println("B"); super.f(); } }
   class C extends B { void f() { super.f(); System.out.println("C"); } }
   A x = new C(); x.f();
   ```
   → `B`, `A`, `C`.
3. ★★★ Поля не полиморфны:
   ```java
   class Parent { int value = 1; int get() { return value; } }
   class Kid extends Parent { int value = 2; @Override int get() { return value; } }
   Parent p = new Kid();
   System.out.println(p.value + " " + p.get());
   ```
   → `1 2` — поле по ярлыку, метод по объекту.
4. ★★★ static не переопределяется:
   ```java
   class A { static String name() { return "A"; } String who() { return name(); } }
   class B extends A { static String name() { return "B"; } }
   System.out.println(new B().who());
   ```
   → `A` — внутри A вызов static name() привязан к A.
5. private не переопределяется:
   ```java
   class A { private void hi() { System.out.println("A"); } void go() { hi(); } }
   class B extends A { public void hi() { System.out.println("B"); } }
   new B().go();
   ```
   → `A`.
6. ★★★ Конструктор родителя вызывает переопределённый метод:
   ```java
   class Base { Base() { System.out.println(describe()); } String describe() { return "base"; } }
   class Item extends Base {
       private String title = "книга";
       Item() { System.out.println(describe()); }
       @Override String describe() { return "item: " + title; }
   }
   new Item();
   ```
   → `item: null`, затем `item: книга`.
7. Порядок конструкторов:
   ```java
   class A { A() { System.out.print("1"); } }
   class B extends A { B() { System.out.print("2"); } B(int x) { super(); System.out.print(x); } }
   class C extends B { C() { super(9); System.out.print("3"); } }
   new C();
   ```
   → `193`.
8. Перегрузка по ярлыку, переопределение по объекту:
   ```java
   static void feed(Animal a) { System.out.println("корм для животного"); }
   static void feed(Cat c) { System.out.println("корм для кота"); }
   Animal a = new Cat();
   feed(a);
   ```
   → `корм для животного` — перегрузка выбрана при компиляции по типу переменной.
9. `Animal a = new Cat(); System.out.println(a.getClass().getSimpleName() + " " + (a instanceof Animal));` → `Cat true`.
10. ★★★ equals-перегрузка:
    ```java
    class Id { int v; Id(int v) { this.v = v; } public boolean equals(Id o) { return v == o.v; } }
    Object a = new Id(5); Object b = new Id(5);
    System.out.println(a.equals(b));
    ```
    → `false` — переменные типа Object, вызывается equals(Object) из Object, а equals(Id) — перегрузка.
11. Без toString: `System.out.println(new Cat("Мурка"));` → `Cat@…` (хэш, точное число не угадать). С toString в родителе через `getClass().getSimpleName()` → имя реального класса.

### Скомпилируется ли?
12. `class Cat extends Animal, Pet {}` → **нет**, один родитель.
13. У `Animal` только `Animal(String)`; `class Fish extends Animal { }` (без конструктора вообще) → **нет!** Java создаёт Fish() по умолчанию, а он вызывает super() — такого нет. Неочевидно: «я же ничего не писал».
14. `@Override public String tostring() { … }` → **нет**: опечатка в регистре, у Object нет tostring.
15. `@Override String toString() { … }` (без public) → **нет**: weaker access privileges.
16. `final class Money {}` + `class Euro extends Money {}` → **нет**: cannot inherit from final.
17. `Cat c = new Cat(); Dog d = (Dog) c;` → **нет**: incompatible types. А `Animal a = c; Dog d = (Dog) a;` → **да** (упадёт при запуске).
18. `Animal a = new Cat(); Cat c = a;` → **нет**: вниз только явно.
19. `if (a instanceof Cat c && c.isIndoor())` → **да**. `if (!(a instanceof Cat c)) return; c.meow();` → **да** (★★★: после return переменная c видна ниже — компилятор понимает «если дошли сюда, a — кот»).
20. Метод `static void hi()` в родителе и `void hi()` (не static) в наследнике → **нет**: `hi() in B cannot override hi() in A; overridden method is static` — static-метод можно только спрятать таким же static-методом.

### Скомпилируется, но что при запуске?
21. Массив `Animal[]` с котом и собакой, цикл с `((Cat) zoo[i]).meow()` → первый «Мяу», потом **ClassCastException**.
22. equals без проверки null: `return name.equals(((User) o).name);`, вызов `user.equals(null)` → **NullPointerException** (o == null → ((User) null).name). А `equals("строка")` → **ClassCastException**.
23. ★★★ `public String toString() { return "Cat " + this; }` → **StackOverflowError** (бесконечная рекурсия).
24. ★★★ (на опережение, модуль 13) Только equals переопределён: `Set<Point> s = new HashSet<>(); s.add(new Point(1,2)); System.out.println(s.contains(new Point(1,2)));` → почти наверняка **false**.
25. ★★★ Изменяемый ключ: hashCode по полю x, положили точку в HashSet, потом поменяли x через сеттер → `contains(той же точки)` → **false**: объект лежит на старой полке. (Только как идея, на опережение.)

### Найди ошибку
26. ```java
    class Shape { private String name; Shape(String name) { this.name = name; } }
    class Circle extends Shape {
        double r;
        Circle(double r) { this.r = r; }
        @Override public double area() { return 3.14 * r * r; }
        public String toString() { return name + " " + r; }
    }
    ```
    → нет super(...) (у Shape нет конструктора без параметров); @Override над area(), которой нет у Shape; name — private у родителя.
27. ```java
    class Point {
        int x, y;
        public boolean equals(Point p) { return x == p.x && y == p.y; }
    }
    ```
    → параметр не Object (перегрузка), нет @Override, нет hashCode, нет проверки null.
28. `class Car extends Engine { … }` → «ошибка» проектирования: машина не является двигателем, нужна композиция.

### Почему здесь ошибка?
Покажи сообщение — пусть объяснит своими словами:
29. `error: constructor Animal in class Animal cannot be applied to given types; required: String; found: no arguments` → неявный super().
30. `error: method does not override or implement a method from a supertype` → @Override над методом, которого нет у родителя (опечатка/другие параметры).
31. `error: speak() in Cat cannot override speak() in Animal; attempting to assign weaker access privileges; was public` → сузили доступ.
32. `error: cook() in Omelet cannot override cook() in Recipe; overridden method is final` → у родителя метод final, наследник не может его переопределить.
33. `Exception in thread "main" java.lang.ClassCastException: class Dog cannot be cast to class Cat` → нисходящее приведение без instanceof.

## Дополнительно: кому переопределять equals (урок 10.5, шаг «Кому переопределять, а кому нет»; таблица — в блоке «для любопытных», её подробности не требовать)
- «Надо ли писать equals для String / Integer / List?» → **суть:** нет, в JDK уже переопределён и сравнивает содержимое; писать нужно только в своих классах. **Заблуждение:** «String надо переопределять» или «у String equals == ==».
- «`new StringBuilder("ок").equals(new StringBuilder("ок"))`?» → **false**: у StringBuilder equals не переопределён. Сравнивают через `toString().equals(...)`.
- «`int[] a = {1}; int[] b = {1}; a.equals(b)`?» → **false**; правильно `Arrays.equals(a, b)`.
- «enum сравнивают через == или equals?» → можно `==`: каждое значение enum существует в одном экземпляре.
- «`cart.contains(new Product("Хлеб", 50))` возвращает false, хотя такой товар в корзине лежит. Почему и что делать?» → в Product нет своего equals, сравниваются ссылки; переопределить equals+hashCode или сделать record.
