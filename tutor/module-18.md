> Файл для наставника. Здесь ответы — ученику не показывать (см. CLAUDE.md).

Модуль про то, как писать код, который легко читать и менять: код-стайл и принципы DRY, KISS, YAGNI (урок 18.1), SOLID (18.2), паттерны проектирования (18.3 — порождающие, 18.4 — структурные и поведенческие). Уровень — собеседование Java junior: узнать принцип или паттерн в коде и объяснить своими словами, а не выучить определения.

**Это последний модуль курса.** Блок «Автотесты» ещё не вышел (черновик — `docs/later/autotests-m18/`), не предлагай его ученику. После зачёта модуля поздравь с окончанием курса и пройдись по финалу из урока 18.7 «Финал курса»: карта модулей 0–18, план на 2–3 месяца строго по порядку (SQL/PostgreSQL → JDBC → HTTP и REST → Spring Boot), один пет-проект на выбор (трекер расходов, домашняя библиотека, список дел, мини-банк, погодный помощник), свой пет-проект на GitHub с README и тестами, «Тренинг код» (`/training.html`) по 20–30 минут каждый день. Помоги ученику выбрать проект и разбить первый этап плана на недели.

## Цели модуля и вопросы

Формат: вопрос → **суть правильного ответа** → типичные заблуждения.

### О1. Чистый код: стиль, DRY, KISS, YAGNI (урок 18.1)
- «Как в Java называют класс, метод, переменную, константу, пакет?» → **PascalCase; camelCase с глагола у метода; camelCase; UPPER_SNAKE_CASE; маленькими буквами.**
- «Что такое магическое число и как от него избавиться?» → **число без объяснения смысла; именованная константа `static final` (Ctrl+Alt+C) или enum.**
- «Что значат DRY, KISS, YAGNI? Пример нарушения каждого?» → **одно знание — в одном месте; самое простое из рабочих решений; не писать код «на будущее».** Заблуждение: «DRY — склеить всё, что выглядит одинаково» (два разных тарифа по 50 ₽ — два правила, а не одно).
- «Чем помогает Checkstyle?» → **автоматически проверяет стиль при сборке, спор о стиле решает инструмент, а не ревьюер.**

### О2. SOLID (урок 18.2)
- «Расшифруй SOLID, по примеру на каждую букву» → **S — одна причина для изменения; O — новое добавляем новым классом, не правя старый; L — наследник работает везде, где родитель; I — маленькие интерфейсы вместо толстого; D — логика зависит от интерфейса, конкретику передают снаружи.**
- «Single Responsibility — это "один метод в классе"?» → **нет: одна забота, одна причина меняться.**
- «Чем Dependency Inversion отличается от Dependency Injection?» → **первое — принцип (зависеть от абстракций), второе — приём (передать зависимость через конструктор).**
- «Как D помогает тестам?» → **в конструктор можно передать фейк вместо настоящей базы, почты, обогревателя.**

### О3. Паттерны проектирования (уроки 18.3–18.4)
- «Что такое паттерн? Какие три группы?» → **проверенный рецепт для типичной задачи (GoF, 1994); порождающие, структурные, поведенческие.** Заблуждение: «паттерн — готовый код/библиотека».
- «Как сделать Singleton и чем он плох?» → **приватный конструктор + `private static final` поле + `getInstance()` или enum; глобальное состояние, скрытые зависимости, мешает тестам, ленивый вариант небезопасен в потоках.**
- «Зачем Builder, если есть конструктор?» → **читаемый вызов, необязательные параметры без россыпи конструкторов, проверка в `build()`, неизменяемый результат.**
- «Поверхностная и глубокая копия?» → **копия ссылок против копии вложенных объектов; `clone()` у массива поверхностный.**
- «Чем Adapter, Decorator и Proxy похожи и чем отличаются?» → **все — обёртки; адаптер меняет интерфейс, декоратор добавляет способность, заместитель управляет доступом (лень, кеш, права).**
- «Где Strategy и Iterator в JDK?» → **`Comparator` и лямбды в `sort`/`filter`; `Iterator` и for-each через `Iterable`.**
- «Mediator и Observer — в чём разница?» → **посредник — центр, через который общаются все; наблюдатель — подписчики получают уведомление от одного источника.**

## Банк головоломок

### Что не так? Какой принцип? Какой паттерн?
- `if (age >= 18) return true; else return false;` — что упростить? (KISS: `return age >= 18;`)
- `w > 20 ? "L" : w > 5 ? "M" : "S"` при `w = 20`? (M; и почему вложенный тернарник — плохо)
- Склеить `deliveryPrice(kg) { kg * 50 }` и `packagingPrice(boxes) { boxes * 50 }` в `multiplyBy50`? (нет: два разных правила; DRY — про знание, а не про буквы)
- Пингвин наследует `Bird` и бросает исключение в `fly()`: скомпилируется? что при запуске? какой принцип? (да; исключение на пингвине; L)
- `private final Heater heater = new GasHeater();` в классе с логикой — какой принцип нарушен? (D)
- `interface Worker { work(); eat(); }` и `Robot` с пустым `eat()` — какой принцип? (I)
- `Integer.valueOf(1000) == Integer.valueOf(1000)`? (false: кеш фабрики только −128..127)
- Метод строителя `void cheese()` — скомпилируется ли цепочка `.cheese().sauce(…)`? (нет: цепочка держится на `return this`)
- Конструктор копирования `this.players = other.players` — что будет после `b.add(…)` с игроками `a`? (выросли: копия поверхностная)
- `Arrays.asList(a)`, потом `a[0] = …` и `l.add(…)`? (замена видна; add → UnsupportedOperationException: адаптер над массивом)
- `new WithMilk(new WithSyrup(new Espresso()))` — в каком порядке добавки в названии? (сироп, потом молоко: изнутри наружу)
- Ленивый заместитель картинки: 3 объекта, у второго дважды `show()` — сколько загрузок? (одна)
