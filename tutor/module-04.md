## Цели модуля и вопросы

Формат: вопрос → **суть правильного ответа** → типичные заблуждения.

### О1. if и условие
- «Что может стоять в скобках после if?» → **любое выражение типа boolean: сравнение, &&/||/!, boolean-переменная, вызов, возвращающий boolean.**
- «Почему `if (count)` с `int count` не компилируется?» → **в Java нет правила «ноль — ложь»; число не boolean.**
- «Что значат фигурные скобки после if? Что будет с переменной, объявленной внутри?» → **блок; переменная видна только внутри блока (область видимости).**
- «Нарисуй блок-схему if» → **ромб с вопросом, два выхода «да/нет», дороги сходятся после блока.**
- Заблуждение: `if (flag == true)` — «так правильнее». Нет, достаточно `if (flag)`; сравнение с true открывает дорогу ловушке `=`.

### О2. else, else if, порядок веток
- «Сколько веток выполнится в `if/else if/else`? А без последнего else? А в трёх отдельных if?» → **ровно одна; 0 или 1; от 0 до всех трёх.**
- «Почему в цепочке `score >= 90 … else if (score >= 75)` не пишут `score >= 75 && score < 90`?» → **раз дошли до второй ветки, первая ответила «нет», значит, score < 90 уже известно.**
- «Покажи ветку, которая никогда не сработает» (дай `if (n > 0) … else if (n > 100)`) → **широкое условие сверху «съедает» узкое; порядок — от узкого к широкому.**
- Заблуждение: «Java проверяет все условия и выбирает самое подходящее». Нет — первое истинное сверху.
- «Почему `String r; if (s >= 90) r = "5"; else if (s >= 60) r = "3"; println(r);` не компилируется?» → **`variable r might not have been initialized`: есть дорога, где ни одна ветка не сработала; нужен последний else или начальное значение. Компилятор не разбирает смысл условий — даже два взаимоисключающих отдельных if его не убедят.**

### О3. Вложенные if и логические операции
- «Когда вложенный if, а когда `&&`?» → **если для промежуточного случая нужно своё действие/сообщение — вложенный; если нет — `&&`.**
- «К какому if относится else без скобок?» → **к ближайшему if без пары (висячий else).**
- «Что выведет `if (x != 0 && 10 / x > 1)` при x = 0?» → **ничего не упадёт: && ленивый, правая часть не вычисляется.**

### О4. Ловушки
- `=` vs `==`: «Почему `if (x = 5)` с int — ошибка, а `if (ok = true)` с boolean компилируется?» → **присваивание возвращает присвоенное значение; int не boolean, а true — boolean, и условие всегда истинно.**
- `;` после if: «Что делает `if (cond);`?» → **пустая инструкция — тело if; следующий блок выполняется всегда.**
- if без скобок: «Почему вторая строка с отступом выполняется всегда?» → **без скобок if берёт одну инструкцию; отступы для компилятора ничего не значат.**
- Строки: «Почему `answer == "Да"` даёт false для ввода с клавиатуры?» → **== сравнивает ссылки; строка из Scanner — новый объект; текст сравнивают `"Да".equals(answer)`.** Глубже (пул строк, null) — модуль 8, не требовать.
- double: «Почему нельзя `if (sum == 0.3)`?» → **погрешность двоичного представления; сравнивают с допуском `Math.abs(a - b) < eps`.**
- «Почему не компилируется `0 < x < 10`?» → **`0 < x` даёт boolean, boolean с int не сравнить; нужно `x > 0 && x < 10`.**

### О5. Тернарный оператор
- «Перепиши if-else, выбирающий цену, тернарным» → **`int price = age < 18 ? 150 : 300;`**
- «Почему `println("Возраст: " + age >= 18 ? "да" : "нет")` не компилируется?» → **у + приоритет выше, у тернарного — ниже всех: сначала склейка в строку, потом строка >= 18 — ошибка; нужны скобки.**
- «Можно ли `ok ? println("a") : println("b");`?» → **нет: тернарный — выражение, выбирает значение; у println значения нет.**
- «Когда тернарный вредит?» → **вложенные тернарные, длинные условия, больше двух вариантов.**
- «Как короче: `if (x > 0) ok = true; else ok = false;` или `ok = x > 0 ? true : false`?» → **`boolean ok = x > 0;` — сравнение уже даёт boolean.**

### О6. Классический switch
- «Что такое провал (fall-through)?» → **case — точка входа; без break выполнение идёт вниз через следующие метки, в т.ч. через default.**
- «Когда провал полезен?» → **группировка: `case 6: case 7: …выходной…; break;`**
- «По каким типам можно switch?» → **int (byte, short), char, String, enum (позже); нельзя long, double, float, boolean.**
- «Можно ли в case написать `score >= 90`?» → **нет, только литералы или константы (`final`-переменная, инициализированная литералом); диапазоны — if.**
- «Нужен ли break в последней ветке?» → **нет, после неё switch и так кончается; ставят по привычке, чтобы новый case снизу не получил провал.**
- «Где может стоять default и что, если он первый без break?» → **где угодно; при входе в него провалится в следующий case.**

### О7. Новый switch и switch-выражение (Java 14+)
- «Чем `case 1 ->` отличается от `case 1:`?» → **нет провала, break не нужен; несколько значений через запятую `case 6, 7 ->`.**
- «Зачем default в switch-выражении?» → **выражение обязано вернуть значение для любого входа; без default — ошибка компиляции «does not cover all possible input values».**
- «Зачем `;` после `}` switch-выражения?» → **это конец оператора присваивания `String s = …;`.**
- «Как switch по String сравнивает строки?» → **по тексту (equals), с учётом регистра. Принять любой регистр: `switch (cmd.toLowerCase())`, метки — маленькими буквами.**
- `yield` — знать, что существует (для блоков в switch-выражении), не требовать. Если спросит про return: внутри switch-выражения он не компилируется (`attempt to return out of a switch expression`).

### О8. Мастерская: от задачи к условиям
- «Расскажи шесть шагов решения» → **пойми вход/выход → руками → таблица случаев → псевдокод → код → прогон по таблице.**
- «Что такое граничные значения? Какие числа проверишь для «скидка от 1000 до 5000 включительно»?» → **числа на стыках диапазонов и их соседи: 999, 1000, 5000, 5001 (+ по одному из середины).**
- «Где ставить проверку некорректного ввода?» → **первой в цепочке.**
- «Как найти максимум из трёх без лесенки if?» → **рекордсмен: `max = a`, потом по отдельному if на каждое следующее число. Стартовать с первого числа, не с 0.**
- Связь с тестированием: таблица случаев = классы эквивалентности + граничные значения = будущие тесты JUnit. Хорошо, если ученик сам это сформулирует.

## Банк головоломок

Давай по одной, ответ — только с «почему». ★★★ — честно предупреждай, что на опережение.

### Что выведется?
1. ```java
   int t = 35;
   if (t > 20) System.out.println("Тепло");
   else if (t > 30) System.out.println("Жара");
   ```
   → `Тепло` (ветка «Жара» мёртвая — порядок).
2. ```java
   int x = 3;
   if (x > 5);
       x = x * 2;
   System.out.println(x);
   ```
   → `6` (`;` — пустое тело).
3. ```java
   int a = 7;
   if (a > 10)
       System.out.println("big");
       System.out.println("number");
   ```
   → `number`.
4. Висячий else:
   ```java
   int x = 10;
   if (x > 5)
       if (x > 20) System.out.println("A");
   else System.out.println("B");
   ```
   → `B`. А при `x = 3`? → **ничего** (внешний if ложен, else принадлежит внутреннему).
5. ```java
   int level = 2;
   switch (level) {
       case 1: System.out.println("Новичок");
       case 2: System.out.println("Опытный");
       case 3: System.out.println("Мастер"); break;
       default: System.out.println("???");
   }
   ```
   → `Опытный`, `Мастер`.
6. Тот же switch при `level = 7` → `???`. При `level = 1` → `Новичок`, `Опытный`, `Мастер`.
7. default первым, `n = 5`:
   ```java
   switch (n) { default: System.out.println("D"); case 1: System.out.println("1"); break; case 2: System.out.println("2"); }
   ```
   → `D`, `1`. При `n = 2` → `2`.
8. `System.out.println(5 > 3 ? "да" : "нет" + "!");` → `да` (`+ "!"` прилип только к «нет»).
9. `System.out.println(1 > 3 ? "да" : "нет" + "!");` → `нет!`.
10. ```java
    int n = 15; String s = "";
    if (n % 3 == 0) { s += "Fizz"; }
    if (n % 5 == 0) { s += "Buzz"; }
    System.out.println(s);
    ```
    → `FizzBuzz` (а с `else if` — только `Fizz`).
11. ```java
    boolean admin = false;
    if (admin = true) System.out.println("Доступ открыт");
    System.out.println(admin);
    ```
    → `Доступ открыт`, `true`.
12. ```java
    int n = 2;
    switch (n) { case 1 -> System.out.println("один"); case 2 -> System.out.println("два"); case 3 -> System.out.println("три"); }
    ```
    → `два` (стрелки — без провала).
13. `int x = -7; System.out.println(x % 2 == 1 ? "нечётное" : "чётное");` → `чётное`! (−7 % 2 = −1). Классическая ошибка в проверке нечётности.
14. ★★★ `System.out.println(true ? 1 : 2.0);` → `1.0` (общий тип ветвей — double).
15. ★★★ `char c = 'b'; switch (c) { case 'a' -> System.out.println("A"); case 98 -> System.out.println("98"); default -> System.out.println("?"); }` → `98` (char — это число, код 'b' = 98; константа 98 подходит к char).

### Скомпилируется ли?
16. `int x = 5; if (x = 5) { }` → **нет**: `incompatible types: int cannot be converted to boolean`.
17. `if (0 < x < 10) { }` → **нет**: `bad operand types for binary operator '<'`.
18. `String s = switch (n) { case 1 -> "один"; case 2 -> "два"; };` → **нет**: не покрыты все значения, нужен default.
19. `double p = 9.5; switch (p) { case 9.5 -> … }` → **нет**: switch не работает с double.
20. Два `case 1:` в одном switch → **нет**: `duplicate case label`.
21. Смешанный switch: `case 1 -> …; case 2: …` → **нет**: `different case kinds used in the switch`.
22. `if (x > 0) int y = 5;` → **нет**: объявление переменной не может быть единственным телом if без скобок (`variable declaration not allowed here`). Со скобками — можно.
23. `else (x < 0) { }` → **нет**: у else нет условия.
24. `age >= 18 ? System.out.println("да") : System.out.println("нет");` → **нет**: тернарный — не инструкция, у println нет значения.
25. `if (x > 0) { } else { } else { }` → **нет**: `'else' without 'if'`.

### Скомпилируется, но что при запуске?
26. `int x = 0; if (10 / x > 1 && x != 0) { … }` → **ArithmeticException: / by zero** — левую часть && вычисляют первой. Поменять местами — и всё работает.
27. `String answer = scanner.nextLine(); if (answer == "да") …` при вводе «да» → ветка не выполнится (сравнение ссылок).
28. `double total = 0.1 + 0.2; if (total == 0.3) … else System.out.println("Ошибка в расчётах!")` → «Ошибка в расчётах!».
29. switch по строке `"Start"` при `case "start" ->` → попадёт в default (регистр важен). А `switch (cmd.toLowerCase())` при вводе `STOP` и `case "stop" ->` → попадёт в «stop».

### Найди ошибку
30. ```java
    if (balance < 0); {
        System.out.println("Долг!");
    }
    ```
    → `;` после if.
31. ```java
    if (score >= 60) grade = "3";
    else if (score >= 75) grade = "4";
    else if (score >= 90) grade = "5";
    ```
    → порядок: ветки «4» и «5» мёртвые.
32. ```java
    int max = 0;
    if (a > max) max = a;
    if (b > max) max = b;
    ```
    → на отрицательных вернёт 0. Старт рекордсмена — `max = a`.
33. ```java
    switch (day) {
        case 6: System.out.println("Суббота");
        case 7: System.out.println("Воскресенье"); break;
    }
    ```
    → для 6 напечатает обе строки: забыт break.
34. Треугольник: проверка «a == b || b == c» без `a == c` → `5 8 5` не распознан как равнобедренный.

### Почему здесь ошибка? (код + сообщение javac → объяснить)
35. `incompatible types: int cannot be converted to boolean` на строке `if (lives)` → условие должно быть boolean.
36. `cannot find symbol: variable status` после `if (…) { String status = …; }` → область видимости.
37. `the switch expression does not cover all possible input values` → нет default.
38. `bad operand types for binary operator '>='` на `println("Возраст: " + age >= 18 ? …)` → приоритет: нужны скобки вокруг тернарного.
39. `variable sign might not have been initialized` после `String sign; if (x > 0) sign = "+"; if (x <= 0) sign = "-";` → два отдельных if, компилятор видит дорогу без присваивания; нужен `if … else`.

Цель выполнена — поездка кончается сама.

Свои методы ученик ещё не проходил (модуль 7). В уроке дано на уровне: `step` — метод, который игра вызывает на каждом ходу; `robot` — твой робот, датчики и команды через точку, как `scanner.nextInt()` и `System.out.println()`. Код не писать, даже кусок условия. Метод расследования, которому учим: взять ответы датчиков с хода, пройти `step` глазами сверху вниз, найти первую ветку с `true`; нужного датчика нет в списке — значит, выше сработала другая ветка.

### Уровень ★ `m04-c1` «Коридор»
**Идея:** «впереди свободно — ехать, иначе повернуть туда, где нет стены». В коридоре без развилок при стене впереди свободна ровно одна сторона, поэтому хватает одной проверки стороны и `else`.
**Типичные ошибки:**
- Заготовка как есть (`robot.move()` всегда) — врезается на первом повороте, в «спросил» — «ничего».
- «Стена впереди → всегда turnLeft()»: на правом повороте разворачивается и едет назад, туда-сюда → «Ходы кончились».
- `wallAhead()` без `!` (перепутал «есть стена» и «свободно») — врезается сразу или крутится.
- Два отдельных `if` вместо цепочки (`if (…) move(); if (…) turnLeft();`) — на некоторых ходах срабатывают обе команды → «За один ход — одна команда».
- `if` без `else` для последнего случая — на каком-то ходу ни одна ветка не сработала → «За этот ход Джавик не получил команду».
**Вопросы ученику:** «Что ответили три датчика на ходу, где он врезался?», «Если впереди и слева стены — что остаётся?», «Какая ветка дала команду на этом ходу?».
**Ступеньки:** ① «Что Джавик спросил перед ходом, где врезался? Был ли там `wallAhead()`?» → ② «Когда впереди стена, спроси про одну сторону; другая — в else» → ③ «впереди нет стены → move(); иначе слева нет стены → turnLeft(); иначе → turnRight()».

### Уровень ★★ `m04-c2` «Первая посылка»
**Идея:** **порядок условий** — особые случаи («тут посылка», «я на адресе и везу») первыми ветками цепочки, общее правило движения — последним; срабатывает первая подходящая ветка. Правило из ★ не трогаем, только добавляем ветки сверху.
**Типичные ошибки:**
- Проверка посылки после правила движения — проезжает мимо 📦 (ветки движения покрывают все случаи). На 🏠 без посылки: либо `drop()` → «у Джавика нет посылки», либо крутится в тупике → лимит ходов.
- Проверка посылки отдельным `if` над цепочкой движения — на клетке с посылкой срабатывают `take()` и `move()` → «За один ход — одна команда».
- `drop()` только по `atTarget()` без `carrying()` — на этих картах обычно проходит, но спроси «а если приехал без посылки?» — пусть сам предложит `&&`.
- Переписал файл заново и сломал уровень ★ — напомни: один файл, решение ★★ должно проходить и ★.
**Вопросы ученику:** «Почему take() выше move()? Что будет, если поменять местами?», «Когда можно отдавать — какие два условия?», «Почему после take() Джавик не берёт посылку снова?» (её больше нет на клетке, `parcelHere()` = false).
**Ступеньки:** ① «Найди ход на клетке с 📦: есть ли в списке `parcelHere()`?» → ② «Кто проверен первым, тот и решает: особые случаи — выше; для адреса нужны два датчика через &&» → ③ «посылка → take(); на адресе и везу → drop(); дальше правило из ★».

### Уровень ★★★ `m04-c3` «Ямы»
**Идея:** на прямых участках ямы. Яма — не стена: перед ней `wallAhead()` = `false`, поэтому правило из ★ («впереди свободно — `move()`») роняет Джавика. Проверку `pitAhead()` ставим после посылки и адреса, но **до** движения; есть яма — `jump()` (перелетает яму и приземляется за ней, это один ход). Тот же урок, что в ★★: особый случай — выше общего правила, срабатывает первая подходящая ветка.
**Типичные ошибки:**
- `pitAhead()` ниже `!wallAhead()` → ветка движения срабатывает раньше, «Джавик упал в яму».
- `jump()` вместо `move()` везде или `if (!robot.pitAhead()) robot.jump()` (перепутал условие) → «прыгнул, а ямы впереди нет».
- Две команды в ветке ямы (`robot.jump(); robot.move();`) → «За один ход — одна команда».
- Остался `robot.sign()` из старой версии игры → ошибка компиляции «cannot find symbol: method sign()»; сайт подскажет убрать его.
**Вопросы ученику:** «Почему проверка ямы выше движения?», «Что ответит `wallAhead()` перед ямой и почему этого мало?», «Сколько клеток пролетает `jump()` и сколько это ходов?».
**Ступеньки:** ① «Найди ход, где Джавик упал: какие датчики он спросил перед этим ходом, был ли `pitAhead()`?» → ② «Яма — особый случай, как посылка: проверь её раньше, чем "впереди свободно — едем"» → ③ «посылка и адрес как в ★★; яма впереди → jump(); иначе правило из ★».

На экзамене по игре: «Расскажи свой step словами сверху вниз и объясни, почему ветки стоят именно в таком порядке». Суть ответа: особые случаи (посылка, адрес, яма) раньше общего правила, потому что в цепочке `if` / `else if` срабатывает первая подходящая ветка, а за ход нужна ровно одна команда.
