# «Тренинг код»: как писать задачи

Раздел «Тренинг код» — сотни коротких задач, чтобы набить руку. **Только «напиши код сам»**, в духе простых задач LeetCode: «разверни строку», «проверь, что число простое», «найди максимум в массиве» — и выведи ответ. Не делаем «допиши готовый код», «почини» и «сократи» — для этого есть задачи в «Практике» модулей.

## Где что лежит
- Тема — папка `tasks/tr-<тема>/` (латиница, без цифр и дефисов внутри имени: `tr-strings`, `tr-loops`).
- `tasks/tr-<тема>/_topic.json`: `{ "title": "…", "icon": "🔤", "after": "m08", "order": 7, "summary": "одна фраза о теме" }`. `after` — модуль курса, после которого тема по силам: задачи используют только то, что пройдено к концу этого модуля.
- Задача — `tasks/tr-<тема>/NNN-коротко.task` (`001`, `002`… — порядок показа).
- Эталонное решение — `tutor/solutions/trainer/<тема>/<Класс>.java`. Ученику его не показываем.
- Код ученика — `workspace/trainer/<тема>/<Класс>.java`; сервер сам создаёт папку и помечает её в IDEA как папку с кодом.

## Формат задачи
```
## id: tr-strings-007
## title: Палиндром?
## file: trainer/strings/PalindromeCheck.java
## class: PalindromeCheck
## level: 1
## category: Переворот и палиндромы
@@ description
<p>Напиши класс <code>PalindromeCheck</code>. Программа читает одно слово и печатает <code>true</code>, если оно читается одинаково слева направо и справа налево, иначе <code>false</code>.</p>
<pre class="terminal"><span class="out">ввод:  шалаш      вывод: true
ввод:  java       вывод: false</span></pre>
<div class="callout tip"><span class="callout-title">🧰 Пригодится</span><ul>
<li><code>new StringBuilder(s).reverse().toString()</code> — возвращает строку задом наперёд</li>
<li><code>a.equals(b)</code> — сравнивает строки по содержимому (не <code>==</code>!)</li>
</ul></div>
@@ test: Палиндром
@@ input
шалаш
@@ expect
true
@@ test: Не палиндром
@@ input
java
@@ expect
false
@@ test: Одна буква
@@ input
а
@@ expect
true
```

## Правила
1. **Каждая задача — новый класс** с понятным английским именем в стиле Java (`PalindromeCheck`, `MaxOfThree`, `CountVowels`). Имя уникально во всём курсе: проверь `grep -rh "^## class:" tasks`.
2. **Условие** — что написать, формат ввода (через `Scanner`, каждое значение с новой строки или через пробел — скажи явно) и точный формат вывода, 1–2 примера. Иногда — «напиши метод `static boolean isPrime(int n)` и вызови его из `main`» (тогда добавь `@@ require: static\s+boolean\s+isPrime | …`).
3. **«🧰 Пригодится»** — 1–4 метода или приёма, которые помогут: что делает каждый, одной строкой. Не решение и не готовый алгоритм. Можно без блока, если всё нужное очевидно.
4. **Уровни — только два** (курс для начинающих): 1 🟢 — одно действие или короткий цикл; 2 🟡 — несколько шагов или аккуратный разбор ввода. Примерно 55% / 45%, лёгкие — первыми. Уровня 3 нет; прежние сложные задачи лежат в `docs/later/trainer-hard/`.
5. **Тесты: 3–6**, обязательно крайние случаи — ноль, отрицательные, пустая строка, одна буква/один элемент, повторы, большие числа (переполнение `int`), регистр букв, пробелы. Выводы — точные, проверенные эталоном.
6. **Разнообразие.** Не повторяй одну задачу с другими числами. Разные сюжеты (магазин, погода, спорт, школа, игры, банк, транспорт) и разные формы вывода (`true`/`false`, число, строка, список через пробел, несколько строк).
7. **Только пройденное** к модулю `after`. Никаких автотестов, Selenium и т.п. в сюжетах.
8. **Правильная речь:** в условиях — термины из `docs/terms.md` («объяви переменную», «метод возвращает», «вызови метод и передай аргумент»).

9. **По нарастающей.** Номера файлов идут от самой простой задачи к самой сложной: сначала все 🟢, потом 🟡, и внутри уровня — от лёгкого к трудному. Ученик может решить 20, 100 или все задачи подряд, и каждая следующая чуть труднее предыдущей.
10. **Категория.** `## category:` — подтема внутри темы (4–8 на тему, 1–3 слова: «Цифры числа», «Матрицы», «Рекурсия»), в каждой ≥ 3 задач разных уровней. На странице темы по ним есть фильтр.
11. **Одна задача — один файл.** Публичный класс с `main` — тот, что в `## class`. Нужны вспомогательные классы (record, enum, свой класс) — пиши их в том же файле без `public`.

## Технические ловушки (проверено на движке)
- Дробные числа **не печатай через `printf`/`String.format`**: на компьютере ученика с русской локалью выйдет `3,14`, а в проверке — `3.14`. Нужно округлить — `Math.round(x * 100) / 100.0`, и в условии так и скажи.
- **Порядок вывода должен быть однозначным.** `HashSet`/`HashMap` печатают в непредсказуемом порядке — в условии проси сортировку или используй `TreeMap`/`TreeSet`/`LinkedHashMap`.
- Формат ввода пиши в условии явно: «в первой строке — количество n, во второй — n чисел через пробел». До модуля 5 (циклы) количество входных значений фиксированное.
- Лишние пробелы в конце строк и пустые строки в конце вывода движок прощает, остальное сравнивается точно.

## Проверка
`node tools/check-tasks.js tr-<тема>` (сайт запущен на localhost:7070) — все задачи темы должны пройти на эталонах. Скрипт возвращает файлы ученика и убирает свои записи из журнала проверок. После новых тем — `node tools/build-course.js`.
