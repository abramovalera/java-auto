# Проход «скрины везде» по урокам

Курс «Java с нуля» (`C:\Users\V\IdeaProjects\java-course`, сайт — `site/`, уроки — `site/lessons/mXX/*.html`). Автор курса недоволен: в уроках пишем «ошибка компиляции», «stack trace», «консоль», «отладчик», «меню Refactor», «панель Git» — а новичок этого никогда не видел. Его слова: «всё, о чём мы ведём речь, должно подсвечиваться… человек ошибку компиляции никогда не видел и не понимает, о чём речь. Нужно приложить скриншот… чтобы человек видел, что за ошибка, как её читать, на что обращать внимание».

## Твоя задача
Пройди **каждый урок своих модулей** и там, где текст говорит о чём-то, что ученик увидит на экране IntelliJ IDEA, вставь рядом «скрин» — компонент `data-widget="ide"` с выносками-номерами. Типичные места:
- ошибка компиляции (любая: несовместимые типы, missing return, cannot find symbol, unhandled exception, final, static context, unreachable…) → редактор с красной волной (`errors` + `tip: true`), при необходимости панель `build`;
- исключение / stack trace / exit code → `console` со строками `err` (каждая `at …` отдельной строкой, ссылки `(X.java:N)` станут синими);
- вывод программы, ввод с клавиатуры (Scanner) → `console` (`in` — зелёный ввод);
- предупреждения IDEA (жёлтое), серый неиспользуемый код, подсказки Alt+Enter → `warnings`, `dimLines`, `menu`;
- отладчик (точки останова, Step Over/Into, Frames, Variables) → `breakpoints`, `execLine`, `debug`;
- меню и диалоги IDEA (Generate Alt+Insert, Refactor/Rename, New Java Class, Project Structure, Maven, Git commit/push…) → `menu`, `popup`, `dialog`, `tree`;
- запуск тестов JUnit → `tests`.

Формат и все поля компонента — `docs/module-brief.md`, раздел **`ide` — «скрин» IntelliJ IDEA** (прочитай целиком, там же `div.cheat`). Образцы (прочитай оба, перед тем как писать): `site/lessons/m01/04-first-program-idea.html` и `site/lessons/m01/08-errors.html` — так должно выглядеть.

Ещё:
- **«📝 Выпиши себе»** (`div.cheat`, образец — урок 1.4): если в модуле впервые появляются горячие клавиши или команды (например, отладчик F8/F7/F9, Alt+Insert, Shift+F6, Ctrl+B, Ctrl+Alt+V, Git push/pull/commit/rebase, Maven), — добавь шпаргалку в начало первого урока, где они нужны. Не дублируй то, что уже было в урок 1.4 (psvm, sout, Ctrl+Alt+L/O, Ctrl+Y, Ctrl+D, Ctrl+/, Alt+Enter, Ctrl+Space, Ctrl+Shift+F10).
- Тексты ошибок в скринах — **как в настоящей IntelliJ IDEA** (английские формулировки редактора; у javac бывают другие — можно об этом сказать). Не выдумывай то, в чём не уверен.
- Номера колонок/строк в `errors`/`build` должны совпадать с кодом скрина. `text` в `errors` должен реально встречаться в этой строке.
- Выноски `marks`: 2–5 на скрин, каждая — «на что смотреть и что это значит», простым языком. Скрин без пояснений бесполезен.
- Если рядом уже стоит `<pre class="terminal">` с выводом, который ученик увидит **в IDEA** («в панели Run видишь…»), — замени его скрином с консолью. Вывод **сайта** (кнопка «Проверить») оставь как есть.
- Не перегружай: скрин там, где о предмете говорится впервые или где важно показать, куда смотреть. Обычно 1–4 скрина на урок; уроки чисто про синтаксис без экранных «предметов» можно не трогать.
- id скринов уникальны в уроке (`shot-…`).

## Нельзя
- Менять `site/js/*`, `site/css/*`, задачи, `_manifest.json`, уроки чужих модулей. Если компоненту чего-то не хватает — не обходи хаками, а напиши в отчёте.
- Тип `blank` в проверках (запрещён). Удалять существующие проверки и содержание (можно заменять `pre.terminal` на скрин, как сказано выше).
- Пользоваться браузером (он занят другим агентом). Проверяй статически.
- git commit/push.

## Самопроверка
1. Все `<script type="application/json">` в изменённых файлах — валидный JSON:
   `node -e "const fs=require('fs');for(const f of process.argv.slice(1)){const s=fs.readFileSync(f,'utf8');for(const m of s.matchAll(/<script type=\"application\/json\">([\s\S]*?)<\/script>/g)){try{JSON.parse(m[1])}catch(e){console.log(f,e.message)}}}" site/lessons/mXX/*.html`
2. Для каждого `errors[i].text` — подстрока есть в строке `line` кода; для `col` — не дальше длины строки + 1.
3. Страницы отдаются сервером: `curl -s -o /dev/null -w "%{http_code}" http://localhost:7070/lessons/mXX/файл.html` → 200.
