Повторение

Selenium и Selenide

Браузером из Java управляет библиотека Selenium WebDriver — мировой стандарт с 2000-х. Она умеет всё, но многословна: чтобы дождаться кнопки и нажать её, нужно несколько строк служебного кода. Selenide — обёртка над Selenium, написанная автоматизаторами для автоматизаторов: коротко, читаемо и, главное, сама ждёт элементы.

Аналогия: коробка передач

Selenium — механика: всё под контролем, но на каждом перекрёстке сам выжимаешь сцепление и переключаешь передачи. Selenide — автомат: нажал «газ» — едешь, переключения он делает сам. Ехать можно на обоих, но на автомате думаешь о дороге, а не о педалях.

Словарь Selenide

Почти все тесты собираются из десятка методов: статических методов класса Selenide и методов элемента. Статические методы подключают статическим импортом — тогда можно вызывать open(…) и $(…) без имени класса:

import static com.codeborne.selenide.Selenide.*;     // open, $, $$
import static com.codeborne.selenide.Condition.*;    // visible, text, value…
Вызов методаЧто делает
open("/login")открывает адрес; если он начинается с /, к нему приклеится Configuration.baseUrl
$("локатор")локатор передаётся аргументом; метод возвращает элемент страницы — объект SelenideElement, первый подходящий по CSS-селектору
$x("//xpath") или $(byXpath("…"))один элемент по XPath
$$("локатор")коллекция всех подходящих элементов
.setValue("anna")действие: очищает поле и вводит текст из аргумента
.click()действие: кликает по элементу
.shouldBe(visible)проверка состояния: элемент виден — метод получает аргументом условие visible (есть и hidden, enabled, disabled)
.shouldHave(text("Привет"))проверка: текст элемента содержит «Привет»
.shouldHave(exactText("Привет, anna!"))проверка: текст совпадает целиком
.shouldHave(value("anna"))проверка: значение поля ввода
.getText()просто возвращает текст элемента как значение типа String (без ожидания и проверки)
$$(".book-card").shouldHave(size(3))проверка коллекции: ровно 3 элемента
$$(".book-card").findBy(text("Чистый код"))из коллекции — элемент с нужным текстом

Да, метод называется просто $. В Java доллар — законный символ имени, как буква. $ — обычный статический метод класса Selenide, который возвращает объект SelenideElement. А у объекта — методы click(), setValue(), shouldHave(). Строку $("#login").click(); читаем так: вызываем статический метод $ с аргументом-локатором "#login", он возвращает элемент страницы, и у этого объекта сразу вызываем метод click — цепочка вызовов. Никакой магии: это классы и методы из модулей 9–11.

Чем отличаются shouldHave(text("Войти")) и shouldHave(exactText("Войти")) для кнопки с текстом «Войти через почту»?

Первая проверка пройдёт: условие text ищет подстроку, а «Войти» внутри есть. Вторая упадёт: exactText требует совпадения целиком. Регистр букв обе по умолчанию не учитывают (для строгого сравнения есть textCaseSensitive). Частая ошибка новичка — проверить text("1") у счётчика с числом 12 и получить ложный «зелёный».

Умные ожидания: секрет Selenide

Страницы живут своей жизнью: данные грузятся, кнопки появляются через полсекунды, ошибки всплывают с анимацией. Если тест проверит «прямо сейчас», он то пройдёт, то нет — станет flaky.

Новичок «чинит» это так: Thread.sleep(5000) — «подожду 5 секунд на всякий случай». Плохо дважды: если элемент появился через 0,3 с, тест зря стоит 4,7 с (а таких мест в наборе сотни), а если сервер сегодня медленный и элемент появился через 6 с — тест всё равно упал.

Selenide делает иначе. Каждая проверка состояния should… повторяется каждые 200 мс, пока не выполнится, — но не дольше Configuration.timeout (по умолчанию 4 секунды). Действия click и setValue тоже сначала ждут, пока элемент появится.

Аналогия: ждёшь друга у подъезда

sleep — «простою 10 минут, потом поднимусь», даже если друг вышел через минуту. Selenide — «смотрю на дверь каждые пару секунд: вышел — идём; не вышел за 10 минут — звоню, что-то случилось».

Ошибка «Неверный пароль» появляется через 0,5 с после клика. Тест: click(), затем $(".error").shouldBe(visible). Пройдёт?

Да. shouldBe будет проверять видимость каждые 200 мс и через ~0,6 с увидит ошибку. Тест пройдёт за полсекунды, без всяких sleep. А если ошибка не появится за 4 с — тест упадёт с понятным сообщением.

Свою «умную паузу» ты напишешь в задаче «Умное ожидание вместо sleep» — и увидишь, как она устроена внутри.

Тест логина целиком

Вот настоящий UI-тест для формы входа магазина Nook (адрес выдуманный: домен .test зарезервирован как раз для примеров). Прочитай его медленно — почти каждую строку ты уже понимаешь.

import com.codeborne.selenide.Configuration;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import static com.codeborne.selenide.CollectionCondition.sizeGreaterThan;
import static com.codeborne.selenide.Condition.*;
import static com.codeborne.selenide.Selenide.*;

class LoginTest {

    @BeforeEach
    void setUp() {
        Configuration.baseUrl = "https://nook-shop.test";
        Configuration.browser = "chrome";
        Configuration.timeout = 4000;
        open("/login");
    }

    @AfterEach
    void tearDown() {
        closeWebDriver();
    }

    @Test
    void userCanLogInWithValidPassword() {
        $("[data-test-id='login']").setValue("anna");
        $("[data-test-id='password']").setValue("qwerty123");
        $("[data-test-id='login-button']").click();

        $("[data-test-id='greeting']").shouldHave(text("Привет, anna!"));
        $$(".book-card").shouldHave(sizeGreaterThan(0));
    }

    @Test
    void wrongPasswordShowsError() {
        $("[data-test-id='login']").setValue("anna");
        $("[data-test-id='password']").setValue("12345");
        $("[data-test-id='login-button']").click();

        $("[data-test-id='error']").shouldBe(visible)
                .shouldHave(exactText("Неверный логин или пароль"));
        $("[data-test-id='greeting']").shouldNotBe(visible);
    }
}
Configuration.baseUrl

Адрес стенда. Все open("/…") приклеятся к нему. Сменить стенд (тестовый → предрелизный) — поменять одну строку, а лучше вынести в файл настроек (урок 6).

Configuration.browser

Каким браузером запускать: chrome, firefox, edge. Драйвер для него Selenium скачает сам.

open("/login")

В методе с аннотацией @BeforeEach: каждый тест начинает со страницы входа — тесты независимы.

closeWebDriver()

В @AfterEach: закрыть браузер. Следующий тест получит чистый — без куки и входа от предыдущего.

.setValue("anna")

Действие: найти поле (подождав, если надо), очистить и ввести текст — аргумент "anna".

.shouldHave(text(…))

Проверка состояния — ожидаемый результат тест-кейса: метод shouldHave получает аргументом условие text(…) с ожидаемым текстом. Без этой строки тест был бы «кликалкой» без проверки.

sizeGreaterThan(0)

Условие для коллекции: каталог не пустой. Это статический метод класса CollectionCondition.

.shouldNotBe(visible)

Негативная проверка: после ошибки приветствия быть не должно. Тоже ждёт — пока элемент не исчезнет.

Что будет, если в первом тесте сайт поздоровается «Привет, Anna!» с большой буквы?

Тест пройдёт: условие text по умолчанию не учитывает регистр. Если регистр важен по требованиям — нужна строгая проверка textCaseSensitive или exactTextCaseSensitive. Вывод: всегда понимай, что именно проверяет твоё условие.

Когда тест падает

Если проверка не выполнилась за таймаут, Selenide выбрасывает исключение (это AssertionError-наследник, как у AssertJ) с подробным сообщением, а заодно сам делает скриншот и сохраняет HTML страницы:

Читать сообщение — как читать stack trace из модуля 12: ожидаемое значение (текст «Привет, anna!»), где (локатор), фактическое значение (Привет, гость!). Здесь вход, похоже, не случился. Скриншот покажет, что было на экране в момент падения, — открываешь и разбираешься: баг в продукте или проблема в тесте.

Сначала — «мой ли это тест?»

Красный тест — не всегда баг продукта. Сначала проверь: стенд работает? Данные (пользователь anna) на месте? Локатор не устарел? Только убедившись, что виноват продукт, заводи баг-репорт — с шагами, ожидаемым и фактическим результатом и скриншотом.

Как запустить у себя

На сервере нашего курса браузера нет, поэтому задачи модуля сделаны на «заглушках» — обычных Java-классах, которые имитируют страницу. Настоящий Selenide ты запустишь в своём Gradle-проекте, который соберём в уроке 6:

  1. Установлен Chrome (или Firefox) — тот, что у тебя уже есть.
  2. Gradle-проект с зависимостями (подключёнными библиотеками) selenide, junit-jupiter, assertj-core в build.gradle.kts (через testImplementation) — после Load Gradle Changes IDEA сама их скачает.
  3. Тест в src/test/java, запуск — зелёный треугольник ▶ у класса или метода. Откроется окно браузера, и ты увидишь, как тест сам печатает и кликает.
Посмотреть глазами

Первые тесты запускай с видимым браузером и смотри, что он делает. Когда тесты пойдут на CI, там включают «безголовый» режим Configuration.headless = true: браузер работает без окна.

Проверь себя

Поговори с наставником

Напиши: «Объясни мне своими словами разницу между sleep и ожиданиями Selenide, а потом спроси меня, как я понял, — с примером, где sleep ломает тест».

Коротко

  • Selenide — обёртка над Selenium: короткий синтаксис, автоматические ожидания, скриншоты при падении.
  • open — открыть страницу; $, $$ — найти элемент страницы (или коллекцию) по локатору; setValue, click — действия; shouldBe(visible), shouldHave(text/exactText/value), size — проверки состояния.
  • Проверки повторяются каждые 200 мс до Configuration.timeout (4 с). Thread.sleep не нужен.
  • text — подстрока, exactText — целиком; регистр по умолчанию не важен.
  • Configuration.baseUrl, browser, timeout — общие настройки. Каждый тест: открыть страницу в @BeforeEach, закрыть браузер в @AfterEach.
