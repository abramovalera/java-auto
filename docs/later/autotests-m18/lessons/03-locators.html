Локаторы: CSS и XPath

Локатор — адрес элемента на странице. От того, как ты его напишешь, зависит, проживёт тест год или сломается завтра. Главный навык UI-автоматизатора — и тренируется он только руками.

Повторение

Локатор — это адрес

Автотест не видит страницу глазами. Чтобы нажать кнопку, ему нужно точное описание: «тот элемент, у которого вот такой атрибут». Это описание — локатор (от англ. locate — «находить»). Пишут их на одном из двух языков: CSS-селекторы и XPath.

Аналогия: доставка пиццы

Можно объяснить курьеру: «от остановки третий дом слева, второй подъезд, пятая дверь после лифта». Работает — пока не построят новый дом или не перекрасят двери. А можно дать адрес: «ул. Садовая, 5, кв. 12». Он не зависит от того, что вокруг. Хрупкий локатор — первый способ, стабильный — второй.

CSS-селекторы

CSS — язык оформления страниц. Дизайнеры им говорят «покрась вот эти элементы», а мы — «найди вот эти элементы». Короткий и быстрый, его в Selenide используют чаще всего.

Пробел в CSS — не украшение

button.green — «кнопка, у которой класс green». button .green (с пробелом) — «элемент с классом green внутри кнопки». Один пробел — совсем другой локатор.

Сколько элементов найдёт .book-card button? А .book-card button[disabled]?

Первый — 3: в каждой карточке по кнопке. Второй — 1: квадратные скобки без значения [disabled] значат «у элемента есть такой атрибут». Неактивна только кнопка «Нет в наличии».

XPath

XPath — язык путей по дереву документа. Длиннее, чем CSS, но умеет то, чего CSS не умеет: искать по тексту и ходить вверх, к родителю.

XPathЧто найдёт
//inputлюбой input на любой глубине (// = «где угодно ниже»)
//input[@id='nook-search']input с атрибутом: в XPath перед именем атрибута ставят @
//*[@data-test-id='buy-101']* — любой тег. Для тестовых атрибутов так и пишут: тег не важен, пусть верстальщик его меняет
//button[text()='В корзину']кнопка с точным текстом
//h4[contains(text(),'Java')]заголовок, в тексте которого есть «Java»
//div[contains(@class,'book-card')]класс содержит book-card
//*[@data-test-id='book-102']//buttonкнопка где-то внутри карточки 102
//h4[text()='Чистый код']/.... — родитель: карточка, в которой этот заголовок
//div[@class='cards']/divодиночный / — ровно на уровень ниже (как > в CSS)
Ловушка с классом в XPath

//div[@class='book-card'] не найдёт <div class="card book-card">: XPath сравнивает всю строку атрибута целиком, а там "card book-card". Для классов используй contains(@class,'book-card') — или CSS .book-card, который понимает классы правильно.

Как найти кнопку именно у книги «Чистый код», если у кнопок нет data-test-id?

Найти заголовок по тексту, подняться к карточке и спуститься к кнопке: //h4[text()='Чистый код']/../button. В CSS так нельзя: CSS не умеет искать по тексту и не умеет ходить вверх. Это главная причина, по которой XPath живёт рядом с CSS.

🔎 Для любопытных: оси XPath

Кроме .. в XPath есть «оси» — направления движения по дереву: ancestor::div — любой предок-div, following-sibling::button — кнопка-соседка после текущего элемента, preceding-sibling:: — соседи до. Пример: //h4[text()='Чистый код']/ancestor::div[contains(@class,'book-card')]. Нужно редко, но на собеседовании про оси иногда спрашивают.

Правило на практике: сначала CSS по тестовому атрибуту. XPath — когда без текста или родителя не обойтись.

Стабильные и хрупкие локаторы

Любой локатор, который находит элемент сегодня, — рабочий. Хороший — тот, что найдёт его и после изменений вёрстки. Вот лестница: чем выше, тем надёжнее.

Почему низ лестницы хрупкий:

  • Абсолютный путь /html/body/div[3]/div[2]/button зависит от каждого элемента на пути. Добавили баннер вверху — номера сдвинулись, тест упал.
  • Номер элемента (//button)[2], li:nth-child(3) — сломается, если поменяется порядок или добавится книга.
  • Длинная цепочка классов .page .content .left .catalog .row .card .btn — сломается от любой перестройки блоков.
  • Текст зависит от копирайтера и языка: «В корзину» → «Добавить в корзину» — и тест красный.
Нет data-test-id? Попроси

Нормальная рабочая ситуация: автоматизатор пишет разработчику «добавьте, пожалуйста, data-test-id на кнопку оплаты и поле промокода». Это пять минут их работы и годы спокойной жизни твоих тестов.

Практика: составь локаторы руками

Правило этого курса (и практика его автора на работе): локаторы ты составляешь сам. Не копируй из DevTools через «Copy selector» / «Copy XPath» — браузер выдаёт длинный хрупкий путь вроде #root > div > div:nth-child(3) > button. И не проси ИИ «дай локатор» — проси объяснить, почему твой не находит. Глаза и руки учатся только так.

Для каждого пункта: найди элемент в песочнице через Ctrl+Shift+C, напиши локатор на бумажке или в блокноте, проверь его во вкладке Console: $$("твой CSS") или $x("твой XPath") — в ответе увидишь, сколько элементов нашлось. Только потом открывай ответ.

1. Поле поиска — CSS по id

#nook-search. Проверка: $$("#nook-search") → массив из одного элемента.

2. Кнопка «В корзину» у книги 101 — CSS и XPath по тестовому атрибуту

[data-test-id='buy-101'] и //*[@data-test-id='buy-101']. Заметь звёздочку в XPath: тег не важен.

3. Все три цены — одним CSS-локатором

.book-card .price (или просто .price, если на странице нет других цен). В тестах такой «списочный» локатор передают аргументом в метод Selenide $$(…) (урок 4) — он возвращает коллекцию элементов, чтобы посчитать их или проверить тексты разом.

4. Заголовок книги «Чистый код» — XPath по точному тексту

//h4[text()='Чистый код']. Проверь в консоли: $x("//h4[text()='Чистый код']").

5. Все книги, в названии которых есть слово «Java»

//h4[contains(text(),'Java')] — найдёт два заголовка. Точный text()='Java' не нашёл бы ничего: такого заголовка целиком нет.

6. Неактивная кнопка в карточках — CSS

.book-card button[disabled]. Без .book-card в начале нашлись бы и другие неактивные кнопки на этой странице — например, «Проверить» в быстрой проверке ниже, пока ты не выбрал ответ. Отличный пример, зачем уточнять «где искать».

7. Счётчик товаров в корзине (цифра 0)

Хорошо: [data-test-id='cart'] .badge — «значок внутри ссылки на корзину». Хрупко: .badge — значков на реальном сайте обычно много.

Проверь себя

Поговори с наставником

Напиши: «Дай мне кусок HTML и 5 элементов в нём. Я сам напишу на каждый CSS и XPath, а ты скажи, какие из моих локаторов хрупкие и почему». Задача на сайте: «Построитель локаторов» и «Ревизор локаторов».

Коротко

  • Локатор — адрес элемента. CSS: #id, .class, [attr='v'], пробел — «внутри», > — «прямой ребёнок».
  • XPath: //tag[@attr='v'], //*[@data-test-id='…'], text(), contains(), .. — к родителю.
  • По умолчанию — CSS; XPath — когда нужен текст или путь вверх.
  • Лестница стабильности: data-test-id → id → name → класс → текст → путь с номерами.
  • Локаторы пишешь руками и проверяешь в DevTools: хороший находит ровно один элемент.
