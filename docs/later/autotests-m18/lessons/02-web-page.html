Как устроена веб-страница для тестировщика

Чтобы автотест нажал кнопку, он должен её найти. А чтобы найти, надо понимать, из чего сделана страница. Заглянем под капот любого сайта — клавишей F12.

⏱ 20 минут🌐 HTML и DevTools🧩 без Java-кода

Повторение

Страница — это текст с тегами

Когда ты открываешь сайт, браузер получает от сервера обычный текст на языке HTML (HyperText Markup Language — язык разметки). В нём содержимое страницы размечено тегами — словами в угловых скобках. Вот форма входа магазина Nook:

<form id="login-form" class="card">
  <h1>Вход</h1>
  <input id="login" name="login" placeholder="Логин" data-test-id="login">
  <input type="password" name="password" data-test-id="password">
  <button type="submit" class="btn btn-primary"
          data-test-id="login-button">Войти</button>
  <div class="error hidden" data-test-id="error"></div>
</form>

<button> — открывающий тег, </button> — закрывающий, между ними — текст кнопки «Войти». Всё вместе — элемент. У некоторых тегов закрывающего нет, например у <input>: поле ввода не содержит текста внутри.

Элементы вложены друг в друга, как { } в Java: форма внутри страницы, поля и кнопка — внутри формы. Браузер строит из этого дерево элементов — его называют DOM (Document Object Model, «объектная модель документа»).

Аналогия: склад

Страница — это склад. Стеллажи (форма) стоят в залах (страница), на стеллажах — коробки (поля, кнопки). Чтобы робот-погрузчик взял нужную коробку, ему нужен адрес: «зал 2, стеллаж с табличкой "Вход", коробка с наклейкой "login"». Такой адрес элемента и есть локатор — строка, по которой тест находит элемент на странице; о нём следующий урок.

Теги, которые встречаются в тестах чаще всего

ТегЧто этоЧто с ним делает автотест
<input>поле ввода: текст, пароль, галочка (type="checkbox")вводит текст, отмечает галочку, читает значение
<button>кнопканажимает, проверяет «активна ли»
<a>ссылка, адрес — в атрибуте hrefпереходит по ней, проверяет адрес
<select> + <option>выпадающий списоквыбирает пункт
<div>, <span>«коробки» без особого смысла — из них собрана вёрсткачитает текст сообщений, карточек, счётчиков
<h1>…<h6>заголовкипроверяет, что открылась нужная страница
<ul>/<li>, <table>/<tr>списки и таблицысчитает строки, ищет нужную
<form>форма, объединяет поля и кнопку отправкиобычно служит «контейнером» для поиска

Учить HTML как верстальщик не нужно. Тестировщику достаточно читать его и понимать, где какой элемент.

Атрибуты: таблички на коробках

Внутри открывающего тега пишут атрибуты — пары имя="значение". Они уточняют элемент. Для автотестов важнее всего вот эти:

id="login"

Уникальный номер элемента на странице. По правилам HTML двух одинаковых id быть не должно (хотя на практике бывает — это баг вёрстки).

class="btn btn-primary"

Классы оформления — для дизайна (цвет, размер). Через пробел — несколько классов: здесь btn и btn-primary. Один класс носят много элементов сразу.

name="login"

Имя поля, под которым значение уйдёт на сервер. Обычно у полей форм стабильное.

type="password"

Вид поля или кнопки: text, password, checkbox, submit.

placeholder="Логин"

Серая подсказка в пустом поле. Это текст для людей — его могут перевести или переписать.

data-test-id="login-button"

Атрибут специально для тестов. Всё, что начинается с data-, браузер не показывает и дизайн не трогает. Разработчики добавляют такие атрибуты по просьбе автоматизаторов — и обещают их не менять. Название бывает разным: data-test-id, data-testid, data-qa, data-autotest.

Почему не искать кнопку по классу btn-primary? Потому что классы — для дизайна. Завтра дизайнер сделает кнопку зелёной, класс станет btn-success, и тест упадёт, хотя кнопка работает. А data-test-id никто, кроме тестов, не использует — его незачем трогать.

У элемента <div class="error hidden" data-test-id="error"> сколько классов?

Два: error и hidden. Классы в атрибуте разделяются пробелами. Класс hidden здесь, скорее всего, прячет блок ошибки, пока ошибки нет, — после неудачного входа его уберут, и блок станет видимым.

DevTools: рентген для сайта

В каждом браузере есть инструменты разработчика — DevTools. Открываются клавишей F12 (или правый клик по странице → «Просмотреть код»). Это главный инструмент автоматизатора наравне с IDEA.

  1. Найти элемент. Нажми Ctrl+Shift+C (стрелочка в левом углу DevTools) и кликни по кнопке на странице. Во вкладке Elements подсветится её HTML со всеми атрибутами.
  2. Прочитать атрибуты. Есть data-test-id? id? Отлично. Есть только классы вида css-1x8f3k? Их генерирует сборщик — после следующей сборки они другие. Такие брать нельзя.
  3. Проверить локатор. Во вкладке Elements нажми Ctrl+F и впиши локатор. Справа появится «1 of 1» — локатор находит ровно один элемент. «1 of 3» — элементов три, локатор надо уточнить. «0 of 0» — ошибка в локаторе.
  4. Консоль. Во вкладке Console можно спросить: $$("[data-test-id='login']") — вернёт все элементы по CSS-селектору, $x("//button") — по XPath.

Есть в HTML ≠ видно на экране

Важная тонкость для тестировщика. Элемент может быть в дереве DOM, но пользователь его не видит: блок ошибки спрятан классом hidden, всплывающее окно ещё не открыто, элемент за краем экрана. Поэтому автотесты проверяют не «элемент существует», а «элемент виден» — как человек.

👁️

visible

Элемент есть и показан на экране. Только по видимому элементу можно кликнуть.

🫥

hidden

Элемент есть в DOM, но спрятан. Например, ошибка до первой попытки входа.

🚫

disabled

Виден, но неактивен: серая кнопка «Купить», пока не выбран размер. Атрибут disabled.

Ещё одна тонкость: у поля ввода введённый текст лежит не между тегами, а в его значении (value). Поэтому «текст элемента» и «значение поля» в тестах проверяют с разными условиями — text и value, увидишь в уроке 4.

Сайт показывает ошибку «Неверный пароль» через полсекунды после нажатия «Войти». Тест сразу после клика проверяет, что ошибка видна. Что будет?

Если проверить мгновенно и один раз — тест упадёт: ошибка ещё не появилась. Это классическая причина «мигающих» тестов. Selenide решает это сам: его проверка состояния (shouldBe, shouldHave) не проверяет один раз, а ждёт до 4 секунд, пока условие выполнится. Подробно — в уроке 4.

Проверь себя

Поговори с наставником

Напиши: «Я открыл DevTools на сайте ____. Вот HTML кнопки, которую я нашёл: … Какие атрибуты в нём стабильные, а какие могут поменяться?»

Коротко

  • Страница — HTML: элементы из тегов, вложенные друг в друга. Браузер строит из них дерево — DOM.
  • Атрибуты уточняют элемент: id — уникальный, class — для дизайна, data-test-id — для тестов.
  • DevTools (F12): Ctrl+Shift+C — выбрать элемент, Ctrl+F в Elements — проверить локатор («1 of 1»).
  • Есть в DOM ≠ видно на экране. Тесты проверяют видимость, как человек.
